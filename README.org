#+title: Yuanxu · 垣序

* Yuanxu: Model · Compose · Evolve

Yuanxu is the romanization of 垣序. The first character, 垣 (yuán), evokes
the Three Enclosures of traditional Chinese astronomy. Each enclosure groups
stars within a region of the sky. The second character, 序 (xù), means order.
The name reflects how Yuanxu models systems as objects with boundaries and
gives their relationships, composition, and evolution an explicit order.

The repository is [[https://github.com/tao3k/gebril-yuanxu][tao3k/gebril-yuanxu]]. The root [[file:gerbil.pkg][gerbil.pkg]] owns the
single =yuanxu= Gerbil package. Library modules use =:yuanxu/...=;
there is no second package root or old-namespace forwarding layer. A consumer's
checkout directory may still be called =core=; this filesystem choice does not
change a module's identity.

** Ordinary dependency usage

Consumers declare the dependency and explicitly import the libraries they need.
They do NOT need to select a Yuanxu prelude:

#+begin_src scheme
;; Consumer gerbil.pkg
(package: my-application
 depend: ("github.com/tao3k/gebril-yuanxu"))

;; Consumer source
(import :yuanxu/module-system/source/link)
#+end_src

Use a chosen revision in the dependency reference when reproducibility requires
it. Merely declaring a dependency does not execute a Script or select modules.

** Optional prelude

[[file:prelude.ss][prelude.ss]] lives directly beside =gerbil.pkg=. Its file-local
=package: tao3k/yuanxu= gives this single entry the public identity
=:tao3k/yuanxu/prelude=; the root library package remains =yuanxu=.
There is no =lang/= directory or =:yuanxu/prelude= forwarding alias.
Consumers may deliberately select the optional language in their own package:

#+begin_src scheme
(package: my-configuration
 prelude: :tao3k/yuanxu/prelude
 depend: ("github.com/tao3k/gebril-yuanxu"))
#+end_src

Ordinary library imports do not require this choice. Yuanxu itself defaults to
its own prelude; the prelude and its small build bootstrap explicitly use
=:gerbil/core=. The build binds the actual root prelude's runtime module context
before reading implementation sources, so source-only bootstrap does not need
a previously installed Yuanxu language. Role-specific module/config preludes
retain their phase duties. Compile-time POO construction declares its runtime
=for-syntax= dependency explicitly. [[file:t/prelude-test.ss][The focused prelude test]] checks phase bindings;
[[file:t/package-bootstrap-test.ss][the cold bootstrap test]] checks the source-only build entry.

* What Yuanxu owns

Yuanxu is the =yuanxu= Gerbil package: reusable POO mechanisms shared by
Agentic AI Lab, gerbil-parser, and other consumers. The package root is the module
root, so consumers import a precise owner such as =:yuanxu/module-system/config=.
There is no eager umbrella module or compatibility alias.

Core depends on Gerbil v0.19 and =gerbil-poo=; it does not depend on Agentic AI Lab,
ASP Scheme, or a product runtime. Agentic AI Lab includes Core as a Git submodule and
builds its sources before its own modules. It does not repeat that submodule as
a =gerbil.pkg= dependency.

* Responsibility map

| Area | Shared mechanism |
|------+------------------|
| =object-family/=, =types.ss= | POO object families and Types |
| =object-syntax/path-slots= | Bounded dotted-path declarations lowered to POO refinements |
| =graph/=, =composition/lineage.ss= | Unified graph topology, ordered POO operations and pure lineage analysis |
| =contribution/= | Contribution values, capability admission, receipt issuance and revocation |
| =module-system/= | Runtime Module values, schemas, inheritance, SourceRef, static Loader and Catalog |
| =profile-composition/= | Indexed Module Profile selection and pure ProfileBundle composition |
| =observability/= | Observations, feedback, slot presentation, memory sampling, testing Case |

Within =module-system/=, =types.ss= and =objects.ss= own values and Contracts;
=funs.ss= and =graph/funs.ss= own pure operations; =config.ss= owns generic
interface construction. The =schema/=, =source/=, =loader/=, and =catalog/=
subdirectories separate their respective mechanisms. Consumers import these
leaf owners directly.

Semantic Module imports use POO prototype composition. Gerbil POO's C4
orders and de-duplicates ancestors; the =contributions= slot rule places local
values before inherited values. Core does not add a general-purpose merge
evaluator. Explicit graph contributions execute once in declaration order.
Their receipts record application and whether that pass changed the graph; they
do not assert idempotence or fixed-point convergence.

CLOS consumers import =:clan/poo/clos= from Gerbil-POO. Its CLOS layer
adds multiple dispatch, method combination, and class lifecycle over
the existing object and Slot model.

* Boundary with Agentic AI Lab

Core values are inert until a product owner admits or executes them. Agentic AI Lab
owns its Module branding, default authoring Profile, Loader selection, source
interpretation, Doctor presentation, Profiles, and runtime handoff. Core's
contribution verification can issue or revoke a host-trusted receipt; it does
not grant runtime authority or execute an effect.

The remaining Agentic AI Lab =src/module-system/= is being separated by ownership:
shared mechanisms move here, while product policy stays in Agentic AI Lab. A file's
location during migration is not a second permanent implementation contract.

* Build and test

Use one explicit package environment and the official Gerbil commands:

#+begin_src sh
export GERBIL_PATH="$PWD/.gerbil"
gerbil deps --install
just build
just test-file t/testing-script-test.ss
just test-directory modules
just test-build-input-context-mutations "$PWD/.cache/build-input-context"
just test-selected-modules
#+end_src

=just build= delegates to =gerbil build=. Test aliases only supply the original
resource limits and arguments to =gerbil test=. There is no development test
executor or generic launch-receipt admission layer. Use =just test-file PATH=
for a focused run and =just test-directory GROUP= for an ordinary CI domain.
The CI metadata inventory checks exact coverage; CI does not append another
full-suite run after the domain jobs.

Compiled callback tests require =just test-mop-store-boundary DIRECTORY=;
source-gateway tests require =just test-source-tail-gateway DIRECTORY=. These
retain the existing compiler limits, coherent source selection and artifact
checks. Authority tests require an isolated =CORE_STORE_ROOT=. The CI workflow
performs this preparation explicitly rather than silently interpreting compiled
fixtures as source. See [[file:dev/sysml/20-module-loading/20.30-test-discovery-and-domain-demand.org][the test execution boundary and preparation map]].

Ordinary tests use a 2 GiB VM heap; ten-thousand-module cases use 4 GiB with
the 180-second Case performance deadline. The dense declaration and selection
cases temporarily disable that performance ceiling for a CI timing run and
inherit the normal 600-second resource watchdog; all assertions remain. This
diagnostic run does not qualify the 180-second requirement. Compiler capacity follows actual host
cores. A failing performance or idle gate remains a failure. Reproduce from
the exact checkout and pinned toolchain; keep complete failed logs in ignored
cache or expiring CI artifacts. Production build memory is not a test quota.

Core's =t/= tests cover shared semantics. Agentic AI Lab retains product selection
and cross-package integration tests.
