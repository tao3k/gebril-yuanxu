#+title: 10.11 Owner Currentness and Publication View
#+language: en
#+property: STATUS design-review

* Required separation

The current =source/link.ss= merges every known publication's preparation and
admission roots. [[file:10.10-first-demand-implementation-obligations.org][10.10]] records the measured scope replay multiplication and
the rejected fixed-collector experiment. This document specifies the evidence
needed to change the replay domain, not a replacement loader or cache.

Keep three relations separate:

| Relation | Existing mechanism | Meaning |
|----------+--------------------+---------|
| Module owner to Module provider | Selected dependency graph | Which owners a requested scope/Build/Test actually needs |
| Certificate receiver to POO read receiver | POO observation and native reverse dependencies | Which Type, policy, source or method state can invalidate a certificate |
| Published snapshot to certificate and registration | POO component publication | Which immutable view and ticket authorize that read |

A Module =requires= index does not register every POO Type/policy input.
A publication head pointer does not certify the mutable metadata it refers to.
Copying that metadata into another table does not create either authority.

* Selected root projection

=PublicationReads.ScopeProjection.ScopeCurrent= requires current shared
source-policy facts plus the original receipt of every owner in the selected
Module dependency closure. =scopeRoots= appends their roots to the shared roots.
=projected_current_exact= proves that replaying this projection is equivalent
to this scoped contract when the indexed walk supplies exactly that closure.

The existing =merge-publication-read-roots= may normalize root identities when
constructing the receipt. Retain its spine for later native topology lookup.
Each actual independent effect boundary still authenticates original records
and their signed dependencies; no previous success is restored. Construction
must read already admitted source/publication evidence and create zero business
scopes. The closure includes required providers and mandatory branches, not just
the tags that chose the initial roots.

This contract deliberately does not claim the entire selected graph is current.
=local_scope_does_not_certify_unselected_owner= proves a counterexample: one
selected owner remains current while an unrelated owner's receipt is stale.
Whole-graph build/test/certification keeps its whole requested proof. The
existing global link guard is therefore not interchangeable with the scoped
contract without an explicit integration change and regression controls.

Every genuinely global policy fact must remain in shared support. A narrower
root list chosen by its consumer cannot decide that a collision, source-cut or
Contract obligation is irrelevant. The source/Contract producer must issue the
projection against the actual immutable view.

* Controlled edit transport

=PublicationReads.TrackedEdit.Covers= requires native registration of every
receiver in a certificate's transitive original read support. These are actual
POO receiver identities, including shared Type/policy inputs, not matching names
or nominal owner labels. Conservative extra registration is permitted.

=clean_owner_has_no_changed_read= proves that an owner outside the affected
old reverse closure has no support receiver in the changed set. Combined with
the native writer frame, =retain_current_after_tracked_edit= preserves that
owner's existing currentness. The runtime may then retain its evidence through
the existing publication path without rewalking the directory or its proof.
The law does not itself execute a reverse traversal. The existing
=IncrementalRoles.recheck_owners_exact= supplies the indexed affected set.

The writer frame is essential: it must cover every changed freshness fact,
including issuance, route, value/state and source effects. It is derived from
the real producer/write operation, never a caller-supplied purity Boolean.
The proof retains the captured root identity and signed dependency lists.
Dependency declaration changes use the old reverse index for invalidation and
the new forward graph for admission, as in the existing publication model.

=DependencyPublication.registration_membership_matches_cold= specifies the
successor reverse index from the exact predecessor and the rewritten consumer
rows. Registrations of other consumers are inherited. A rewritten consumer
keeps precisely its successor providers, so an old-only provider must lose
that consumer. =exact_of_registration_delta= composes these laws with the
forward frame to obtain the publication's exact-index premise. The native
implementation must establish the laws through the existing POO persistent
bucket edits. The theorem does not certify a particular bucket iterator or
claim its enumeration cost.

The following records are historical investigations at the revisions named
below. Candidate runtime paths are not asserted to be present in v0.1.0, and
partial or failed checks do not qualify its performance or mutation gates.

For an unaffected owner, =TrackedEdit.retained_demand_matches_successor=
requires the exact retained root spine and unchanged signed edges on its
unchanged receivers. It then proves equality of old and successor demanded
support. =retain_current_in_successor= combines this shape guarantee with the
writer's separate freshness frame. Unreported edges can introduce new
required reads even when the root and its previously checked value stay live.

=retained_preorder_matches_successor= strengthens the frame to ordered
traversal. The same signed rows give the same pending and visited lists at
every fuel bound, including before the walk finishes. The existing indexed
discovery refinement transfers the result to its ordered projection. This
retains the order needed for first-refusal diagnostics when an owner reuses
the captured support.

Two new constructive counterexamples constrain the implementation:

- =incomplete_index_can_miss_stale_support=: an omitted shared provider edge
  makes an affected owner appear clean even with a correct writer frame.
- =untracked_write_cannot_transport_currentness=: a complete index and unchanged
  reported roots cannot transport approval after an untracked freshness change.

Raw read-table edits, route replacement, unknown callbacks and filesystem
mutation retain ordinary checking unless the real issuer supplies that full
frame. A witness revision alone cannot substitute for these premises.

* Bind the same publication view

=DependencyPublication.successful_read_keeps_view= strengthens the existing
concurrent-read law: a successful read retains the complete captured state,
not just its returned certificate/index fields. Root projections are functions
of that same immutable bundle. =TrackedEdit.publication_read_keeps_current_roots=
composes this view binding with controlled-edit currentness transport.

Native correspondence must bind generation, ticket, owner certificate,
forward/reverse registration and receipt roots together. A callback that
commits a rival generation cannot release a mixture. Retired tickets and failed
admissions retain the existing refusal/fencing behavior. No new epoch store or
parallel certificate registry is needed.

A producer that returns from an external effect must stage against its
original snapshot handle. Checking the head and then asking =stage= to select
the current one leaves a gap in which a rival can publish. The POO candidate
uses =stage expected:= to authenticate and bind the handle under the head
lock. Submit retains its own head and ticket checks. Lean's
=expected_snapshot_binds_exact_handle= covers the identity binding, and
=GraphSnapshot= now exercises a rival before staging as well as a rival
during admission. The native case keeps old and new certificate objects
paired with their respective graphs across dependency deletion, refusal and
subsequent provider edits.

handoff and joint/mismatched artifact refusals. The trial qualifies that
consumer call path. The checked-in Core dependency still selects its previous

POO already has =schedule-invalidation= continuation, weak dependency stamps,
witness trees, construction caches and coordinated component snapshots. Their
preconditions still matter. =component-publication:call-with-snapshot= currently
calls =graph-cache-current!= on the complete graph; wrapping a scope in it does
not magically provide a scoped proof. Likewise witness-tree freshness covers
registered supported writes, not arbitrary raw metadata mutation. The actual
source certificate and its write coverage must be connected before using these
mechanisms to avoid the global replay.

The current directory =.refresh= constructs a new Context and offers native
reader contexts for checked transfer. It does not submit a Module source delta
through component publication. The build-artifact completion issuer uses that
publication API for a different, single-completion domain; it is not the Module
certificate publisher. Reusing either fact as proof of this integration would
be incorrect.

The producer audit found a separate upstream handoff gap at POO =6446abe=.
=component-publication= retains a lineage invalidation continuation, but
=feedback-graph:%feedback-component-revision-action= passes it only through
the non-owned branch. =owned-component-revision= calls
=cache:%revise-with-builder=, whose schedule revision walks the successor
reverse index afresh. Existing continuation tests therefore do not prove reuse
on the main owned-source publication path.

The new local LeanPoo =GraphRevision= draft proves
=Revision.apply_reads_frame= and =StrongComponents.edited_root_closure_exact=:
with stable node identity/support, editing rows only at invalidation roots
preserves the affected set between old and successor graphs. The proof allows
cycles. =missing_edited_consumer_is_unsound= shows why every edited consumer
must be a root. =retained_root_count_exact= certifies retention of every old
root using distinct native keys; =accumulated_roots_exact= permits continuing
the old work in that case. A dropped root requires restarting from the exact
replacement roots on the same old reverse index. The focused 78-job build
passed; these are structural laws, not a Scheme refinement or latency proof.

Connect that continuation through the existing owned schedule/cache path before
claiming append-only native work. Do not reuse the old traversal across changed
SCC group identities without their mapping proof. =restage= replaces a complete
proposal, so dropped roots also need explicit handling: a previous cumulative
visited set is not automatically the exact closure of the replacement's roots.
The issuer must derive these conditions from its real revision ticket; a caller
must not provide a clean-owner predicate. Existing complete paths remain the
safe fallback while those premises are unavailable.
