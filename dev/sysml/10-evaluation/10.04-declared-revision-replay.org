* Where the native MOP can own a projection

| Existing entry | Authority | What it cannot supply |
|----------------+-----------+-----------------------|
| Private =object-record-read= | Mints registry/closure association and copied dependency payload | Not accessible as a Core-issued certificate |
| =object-read-issuance= | Inspects the original native association and copied payload | Does not grant authority to mint a replacement record |
| =object-read-issued?= | Re-authenticates record, original closure and exact dependency sequence | Does not certify current external sources |
| Private =call-with-issued-reads= | Authenticates closure, builds preorder and receiver set, installs dynamic frame, checks after consumer | No retained structural projection in this REV |
| =replay-slot-reads!= | Checks before each visitor and again after the consumer | Passing a cached list still reconstructs traversal structures |
| =reobserve-slot-reads!= | Delivers ORIGINAL tokens within the same protected native traversal | Not a shortcut around issuance or final checking |
| =ConstructionCache.start / refresh= | Reuses checked component values/schedules for its declared source | Does not authenticate MOP reads or automatically observe reflected payload edits |

The common ownership location is =call-with-issued-reads=, not Core's reader.
Both public replay routes already delegate to it. A future retained projection
must remain a private native derived value under that same issuer and boundary.
It may retain preorder and a read-only receiver membership table; it must not
retain a mutable DFS visited state or a successful admission verdict.

The actual entry currently contains:

#+begin_src scheme
(without-observation (lambda () (for-each collect roots)))
(let (traversal (reverse ordered))
  (parameterize ((active-read-replays
                 (cons receivers (active-read-replays))))
    (begin0 (consume traversal require-current!)
      (without-observation
        (lambda () (for-each require-current! traversal))))))
#+end_src

The producer can derive a structural reuse key from ordered root identities and
their signed dependency sequences. Each hit must authenticate every retained
record against the live registry/original closure; same root identity or receiver
revision alone is insufficient. A changed signed sequence is refused, not silently
normalized. New roots require a new projection; new child receivers require their
own issued records. Supported invalidation clears native value/read state.
Native frame installation/unwind and preflight ordering remain per invocation.

This REV has no retained projection entry. Introducing a POO object in Core with
a cached traversal slot would neither obtain issuer authority nor avoid native
traversal construction. No such object, Core cache protocol or Builder was added.
Implementation of a native projection remains a separate dependency change;
this study does not claim it has been implemented or benchmarked.
