#+title: Efficient Caching — Ownership, Effects and Measured Work

* Scope and evidence

[[file:10.01-efficient-caching.sysml][SysML v2 model]] describes native cache ownership and effect
boundaries. It is a development model, not a production module, user API,
Builder or replacement cache format. Structural constraints express obligations;
they are not proofs that Scheme implements them. No SysML parser/solver run is
claimed. The action declarations express required ordering, not timing bounds.

The model uses the official [[https://github.com/Systems-Modeling/SysML-v2-Release/blob/master/sysml/src/examples/Vehicle%20Example/SysML%20v2%20Spec%20Annex%20A%20SimpleVehicleModel.sysml][SysML v2 example]]
as syntax reference. It does not copy domain behavior from that example.

The installed-runtime follow-up is [[file:10.02-runtime-accounting.org][10.02 Runtime Accounting and Source-Window Work]].
It replaces new raw field-7 instrumentation with native =##exec-stats= while
retaining the historical receipts below. Corrected VM accounts still do not

| Result | Existing owner | Reuse identity | What must still run |
|--------+----------------+----------------+---------------------|
| Lazy slot result | POO receiver/MOP | receiver, slot, issued revision and dependency graph | native invalidation and dependency replay |
| Shared graph computation | feedback-cache / generalized graph | native graph and retained closed result | guards and authoritative publication-head check |
| Compiled test products | Core .compile + component-publication | exact selected sources, compiler context, identities and output directory | source, approval, record and product checks |
| File bytes during pure validation | existing source-read window | exact path within the same bounded pure check | a fresh window after every effect |
| Test verdict | native Harness | none across explicit runs | every selected Case and final Harness admission |

There is no global cache of successful currentness, no inherited passing verdict,
and no all-modules scan to obtain a hit. Recovery is internal to demanding the
selected publication. A public =init.exports.restore*= family would expose
implementation sequencing without establishing stronger atomicity. Do not add
it merely to name the internal cache. If an independent recovery use case later
exists, first define its effect, ownership and failure contract.

An internal name or prefix is a discoverability convention, not an access-control
proof. Authority stays with the actual native publication owner and retained
issuance. Ordinary users configure values and invoke the selected execution;
they do not sequence restore, invalidation, source checks and Harness startup.

* State and effect fences

| Transition | Gate | Reuse allowed |
|------------+------+---------------|
| unbound -> selected | selected init graph and demanded files | lazy metadata only |
| selected -> recovered | selected package approval matches current projection | retained native issuance, not a verdict |
| selected -> building | no approved completion | owned fresh staging |
| recovered -> admitted | current sources, record and product digests | current receiver's admitted publication |
| admitted -> running | currentness immediately around explicit Make / Harness effects | no previous effect's currentness result |
| running -> admitted | successful Harness and fresh return checks | receipt for this explicit execution |
| any checked state -> rejected | stale source/head, missing or replaced record/product | no fallback that blesses altered outputs |

Atomicity is the native =component-publication.stage/submit!= installation of a
receiver-owned result. It does not make external filesystem edits, arbitrary
callbacks or the whole Harness atomic. Source freshness and conditional external
effects remain separate requirements. A directory lock coordinates cooperating
builders; it does not authenticate the package installation.

* Derivation and sharing

A child receiver gets its own effective computation. It may reuse verified
products only when the selected build identity matches; a parent's cached plan
cannot substitute for the child's final configuration. Object identity can
deduplicate shared dependency nodes, while all dependency edges, both independent
requirements and the first-diagnostic/observer ordering must survive.

Do not replace native protection with membership scans on every hot access.
The latest Table optimization reuses exact structural sharing and still checks
instantiation. Any analogous Core optimization needs measured repeated work,
an unchanged semantic boundary and a negative control before adoption.

* Cost model and acceptance

Measure distinct intervals: context setup; init import; selection delta; support
projection; recovery; full artifact/currentness admission; Make process startup;
=std/make= import; Make scheduling/compilation; Harness startup; Case bodies;
return checks. Recovery includes nested admission: its time must not be added
again to inclusive currentness totals. Report actual compile actions, not spec size.

Warm acceptance requires a new Just process, unchanged selected inputs, approved
products, zero compiler actions, a fresh Harness verdict and unchanged stale-source,
joint-replacement and parent/child refusal controls. It does not require zero
filesystem reads or zero process launches. Optimize only an identified redundant
operation; preserve checks separated by effects. A faster run with different
Case ownership is not an A/B improvement.

* POO publication reuse after zero compilation, 2026-10-22

** Actual owner and the expensive work around a hit

The primary cache path is =issued-state= in =building/artifacts.ss=:

#+begin_src scheme
;; Existing native owners; not a second Core cache protocol.
(let (owner (hash-get issued graph))
  (and owner
    (closed-raw
      (group-closed
        (graph-cache-ref (publication.current owner) 'completion)))))
#+end_src

The weak table associates the exact Graph receiver with its native publication
owner. The actual completed result lives in the native graph/closure machinery.
The slot/MOP cache and dependency replay are a separate existing owner: neither
should be replaced by a Make layout model or a global currentness cache.
In-process completion lookup, cross-process recovery and validation of mutable
external sources are three different operations. A new process cannot inherit
another VM's object identities; recovery establishes its own publication.

The current =.compile= boundary deliberately stages =build-required= before the
opaque Make action. It then installs a checked completion using native
=stage/submit!= and the expected head. Removing that invalidation solely because
the preceding lookup hit would leave the previous completion publishable during
the action. Likewise, retaining a completion does not authorize skipping source,
product, approval or post-Harness checks. Those are not failed POO cache hits.

Diagnostic mode now measures native =issued-state= lookups and their count
separately from inclusive artifact/currentness checks. Disabled diagnostic mode
does not allocate a timing table or a per-lookup timing closure. No user-facing
=restore*= API, persistent cache format or alternative publication owner is added.

** Bounded replay reduction, not a cache of passing checks

=publication-metadata-current= is private to the reader. Its two non-void
replay closures are made only by =publication-read-current=; contributors do
not supply them. With no source observer, they call the existing native
=replay-slot-reads!= with a void visitor. The native path authenticates records,
checks metadata routes before dispatch, and reads revisions/instance identity;
it does not invoke a cold getter or a contributor MOP hook. The intervening
policy guard is =source-object-policy= over captured native revisions.

Consequently the same serial call retains ordered preparation replay, admission
replay and policy checks, but omits the third preparation replay. There is no
stored successful check and no reuse across calls. When a source observer is
present before replay, the original third replay remains, even if its callback
removes itself. Location/file validation, reader/source tails, package callbacks,
final .admit and Harness boundaries remain independent and unchanged.

Do NOT concatenate both root graphs into one preflight merely to reduce DFS
work: authenticating an unissued admission record before checking a stale
preparation record can change the first diagnostic. Retain original record
identity, both traversals and their order. No dependency edge or delivery event
is removed by the tail reduction. This is not a general law for opaque checkers.

** Remaining opportunities

Native Graph caching already eliminates reconstruction on the second demand.
New-process import/bootstrap and role evaluation are separate costs, not cache
misses to repair by storing successful admission. Source checks around role
initializers, callbacks and final return remain mandatory. Further native
replay work needs measured visited nodes/allocation/GC and the same authentic
record, first-diagnostic and observer-order controls; work-count algebra alone
does not establish a capacity or latency improvement. Do not broaden a pure
source window across those effects or add a persistent worker/cache protocol
merely to hide independent-process startup.

** Explaining the warm-currentness reversal (2026-10-22)

The next qualification separates actual native DFS visits, physical source IO,
CPU, GC and wall time. It does not infer work from replay-call counts alone.
The existing =trace= option now makes twenty bounded same-VM demands before
running the original Harness once. Ordinary =just test-file= makes no extra
demand, allocates no diagnostic report and does not force GC. Every demand
retains its independent currentness check and the original Graph identity.

The private measurement factory owns its scalar table throughout the action.
=module-source-measure-replay= uses a fixed scalar visitor, not a source/slot
observer: enabling those observers changes the required tail from two replays
back to three. No read token, receiver or traversal is stored in the report.
The =source-read= span surrounds the actual port read; source counters reuse
the existing observation sites without enabling their callback. Statistics
spans are inclusive; nested spans must not be added together. These are
instrumented attribution results, not corrected uninstrumented benchmarks.
The native visitor reports one visit per current record in each successful
replay. Totals sum those per-replay identity-deduplicated visits; they are not
distinct receivers across all calls or dependency-edge counts. Early native
authentication failure can precede any visitor call. Preflight authentication
and final native checks still run; a zero visitor count does not certify that
a rejected graph did no work.

qualification context as above. No compiler source, heap, idle/total budget,

*** Allocation qualification and the optimization decision

The VM's raw statistics field 7 is NOT qualified as an allocation counter for
this workload. It goes backwards across collections and, in the earlier
twenty-sample run, jumped from approximately 13.4 million to 530.7 million on
a non-GC demand with unchanged work. Keep =allocation-counter= deltas as raw
diagnostics; =allocation-invalid= flags negative/GC-crossing spans but zero
does not certify the stream. Do not interpret positive deltas as allocated
bytes, retained memory or per-node ownership. No GC is forced to manufacture a
clean result. A reliable allocation measurement remains an explicit gap.

There is no evidence here of renewed POO Graph construction on warm demand:
the receiver is identical, role evaluation stays cold and native Make remains
at zero. The source-read counts already reflect one existing pure window;
they do not establish that all 128 reads are redundant. Saving the window or
its successful verdict for the next demand would break changed-source refusal.
No additional runtime check was removed on the strength of these timings.
The earlier ordered-tail reduction remains, including its observer fallback.
Further optimization must account for native traversal construction and a
qualified allocation stream before proposing reuse of structure. It must not
cache authentication/currentness success, omit dependency edges, skip native
checkers or broaden a read window across a callback.

*** SysML, QNT and Lean correspondence

=SelectionCostSample= adds separate work, IO, CPU, collection and raw-counter
dimensions to the existing SysML owner model. It is a development model, not
a solver-qualified timing prediction. =SelectionReplay= retains its ordered
diagnostic, two-requirement, parent-isolation and unused-branch invariants.
The =FewerMeansFaster= control deliberately fails when independent collection
cost is introduced: six replay units plus 45 collection units can cost more
than nine replay units. These are illustrative units, not fitted measurements.

Lean =matched_work_bound= requires identical source, collection and wait terms;
=fewer_replays_can_be_slower= rejects the invalid count-to-latency inference.
=remove_collection_for_matched_comparison= is arithmetic accounting, not a
claim that subtracting CPU GC time yields uncontaminated wall performance.
The existing LeanPoo cache-hit law and =SourceWindows= source/competing-demand
laws remain the semantic basis. Native issuance, supported serial checker
routes and stable bytes within each pure window remain correspondence premises.
