* Question

Can replay reuse identity tables and preorder lists without caching admission,
discarding signed dependency edges or changing the first diagnostic?

The owning architecture remains [[file:10.01-efficient-caching.sysml][10.01]].
[[file:10.02-runtime-accounting.org][10.02]] records the allocation-accounting limits.
This study does not change the compiler, add a Core graph cache or relax a gate.

| Structure | Actual owner | Reuse decision |
|-----------+--------------+----------------|
| Receiver value and original read records | =object-%instance / object-%reads= | Already native-cached; cleared together by invalidation |
| Root record sequence | Publication closure | Retained original signed identities; already deduplicated at collection |
| DFS =seen= table | One =call-with-issued-reads= invocation | Never retain populated mutable state across invocations |
| Protected receiver set | One dynamic replay frame | Reinstall per invocation; immutable sharing would require native ownership |
| Ordered DFS list | One native replay | Candidate derived structure only; no public native cached projection exists |
| Successful issuance/currentness/admission | Current check | Never retain as a reusable verdict |

=object-record-read= captures a copied dependency sequence in its private birth
closure. =object-read-issued?= authenticates registry/closure identity AND sequence
contents, not merely the list-spine pointer. Replacing the spine with the same
record sequence remains authentic; adding a dependency to the same root does not.
The same receiver/key pair is insufficient: transient misses can have distinct
signed identities and need not be stored in the receiver's read table.

Supported prototype, default, protocol, parent and instance changes invalidate
native derived state and advance revision through the existing dependency graph.
Parent and child are different receivers, never interchangeable cache keys.
Raw reflection of a read payload is not a supported invalidation operation;
therefore revision equality alone cannot certify cached topology.

* What a future native structural hit must establish

1. Identical ORDERED root record identities, not a root set or receiver/key index.
2. Authentic dependency sequences for every retained reachable record, including
   preparation records and transient misses. A hit still authenticates them.
3. The same preorder, record identity deduplication and receiver protection set.
4. No shared mutable visitation state, and fresh nested dynamic frame ownership.
5. Original preflight ordering, per-record route/current checks before delivery,
   unchanged observer delivery order, and full final checks after the consumer.

The existing entry unconditionally constructs two tables and two list spines.
Core cannot implement this optimization merely by caching a list in a POO slot:
passing it to =replay-slot-reads!= rebuilds these structures; bypassing that entry
loses native authentication and protection. A native issuer-owned derived value
could reuse the STRUCTURE under these conditions, but current public APIs do not
expose that capability. This is a concrete ownership gap, not permission to add
a second Core cache protocol. No production traversal cache is introduced here.

Fresh work includes registry/payload authentication, metadata route validation,
revision/instance/value checks and external-source certification. Callback
effects require independent post-callback validation; the existing pure source
window cannot span effects or separate admissions. Never fuse preparation and
admission preflights: doing so can change the first error.

* Formal correspondence

[[file:../../proofs/lean/YuanxuProof/Admission/SelectionReplay.lean][SelectionReplay]]
adds a fuel-bounded identity preorder and proves:

- =topology_reuse_keeps_identity_order=: identical dependency functions and roots
  produce identical ordered output. This is a conditional refinement law;
  native snapshot extraction is NOT proved by function extensionality.
- =same_root_does_not_certify_edges= and =roots_are_ordered_not_a_set= reject
  weaker cache keys.
- =sharing_seen_suppresses_delivery= demonstrates why visited state is per run.
- =topology_is_not_authentication / topology_is_not_final_currentness= keep
  current authentication independent of structural reuse.

[[file:../../proofs/lean/YuanxuProof/Admission/IdentityDFS.lean][IdentityDFS]] retains
the existing graph closure/termination and reachable final-check theorems.
Those require a finite closed graph and complete discovery; they do not certify
a new native cache extractor. A bounded preorder alone proves neither termination
of arbitrary native cyclic payload corruption nor compiler correspondence.

[[file:../../proofs/quint/SelectionReplayTopology.qnt][SelectionReplayTopology]]
checks a bounded certificate policy and three negative controls: reusing a
passing verdict, ignoring root order, and sharing a populated seen table.
Parent identity, both requirements and untouched unused branches remain explicit.
They are modeled invariants, not measurements of Scheme effects. SysML remains
an architectural allocation without a qualified SysML parser/solver.

* Runtime controls

The existing =t/mop-checker-origin-test.ss= raw-record Case now checks equal
dependency-spine replacement, added-edge refusal before any visitor, restoration,
duplicate-root identity deduplication and delivery on each subsequent replay.
Reflection is destructive fault injection used only in this test. All validation
is performed by the real native issuance/currentness/replay entry, not an alleged
Core authenticity table. The existing service Case retains both requirements,
child obligation evidence, stale parent-plan refusal and source-error ordering.

Cold/warm timing uses the existing =just test-file= entry and trace mode with
20 same-VM demands followed by the original Harness once. A new Just process
starts with cold POO receiver state even when compiled support is reusable.
Counts are construction work, not physical allocation: six successful replays
with 5647 visited records imply 12 table construction sites and 11294 list-pair
construction sites. This is NOT a measured saving; no production path changed.
Timing probes allocate and GC placement can dominate individual samples.

Results are recorded below after serial verification. Preserve source-change
refusal, parent isolation, both requirements, child obligations and unused-branch
laziness. No timeout, heap budget, runtime source or admission guard is changed.

remain its consumer rather than create a competing traversal validator.
