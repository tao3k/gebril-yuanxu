* Question

Can replay reuse identity tables and preorder lists without caching admission,
discarding signed dependency edges or changing the first diagnostic?

The owning architecture remains [[file:10.01-efficient-caching.sysml][10.01]].
[[file:10.02-runtime-accounting.org][10.02]] records the allocation-accounting limits.
This study does not change the compiler, add a Core graph cache or relax a gate.

* Actual runtime owners

The observed declaration diagnostic uses the existing =stages= mode on
=t/module-declaration-10000-test.ss=. It reports
=publication-guard-sweep= for the complete fallback pass and
=observed-metadata-replay= for native read validation inside each guard.
These windows overlap. Observer delivery before and after native validation
belongs to the enclosing guard. The normal Case and its observer still run
with their original limits and checks. Compare the diagnostic separately
with the normal run, since accounting has a per-guard cost.

** Private Interface import state

The installed Gerbil's =core-import-module= records source Contexts in
the expander registry. Evaluation of a top-level =import= also records
the Context as a strong key in =__modstate=, under the runtime import
mutex. The deferred-reader test observed =ready= after the closed
Interface had delivered its POO publication and its expander registry
aliases had been removed. The value in the runtime entry was =void=.
The runtime entry still reaches the Context and its import descriptors.
Counting the expander aliases alone therefore understates retention.

Any lifecycle change must use Gerbil's module evaluation and preserve
the same import authorization, prelude and one-time initializer promise.
Keep authored imports inside the owner Context, including their phase,
initialization order and failure. Releasing private Interface state
requires proving that no other lookup uses its private Context as a
public module. The diagnostic confirms one remaining root. It does not
measure its retained bytes or its share of GC time.

The 16/32-owner census also traced cross-fixture retention after deleting
the first fixture's source tree and collecting twice. The first init's
path and module ID still resolved to the same registered Gerbil Context.
Reading its existing public export binding recovered the identical POO
Exports object, whose cached namespace was still the first fixture's
namespace. The first selection source still held its cached Graph. The
test retained only weak object witnesses and path strings between the
fixtures. Authenticating the historical Graph still refused the missing
source, and the second fixture completed independently.

This identifies surviving runtime roots between fixture lifetimes. The
10,000-owner gate uses one fixture, so the result does not attribute the
single-fixture admission peak to the prior init binding. A comparison of
per-owner publication evidence and reader state remains necessary.

* Prepared Gerbil identity

Preparation resolves the Interface identity with =core-read-module/sexp=.
It keeps the identity on the prepared input and verifies the associated
source bytes and Gerbil package observations. Root-qualified publication
admission reads the Interface again after validation, before comparing the
declared owner. That position matters because expansion and Contract methods
can execute effects.

[[file:../../proofs/lean/YuanxuProof/Admission/PreparedModuleIdentity.lean][PreparedModuleIdentity]]
proves that a prepared identity preserves the first refusal and result if its
complete native inputs still agree with the inputs at admission. It also
proves that a previously matching identity can accept a source whose current
identity fails. Source bytes alone do not establish the premise. The runtime
must also account for the Gerbil reader and package resolution state after
effects. The Scheme admission path still calls the native reader at the
original boundary.

* Ordered source evidence experiment

The existing collector stores accepted rows in reverse order and copies the
spine on replay. The candidate kept them in first-observed order and captured
the last pair before replay. The Lean source-window model proves the ordered
prefix remains exact when an observer appends a row. A runtime control
enrolls a source during replay, mutates it, and checks that the next replay
refuses it with the recorded diagnostic. The source observation and source
admission suites passed with the candidate.

Four guarded 1,000-owner runs in ABBA order all completed. The candidate
reduced sampled process-tree peak from a median 1.484 GB to 1.436 GB.
Post-collection live bytes stayed near 483.65 MB. Graph CPU rose from
19.89 s to 23.78 s and Graph wall from 22.09 s to 27.30 s. GC wall
rose from 1.71 s to 4.05 s. The production candidate was reverted.
The semantic control also applies to the original collector.

* Candidate eligibility and publication evidence

The linker reads the original admitted evidence from each linked
publication when producing the selected runtime record. Its public
=publication-evidence= refers to the normalized candidate, as exercised
by =t/module-declaration-value-test.ss=. Dropping that evidence at the
Graph handoff would change the linked record and its identity contract.

The separate eligibility list probe ran 1,000 times in the guarded
1,000-declaration fixture. It accounted for 3.57 ms CPU and 4.48 ms wall
with no overlapping GC. The complete run passed in 45.105 seconds at a
sampled 1,436,270,592-byte process-tree peak. The probe was removed. The
linear list lookup still has a quadratic worst case for the full roster,
but this measurement does not prioritize an additional index over the
measured publication and replay work.

| Structure | Actual owner | Reuse decision |
|-----------+--------------+----------------|
| Receiver value and original read records | =object-%instance / object-%reads= | Already runtime-cached; cleared together by invalidation |
| Root record sequence | Publication closure | Retained original signed identities; already deduplicated at collection |
| DFS =seen= table | One =call-with-issued-reads= invocation | Never retain populated mutable state across invocations |
| Protected receiver set | One dynamic replay frame | Reinstall per invocation; immutable sharing would require runtime ownership |
| Ordered DFS list | One runtime replay | Candidate derived structure only; no public runtime cached projection exists |
| Successful issuance/currentness/admission | Current check | Never retain as a reusable verdict |

=object-record-read= captures a copied dependency sequence in its private birth
closure. =object-read-issued?= authenticates registry/closure identity AND sequence
contents, not merely the list-spine pointer. Replacing the spine with the same
record sequence remains authentic; adding a dependency to the same root does not.
The same receiver/key pair is insufficient: transient misses can have distinct
signed identities and need not be stored in the receiver's read table.

Supported prototype, default, protocol, parent and instance changes invalidate
runtime derived state and advance revision through the existing dependency graph.
Parent and child are different receivers, never interchangeable cache keys.
Raw reflection of a read payload is not a supported invalidation operation;
therefore revision equality alone cannot certify cached topology.

* What a future runtime structural hit must establish

1. Identical ORDERED root record identities, not a root set or receiver/key index.
2. Authentic dependency sequences for every retained reachable record, including
   preparation records and transient misses. A hit still authenticates them.
3. The same preorder, record identity deduplication and receiver protection set.
4. No shared mutable visitation state, and fresh nested dynamic frame ownership.
5. Original preflight ordering, per-record route/current checks before delivery,
   unchanged observer delivery order, and full final checks after the consumer.

The existing entry unconditionally constructs two tables and two list spines.
Core cannot implement this optimization merely by caching a list in a POO slot:
passing it to =replay-slot-reads!= rebuilds these structures; bypassing that entry
loses runtime authentication and protection. A runtime issuer-owned derived value
could reuse the STRUCTURE under these conditions, but current public APIs do not
expose that capability. This is a concrete ownership gap, not permission to add
a second Core cache protocol. No production traversal cache is introduced here.

Fresh work includes registry/payload authentication, metadata route validation,
revision/instance/value checks and external-source certification. Callback
effects require independent post-callback validation; the existing pure source
window cannot span effects or separate admissions. Never fuse preparation and
admission preflights: doing so can change the first error.

* Formal correspondence

[[file:../../proofs/lean/YuanxuProof/Admission/SelectionReplay.lean][SelectionReplay]]
adds a fuel-bounded identity preorder and proves:

- =topology_reuse_keeps_identity_order=: identical dependency functions and roots
  produce identical ordered output. This is a conditional refinement law;
  runtime snapshot extraction is NOT proved by function extensionality.
- =same_root_does_not_certify_edges= and =roots_are_ordered_not_a_set= reject
  weaker cache keys.
- =sharing_seen_suppresses_delivery= demonstrates why visited state is per run.
- =topology_is_not_authentication / topology_is_not_final_currentness= keep
  current authentication independent of structural reuse.

[[file:../../proofs/lean/YuanxuProof/Admission/IdentityDFS.lean][IdentityDFS]] retains
the existing graph closure/termination and reachable final-check theorems.
Those require a finite closed graph and complete discovery; they do not certify
a new runtime cache extractor. A bounded preorder alone proves neither termination
of arbitrary runtime cyclic payload corruption nor compiler correspondence.

[[file:../../proofs/quint/SelectionReplayTopology.qnt][SelectionReplayTopology]]
checks a bounded certificate policy and three negative controls: reusing a
passing verdict, ignoring root order, and sharing a populated seen table.
Parent identity, both requirements and untouched unused branches remain explicit.
They are modeled invariants, not measurements of Scheme effects. SysML remains
an architectural allocation without a qualified SysML parser/solver.

* Runtime controls

The existing =t/mop-checker-origin-test.ss= raw-record Case now checks equal
dependency-spine replacement, added-edge refusal before any visitor, restoration,
duplicate-root identity deduplication and delivery on each subsequent replay.
Reflection is destructive fault injection used only in this test. All validation
is performed by the real runtime issuance/currentness/replay entry, not an alleged
Core authenticity table. The existing service Case retains both requirements,
child obligation evidence, stale parent-plan refusal and source-error ordering.

Cold/warm timing uses the existing =just test-file= entry and trace mode with
20 same-VM demands followed by the original Harness once. A new Just process
starts with cold POO receiver state even when compiled support is reusable.
Counts are construction work, not physical allocation: six successful replays
with 5647 visited records imply 12 table construction sites and 11294 list-pair
construction sites. This is NOT a measured saving; no production path changed.
Timing probes allocate and GC placement can dominate individual samples.

Results are recorded below after serial verification. Preserve source-change
refusal, parent isolation, both requirements, child obligations and unused-branch
laziness. No timeout, heap budget, runtime source or admission guard is changed.
