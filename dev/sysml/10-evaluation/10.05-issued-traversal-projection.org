The native entry owns:

- A private weak key/value index from the original root-list identity to a native
  cache receiver. Neither side is a global strong root for the read graph.
- An ordinary native cached =projection= slot. Standard slot computation installs
  only a successfully completed private projection; no second value evaluator is
  introduced.
- A private projection containing its owner, copied ordered roots, original
  preorder and read-only receiver membership table. No populated DFS seen table
  or passing authentication/admission result is retained.

Neither the index, its owners, the projection type nor construction helpers are
exported. =object-read-issuance= retains its existing inspect-only authority. Core
cannot mint a projection or supply a purity/immutability flag.

* Reuse and invalidation

| Event | Structure behavior | Authentication behavior |
|-------+--------------------+-------------------------|
| Same live root-list identity and same ordered tokens | Native slot hit | Re-authenticate every saved token in DFS order |
| Distinct root-list identity, even equal contents | Cold projection | Original complete DFS preflight |
| Mutated root order/contents | Replace owner after successful new DFS | Original order/first refusal retained |
| Weak owner collected | Cold projection | No old verdict is available |
| Altered signed dependency sequence | Refuse at the original token | No callback before complete preflight |
| Receiver revision/instance/value changed | Shape is not a validity claim | Original fresh currentness check refuses |
| Transient miss later populated without revision change | Shape can stay the same | Native cache-absence check refuses |
| Child receiver/new issued records | Independent identity/key | Never borrows parent plan/cache validity |
| Failure while building | No owner installed in index | Preserve original exception |

The producer's private birth closure authenticates exact dependency sequences.
Thus, after the copied root sequence matches and all stored tokens authenticate,
their previous preorder still covers the same selected closure. Hit processing
does not inspect unselected object slots. Each call separately installs/unwinds
the selected receiver frame, performs unchanged route/current checks before
delivery, and performs unchanged full final checks after the consumer. External
source checks and final domain admission retain their Core boundaries.

GC eviction is permitted at any time; the optimization is opportunistic, not a
persistent cache or a bound on the number of cold traversals. Receiver invalidation
does not need to erase an immutable SHAPE before the fresh checker can reject an
old token. No stale read is silently refreshed and no getter is rerun by replay.
Callback/source changes cannot reuse a previous passing result.

** Cache construction must not open a callback boundary

Ordinary native object construction dispatches CLOS initialization. Before a cold
cache receiver is allocated, the implementation compares the actual native object
and object-state initializer procedures with their library-initialization values.
If either changed, it uses the original non-cached DFS and does not invoke that
new initializer. A valid existing hit needs no constructor call.

This is derived from runtime metadata; callers provide no purity marker. The
supported sequential runtime and trusted module-initialization premises are the
same as the issuer/metadata-route model. Arbitrary VM/FFI rewriting and concurrent
mutation are not proved safe by this change. Source-file checking is not an
atomic transaction with external files or deployment effects.

* Proofs before implementation

[[file:../../proofs/lean/YuanxuProof/Admission/SelectionReplay.lean][SelectionReplay]]
adds the following checked laws, with the existing LeanPoo dependency held fixed:

- =topology_reuse_on_selected_closure=: equality of authenticated edges on the
  finite selected closure suffices for identical DFS preorder. Edges and getters
  outside that closure need not be inspected. =IdentityDFS= owns closure coverage
  and termination under its existing finite-graph premises.
- =authenticated_edges_match_frozen=: dependency equality derives from native
  registry/original-closure projection, not a public Birth claim.
- =projection_hit / changed_roots_rebuild / weak_eviction_rebuild=: separate native
  value reuse from key change and weak collection.
- =projection_lookup_refines / reuse_preserves_first_diagnostic=: an owned
  structural hit retains the original ordered checking result.
- =receiver_frame_preserved / structural_hit_still_checks_tail=: the selected
  receiver projection and mandatory tail remain unchanged.
- =changed_constructor_uses_uncached_path=: an unrecognized initializer is never
  invoked by cold-cache preparation.

[[file:../../proofs/quint/SelectionReplayTopology.qnt][SelectionReplayTopology]]
models live/evicted owners, root-order changes, receiver revision, altered edges,
forged records and constructor metadata. The existing scoped gate checks 11
positive/expected-negative cases. A new constructor counterexample demonstrates
why calling an unrecognized initializer is not a closed authentication step.

The Lean order/diagnostic equalities are pure laws, not proofs of compiler
correctness or native callback effects. Runtime correspondence is supplied by
the actual native and service regressions below, under the stated premises.
SysML assigns ownership; it is not itself a qualified theorem prover.

* Native regression and measurement protocol

The existing gerbil-poo =issued-read= suite now contains 17 Cases. Four additions
check actual preorder identity, root-order replacement, forged cached dependencies,
transient-miss staleness, child isolation, weak eviction and changed constructors.
Private extern access checks structural identity only; it is not a public API.
Reuse is checked between TWO captures inside a measured no-GC interval, so
collection before the interval cannot falsely fail an allowed cold miss. Explicit
GC occurs only in lifetime unit controls, never in timing windows.

the installed toolchain, within the original 120 s compile bound. Tests retain
their own original Just heap/watchdog policies. Core timing runs use default

tests run serially; no local compilation or formal verification overlaps timing.

The paired images share the =9ebd76f= source baseline. The candidate changes only
the replay entry and its direct import; Core bootstrap layers are identical and
expose no old =clan= fallback. Existing signed test preparation warms both prefixes
before timing. Native dependency rebuild and Core bootstrap reuse are distinct

Three A/B rounds are retained, each new process making 20 same-VM warm demands
then running the original three-Case Scenario Harness once. Cold means cold POO
selection in that process, not an erased compiler/store/filesystem cache. Runtime
certification is rerun in both images; no admitted result crosses processes.
