* Source observations before optimization

1. =instantiate-object!= first computes checked precedence and the complete
   effective thunk table, then installs the receiver instance and preparation
   read. An exception clears the partial native caches before propagation.
2. =declaration-specifications= calls the actual Slot protocol for declared
   descriptors and registers descriptor/type dependencies. An absent explicit
   inheritance protocol alone does not eliminate declaration callbacks.
3. =compute-slot-funs!= builds standard functions, then runs =compute-slot= in
   the existing hash-table enumeration order. Source declaration order and
   prototype order are not claimed to be that execution order.
4. =next= closes over the ONE already assembled standard function. Repeated
   =next= calls return the same function; a factory producing fresh functions
   would change that observation even when their bodies return equal values.
5. The exported =object-%slot-funs= accessor exposes the populated function
   table. Even a receiver with no protocol and no descriptor declarations can
   expose an unforced function and observe its identity before its value runs.

* Which construction may be delayed?

| Boundary | Result |
|----------+--------|
| Value body of an unselected slot | Already lazy; retain existing native behavior |
| Custom construction callback with observable events or refusal | Preserve before first selected-value return and retain native order |
| Standard function observed by a hook's =next= | Materialize one identity before that observation; do not replace it on subsequent =next= |
| Function exposed by full metadata reflection | Materialize before exposure; a missing or proxy entry changes the existing observable API |
| Function absent from a proven restricted observation projection, with no moved callback | Identity projection can be unchanged under deferral, conditional on that observation restriction |
| Every cold entry inferred eligible solely from value-cache absence or no protocol | Unsound |

The conditional row is not a user-maintained purity flag and not an existing
native certificate. Current raw metadata export does not establish absence of
future reflection. Thus this audit does not turn the 3341 cold-only entries into
3341 automatically removable or delayed closures. There is no production MOP
change, second cache or wrapper entry pretending to close that gap.

A future native implementation would need a materialization boundary that also
covers metadata exposure, construction callbacks, exceptions and receiver
revision changes, using the existing native cache/invalidation ownership.
Merely delaying Core calls or returning an incomplete table cannot provide it.
That is a native interface/temporal question, not a manual purity annotation.

* SysML, Lean and Quint responsibilities

The [[file:20.04-payload-ownership.sysml][SysML owner]] assigns:

- Lean =otherThunkIdentityPreserved= and =unobservedThunkProjectionPreserved=:
  identity projection equivalence outside a deferred entry. The theorem has an
  explicit non-observation premise, not arbitrary Scheme purity.
- Lean =exposedThunkCannotDisappear=: a published function identity cannot be
  replaced by an absent entry while preserving the same observation.
- New QNT =ThunkConstruction=: the DISTINCT temporal question of construction
  events, =next= identity, stable repeated function access and complete metadata
  publication. This does not duplicate read-coverage/currentness models.
- Existing QNT =ReadRetention=: all original reads/misses, two requirements,
  currentness across effects, parent isolation and unselected VALUE laziness.
- Scheme consumer regressions: real native functions, actual hook enumeration,
  eager unselected hook refusal, cache cleanup and parent/child identities.

The QNT restricted-kind branch is a mathematical observation restriction.
It is NOT extracted from a native object or asserted as a production fast path.
The model uses two schedules to avoid assuming declaration order; runtime
compares against the actual native enumeration in the same constructed table.
It does not establish a deterministic order across separate hash tables.
