* Attribution from actual entrypoints

The failing log =owner-shell-final-cold-20261025.log= contains fourteen selected
support targets and nine compile announcements, each with a distinct target.
An announcement is a start, not a completed unit. Installed std/make rejects
duplicate target paths before scheduling, tracks completions by module identity,
and derives source/output paths from one settings object. There is no force
request. Thus no within-invocation repeated target compilation was observed.

A failed fresh issuance discards its temporary output directory and publishes
no approval. A subsequent attempt can legitimately repeat cold work. Reusing
these unissued partial products would weaken the current publication boundary
and is not the repair.

The 120-second outer preparation watchdog includes projection, currentness,
recovery, the child Make process and completion admission. The old failure has
10.303 seconds of support projection, plus a 64.306-second selection span that
is outside that watchdog. Nested selection/currentness/GC spans are inclusive;
they must not be added to their parent spans. The old log has no successful
Make receipt or descendant CPU total, so it does not justify assigning all
remaining time to the compiler or to host scheduling.

* Concrete scheduling defect and native repair

=prepare-testing-script= overrode =GERBIL_BUILD_CORES= with the literal =1=.
This silently discarded the existing caller's explicit =2= worker budget.
Installed std/make derives both its worker count and its compiler parallel flag
from this native setting. With one worker it invokes the backend synchronously;
with more than one, native Make drains pending compiler jobs before returning.
The same native completion barrier, products and .compile checks remain in use.

Remove only the forced worker override. Preserve explicit Script environment
settings and the inherited process environment. An unset setting retains the
SDK's native default; no CPU-count inference or unbounded worker policy is
added here. The focused Scheme tests still run serially, and the caller's
existing two-worker compiler allocation is not increased. The VM heap fence,
60-second idle watchdog, 120-second preparation and 600-second outer limits
remain unchanged.

* Measurement without a second execution system

The existing opt-in observation now emits compiler-entry elapsed time and the
already-collected recovery/currentness totals before launching Make. The child
reports its actual native worker setting. POSIX =/usr/bin/time -p= surrounds only
that observed compiler command, reporting wall, user and system time including
its descendants. Normal unobserved commands gain no timing wrapper.
These lines do not count as work in the existing progress reader.

CPU/wall residual can include IO, daemon/process waits, paging, GC clock effects
and host scheduling. Do not label it scheduler time without further evidence.
The existing source-read metrics and make target/job announcements separate
actual repeated work from waiting. No Scheme checker is memoized, no source
fingerprint is rewritten, and no currentness guard crosses the compile effect.

reported =cores=2=, process wall =12.394 s=, POSIX =real 12.24 / user 17.11 /
sys 3.62=. Projection was =0.840 s=, compiler-entry preparation =0.146 s=,

parallel descendants; it is not an exclusive attribution of the historical
timeout. Host load dropped sharply, so this is not a matched speedup estimate.

shell it attempted to copy 1,079,814 unique SDK nodes into another union table.
No actual work progress was relayed during that final copy; the unchanged idle
watchdog refused it. This is a different failure from Fixture compilation.

The diagnostic now counts the intersection by scanning the smaller existing
support and uses =|A| + |B| - |A intersection B|=. It does not allocate a second
million-node union. The existing Ops progress reports only actual processed
identities, in the same 1024-node batches as the existing walker. No timer or
synthetic heartbeat is used. Production read edges and deliveries are untouched.

Source inspection also found that exact descriptor-id comparison failed to
