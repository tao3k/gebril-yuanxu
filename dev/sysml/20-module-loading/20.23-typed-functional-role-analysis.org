* Problem and construction boundary

The last capacity result remains a failed 10000-declaration Case: the 600-second
limit ended the run after the 3100 checkpoint. No startup-only explanation or
larger heap establishes capacity. Build execution is measured separately.

The old authoring batch constructed and validated an admission object for each
datum, immediately projected its diagnostics, then constructed and validated an
aggregate object. Its reading region correctly retained the original reads of
these objects. The fix must avoid unnecessary construction, not delete records
from an already-issued dependency graph.

This change makes diagnostic analysis the result of the existing extensible
Generic. POO admission objects remain the public admission result; they
are created where a caller actually requests admission.

* One protocol, two kinds of public demand

=module-system/authoring/admission.ss= now declares:

#+begin_src scheme
(def YuanxuModuleAuthoringDiagnostics (List YuanxuModuleAuthoringDiagnostic))

(.defgeneric module-authoring-analyze (executor role interface datum)
  (protocol ModuleAuthoringAnalysisProtocol))

(.defmethod-bundle ModuleAuthoringCoreMethods
  ModuleAuthoringAnalysisProtocol
  (authoring-method ModuleSourceRole. yuanxu-module-authoring-diagnostics/common)
  (authoring-method ConfigSourceRole. yuanxu-module-authoring-diagnostics/config))
#+end_src

The internal =authoring-method= remains a =defrules= lowering to ordinary
=.defmethod=. It owns the real body and direct Function entry together. Default
methods return diagnostics instead of calling an admission-object wrapper.
Neither a contributor tag nor a cached admission result selects the Function
route: existing live declaration/observer checks and per-row applicability stay
in place. Changed/open methods still use the open Generic path.

=yuanxu-module-authoring-analyze-datum= resolves the current executor/role,
invokes that crossing, and applies =validate YuanxuModuleAuthoringDiagnostics=
to EVERY result. A contributed non-list or malformed diagnostic is rejected.

Public demand determines construction:

The private =with-authoring-analysis= resolves executor/role once and passes
the actual role together with checked diagnostics to its consumer. A contributed
method may rebind the Profile while running; single admission must still describe
the role dispatched for that datum. This avoids both repeated lookup and an
incorrect association with the replacement role. The runtime rebinding control
exercises the real method registration and mutation path.

| Entry | Per-datum work | Admission objects constructed |
|-------+----------------+--------------------------------|
| analyze-datum | Generic/Function analysis and result Type validation | zero |
| admit-datum | typed analysis | one |
| admit-datums | typed analysis for each datum in order | one aggregate |
| admit-port | the same typed analysis through the existing streaming reader | one aggregate |

The three =admit-= entry signatures and their final POO result shape remain.
Batch and port consume the same diagnostic lists; the order-preserving map/fold
and existing streaming helper are retained. No receipt pool, dynamic strategy
parameter, environment input, Builder or approval cache is introduced.

* Explicit extension-contract migration

This is a directed protocol change, not a claim that arbitrary old receipt
callbacks can be erased without changing their meaning:

- =ModuleAuthoringAdmissionProtocol/Generic= are replaced by
  =ModuleAuthoringAnalysisProtocol/Generic=; there are no compatibility aliases.
- A method bundle returns typed diagnostic lists, rather than a POO admission
  object. =call-next-method= combines diagnostic contributions in normal method
  order. The product's clinical contribution is migrated to =.defgeneric=,
  =.defmethod-bundle= and =.defmethod=, removing its manual specializer/lambda
  declarations and its extra receipt wrapper.
- A requirement intended to reject each datum belongs in the analysis method
  (which has executor, role, interface and datum) or in the typed analysis result
  contract. It must not remain hidden in an aggregate-receipt shape predicate.
- =YuanxuModuleAuthoringAdmission= still checks every actually constructed
  admission object, including explicit single-datum demands. On a batch it
  checks the aggregate once. Tests separately exercise per-datum refusal and
  aggregate shape validation, making the ownership change visible.

Ordinary Module declarations, config values and Scenario admission callers do
not need another registry or another internal policy setting.

* Proof allocation and limits

** Closed Function profile selection

The former Function branch still called
=poo-clos-compute-applicable-methods= for every datum. That public query validates
the Generic descriptor, builds distance rows and sorts them. The default source
analysis has only two maintained primary methods with equal executor/interface
prototype axes and an equal universal datum axis. Only role C4 distance differs.

The production reader now issues two private Function profiles by calling that
same public Generic query at initialization, on the real Config and Module role
prototypes. Each profile retains the actual selected Method object. On a real
datum, existing live MOP/observer authentication must still succeed; native C4
checks executor/interface membership and selects the first indexed role parent.
Profile declaration order and public identity labels do not decide specificity.
No argument receiver, invocation value, acceptance result or new cache is saved.

Changed registrations, modified policy payloads, open hooks, cold/unknown
arguments and POO object datums retain ordinary Generic dispatch. The original
issued metadata is still reobserved, and body/primary capture remains before the
open ownership guard. Diagnostic output Type validation still runs per datum.
The maintained route checks its payload and selects the actual warm C4 method
inside native re-observation, after complete preflight and before the first
delivery. That operation authenticates each delivered read and checks the
return. A pre-delivery refusal uses the Generic; a failure once delivery
starts propagates from that invocation.

=PublicationReads.join_preflight_in_same_read_state= is limited to the
authenticated pre-delivery state. A separate effect can invalidate that state
and still owns independent checks. The authoring dispatch tests retain the
original issued dependencies, later-revision refusal and actual Generic
fallback.

=Queries.firstProfile_ordered_reference= and =firstProfile_least_position= prove
the ordered/minimum-position lookup law; =profile_search_bounded_by_c4_depth=
bounds visited C4 entries. The catalog has two identity keys, so each entry has
bounded lookup work. These laws do not prove general CLOS qualifiers or infer a
closed method set from a role name. The actual issued default-method snapshot,
native prototype identity/order and equal non-role specializers are source
correspondence conditions, checked by runtime controls. Existing RoleFunction
Quint controls retain ownership of revision/observer/origin fallback and fresh
per-datum checks; no second transition model is introduced.

The maintained authoring test compares this route against the actual Generic
on extra-parent, reversed-parent, shared-parent diamond and derived-chain roles.
The pinned POO release's generators, property runner, shrinking/replay and
=require-passed= own the seeded property check inside ordinary std/test. Late
registration, contributed qualifiers, malformed results and Profile rebinding
remain in the same consumer suite. The dispatch-work test separately measures
original read support and preserves the open-observer delivery controls.

The work reduction is removal of repeated generic-descriptor traversal and
rank-vector/sort preparation on the closed route. A latency or capacity gain
still needs the complete selected-graph consumer: unchanged retained read counts
are expected because dependencies are not removed. Attribute fresh source
authentication, compiler work and scheduling separately before claiming an
end-to-end improvement.

** Existing assurance owners

SysML =TypedFunctionalAnalysis= assigns the obligations:

- Lean =typedAnalysisPreservesOrder= establishes the concatenation order of
  successful typed diagnostic results. =analysisRefusalStopsAggregation= and
  =successfulPrefixCannotHideRefusal= establish propagation of a Type failure.
  These are projections of typed results, not proofs of arbitrary Scheme code.
- Existing RoleFunction QNT gates own route selection, revision/observer
  fallback and its existing per-row invocation checks. They do not establish
  that a result can be validated before it is produced. Actual result validation
  occurs after analysis and before aggregation; Lean and runtime controls own
  that result boundary. Existing ReadRetention gates continue to own source
  freshness, both requirements, receiver isolation and unselected demand.
- Runtime tests own dynamic registration, contributed qualifiers, malformed
  result rejection, actual Type call counts and original read-owner identities.
  A closed three-datum batch observes exactly one admission receiver and no
  effective-method/invocation-frame carriers. Open observer tests retain their
  per-datum carrier checks; no callback is suppressed.

LeanPoo ContractConsequence retains the same value family when deriving proof
consequences. It cannot, by itself, justify this construction/API change. The
new result-flow proof and runtime controls are required; no runtime approval is
reused through that theorem. SysML records allocation, not a parser-qualified
execution model or a heap bound.
