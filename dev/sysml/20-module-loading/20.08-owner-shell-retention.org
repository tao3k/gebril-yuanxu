* Accounting boundary

The existing trace-only census now opens the raw shells of already observed
receivers and SDK expander contexts. Installed Gerbil's =expander/core.ss=
defines context inheritance, binding tables, imports, exports and code fields.
The shell projection reads existing struct fields without calling getters,
checkers, imports or slot preparation. Nested receivers and contexts remain
explicit frontiers; weak tables and class descriptors are not strong edges.
SDK contexts discovered during the SDK shell walk are not recursively opened.
Thus this is a bounded one-hop owner projection, not the entire SDK heap.

For specifications, thunk environments, receiver shells and SDK shells the
report includes reachable identities, payload words, repeated edges and explicit
frontiers. A single identity union across categories prevents double charging.
Each category's =added= count is marginal in the printed order, NOT dominator
or exclusive retained memory. No category sum is reported as physical bytes.
VM post-GC live includes independent roots and cannot establish marginal cost.
String backing storage, headers, code, foreign storage and weak ownership remain
outside the word account. Equal-looking distinct closures are not pooled.

* Assurance allocation and repair gate

[[file:20.04-payload-ownership.sysml][Payload ownership]] remains the architecture owner.
Lean =PayloadSharing.sharedNodeAccountedOnce= justifies identity deduplication
in diagnostic accounting, not deletion of production dependency edges.
=distinctEnvironmentRetained= prevents equality of printed payloads from
collapsing distinct identities. Receiver/revision/instance anchors remain local.
Existing QNT =IssuedRootForwarding=, =ReadRetention= and =IncrementalRoles=
continue to own callback, source change, invalidation and parent/child traces;
there is no duplicate payload state machine. Runtime graph classification is
an executable correspondence observation, not a theorem about physical bytes.

No production sharing repair is justified until the measured duplicate has an
owner, immutable representation and preserved ordered lookup/callback behavior.
The native canonical layout and persistent prototype map already share some
structure; replacing them with an additional Core pool would duplicate policy.
All source checks, original records and observer deliveries stay intact.
