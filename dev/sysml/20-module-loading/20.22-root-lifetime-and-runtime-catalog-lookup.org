* Production change: one source-attribution data flow

=configuration/slot-origin.ss= previously reflected all direct specifications
into owned entry lists before each =assq=. Source annotation repeated this for
each row, and inherited attribution repeated it for each parent and field.
The resulting pairs were temporary copies, not necessary source identities.

The producer already owns a persistent ordered name index. Source attachment,
method lookup and declaration-barrier lookup now consume =prototype-map-ref=
directly. No second field table, lookup cache or admission verdict is introduced.
Compact maps keep bounded lookup; larger maps use the runtime indexed backend.
An explicit private missing identity distinguishes absence from a present =#f=.

Unchanged behavior includes first contribution, actual SlotSpec/descriptor identity,
row/C3 order, conservative ancestor source requirements, opaque barriers, nested
getter/effect boundaries and independent currentness checks before return. The
new negative control checks false method and declaration metadata without forcing
or admitting either invalid value. It cannot borrow the parent's locator.

This removes repeated reflection allocation. It is not a repair of every retained
receiver, does not lower the 9105/6134 counts, and has not closed the memory goal.

=reader.ss:read-candidate= currently constructs a private tool-source table from
=interpreter-observations= for every candidate. This is demonstrable structural
allocation; its survival after the candidate returns has not been established.
It must not be called the dominant retained payload without a strong-path witness.

A proposed change shared one private baseline and copied it before a write. It
preserved missing versus present-false entries and distinguished identical byte
objects from equal-text replacements. A runtime test rejected its remaining

#+begin_example

currentness callback order or equal first diagnostics. The test was not weakened

and its counters were removed. Existing working-tree changes were preserved.

** Construction boundaries that need redesign

The source audit identifies two different mechanisms which must stay distinct:

1. =authoring/admission.ss:yuanxu-module-authoring-admit-datums= obtains and
   validates an admission object for each datum, reads its diagnostics, then
   builds and validates an aggregate object. The current recording region
   forwards every original read. A previously measured current-root census
   included 403 authoring-admission receiver frontiers for 32 selected Modules.
   This establishes a path into the retained read support; it is not exclusive
   heap attribution. Removing these records afterwards is not an optimization.
   A future default functional analysis path must avoid unnecessary intermediate
   construction, preserve per-datum diagnostics/Type obligations, and retain the
   public Generic path whenever live methods, Types, protocols or observation
   can alter the result. The existing method-policy guard alone does not prove
   all of those Type conditions. No such bypass is enabled by this investigation.
2. Source indexes and diagnostic schedules have different semantics. A path
   lookup index can share immutable structure, but a check schedule needs its
   own justified order from actual observed support. Replacing a hash table with
   another representation without that correspondence can change a refusal.
   Approval, source snapshots, callback frames and receiver instances remain
   separately owned.

Additional algorithmic candidates are visible in production:
=link.ss:scope-tree= filters a complete row list per demanded name;
=publication.ss:module-scope-context?= tests each selected member with =memq=;
=link.ss:eligible!= repeats list membership. These are potentially quadratic
across many demands. Their contribution to the 600-second failure is not yet
timed. A cached index over a publicly mutable list is unsafe without the actual
source/revision correspondence; ordinary receiver revision alone cannot justify
it. These sites must be measured alongside construction rather than assumed to
be the dominant cost or patched with another cache protocol.
