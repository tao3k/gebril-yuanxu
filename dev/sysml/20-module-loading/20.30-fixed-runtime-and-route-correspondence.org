* Production owner and obsolete qualification wrapper

The native =read-route.ss:require-read-route!= owns both supported storage
routes. The standard HashTable interface wraps either a symbolic hash backend
or the receiver's vector layout. The vector route checks the lookup method,
cells, missing sentinel, shape identity and the symbolic index table before
calling a mutable method. Core must not duplicate this as a hash-only guard.

The obsolete Core qualification accepted only the symbolic hash method identity
for an instance and therefore rejected a genuine vector receiver before the
first positive assertion. Replace that private copy with the producer's route
entry. Keep read record/checker identity checks and call native
=object-read-current?= afterwards: a valid route never authenticates a forged
credential. Transient misses remain issued without being inserted into the
receiver read cache.

The raw-setter experiment visits the read table, vector value wrapper and shape
index. Hash/test/seed mutations apply to the two actual raw hash backends;
method/backend mutations also apply to the vector wrapper. This preserves and
extends the control to twelve restored writes and three actual wrapper calls.
It does not pretend that endpoint inspection prevents raw reflective ABA writes.
Supported receiver writes still reject before mutation, and parent/child reads
retain distinct credentials and values. Unselected slots remain unforced.

before the first selected Harness. These spans include each package's own source
selection and native build; they are not the time spent in the selected Cases,
not a module-load benchmark and not evidence of repeated code generation.

are unchanged. No manifest entry or test has been deleted to reduce this cost.

A future correction must derive preparation from the requested test publication,
using its existing std-make-spec and admission boundary. Native imports can
close explicit library dependencies, but cannot infer arbitrary package paths
passed as data inside a future Case. Preserve the three real package-option/
reuse qualifications and selected-module support; do not replace this global
loop with a second handwritten filename-to-fixture map or move a hidden build
into every Case. This dependency edge must be represented once by its actual
owner before removing the global prerequisite.
