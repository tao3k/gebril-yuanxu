* What the runtime implementation now owns

** Declaration source edges belong to construction

=:init!= registers every direct declaration descriptor as an actual source.
This also covers =.cc= and =.+=, which use the same constructor. Core must not
introduce a parallel descriptor-source registry to repair these paths. Descriptor
identity remains necessary even if two descriptors have equal fields.

Before any =.slot.define= hook, =prepare-declaration-specifications= resolves
and registers actual Type identities across the whole C3 family. Only then are
the per-catalog scratch receivers populated in order. Its one-shot actions are
cold preparation costs; they are not stored as reusable approval or pending
actions on the receiver. Counting every observed preparation closure as a live
retained closure would therefore be wrong.

This establishes a concrete invalidation path, not callback purity. Resolution
may have effects or fail; those errors precede definition effects. Runtime tests
must cover later-C3 Type changes and failed preparation without a published
partial method table.

** Public parent inspection owns its spine

=object-supers= returns an owned list while preserving parent object identities.
The checked setter installs topology through the normal invalidation boundary;
runtime internal construction/lookup uses the private canonical list. Core's
existing parent traversal must not assume that repeated public inspection is
allocation-free or that mutating an inspection result edits topology.

This is not permission to replace all Core reads with raw metadata access.
Any such change must preserve callback ordering, revision fences and original
parent occurrences. The number of allocated inspection pairs is distinct from
retained record/receiver ownership. No Core raw-parent fast path is added here.

* A rejected retention hypothesis

=reader-evaluation-observers= records the exact context/body after successful
evaluation. =release-reader-expansions!= clears matching private context code,
then calls =hash-clear! completed=. Therefore this table is not, by itself, a
remaining owner of all successfully released expanded bodies. Removing the
table or weakening its exact-program/evaluation check would fix no established
leak and could authorize premature release.

The remaining runtime context, imports, bindings, phase data and initializer
promise are deliberately preserved. Deferred role resolution reuses those
contexts and the same confined import/source registry. A source-body count or
whole-VM byte delta does not establish that these structures can be deleted.
The existing publication regression, including exported macros and preserved
compiler-tool contexts, remains the concrete release boundary.

* Assurance allocation and acceptance boundary

SysML =DirectCaptureOwnership= and =ImportedEntryLifetime= continue to own the
research questions. Lean reuses =snapshotReflectionRoundtrip=,
=snapshotParentsExact=, =snapshotPreservesEveryOccurrence= and
=privateCatalogFoldOrder=; do not create a second immutable-list model.
These theorems do not prove Gambit GC liveness or mutable Scheme non-aliasing.

Existing ReadRetention Quint cases own mutation/return boundaries, both
requirements, lazy branches and receiver isolation. Runtime inheritance-hook,
declaration-index and issued-read tests own the concrete setter, registration,
definition-order and finite-root correspondence. A new producer digest must
not be installed in the source-bound proof gate before runtime qualification.

Build preparation and module loading are separate measurements. First qualify
the new producer, then rebuild its Core consumers through the original entry,
then repeat the existing bounded census and real Gitea/PostgreSQL controls.
The old source-bound receipts remain tied to the old cohort until replaced by
new evidence. No approval cache, second Loader, automatic dependency-pin update,
timeout increase, or ten-thousand-module rerun follows from this source audit.

** Preparation roots and validation-only replay

The 16/32-owner census observed 15/31 preparation captures with
3,450/7,130 original roots, or 230 roots per observed capture. These
counts describe original issued roots, including roots shared between
owners. They do not measure exclusive heap bytes. The receipt census
also identifies per-role authoring admission receivers among the issued
records. The closed source-only candidate reduced that census to 206 roots
per capture and reduced the 32-owner issued identity union from 6,232 to
5,176. It retains live Type and owner support through the original POO
reads. The source guard and the public receipt validator keep their usual
effect checks. The counts do not establish the dense heap or time limit.

Publication admission combines three independent facts. The reader checks the
selected source and native import context. POO authenticates the original
ordered reads and live receivers. The Module Contract validates the candidate.
Publication admission matches the checked receiver's owner to the selected
source before the linker enrolls the publication. The selected Graph's final
check covers the complete selected support.

For validation without checkpoint work, Core asks the existing POO operation
for a fixed result. It authenticates the same ordered traversal. Diagnostic
accounting records the returned count after validation. Source or policy
checkpoints retain protected entry and return. The publication reader delivers
the same observer start, visit count and end events. Its native visitor only
counted records, so a successful pass uses POO's fixed-result count between
those events. A refusal recovers the original visited prefix in the same
synchronous state and propagates the first failure. The equivalence in
=PublicationReads.validation_only_same_state_needs_one_live_pass= assumes
equal live observations within the supported serial replay. The existing
=t/module-session-metadata-index-test.ss= checks both success and refusal,
including an entry observer that mutates a receiver and removes itself.

** Private interpreter result lifetime

With the 64-owner directory fixture, retaining the admitted Module values
while releasing eight Reader tables and guard lists freed about 0.33 MB.
After dropping the result rows in a separate terminal probe, releasing the
64 generated role-loader globals alone had no measurable effect. Releasing
the 64 private Interface globals then freed 11.46 MB. That amount includes
the reachable values and closures. Neither probe changes a live Reader or
establishes an exclusive byte cost per object.

The native wrapper still expands and evaluates the owner's declaration.
When the stock expander proves every value reference comes from a bound
role alias or the fixed grammar, no declaration can refer back to its
generated Interface export. This permits the evaluator to deliver the
same POO value to the Reader once, with the exact originating Context.
The lazy role resolver is lexical. The temporary module promise retains
void after the handoff, and the Reader consumes its local result before
the independent post-evaluation check. Open and compiled declarations
continue to use their regular Gerbil binding and export.

=PublicationReads.wrapper_delivery_is_exact=, =foreign_wrapper_cannot_deliver=,
=repeated_wrapper_cannot_deliver= and =closed_delivery_preserves_checks=
state the result and refusal contract. They assume the owner and payload
produced by native expansion. The Scheme tests check that concrete
correspondence and the existing source and effect checks.

** Ordered common reads in one checkpoint

The 64-owner native fixture captured the original preparation and admission
roots. Walking their signed dependency records by identity found 7,589 distinct
records and 74,955 visits across the separate owner lanes. All 64 lanes
contained the same 1,026 issued records. Receiver and slot equality alone
would not establish this identity correspondence.

The same-process comparison interleaved separate, batch, batch and separate
replay of those unchanged root lists. Each measurement repeated the replay
six times. The separate lanes took 0.930 to 0.934 seconds wall time and
0.928 to 0.934 seconds CPU. Batch validation took 0.093 to 0.094 seconds
wall time and CPU, and visited 7,589 records on each repeat. This is the
existing pure POO checkpoint used for the final Graph, with source and
owner checkpoints still inside their established boundaries.

=PublicationReads.same_window_preserves_first_refusal= proves the ordered
flattening law with a fixed authenticator. Its effect counterexample checks
the same token before and after a changed observation and requires refusal.
Native expansion and author callbacks keep independent validation on both
sides. The capacity work is to reduce evidence produced by each admission
before those checks, including shared authoring and validation support.

** Maintained authoring Profile replay

The 64-owner diagnostic split the original joined roots at the actual
admission suffix. Preparation visited 58,624 records separately and 1,861
in one native replay. Admission visited 25,931 separately and 6,193 in one
replay. Some records appear in both stages. Each preparation contained the
same signed =%authoring-interface= root with 728 reachable records.

Six interleaved measurements repeated that exact root 256 times per lane.
Visitor replay with a fresh spine took 0.489 and 0.610 seconds wall time.
The validation-only primitive with a fresh spine took 0.591 and 0.614.
With one stable spine it took 0.382 and 0.383. Changing the visitor alone
does not establish a speedup. The maintained policy's native slot holds a
closure over the private stable spine. It compares its token to the one
actually observed this time. POO's original topology index owns reuse, and POO
validates the complete record graph on every invocation.

=PublicationReads.profile_checkpoint_preserves_issued_order= and
=profile_checkpoint_keeps_fresh_refusal= model the identity match and
rejection. Their premise is the exact signed record identity, never a
matching receiver, slot name, or previous successful verdict.

Splitting the Profile root out of each preparation lane was also tested on
the same 64 owners. Separate Profile and remainder validation visited 60,544
records per pass, compared with 58,624 in the original lanes. Both paths
took about 0.71 to 0.72 seconds wall time for six repeats. Some Profile
descendants are reachable through other preparation roots. Keep the original
combined preparation replay and reduce evidence where it is produced.

** Initializer guard custody

Transfer requires the same native Context to supply a private source input,
owner and initialization guard. The Interface wrapper has its own publication
return checks and forwards the original read trace. Its Context has no
private role input or owner, so the reader omits its entry from the role
initializer index. Actual role Contexts keep the same guard and call it at
transfer. =SourceClosureWork.unowned_interface_has_no_initializer_transfer=
and =owned_role_keeps_its_exact_initializer= cover the two cases.

In the 128-owner local probe, each owner had one Interface entry without
a role source or owner. Removing those 128 entries in the same process
released 25,488 live bytes after collection. Source currentness still
passed before the terminal part of the probe. The bounded retention census
checks the installed rule by comparing the number of initializer entries
with the private role Context count.

In the terminal part, the same 128 publication rows held their Module
values while the probe released their metadata guard columns and then
their evidence references. The two steps released 4,082,016 and 3,624,528
live bytes, respectively. Those deltas depend on release order. The
metadata and evidence remain part of the live publication contract.
