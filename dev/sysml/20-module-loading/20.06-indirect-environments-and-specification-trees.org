* Question and ownership boundary

How much storage is reachable through a slot thunk's indirect environment,
and how much of the specification forest is already shared by identity?
Root counts and immediate capture counts cannot answer this question.
This bounded investigation does not change the 2 GiB capacity gate or enroll
Loader read edges before the complete CI gate is green.

* Source correspondence

The producer is gerbil-poo =40c61fe6afc8313f297599da0e511f96e3a23dcf=.
=prototype-map.ss= owns the private =specifications= record and the ordered
and name-index RBTrees. Persistent updates reuse unchanged tree paths.
=prototype-map-list= allocates snapshot pairs, so it is not used to inspect
retained tree nodes. The installed Gerbil =std/struct/rbtree.ss= owns the
=RBTree=, =Tree= and =Empty= representations.

=object.ss:compute-slot-funs!= builds receiver-local thunks and can invoke
the native =compute-slot= hook. =apply-slot-spec= can capture a receiver
through another function. Equal printed code or equal slot names therefore
do not authorize environment pooling. A private ordered tree and the mutable
values to which its entries point have different ownership boundaries.

* Measurement

The existing opt-in =ModuleTestingProfile.= follows original issued records.
Its additional diagnostic walk follows closure captures (excluding code),
pair cars/cdrs, vectors, and raw structure fields (excluding the descriptor).
Identity tables terminate cycles and count shared nodes once. POO receivers,
class descriptors and SDK expander contexts are explicit frontiers. No slot,
promise, interface method, checker or callback is invoked by the walk.

Separate walks report the specification forest and the thunk environments;
their intersection reveals double counting between the two categories.
These maps are temporary diagnostic storage, not retained production caches.
The reported words count covered pointer payloads, not GC headers, allocator
overhead, executable code, foreign storage or exclusive/dominator ownership.
String characters are reported separately. Gambit and GC tables are additional
frontiers: weak references cannot be charged as strong retention edges without
an ephemeron model. A transitive reachable union is
not evidence that all those bytes could be freed by removing a thunk.

* Formal boundary

=PayloadSharing.lean:sharedNodeAccountedOnce= establishes accounting
idempotence. =distinctEnvironmentRetained= keeps distinct identities in the
accounting domain. The existing =parentCannotAuthenticateChild= theorem retains
the receiver anchor; no second alias theorem is needed for thunks. Existing theorems retain
the exact read sequence, dependency adjacency and observation order.

There is no matching QNT storage model. That duplicated the Lean question and
has been deleted with its variants and runner/digest entries. Existing
=IssuedRootForwarding=, =ReadRetention= and =IncrementalRoles= QNT models own
callback ordering, invalidation and final authentication. They are referenced
rather than copied. Neither tool proves Scheme heap sizes or arbitrary hook
purity. See =00-development-assurance.sysml:SingleProofOwner= for allocation.

* Decision rule

Share only producer-owned immutable structural storage with a demonstrated
identity-preserving correspondence. Do not intern closures by printed code,
merge receiver instances, suppress deliveries, drop dependency edges, or
reuse an admission verdict. Existing canonical storage must first be measured
as shared storage rather than charged once per root.

Cold/hot measurements use the existing 16/32-module Cases. Real
Gitea/PostgreSQL consumer controls retain both port requirements, source
change rejection, final currentness and parent-cache isolation. A passing
small Case does not qualify the 10,000-module gate.
