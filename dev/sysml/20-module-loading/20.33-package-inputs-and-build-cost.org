* Build and loading remain separate

An exact-source local zero-compile build sample attributed 5.303 s to source
projection and 6.561 s to the native Make dispatch region. A later finer sample
shows that temporary-role catalog restoration is small (0.083 s), while native
imports and role imports are substantial. These are nested regions and must
not be added. The later sample regressed in wall time, so it is retained rather
than treated as a speedup. Entry loading is outside these inner timers.

Those detailed samples used the FULL Core inventory. They do not decompose the
14.295-second warm command in the 41-target source-only bootstrap Fixture.
Detailed source accounting also adds per-read statistics and native replay
visitor work; it is not an uninstrumented wall-time baseline. Do not compare
those cohorts or infer a production speedup from their difference.

Production uses the existing invocation-local operation measurement facility
to distinguish =build-projection=, =build-current=, =native-make=,
=compiler-make=, =compiler-native-import=, =compiler-role-import= and
=compiler-role-restore=. Measurement stores scalar timings only. It is not an
observer, a build verdict or a new source cache. Temporary profiling scripts
are local diagnostics, not committed build/test entrypoints.

* Correct ownership of package language inputs

Target naming previously called =package-prelude-identity= for each target.
That function uses native package resolution and =core-read-module/sexp=:
each call rereads and parses the package's language source.

The production projection now resolves the package language alongside its
package prefix, once for that projection/package row. The existing test package
association carries both values; no second index or registry is introduced.
The target naming function is pure:

#+begin_src scheme
(build-target-name compiler-identity package-prefix language-identity)
#+end_src

It accepts the actual resolved input, performs no file I/O, and contains no
Yuanxu-specific fallback identity. The outer projection still confirms source
paths and compiler identities and retains the complete native source/package
observations. This removes repeated metadata extraction, not source
authentication. No std/make dependency, compiler callback or publication guard
is removed, and a new projection resolves its own inputs afresh.

Test source import routing is a different boundary: an arbitrary native import
can invoke callbacks or change metadata before the next import. It therefore
retains the existing live package/header lookup when choosing the import path.
Holding the pure target-mapping input must not freeze that routing decision.

* Assurance allocation and limits

SysML assigns package/header extraction to the projection owner, target naming
to the pure mapping, and currentness to the existing compiler/publication
boundaries. Lean's existing TestMakeLayout owner adds
=resolved_language_preserves_targets=: holding the same observed language
preserves every target. Its equality premise must come from actual native
package/source observation; the theorem does not establish filesystem purity.
=resolved_language_does_not_approve_changed_source= preserves the existing
source-applicability refusal. This is structural reasoning, so no duplicate
Quint model is added. Existing temporal publication models remain responsible
for source changes, callback boundaries, requirements and parent isolation.

The package-owned-prelude regression now mutates the real language source after
projecting its compiler identities and requires =admit-current= to refuse it.
Wrong expected language registration and foreign namespace refusal remain.
Native role-lifetime, compiler-input currentness and real Gitea/PostgreSQL
tests remain the consumers of the same production code.
