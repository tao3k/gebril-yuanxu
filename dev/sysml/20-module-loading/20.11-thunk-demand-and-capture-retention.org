* Source question

At gerbil-poo =29c58aa9c5be103ba843767e3d22ef8802b79342=,
=object.ss:compute-slot-funs!= assembles the complete effective thunk table and
invokes =compute-slot= on its effective entries. A slot without a cached VALUE
can therefore already have run a construction hook. Do not treat absent value
cache entries as permission to suppress or postpone these hooks.

* Non-forcing measurement

The existing trace enumerates the raw receiver instance table into an ephemeral
identity key set, then classifies each already assembled thunk TABLE ENTRY.
It does not call =HashTable.ref= on receiver-owned metadata: that path can
invoke replaceable hashing/equality callbacks. It does not call a getter, force
an unselected value, change metadata, or retain a new production cache.

A missing recognized raw instance table is unknown, not cold. Present =#f=
values count as cached through key membership. Distinct warm/cold function sets
are compared by identity: a function referenced by both categories is reported
as shared-with-warm, never charged as a cold-only root. Capture fields count
references from cold-only functions; they are NOT unique transitively retained
objects or exclusive GC bytes. Native compute hooks may already have observed
cold-only functions, so even that category is not an elimination certificate.

* Interpretation and next boundary

The 3341 functions at 32 modules are a concrete, receiver-local construction
cost to investigate, not repeated SDK payload. They coexist with 8700 demanded
entries and the complete read graph. This observation narrows the next source
question to native effective-thunk construction; it does not license pooling
receiver state, removing reads or skipping hooks.

Before changing construction, the native MOP's declared slot semantics and
observable =compute-slot= identity/order must distinguish a supported demand
projection from an arbitrary effectful hook. Existing ReadRetention models
cannot supply that missing temporal premise. Keep these functions and all
currentness/observer boundaries intact until that source correspondence and
hook-order argument exist. No manual purity label or Core side cache follows
from the new counts. The ten-thousand-module budget is unchanged and was not
rerun.
