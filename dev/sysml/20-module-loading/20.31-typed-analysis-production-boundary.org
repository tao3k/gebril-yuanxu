* Production data flow

A role datum previously crossed the authoring Generic, constructed a checked
POO admission receipt and immediately discarded that receipt after reading its
diagnostics. The batch then constructed another receipt. The read graph was
correct to retain the dependencies of every object that had actually existed;
removing those issued edges afterwards would be incorrect.

The production Generic now returns diagnostic values. The boundary validates
EVERY returned list with native =List YuanxuModuleAuthoringDiagnostic=, then
aggregates the values in source order. A batch/port demand constructs one
checked POO admission receipt. An explicit single-datum admission still
constructs one receipt and retains the role actually dispatched, including
when a contributor rebinds the Profile during invocation.

#+begin_src scheme
(.defgeneric module-authoring-analyze (executor role interface datum)
  (protocol ModuleAuthoringAnalysisProtocol))

(.defmethod-bundle ModuleAuthoringCoreMethods
  ModuleAuthoringAnalysisProtocol
  (authoring-method ModuleSourceRole. yuanxu-module-authoring-diagnostics/common)
  (authoring-method ConfigSourceRole. yuanxu-module-authoring-diagnostics/config))
#+end_src

The internal =authoring-method= defrules expands only to ordinary .defmethod.
There is no strategy marker, direct-primary field, applicability shortcut,
separate function executor or cached verdict. Every row retains ordinary
Generic method combination, carrier Type validation, qualifiers and native
read observation. The complete combined result is Type-checked after invocation.

* Directed extension migration

The old =ModuleAuthoringAdmissionProtocol/Generic= exports and the two
admit/common/config wrappers are removed. Contributor methods target
=ModuleAuthoringAnalysisProtocol/Generic= and return diagnostic lists; they
combine prior diagnostics with ordinary =call-next-method=. Returning an old
receipt or a malformed element is refused by the result Type.

This is an explicit extension-contract change, not a claim of equivalence to
arbitrary old receipt predicate side effects. Per-datum requirements belong
to the analysis method/result Type. The admission receipt Type still runs at
every actual receipt-construction boundary. No legacy aliases are retained.
Core consumers and the real product contribution test use the same protocol.

* Assurance allocation

SysML assigns this to construction/data-flow ownership, not to a new cache.
The existing PayloadSharing Lean owner adds =collectDiagnostics= and proves
=typedAnalysisPreservesOrder=, =analysisRefusalStopsAggregation= and
=successfulPrefixCannotHideRefusal=. Each Except is a projection of a fresh
actual Type check; the theorem does not certify arbitrary contributor code.

Existing temporal models remain responsible for source changes, callback gaps,
ordered checks, parent isolation and omitted requirements. No second Quint
model is added for the same structural fold. Native tests retain per-row open
carrier-policy observations and check malformed contribution refusal, late
registration, qualifier counts, one aggregate receipt validation and role
rebinding. The real Gitea/PostgreSQL Scenario remains the domain consumer.

* Performance and acceptance boundary

This removes construction of discarded per-row receipts; it does NOT remove
Generic effective-method/invocation frames or the before/after currentness
boundaries. Count and measure the actual native reads/receivers rather than
claiming that a shorter function body proves a lower heap or wall time.

The separate unconditional four-package Just prerequisite remains a known
preparation problem (20.30). It is not solved by changing role analysis.
The original thousand/ten-thousand declaration Case, 2 GiB limit and deadlines
remain unchanged. No capacity pass follows from this structural refactor alone.

* Default Interface construction

The first actual constructor probe found two profile admission receipts for a
fresh Interface: the default argument called the checked public Profile factory,
then make-module-interface checked it again. Reuse the existing internal
make-default-module-authoring-profile for the Interface's private default value.
make-module-interface still validates it before publishing the Interface.
The public Profile constructor remains checked, and an explicitly supplied
Profile still receives its own fresh Interface-boundary check. No prior
acceptance is reused. The probe keeps its one-boundary expectation and the
initial failing two-receipt result is retained as local evidence.
