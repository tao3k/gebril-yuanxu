* Distinguish cold work from repetition

The selected request contains 13 distinct, root-relative =gxc:= targets. The
installed =std/make.ss= rejects duplicate spec files before worker creation and
records target completions within that invocation. Its =build?= checks native
outputs/input timestamps; =build-dependent?= checks imported dependency stamps.
There is no =force:= request in this compiler expression.

The existing test publication key binds runtime/compiler identity, spec,
compiler identities and canonical source observations. Source changes can
therefore select a new output directory intentionally. In a cold generation,
the current implementation compiles into a temporary issuance-owned directory;
that directory is released on failure. A failed attempt does not create an
approved hot generation. Repeating it can repeat cold work without indicating
a broken native Make cache. Do not recover unissued partial products as an
optimization or erase a stale-source refusal.

These source mechanisms do not prove that all warm executions compile zero
targets. That requires a completed, same-source, new-process control and output
identity/mtime checks. Previous successful receipts cannot qualify this failed
source epoch.

* Direct continuation and a distinct idle-progress failure

The waiting automation was disabled at the user's request. The next direct
same-source cold attempt completed native Make and issuance: 13 compiler units,
92.741 seconds subprocess wall, 85.789 seconds in Make. The new-process hot
attempt compiled zero units: 43.578 seconds subprocess wall, 36.754 seconds in
Make. Both completed preparation within its unchanged limits, but both later
failed the Harness's unchanged idle budget. These are compilation/recovery
results, not passing complete test runs or host-normalized speedups.

The first attempt reached the 16-module cold query (35.818 seconds wall,
4.586 seconds CPU). Its pure specification structure contains 18,649 distinct
nodes, 82,213 pointer words, 9,119 RBTree nodes and one shared Empty node. The
broader specification-value and thunk-environment walks overlap on 80,141
identities. Pointer words and a single shared Empty node do not establish an
exclusive byte saving. The 32-module result was not reached by these attempts.

The source audit found a separate progress-reporting gap. The module adapter
updated diagnostic counters/printed lines during real work but did not relay
those completed-work events to the supervising Ops progress channel. Fixture
acquisition occurred before a long query, and printing a later diagnostic line
does not reset Ops idle detection. Do not treat that as a new compiler failure.

The candidate correction uses the existing =execution-progress!= function;
it creates no protocol, scheduler or timer. Native =reader-body-compiled=,
=reader-body-evaluated=, =publication-guard-end= and actual replay-visit counts
are relayed only after the pre-existing source observer returns. Each diagnostic
payload walk also reports each completed batch of 1,024 newly discovered raw
identities. No POO checkpoint receipt is constructed inside admission.
=file-read= is deliberately excluded: its source notification precedes IO and
cannot be relabeled as a completed physical read.

The existing module-observation test Case now uses Ops's injected clock to
check that positive completed work advances idle accounting, zero work does
not, and work cannot revive expired idle or total budgets. Its existing native
read test also checks ordered deliveries. No additional Fixture/test family,
timeout increase or synthetic heartbeat is introduced. Final runtime
qualification of this correction remains separate from the earlier runs.

** Reflection and remaining work

- Imported facades are real dependency roots. Removing an unused facade avoids
  both source-closure work and runtime-library setup/teardown. This is stronger
  evidence than splitting a large test into more workers or adding a Builder.
- Existing native Make already provided cross-process zero compilation. The
  demonstrated defect was unnecessarily broad imports plus a missed native
  Record default, not a need for another cache protocol.
- Preserve publication, domain conflict and final-source guards. A thin source
  receipt is not redundant merely because it wraps a native Slot. Delete
  repeated traversal/type machinery, not those semantic obligations.
- The ten-to-twenty-second selection and independent hot-currentness costs
  remain measurable work. Their further optimization needs the original MOP
  ownership/effect model; this repair does not claim they are solved.
- Timing attribution is an implementation experiment. No duplicate Lean/QNT
  model or Python profiling layer was added. Existing formal owners continue
  to govern semantic sharing and effect/currentness changes.
