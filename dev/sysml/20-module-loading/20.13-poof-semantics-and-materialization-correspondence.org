* Semantic contract before representation

POOF describes prototypes as increments of computation over final self and
inherited computation. Its composition laws do not equate child self with a
cached parent instance. The delayed formulation permits an overriding child to
avoid forcing its inherited computation. It does not promise termination of an
arbitrary recursive definition.

The paper explicitly separates instance/prototype semantics from function,
dictionary and key-list representations. Its dictionary example identifies
repeated dictionary construction as a source of exponential work and introduces
sharing by lazy evaluation. This is the theoretical reason to investigate
representation sharing and demand, rather than adding another Core cache.

This separation does NOT establish Scheme procedure =eq?=, arbitrary raw metadata
reflection or effectful callback equivalence. Those are additional observations
of the present implementation. Preserve supported observations or explicitly
review an API change; do not silently erase them because pure values agree.

* Current Scheme observations that constrain refinement

At this native cut, =instantiate-object!= computes checked precedence and the
entire function table before installing the instance and preparation read.
=compute-slot-funs!= first resolves declaration descriptors, then standard
functions, then invokes =compute-slot= in that table's actual enumeration order.
An exception clears partial caches and rethrows the cause.

=.ref=, =.ref/cached= and =.ref/inline= ultimately depend on this preparation.
In particular, a cached-read miss does not mean preparation was skipped. Names
and layouts require a coherent key set. Full function-table reflection currently
exposes functions for unselected slots without evaluating their value bodies.

The compatibility obligation is one procedure identity per observable slot
function in a receiver revision, stable repeated =next= results, and unchanged
observed callback sequence/refusal. It is not an obligation to identify parent
and child procedures, preserve allocation addresses across invalidation, or force
unselected values. Nor does POOF itself require all procedures to be allocated
eagerly: their current allocation timing and public observability must be
separated before implementing a refinement.

A proposed metadata change must preserve that existing Scenario's complete
observations: final receiver, both requirements, original issued read identities
and ordered dependencies, source diagnostics and currentness-before-return
checks. Unselected service/value bodies stay cold. Source changes still reject;
no field list, synthetic read bundle or successful admission result substitutes
for the actual observation graph. Cached parent metadata is not a child plan.

* Reflection and next decision

The advantage to pursue is less eager representation work under the SAME object
semantics, not a new author-facing configuration language. The paper already
identifies the right abstraction: share computations through their representation
while preserving prototype meaning. It also warns that fully correct mutation
tracking extends beyond an object system when arbitrary language effects exist.

20.12 establishes compatibility counterexamples and measured cold identities;
it does not choose a materialization architecture. Its suggestion of eager
fallback for hooks is a conservative option, not a theorem-derived final design.
The next decision requires M1/M2 and a complete observation boundary first.
No getter interception is selected by this document. No runtime speedup, full-CI
pass or 10000-module capacity result is claimed; the 2 GiB budget and all existing
timeouts remain unchanged.
