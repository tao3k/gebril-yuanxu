* Representation and actual reuse of LeanPoo

The full reference is the existing compiled OPEN method plan. A partial state
holds a receiver/revision scope and optional cells, each containing an opaque
identity observation and an open method. =Represents= requires every installed
cell to belong to the reference's declared keys and, for EVERY final self, to
resolve exactly as that reference plan. Missing cells are pending metadata;
the authoritative declared-key list distinguishes them from absent fields.

#+begin_src lean
abbrev Methods (Key Value : Type) [BEq Key] [LawfulBEq Key] [Hashable Key] :=
  LeanPoo.Object.CompiledPlan Key (fun _ => Value)

def Represents (full : Methods Key Value) (state : Partial Key Value Handle) : Prop :=
  ∀ key cell, state.cells key = some cell →
    key ∈ full.keys ∧ ∀ self, cell.method self = full.plan.resolve key self
#+end_src

This uses a uniform value carrier, which may be a tagged domain value. It does
not establish conversion from arbitrary heterogeneous Scheme values to Lean.
The partial cells do NOT preallocate a canonical procedure for every key.
=demand= installs an offered handle and =full.resolve key= only on a declared
miss; a hit retains the entire original cell regardless of the new offered
handle. =complete= folds that same operation over the reference keys. These are
pure proof-model operations, not a second runtime evaluator or cache protocol.

The new-cell case of =demand_represents= invokes the existing
=full.resolve_sound key declared self=. This is where the locked library
establishes open-recursive method meaning. =TableCarrier.conjugate_read= is NOT
used as if a partial table were already isomorphic to a complete table: pending
entries require a refinement relation rather than a total bijection.

* Machine-checked properties and limits

| New theorem | Proved statement | What it does not prove |
|-------------+------------------+------------------------|
| =empty_represents= / =demand_represents= | Empty and demanded partial tables refine the existing plan | Native descriptor/compiler correspondence |
| =demand_unrelated= / =demand_scope= | Demanding one key changes neither other cells nor receiver/revision scope | Actual Scheme allocation or filesystem currentness |
| =first_install_identity= / =demand_hit= | A miss retains its offered handle; a hit keeps the exact existing cell | Authenticity/freshness of an arbitrary offered native procedure |
| =repeated_demand_stable= | After first demand, demanding the same declared key with ANY other offer returns the same state | Callback execution safety or equality of independently allocated closures |
| =complete_represents= / =complete_lookup= | Every declared key exists after completion, and its method has the original plan meaning at every self | Timing of a real reflection API or execution/termination of method bodies |
| =reflection_identity= | Completing other metadata retains every previously installed cell and its identity | Equal pointer addresses across invalidation, processes or independent receivers |
| =different_scope_rejected= / =reset_has_no_parent_cell= | A foreign receiver/revision cannot use this projected lookup; reset starts with no parent cells | Automatic extraction of native revisions or completeness of native invalidation |

The 17 new theorems and five required integration declarations are included in
the existing Core axiom/shape audit. No arbitrary admission proposition is stored
as a model field. There is no =sorry= or new axiom.

The model does not infer procedure identity from extensional method equality.
Handles may even coincide across distinct slots when the same existing procedure
is legitimately reused. The native issuer/allocator must supply the correspondence
to Scheme =eq?=; proving allocation-wide uniqueness would be a different claim.
No conclusion about hook timing follows from these pure cell operations.

* Minimal native observation control

[[file:../../../t/mop-thunk-construction-test.ss][The existing consumer suite]] is extended with one first-reflection case. It
uses actual =.all-slots/sort=, native metadata, lexical slots and =.get=:

#+begin_src scheme
(def parent
  (.o (:: config [])
    port: 5432
    plan: (.o port: (.get config port))
    unused: (begin (set! bodies (1+ bodies)) 'unused)))
(check-equal? (object-%instance parent) #f)
(check-equal? (.all-slots/sort parent) '(plan port unused))
(check-equal? (length (hash->list (object-%slot-funs parent))) 3)
(check-equal? bodies 0)
(check-equal? (.get parent plan port) 5432)
(.def (child @ parent) port: 5433)
(check-equal? (object-%instance child) #f)
(check-equal? (.all-slots/sort child) '(plan port unused))
(check-equal? (.get child plan port) 5433)
(check-equal? (.get parent plan port) 5432)
#+end_src

The test captures the child's actual plan procedure and checks =eq?= after value
access. The original three cases retain repeated =next= identity, actual native
hash enumeration versus hook trace, eager refusal and failure cache cleanup.
They do not assume declaration order is hook order. The unselected value body
stays cold throughout names reflection and selected reads.

Current native construction is EAGER in its metadata preparation. Therefore this
is evidence that existing reflection exposes a complete table before delivery,
NOT evidence of a deployed partial constructor completing at first reflection.
The latter still needs a native implementation relation and all entry coverage.
No wrapper or simulated lazy constructor stands in for that missing evidence.
