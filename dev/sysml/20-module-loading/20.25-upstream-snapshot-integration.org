* Runtime scope Types: direct migration, not a compatibility route

Module publication, dependency scopes, scope contexts and Build publication
descriptors now use named runtime =Type.= / =Record= descriptors. The former
=yuanxu-predicate-contract= wrappers are removed from these production owners
and their scope fixtures. Product Nix/OpenTofu scope consumers migrate with the
Core boundary. A contextual descriptor is rejected at this value boundary;
there is no fallback to its classification/admission methods.

#+begin_src scheme
(define-type (GiteaScopeContract @ Type.)
  identity: 'gitea/scope
  .element?: (o?/slots '(config document application types policy)))
;; Record/ObjectContract descriptors retain their runtime child constraints.
(def JsonSchemaScopeContract (.cc ScopeFields identity: 'json-schema/scope))
#+end_src

The executable Gitea declaration lives in
=scenarios/gitea-postgresql/gitea/types.ss=. No second field table is introduced
here. The value producer calls runtime =validate=
once, then runs platform policy against that exact normalized subject. Runtime
Type failures retain their cause/diagnostic projection. Descriptor revision
changes during successful validation/policy are rejected. Each independent
call validates again; neither approvals nor policy outcomes are cached.

Actual contextual domain Contracts remain contextual: Gitea Application
admission, child responsibilities, both port requirements, source observations
and plan identity are not replaced by a shape predicate. The demand-projection
fixture now names its application admission separately from its runtime scope
Type, rather than treating the two protocols as interchangeable.

SysML =NamedValueScopeAdmission= owns this separation. Lean
=scopeAdmissionExactSubject=, =scopeValueRefusalStopsPolicy= and
=scopePolicyRetainsBothRequirements= prove the pure value/policy composition;
the selected Lean Schema.Contracts target passed 44 build jobs. These theorems
do not prove callback purity or source currentness. Existing Quint callback /
read-ownership models and runtime source controls own those obligations.

The migration preserves real Type preflight during selection. It does not
claim metadata-only publication, remove dependency edges, skip observers, or
weaken return-time source authentication. Runtime regression and scale results
must be recorded separately; eliminating adapter construction alone is not
evidence that the ten-thousand-module gate is closed.

* Changes that matter to the production path

Upstream =13d01ad= captures a receiver revision around declared-slot read/write
validation. A validator that changes shared metadata cannot return a stale
success or install a proposed value afterward. Its ordinary validation refusal
still precedes the revision refusal.

Upstream =89febc8= separates public and hook-provided C3 snapshots from the
private canonical spine. Mutating an inspection result cannot change cached
inheritance membership. A hook that changes the checked order still refuses;
accepted hook snapshots cannot later mutate canonical membership.

Core's source precheck and slot-origin walk previously called the public C3
query solely for preparation, then discarded its result. With the new ownership
rule this makes an unnecessary snapshot on each warm call. Both callers now
inspect the EXISTING runtime precedence cache first:

#+begin_src scheme
(unless (object-%precedence-list receiver)
  (compute-precedence-list! receiver))
#+end_src

This is a read-only runtime metadata demand, not another cache. Cold/invalidated
receivers still call the same public preparation entry and run the same C3 hook
and refusal path. Warm runtime construction already returns its cached spine
without invoking hooks; these two Core callers do not need to export a copy.
The canonical spine is neither returned to a user nor mutated by this change.
There is no change to source authentication windows or admission results.

* Allocation of assurance work

SysML =PublicPrecedenceSnapshotBoundary= owns the source-to-model boundary.
Reuse LeanPoo =lookupOr_present= and =lookupOr_missing= for the cached/cold
branches; do not create another cache model. The runtime =cond= and the Core
presence test provide the concrete correspondence obligation. Runtime tests
must cover invalidation and hook refusal; the abstract lookup law alone cannot
prove Scheme hook purity or protect arbitrary low-level mutation.

Existing RoleFunction and ReadRetention Quint gates own observer/registration
changes, independent authentication, receiver separation and both requirements.
SelectionReplay additionally binds the actual runtime source owners. Its stale
test-owner path was migrated from =t/issued-read-test.ss= to the upstream
=t/objects/issued-read-test.ss=; no hand-maintained substitute test was added.
