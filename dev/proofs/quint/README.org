#+title: Core Quint Models

* Typechecking entry ownership

The runner invokes Quint 0.33.0's own =load=, =parse= and =typecheck= CLI
functions for every entry, including native import resolution. One Node runtime
serves the serial requests; source maps, resolvers and typechecking state are
fresh for each request. No successful result is retained. Every entry still has
the original five-second wall deadline, including the first runtime startup.
=python3 -m unittest discover -s dev/proofs/quint -p test_typecheck.py= compares
native CLI verdicts and checks that an imported source mutation is rejected by
the next request in the same runtime.

Verification similarly invokes the native =compile= and =verifySpec= stages
with the original TLC options and shared Apalache session. Each case retains
the 45-second wall and five-second real-output deadlines. Native diagnostics
are streamed unchanged; a separate result pipe binds the native status to its
input, main module and invariant. Positive and negative admission still require
the original TLC state counts and success or counterexample evidence. Models,
compiled representations and verification decisions are never reused.
