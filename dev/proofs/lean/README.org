#+title: Core Lean models

=Admission/ReplayOwnership.lean= models the selected receiver-frame and affected
invalidation-closure boundary described by [[file:../../../docs/30-39-research-foundations/32-module-assurance/32.35-replay-receiver-ownership.org][32.35]]. Its pure laws require complete
identity membership and native parameterize/unwinding correctness. Runtime cases
must independently establish those premises. The retained raw-write history law
does not claim that receiver frames mediate SDK structure setters.

The =Admission/RouteMutation.lean= follow-up is documented in
[[file:../../../docs/30-39-research-foundations/32-module-assurance/32.34-metadata-write-boundary.org][32.34]]. It proves endpoint indistinguishability and conditional rejection
under complete monotonic write tracking. The current SDK does not provide that
tracking: the raw restoration counterexample is preserved, not discharged by
an assumed purity annotation or a generated Birth.

One =YuanxuProof= Lake library owns all Core models and their axiom audit.
LeanPoo is a dependency, not another local proof implementation. The dependency
is pinned at =6e6a706e14fa6f8199e4f36711440355b42ef335=, using Lean 4.34.0. The parent Lean consumer uses the same toolchain.
Its Cedar pin is the upstream Lean-4.34 upgrade commit
=acb0db7daa838249d894d2af64c850e1c9bf0d7d=; Batteries is v4.34.0.

Domain predicates describe projected inputs and explicit external contracts. They
are not certificates of native execution, signature authenticity, MOP completeness
or filesystem stability. Unsupported admission-closure records and runtime
atomicity witnesses have been removed rather than counted as verification.
The old =PooC4= catch-all, separate Profile proof namespace and forwarding modules
are gone. C4 appears only where inheritance actually needs it.

Publication atomicity, rollout, retirement, retention, distributed-worker admission,
scheduling fairness, key lifecycle and observation-consistency tag tables are not
current executable models. Their unused hypothetical witness records and
classification-only modules have been removed. The old composition receipt fixture
that merely set five success flags and the hypothetical digest-based source identity
record were also removed; neither computed the claimed facts from current source. Their RFC obligations remain open;
a label such as “runtimeAtomicityWitness” is not an implementation proof.

Removed local mechanisms include the projection/cache/codec framework, predicate
ContractSet accumulation, eight generic phase wrappers, assumed candidate/update
lists, identity-injectivity schemes, shape/entrypoint tag substitutes for typed prototypes, and generic cache entries with unrelated
freshness flags, and hard-coded historical case counts presented as current models. Ordinary domain values, pure predicates and explicit evidence
or authority premises remain domain-owned; they are not another object runtime.

The remaining domain checks compute from data: quorum counts deduplicate actual
principal lists; delegation intersects scopes/actions and bounds expiry/depth;
causal cuts check every listed parent; ProfileBundle repeats compare the actual
selection key, revision/generation or native reference identity. The latter
replaces the hypothetical digest and assumed permutation-normalizer model.
Stored claims of immutability, identity stability, completed implementation,
closure and authority are not admissible substitutes for these checks.

The PooClos Dispatch file now models actual LeanPoo indexed method selection,
registration, candidate-cache soundness and reference-call equivalence.
The Outcomes file separately describes projected outcome data.
=MethodCombination= additionally computes qualifier matching, first-group assignment,
group order, required/ambiguous refusals and ordered method combinations. It uses
LeanPoo method-candidate selection, not another dispatch engine. These finite
semantics do not prove refinement of the complete native evaluator or termination.

The total object-plan resolver is the proof-facing semantics; the partial
memoized reader is checked separately by executable controls. C4 is inheritance,
not a workflow SCC scheduler. The Scheme ancestry traversal remains independent
because replacing it with C4 changes the native admission semantics.

imports every model and rejects =sorryAx= and project-specific axioms throughout
the imported Core closure. Only =propext=, =Classical.choice= and =Quot.sound= are

concrete predicates, dependent proof fields and external policy parameters remain
distinct. This shape audit is a regression guard, not a proof of runtime refinement.
Declaration counts are not counts of independently proved requirements.

the Quint source digest. Its operation result is a completed ordered pass, not a

* Root/child admission projection

=Admission.RootChild.Routing= models the implemented analysis edge in =types.ss=
and =admission/source.ss= through LeanPoo =Factory.choose=. Contract, candidate
and context references must all match; the edge is consumed before callbacks.
Inherited producer re-entry receives no old edge, while an owned responsibility
creates its own child edge. This permission is not a source certificate.

The finite port/contribution reference reuses =Admission.SourceWindows= and
LeanPoo =DeclarativeMetadata.Contract=. It proves root source certificates project to
selected child source obligations; independent port requirements, exact candidate
association and post-effect refusal are retained. Stable-world batching is not a
Scheme optimization or a proof of observation completeness. See
[[file:../../../docs/30-39-research-foundations/32-module-assurance/32.16-root-child-admission.org][32.16]] for the proposed responsibility boundary and native premises.

* Remaining admission source windows

=Admission.ReturnWindows= reuses SourceWindows/LeanPoo CacheLookup and the
RootChild domain predicate. It proves operational check composition, sound
covered reuse, complete-predicate deferral and preserved joint requirements/
receiver identity. It does not classify arbitrary callbacks as pure or implement
Scheme optimization. The aggregate imports the module and requires its critical
laws. The source-bound Quint catalog contains 40 cases. See
[[file:../../../docs/30-39-research-foundations/32-module-assurance/32.20-remaining-read-boundaries.org][32.20]].

* Replay projection and diagnostic order

=Admission.ReplayBoundary= imports the existing ReturnWindows/LeanPoo cache
owners. It proves exact first diagnostic under sound, same-order byte reuse,
complete successful observations, branch union and first-origin collector
coverage. Computed counterexamples show that deferring a JSON check past a
stale token, or substituting a different first origin, changes the diagnostic.
This does not prove arbitrary MOP callbacks or cold metadata hooks pure. The
aggregate requires these theorems; the QNT runner checks the source digest.
See [[file:../../../docs/30-39-research-foundations/32-module-assurance/32.20-remaining-read-boundaries.org][32.20]] for the native producer audit and unproved extraction premises.

* Identity DFS and native traversal frames

=Admission.IdentityDFS= specializes LeanPoo C4's finite pending/unseen-weight
argument to dependency-before-sibling DFS with identity HashSet membership.
=Admission.DFSFrames= proves recursive empty-frame return stuttering, active
step refinement, finite termination and exact reachable identities. Complete
final checking accepts only when every enumerated reachable token matches its
final binding. A shared diamond/cycle example reduces through HashSet lemmas
in the kernel; no native_decide axiom or larger recursion limit is used.
The aggregate requires these owners and preserves existing domain/source/cache
controls. See [[file:../../../docs/30-39-research-foundations/32-module-assurance/32.21-identity-dfs-and-read-boundaries.org][32.21]] for limits of the native Scheme correspondence.

* State-derived entry closure

Admission.ReadOnlyEntry reuses LeanPoo MetaBootstrap/C4 and the existing replay
models. Exact kernel checker identity, cached order or absent selected ancestor
protocols, and absent source observers yield a closed operation program without
user purity flags. It proves independence from all callback implementations and
exact same-order diagnostics. Bootstrap validity does not imply readiness;
sealed roots do not prove purity. Native extraction is not implemented. See
[[file:../../../docs/30-39-research-foundations/32-module-assurance/32.22-state-derived-read-only-entry.org][32.22]].

* Actual MOP snapshot qualification

SnapshotEntry adds exact observed-cut guards and composes them with the existing
ReadOnlyEntry callback-independence and ordered-diagnostic laws. Native MOP
reflection is tested separately; its operational correspondence is not extracted
by Lean. Equal cuts do not imply unchanged sources or no intervening observer.
See [[file:../../../docs/30-39-research-foundations/32-module-assurance/32.23-mop-state-extraction.org][32.23]] for native observations, proof premises and retained failures.

* Constrained return-tail qualification

[[file:../../../docs/30-39-research-foundations/32-module-assurance/32.29-constrained-return-tail.org][32.29]] separates a replaceable caller wrapper from a temporary producer-owned
source-event gate. Opaque observers are refused before invocation; this is not
a purity declaration or a production fix. An independent writer remains a
correct-model limitation requiring snapshot/conditional-commit authority.

The final candidate covers both slot-replay (including cache exit) and
return-currentness. A return-only gate is retained as an unsafe matched control.
Only source-observer calls are restricted; arbitrary MOP record/checker ownership
and external snapshot/commit remain separate premises.
