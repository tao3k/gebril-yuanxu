#+title: Current Core Lean model correspondence review

The inventory below records model owners and their current correspondence. Executable checks are distinguished from
domain policy algebra and runtime adapter observations. An axiom/shape audit does
not establish the correspondence by itself. Classification-only laws are never
counted as runtime implementation closure. No model was retired into an open
obligation in this review. Existing supported owners now have concrete checks
and rejection laws; unsupported runtime effects are not manufactured as witnesses.

The executable aggregate imports every listed model and requires the critical
owner theorems. `Controls` and `SchemeFixtures` are finite controls, not additional
universally proved requirements.

* Changes beyond the preceding four groups

The old PooClos =ProjectionOps= record delegated import closure, capability meet
and bundle digest to opaque callbacks. It is replaced in the existing Dispatch
model by actual LeanPoo indexed selection, registration, candidate-cache soundness
and reference-call equivalence. Replacement-argument and slot-cell lifecycle
models add the missing concrete runtime behaviors. Class storage is allocated
once outside computed slots, so subclass metadata cannot reallocate the shared
class-cell table; the lifecycle counter regression retains its expected value.

Imports now computes the default instance/explicit alias and prepares actual
export factories. Query projection requires the admitted membership proof;
its checked factory computes admission, and a pure projection no longer sets a
runtime-execution success flag. Context now has a checked constructor and an exact
ProofObject certificate rather than only a proposition-valued record constructor.

Realization now requires post-validator package/source currentness. Contribution
coverage checks lengths before zipping and compares exact references, selected
origin fields and resolved payload. Build inputs reject contradictory snapshots
and compiler collisions. Directory ownership walks nearest path ancestors, and
Graph payload proofs model stable-distinct append and value removal rather than
ordinary list append or deletion of the entire slot.

* Runtime compiler regression

=source/declaration.ss= generates the same lazy phase-bound Build binding for an
original interface as the admitted source reader does. Prepared wrappers import
prepared roles once; the included original source location must not trigger a
second import of bare config.ss. Build is still checked outside its cached slot
on every access. =t/module-build-role-test.ss= covers both original compiler input
and prepared wrappers, non-execution during import, phase refusal before/after
cache use, source mutation and root re-entry refusal.

The Funflow regressions also exercise shared JSON artifact definitions in the
explicit Gerbil bootstrap. A canonical shared library beside a Module is reused
with its original context identity; the prepared publication's role files,
including Build, remain forbidden compiler inputs. Current-source checks still
precede consumption. The model rejects unregistered context substitution and
role admission. The two local Funflow scenario publications are ordinary Core
build roots, so their public imports no longer depend on a source-load fallback.
