Core owns =architecture.ss=: POO Diagram, Node and Relation inputs. The host's
published D2 Module owns ASCENT endpoint validation, reachability, visual rows
and D2 serialization. Core copies no rules, graph algorithm or TypeScript toolchain.

* Generate through the existing host entrypoints

Run from the Agentic AI Lab workspace. The existing =d2-export= driver accepts a
source consumer; its default remains the maintained Context example.

#+begin_src sh

bun dev/d2/render.ts --title 'Publication guard boundaries' --out /private/tmp/yuanxu-core-d2/publication-boundaries core/dev/d2/20-module-loading/20.24-publication-boundaries.d2

#+end_src

D2 files are generated outputs of =infer= then =source=, not a second authored
graph. The consumer checks the init source context before writing. The renderer
checks its captured inputs and minimum text size. Inspect its PNG preview before
replacing SVGs; PNG/HTML/receipts stay local. Org embeds SVG file links directly.

The POO architecture inputs are authored design facts, not automatic extraction
from Scheme implementation or measured performance. ASCENT derives which declared
nodes and relations are visible; a successful render does not prove those facts
or imply that the performance problem is solved.
