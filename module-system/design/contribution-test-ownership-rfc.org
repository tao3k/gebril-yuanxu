#+title: Contribution test ownership
#+date: 2026-09-12

* Scope and public syntax
A contribution repository owns its test cases. =:std/test= owns suite and
assertion primitives, while =:clan/testing= owns discovery and execution.
Agentic AI Lab does not add a test declaration macro or another testing framework.
Its package entry derives the ASP POO discovery Profile only to exclude the
independent =packages/lambda-episteme= package from clan's recursive result.
No Agentic AI Lab scanner or explicit test-file list is introduced.
Each test retains ASP's default 1024 MiB process budget unless its own scenario
derives a larger memory Profile. Legacy aggregate suites are split into their
clan-discoverable =*-test.ss= owners instead of raising memory for an aggregate.

#+begin_src scheme
;; t/sdlc/unit/profile-test.ss
(import :std/test)
(export profile-test)
(def profile-test
  (test-suite "SDLC profile contract"
    (test-case "native profile" ...)))
#+end_src

The =*-test.ss= basename and exported suite binding are identical, following
the clan/testing convention directly. Memory, performance, debug and trace
profiles are POO extensions supplied by =asp-gerbil-scheme=; Agentic AI Lab only
selects or derives those profiles for its scenarios.

* Layout
=t/<module_name>/<lane>/*-test.ss= is required. Lanes are =unit=, =source=,
=user-interface= and =integration=. Optional source checks whose dependencies
are outside the default package environment use =*-check.ss= and are therefore
not part of clan/testing's automatic unit-test set.
Non-executable qualification receipts can remain in =t/qualification/=.

There is no second filesystem catalog, layout validator, lane runner or gxtest
subprocess API.

Fixture code that intentionally violates this contract belongs outside the
contribution's runnable test tree. Agentic AI Lab keeps its negative harness fixtures
under its own fixture tree. This work migrates the contribution-related tests;
it does not rewrite the entire existing Agentic AI Lab test suite.

* Entrypoint

Each package uses the upstream-style =unit-tests.ss= entrypoint. Optional
source capabilities must not use the ordinary =*-test.ss= suffix unless their
dependencies are part of that package's default test environment.

* Qualification
Tests demonstrate contribution behavior through ordinary std/test suites. No
parent runtime or complete NASA assurance claim is inferred from them.

* Compiler extent ownership

Prepared role source files live only for one native compiler extent. Gerbil's
module catalog must not retain path or identity aliases pointing into that
removed tree after the extent returns. The compiler input owner restores the
exact previous contexts on success, exception and nested exit. A stable-path importer can still retain a staged dependency. The native import
graph supplies an extent-local reverse index; invalidation propagates through
that graph in O(V+E), including cycles. Unaffected imports remain registered. This restores catalog ownership, without
reloading initializers, creating another registry or granting source admission.

The executable build-graph Scenario checks those boundaries together with the
original changed-source refusal and successful restoration. A later test
publication in the same process must not inherit a deleted compiler path.
This lifecycle check does not close the separate 10K declaration capacity gate.

* Native source observation projection

File, directory and selected-module test publications expose =source-inputs=
from the observations already captured by their native source guards. Reading
this metadata neither invents a source inventory nor demands a business Graph.
Suite bytes and compiler support remain distinct native owners. A receipt may
combine their original observations through =unique-build-inputs=; admission
still calls both original guards. Summary hashes do not authorize compilation
or replace the Nix Source's transitive currentness checks.

* Native compiled-interface observations

A native imported =.ssi= is a compiler interface, not a Module source role.
Bazel projects dependency Tree Artifact files as symlinks in its sandbox. The
interface observation follows that native import path only when its target is a
regular file; =module-source-read= and owner-relative =.ss= confinement retain
their strict symlink refusal.

The original observation pairs retain the imported path and original bytes.
Each live test projection additionally guards the alias kind and followed
filesystem device/inode before compilation, publication restore and execution.
Equal bytes at another target do not replace an interface within that source
epoch. This filesystem identity is a live guard, not a persistent identity
scheme across machines or process restarts. Existing publication handoffs bind
the original path/byte observations and require the fresh projection's guard.

The native build-graph Case preserves positive import observations and negative
controls for same-byte retargeting, byte tampering, disappearance, directory
targets and source-role symlinks, followed by restoration of the original input.
Actual sandbox compilation and native test execution remain separate consumer
gates; an observation-component Case alone does not qualify those consumers.

* Borrowed static compiler inputs

Gambit's native executable linker writes derived C and objects beside imported
user-library Scheme. A dependency's published static Scheme can be read-only.
The existing init-owned Test demand selects these inputs from the native import
graph and compiler namespace encoding. Owned modules and the compiler's prebuilt
runtime stay with their original owners; no directory inventory is introduced.

Each selected input retains its original bytes and live filesystem origin.
Tree Artifact aliases additionally retain their original link kind and followed
target identity; observations bind the canonical regular input. Same-byte
retargeting, missing or directory targets are refused. Ordinary Module source
roles keep their strict symlink refusal.
Its public POO projection cannot replace the private source guard or mutate
the private expected text. Source and compiler observations bind that original
evidence into existing publication identity and currentness admission.

The existing Make dispatch creates one temporary static-input extent, restores
the exact prior load path on every exit, and removes derived files afterwards.
On early refusal the official compiler executor drains before retiring inputs.
Interfaces, dynamic libraries and publication approval are never copied into
this writable extent. The producer's installed library remains unchanged.

Native resource Cases cover return, exception, a real pending compiler job,
changed originals and changed staged Scheme. The executable Scenario imports
an actual POO dependency and preserves changed-source and executable-tampering
refusals. Projection-text mutation and replacement of a public guard are also
refused. Independent read-only Bazel compilation remains a separate gate.
