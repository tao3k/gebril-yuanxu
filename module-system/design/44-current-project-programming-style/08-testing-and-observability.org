#+title: Programming Style 08 - Testing And Observability

* Testing surface

Tests use Gerbil's native =gerbil test= / =gxtest= lifecycle.  POO Flow extends
the ASP Testing Policy through native POO slots; it does not create a second
test runner.  Per-test memory, performance, debug and trace Profiles are
declarative values selected by the Testing Interface.

Default =just= tests retain a bounded heap so an agent-authored infinite loop
or leak fails locally.  Build memory and test-runtime memory are different
concerns: parallel compilation may use available machine resources, while each
test execution must retain its declared safety envelope.

New Core unit cases use =poo-flow-test-case= from
=:core/observability/testing-case=; product tests may use their own public
testing facade without making Core depend on it.
This hygienic declaration expands to native =std/test=; it adds the inherited
POO Case Profile without changing =gxtest= assertions or reporting.  A Case
that needs a different budget uses =poo-flow-test-case/with= and a native POO
object extending =poo-flow-testing-case-profile-prototype=.  Do not encode a
second test runner or duplicate the Testing Interface's managed-heap default.
The Case monitor may interrupt a non-returning native harness thread and report its span;
its heap counters are process-wide, not a thread-local heap quota.  Native
=test-case= declarations that have not migrated still receive the worker-level
managed-heap cap, but not Case-span observation.
For a retained-allocation risk, a Case may opt into
=collect-before-sample?= on its memory-policy slot.  This collects before
each periodic sample so live-growth limits can stop a real allocation before
the worker's hard heap cap; it is intentionally not the default because each
collection has a cost.  The isolated observability suite verifies a bounded
retained-allocation rejection and a subsequent successful Case.  Its receipt
proves process-wide live growth during the Case span; it does not attribute
every byte to that Case alone.

* Test ownership

Core mechanism qualifications (reader/packager internals, MOP metadata copying,
source-currentness controls and destructive temporary-tree relocation) belong
in =core/t/=. A real Module or Scenario used as a fixture does not transfer
ownership of that Core mechanism test into the Module's =tests/= directory.

=modules/<name>/tests/= and =scenarios/<name>/tests/= exercise that owner's
public configuration, Contracts and behavior. Use the existing declarative
=poo-flow-test-case= or resource-owning =poo-flow-test-fixture= macros, which
lower to the native std/test lifecycle. Testing macros are the declaration
surface; a module's tests are not restricted to macro-expansion assertions.
Core imports these macros from =:core/observability/testing-case= and
=:core/observability/testing-fixture=, without depending on a product facade.
There is no parallel module test runner or repeated implementation test list.

* Observability

Observability reports first-event latency, active phase, elapsed time, memory
and final receipt without becoming execution authority.  A timeout must show
which admitted owner or Provider is active.  Tests may refine the observability
Profile for a module, but may not insert ad hoc =display= calls as the only
diagnostic contract.

Parallel batch heartbeats and per-batch debug-call dumps are off by default:
they repeat across workers without identifying a Case.  A targeted debugging
Profile may set =heartbeat-enabled?= or =trace-enabled?=; normal runs retain
the native batch start, completion and failure phases.

* Evidence order

Compile changed modules directly, run atomic tests, then affected scenarios and
public consumers.  Keep build wall time, macro-expansion time and runtime test
time distinct.  A focused green result does not qualify independent closure;
the completion report names exactly which gate ran and which remains blocked.
