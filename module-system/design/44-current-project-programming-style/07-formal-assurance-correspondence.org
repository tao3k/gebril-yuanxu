#+title: Programming Style 07 - Formal Assurance Correspondence

* Authority

Scheme owns the admitted POO Contract and its stable identity/revision.  Formal
languages consume named projections of that Contract.  They do not publish a
second user-facing model or feed proof-engine records back as semantic owners.

* Quint three-part closure

Agentic AI Lab calls a Quint model closed only when three independent artifacts agree:

1. runtime =.qnt= source declares the bounded transition system and
   invariants;
2. the pinned Quint tool typechecks the sources and their imports;
3. Quint verifies the catalogued predicates and produces a Scheme v1 receipt.

Parser acceptance is not model checking.  Quint success is not source ownership.
The aggregate qualification may join the three receipts, but no component may
stand in for another.  Terminal lifecycle states must be modeled explicitly;
do not disable deadlock checking merely to hide an undeclared terminal state.

* Lean correspondence

Lean proves structural and refinement laws that should not depend on a bounded
Quint state space. Lean and Quint use the same Contract identity and semantic
revision. Git versions the local proof and model sources, and the existing
package locks pin external dependencies. The qualification receipt records its
actual inputs and rejects changes during the run.

* Current runtime semantic Query obligations

- Entity roles preserve runtime Object identity.
- Relations close over one Element space.
- admitted Queries select declared Elements.
- Query evaluation preserves semantic revision and never grants action
  authority.
- Provider results bind Query, Provider and revision identities.

The focused owners are =core/dev/proofs/quint/RuntimeSemanticQuery.qnt= and
=YuanxuProof.ModuleSystem.Schema.Query=.

Current verifier versions, cases and receipt boundaries are documented in
=dev/proofs/quint/README.org=.
