Functional Provider capability keys describe available dependencies. They are
not Governance/Host authorization capabilities. The new Agentic AI Lab proof therefore
names these keys Dependency rather than using one overloaded permission term.
Factory bind is a same-input composition law for explicitly supplied producers;
it does not prescribe an Agent's hypotheses, exploration order or action choice.

* Composition rules for the Scheme Modules design

** Prepared machinery versus retained observations

Share a prepared dependency family only when the selected provider functions
and declared requirements are appropriate. Each application supplies its current
Context/consumer cut. A saved outcome is a different object: it carries the
input and implementation identity that produced it and needs current re-admission.
Preparing functions once must not become an excuse to reuse an old subject.

Missing an unrequested dependency can leave a narrower pure query usable.
Missing a required consumer generation/policy dependency must refuse assembly
of the full admission subject. A dependency's mere presence cannot certify that
its reported generation, policy or source is authentic.

** Shared base versus consumer-specific frame

A certified base projection may factor out independently reusable source
properties. It must not factor out a consumer authority dependency needed by
the resulting admission. Two Sessions can share source/Contract data while
retaining distinct generations, reviews, disclosure scopes and permissions.
The output constructor still receives the full outer request on a cache hit.

The complete cache/dependency key is a correctness premise of that fixed family.
Do not assume the existing broad Context cut is a universal reuse key. A theorem
with no consumer dependency can be transported across consumers; a scoped review
or permission check cannot acquire that independence merely by being stored
beside the theorem.

** Focused changes and refusal

Model source, consumer interpretation and authority-related observations as
separate composable parts. A focused change can preserve the source/Contract
frame while advancing the consumer generation. That frame law does not certify
the old admission: the changed generation reopens its dependent obligation.

A refused local update retains the previous whole value. For a sequence or
batch, earlier accepted changes may remain as the reached prefix under the
chosen contract; do not silently claim all-or-nothing rollback. Unaffected old
values and counterexamples remain available. Scheme should consume these
functional/POO laws through named helpers and object composition, not expose
Lean's proof records or another raw dictionary DSL as the normal user interface.

** Current result re-admission

ReceiptWorkflow checks a completed original result against current descriptors
without a recursive cache read or reevaluation budget. It retains its original
program/method/argument identity and preserves the supplied recursive state.
A different implementation requires a new answer indexed by that implementation.

For ORG Context, source revision, actual Contract revision, consumer generation,
policy and authority validity are additional consumer obligations. A restored
descriptor can accept an old mathematical answer again without reviving a
revoked Host grant. Current input/output acceptance and current authority must
remain separate relations and checks.

* Executable parent consumer projection

[[file:../../../../packages/proofs/lean-poo/AgenticAILabContextLifecycleProof/FunctionalComposition.lean][FunctionalComposition]] imports the actual v0.1.1 APIs. Its Cut is a small
formal projection of source, Contract, consumer-generation and policy stamps,
not the complete runtime subject or a new Scheme semantic owner.

Five laws cover current-input application, generation-separated subjects,
focused frame preservation, ordered update composition and refusal retention.
Eight guards check two generations, missing required generation versus a narrow
source-only preparation, policy override with the original provider retained,
and a local generation update. These exercise library functions, not a hand-built
alternative factory or focus implementation.

The Temporal and Context proof roots built successfully under the existing 120s
gate: 61 build jobs. The additional upstream Functional owners built in 92 jobs
under the same bound; existing upstream linter warnings were retained, not disabled.
The five inspected executable use cases were run with lake env lean, each with
the existing 120s bound. FunctionalPipeline and PreparedViews guards passed;
FocusedAllocation reported 960 direction controls plus invalid/factory controls;
CertifiedContextCache distinguished equal-base hits from changed-base misses;
ReceiptWorkflow reported zero-budget/empty-memo reuse, current input/output
refusal, changed-request recomputation and retained batch-prefix controls.

No new axioms or sorry are introduced in the parent proof. The printed
generation-separation theorem uses no axioms; update composition uses propext.
These laws assume trustworthy input stamps and complete dependencies. They do
not discharge authentication, protected I/O or AC-01 through AC-08 in the
authority/disclosure design.

* Responsibilities and open correspondence

Scheme Modules own executable POO declarations and consumer/Host boundaries.
Quint explores bounded temporal changes and explicit unsafe variants. LeanPOO
provides compositional conditional laws and checked witness transport. ASCENT
derives candidates, conflicts and affected obligations from admitted observations;
it does not manufacture grants. ORG retains claim/source/evidence identities.

The new functional projection is proof consumption, not a runtime refactor.
Implementing provider preparation, certified base projections, view retargeting
or focused updates in Modules requires named Scheme semantics and correspondence
controls before claiming parity. No library theorem alone validates that mapping.
No CPU/token/maintenance savings are claimed from these local examples.
