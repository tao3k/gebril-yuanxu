* Subject and ownership

[[file:01-agent-context-lifecycle.org][10.06.43.01]] owns the lifecycle. Modules owns issuance, replacement,
Query selection and admission; Proofs only consumes it. RFC 0015 is a Case.
Content equality is not consumer-subject equality. Review binds registry ID,
generation, Session, full ORG Element/Contract/environment cut, Governance,
scope and canonical payload. Identical rebinding must not recreate a subject.

=consumers.ss= is a process-local serialized issuer. Private state tracks exact
issued POO objects and the current collection. Copies/extensions do not issue
membership or Query authority. Scheme integer generations increase without
wrapping; registry IDs are process-local, not persistent. Core owns review seals.

* Replacement and retention

=org-context-consumer-set= issues generation zero after validation.
=org-context-consumer-replace!= validates before retiring the current set.
Empty slices unbind; identical rebinding advances again. Invalid/stale
replacement cannot update the registry. Replacement is collection-wide:
unchanged Sessions also require fresh selection/review. Selective generations
would require a separately validated protocol.

=org-context-consumer-current?= checks issuance/currency. The stamp is data,
not authority. =org-context-consumer-contexts= remains historical structural
inspection, not live Query. =org-context-query= issues a current selection;
=org-context-query-contexts= rejects stale/copied selections. This is not
another language: unified Query/GQL and its complete result adapter remain
a distinct boundary. Admission rechecks currency at construction, review and
use, binding the issued stamp into the sealed subject. Refusal reopens consumer
obligations; it does not grant effects. ASCENT consumes reevaluated observations.

Project acceptance has independent source/review/permission premises. The
Scheme Case uses a separate target registry and actual Core/Assurance/Governance
checks. Producer replacement leaves it current. This is independent acceptance,
not a persistent Project store. Target premise changes can still reopen its
obligations; historical observations/counterexamples must not be erased.
