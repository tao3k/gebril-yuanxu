* Results and scope

[[file:16-live-registry-generation.org][The registry protocol]] passed the final joint gate with exit 0 and stable
inputs before/after. All 51 Quint Cases passed; six Context Lean roots built
in 77 jobs (49 laws / 50 guards); ASCENT passed 23 checks; the existing ORG
executable passed 90 regression checks; the newly compiled Module consumer
passed 69 Scheme checks (20 added to the previous 49). Overlapping harness
counts are not independent obligations. LeanPOO remains v0.1.1.

The new controls reject old collection, Query and real review after identical
Session unbind/rebind, reject copied objects and mutation of returned stamp
data, require a fresh generation review, withdraw stale ASCENT candidates,
retain independently accepted target knowledge and reject invalid replacement
without retiring the current set. Actual ORG Elements/Contract, Session and
Core/Assurance/Governance objects are used. No effect delivery is invoked.

The first joint run was rejected because source/compiled inputs changed while
the detached-stamp correction was applied. It is not a successful receipt.
The final unchanged-input run alone supplies the identities below. Earlier
heap/elaboration/socket failures remain documented in 10.06.43.16.

* Open boundaries

This is a serialized process-local issuer and conditional formal protocol,
not a durable/concurrent Host implementation or cross-language bisimulation.
External Session retirement must call explicit registry replacement.
Persistent identity, reconciliation, issuer-history reclamation, complete
unified Query/GQL result adaptation, source availability/disclosure and
Project promotion execution remain open. Independent target knowledge still
requires its own current source/Contract/review/permission premises.
Storage executors, bindings and old Memory are unchanged; no CI or remote
head qualification, deployment or performance improvement is claimed.
