before parent/Assurance admission Profile construction. Controls exercise
unapproved initialization/targets, missing or copied binding/control/receipt,
unresolved Governance, real evidence/grant prerequisites, cross-controller and
cross-proposal replay, policy withdrawal before commit, revoked/expired
receipts, target revision, competing captured generations and old Profile/review
refusal after rotation. A -> B -> A is tested with the original bootstrap
receipt still unexpired, isolating configuration-generation refusal from expiry.
Fresh replacement reviews pass; retired consumption obligations reopen and
ASCENT candidates withdraw. Source management never invokes effect delivery.

The source-policy callback revocation Case uses a separate real lifecycle
fixture and actual effect-Host revocation. Approval now checks Host evidence
and permission again after that callback. Proofs does not implement another
approval predicate, mint a successful grant or copy Module commit semantics.

without changing that contract. The historical failure is not counted as
successful authorization refusal. The proposal sequence is captured before
constructing its POO slot so later proposals cannot change its signed subject.

exit, synthetic progress, watchdog suppression or heap/timeout change was used.

input. The named Assurance adapter additionally requires an explicit configured
source-management decision: ordinary business grants alone do not authorize
all targets. The fixture's local configured decision is not a deployed Cedar
policy proof. Remote installation/root credentials and authentication remain
open. Receipt revocation stops pending publication, not implicit rollback of
an already committed historical configuration; live consumption still requires
its own permission/review/source premises.

* Open boundaries

Local controller CAS/receipt revocation and conditional formal properties
are not a distributed transaction across independent Host authorities.
Trusted clocks and controller setup, remote root installation/authentication,
durable/multi-process control, recovery/reclamation, Session reincarnation
and protected unified Query/GQL remain open. Old Profiles stay invalid after
rotation, while independently accepted Project knowledge keeps its own premises.
Storage executors, bindings, old Memory and effect delivery are unchanged.
No CI, deployment, remote identity or performance improvement is claimed.
