* Focused results

[[file:37-session-rebinding-concurrency.org][37 refines the existing Module protocol]]. All sixteen focused Quint Cases
passed: one complete safe exploration (3,553 generated / 672 distinct states),
seven reachability controls and eight deliberately unsafe mutations. Each
negative control requires a real TLC invariant violation, not a syntax failure
or timeout. Reachability includes either competitor winning, fresh consumption,
post-publication permit withdrawal, isolated old-source retirement, retained
history after target retirement and independently approved empty handoff.

Sixteen Context Lean roots built in 87 jobs, adding fifteen theorems/eight guards
(155 theorems / 126 guards across Context roots). The new root imports the prior
Reactivation transition instead of defining another rebind issuer. LeanPOO Focus
expresses old-registry advancement. Printed axioms remain explicit; no =sorry=
was introduced and no claim is made about mutex implementation or remote identity.

The preliminary Scheme replay naturally exited 0 with 591 assertions: 178 observations in
the nine new schedules added to the preceding 413. Repeated common checks across
schedules are not independent universal proofs. Actual threads contend for two
issued binding proposals or perform Module withdrawal/retirement during a real
configured policy callback. After-publication worker operations exercise the
other order. All joins keep the existing two-second limit.

The fixture recovers and activates a real controller for each schedule and
creates two valid permits before either commit. Actual Core/Governance and
ORG Elements/Contract-derived Context are used; Assurance Profile/review/grant
checks occur on the original effect Host owner after workers join. Core fixture
policies are bounded/thread-safe, not remote Human/source authentication.
No fake issuer, binding interpreter, effect delivery or Host owner bypass is used.

* Observed boundaries

- Exactly one competitor publishes control generation one and registry generation
  one; latest points to the actual issued winner, and both old permits fail replay.
- Permit withdrawal/root revocation/target retirement before commit refuses; unaffected competing
  proposals can still publish generation one where authority remains live.
- Old-source retirement before commit advances its registry itself. Fresh empty
  handoff reaches generation two without resurrecting its retired Session slice.
- Root revocation after publication withdraws admission but does not erase the
  current structural collection. Target retirement stales its Query and removes
  the Session from latest. Both consumer obligations reopen.
- With current root/target/review/permission unchanged, withdrawing a consumed
  proposal permit or retiring the old source after publication does not uninstall
  the successor binding or invalidate its unaffected Query.
- After a handoff publishes, old collection proposals and Queries are stale.
  Across all schedules, old controller/review/Profile and source/recovery permits
  cannot restore admission. In the pre-publication root-revocation schedule the
  structural registry is deliberately unchanged, not newly authorized. An
  independently admitted Project view remains admitted in every schedule under
  its own current authority and grant.

* Failed construction attempts, not passes

The initial Quint typecheck rejected action updates inside pure =Set.exists=.
The two finite target alternatives were declared explicitly before running TLC.
The first Lean build rejected a multiline record update and could not reduce a
Focus projection in one lemma; the update was made unambiguous and the existing
=Focus.modify= definition unfolded. The resulting guard/theorem failures from
that unsuccessful elaboration were not accepted as proof. The corrected Context
target built successfully with the same policies and no disabled lint/axiom checks.

The first joint attempt was interrupted explicitly with SIGINT (exit 130) after
100 completed Quint Cases. Review of the old-source-after-publication positive
control identified a missing direct observation of its retirement publication:
an unaffected successor Query alone was insufficient to certify that the old
source had actually advanced. Two assertions were added for revision one and
empty active membership. The initial 591-assertion replay and interrupted joint
attempt do not qualify that strengthened final source cut. The entire gate is
rerun; no failed/incomplete attempt is converted into a pass.

* Scope, limits and reproduction

The existing Modules final checks already cover these schedules; this turn
changes no functional Module code, storage executor, bindings or old Memory.
It adds proof consumers, formal projections and ORG correspondence, not a new
source approval route. Historical receipts remain qualified only for their cuts.
Remote CI, durable/multi-process identity, protected disclosure and distributed
recovery are not qualified here.

TLC remains 60 seconds total / 12 seconds silence, one worker / 512 MiB. Lean
remains 120 seconds. Scheme remains 120 seconds total / 5 seconds silence and
1 GiB heap. All successful replay exits must be natural; no successful exit is
forced and no watchdog or verification policy is relaxed.

Compile the new proof consumer and its admission caller with the current
installed Scheme package; do not rebuild or mutate inputs during the joint
gate. With =CONTEXT_ASCENT_GERBIL_PATH= set to its existing dependency directory,
run from the repository root:

  python3 packages/proofs/context-lifecycle/verify.py
#+end_src

Final outcomes and source/compiled identities are recorded only after the entire
gate and before/after identity comparison pass.

active membership) before asserting successor isolation. Overlapping/repeated
