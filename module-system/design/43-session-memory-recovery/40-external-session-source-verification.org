* Scope and preliminary evidence

[[file:39-external-session-source-admission.org][39]] defines the Module-owned source protocol. Proof consumers construct
inputs and inspect results; they do not implement another source resolver.
The existing ORG handoff gate parses actual Elements/Contract, creates Context
and Session objects, and passes them to the new consumer control suite.

25,612 states / 3,215 distinct states; five reachability controls and seven
deliberately unsafe mutations each yielded the required TLC counterexample.
Safe properties cover checked publication, current admission, no resurrection
and knowledge retention. The focused run precedes a harness choice-list cleanup;
the complete gate must qualify the final harness/source cut independently.

conditional theorems and ten executable guards (168 theorems / 136 guards in
Context roots). LeanPOO Focus expresses revision updates; no =sorry= or disabled
lint was added. Knowledge retention has no axioms; the printed old-review proof
uses standard =propext=, =Classical.choice= and =Quot.sound=, not authentication
axioms. Provider verification and truthful authorization remain stated premises.

* Controlled compiler lifecycle

=compiler_service.py= now owns one installed Apalache 0.62.1 process for the
unchanged serial Case list. It selects an unused loopback endpoint, requires
its own process's startup announcement and actual socket readiness, then sends
every Quint invocation through the supported =--server-endpoint=. A pre-existing
service is not deliberately borrowed. The owned process remains monitored
through every Case and cleanup: its binding failure/unexpected exit cannot
qualify the run even if another process races onto the selected endpoint.
No download or temporary SDK is introduced.

Startup retains the 60-second total / 12-second silence bounds. A real-tool
integration exposed that Apalache prints its ready banner before Netty actually
binds the port: the first integration failed with connection refused and was
not accepted. Bounded readiness probes now wait for the actual listener under
the same deadlines; failed probes produce no output, renew no deadline and
restart no process. An early-banner fault control exercises this order.

Each Case keeps its own existing 60-second total / 12-second useful-output
deadline. TLC still reports genuine state counters every three seconds; unchanged
counters cannot renew the idle deadline. Compiler death, even between Cases,
refuses further use. Detection of Quint attempting its own replacement server
fails the Case, not a transparent fallback. A nonblocking ownership lock rejects
parallel Case use. Compilation errors cannot count as expected counterexamples:
the existing required exit code, nonzero explored-state count, exhaustion or
actual invariant-violation trace requirements are unchanged.

The verifier stops only its owned compiler process group and reaps it with the
existing three-second cleanup bound. Expected requested termination is distinct
from unexpected service death, abnormal shutdown or refusal to terminate. Forced
cleanup of a stubborn service is a failure, never a passing verifier exit.
Exceptions and interrupts propagate after child cleanup; they cannot emit the
Quint pass marker. Installed launcher/JAR SHA256 identities must match before
and after service use. Per-Case TLC processes still run serially with one worker
and 512 MiB; no exploration Case or invariant was removed.

=test_compiler_service.py= contains nineteen lifecycle/fault controls: one owner
across two serial clients; early banner; startup exit/EOF/silence; death during
and between Cases; client/caller failure; interrupt; tool identity drift;
forbidden fallback/parallel use; abnormal/stubborn shutdown; stationary counters;
absolute total deadline; silent client; and strict result classification. Their
small fault-injection processes are lifecycle tests, not model/compiler evidence.
The suite is a required bounded step in =verify.py= before all model Cases.

The preliminary real-service integration passed all thirteen Session-source
Cases with one actual compiler start/stop and unchanged safe state counts.
That focused run did not bind the later harness/source changes or replace the
complete gate. The final joint receipt below qualifies that completed cut.

* Reproduction and limits

Use the current installed Scheme package and dependency pool. Compile Module
consumers/source-control/session-source/interface, the optional Assurance
adapter, then the proof consumer/admission caller in dependency order. Do not
recompile or mutate the captured source/package pool during joint verification.
From the repository root, with the existing ASCENT package directory selected:

#+begin_src sh

  python3 packages/proofs/context-lifecycle/verify.py
#+end_src

TLC keeps 60 seconds total / 12 seconds silence per Case, one worker and 512 MiB;
its three-second checker status reporting does not extend either deadline.
Lean keeps 120 seconds. Scheme keeps 120 seconds total / 5 seconds silence and
1 GiB; existing thread joins keep two seconds. Success requires natural exit
and before/after source plus compiled-input stability. No storage executor,
bindings, old Memory, external identity transport or remote CI is qualified.
