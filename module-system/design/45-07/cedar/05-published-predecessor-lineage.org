* Published predecessor lineage

** Predecessor-lineage requirement

Binding the transition successor to the current checkpoint is necessary but
not sufficient.  The artifact's =oldAuthority= MUST be the directly preceding
published authority context.  Otherwise a caller can invent an old authority
with an empty admitted set: admission monotonicity and projection stability
then hold vacuously even when the real predecessor's admitted content changes
digest.

The predecessor requirement spans three existing owners and therefore cannot
be inferred from any one name:

- the transition artifact owns its prior and current contexts;
- =SuccessorAdmissionClosure= owns fresh coordinator admission, distinct
  execution identities, before/after context binding, and no authority
  widening;
- =AuthorityContextLineage= owns published positions and strictly increasing
  generations;
- the already closed current-checkpoint layer proves the successor context is
  the authority-issued current head.

A total =contextAt : Nat -> ReceiptValidationContext= is a mathematical
lineage, not an assertion that every future position has already been
published.  The checkpoint publication domain therefore MUST equal the lineage
prefix ending at the current position.  Merely passing a lineage and a domain
with the same authority identity leaves them logically independent.

** Vacuous-predecessor counterexample

=fabricatedEmptyOldMakesCompatibilityVacuous= constructs generation =2= with
the right authority and semantic identity but with =admitted = False=.  It is
formally compatible with the drifting generation =4= because both monotonicity
obligations have empty premises.  The actual published generation =3= admits
content =7=, and its digest differs from generation =4=; therefore the
fabricated old state bypasses the real compatibility obligation.

=independentLineageAllowsUnpublishedFabricatedPredecessor= exposes the second
hole: an arbitrary adjacent lineage can contain generations =2 -> 4= and share
the real current head =4= even though the actual publication domain contains
only generations =3= and =4=.  Adjacency inside an unbound lineage is not
publication evidence.

** Predecessor-lineage decision

The transition evidence now carries a prior =ReceiptValidationContext= bound
to the old authority identity and generation.  The outer
=PublishedPredecessorCedarInputIdentityTransitionClosed= contract then:

1. binds prior/current evidence contexts to the exact
   =SuccessorAdmissionClosure= before/after contexts;
2. binds both contexts to one =AuthorityContextLineage=;
3. requires the current position to equal =priorPosition + 1=;
4. binds the lineage authority through the injective identity encoding;
5. requires the checkpoint publication predicate to equal exactly the lineage
   prefix whose upper bound is the current position;
6. retains the inner authority-issued artifact, snapshot projection, trusted
   watermark, and current-checkpoint closure.

Generation inequality alone is no longer treated as predecessor evidence.
Likewise, =SuccessorAdmissionClosure= is reused for its actual coordinator and
execution contract, not misrepresented as proof of publication adjacency by
itself.

** Predecessor-lineage verification checklist

- [X] Construct an empty-admission old authority that makes compatibility
  obligations vacuously true.
- [X] Prove that construction bypasses a digest mismatch on the actual
  admitted predecessor input.
- [X] Commit prior context identity and generation inside validated transition
  evidence.
- [X] Bind prior/current contexts to the exact successor admission.
- [X] Bind both contexts to one published authority lineage.
- [X] Require adjacent lineage positions rather than mere generation increase.
- [X] Separate a total mathematical lineage from its already-published prefix.
- [X] Bind the checkpoint publication domain to the exact lineage prefix ending
  at the current position.
- [X] Retain fresh coordinator admission and distinct execution identity via
  the existing successor-admission owner.
- [X] Prove an unpublished prior context cannot close the transition.
- [X] Prove non-adjacent lineage positions cannot close the transition.
- [X] Prove the bound domain publishes the exact predecessor context.
- [X] Prove every lineage position after the current head is rejected by the
  bound publication domain.
- [ ] Implement and publish the runtime prior-context/successor-admission
  witness at the executable owner; Lean does not synthesize it.
