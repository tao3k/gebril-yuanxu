* Content-identity generation transition

** Generation-transition requirement

The input-identity refinement proves that one admitted grant is bound to the
current authority generation.  It does not by itself constrain how two
successive generations relate.  The architecture therefore needs two distinct
transitions:

- a compatible generation advance keeps the authority identity and semantic
  identity stable, admits every previously admitted input, and preserves every
  digest projection on those old admitted inputs;
- a semantic-identity rotation advances the generation but changes the
  semantic identity, so a receipt issued for the old semantic identity cannot
  be accepted by the current refinement.

This is a v1 identity-transition invariant for the new architecture.  It is
not a compatibility-migration or deprecation policy.

** Generation-transition observation and counterexample

Authority identity, semantic identity, and a strictly increasing generation
are insufficient on their own.  Two authorities may satisfy all three facts
while mapping the same previously admitted Cedar input to different digests.
The executable counterexample
=legacySameSemanticTransitionAllowsDigestDrift= witnesses exactly that hole.

#+begin_export typst
$
  "CompatibleAdvance"(a_o, a_n) :=
    a_o.authority = a_n.authority
    and a_o.semantic-id = a_n.semantic-id
    and a_o.generation < a_n.generation
    and forall u in a_o."admitted": a_n."admitted"(u)
    and forall u in a_o."admitted": a_o.digest(u) = a_n.digest(u)
$

$
  "SemanticRotation"(a_o, a_n) :=
    a_o.authority = a_n.authority
    and a_o.semantic-id != a_n.semantic-id
    and a_o.generation < a_n.generation
$

$
  "Accept"(a_n, r_o) =>
    r_o.semantic-id = a_n.semantic-id
    and r_o.generation = a_n.generation
$
#+end_export

** Generation-transition decision

The machine-owned transition contract is split deliberately:

1. =CompatibleCedarInputIdentityGenerationTransitionClosed= requires stable
   authority and semantic identity, a strictly newer generation, monotone
   admission for request/entities/policies/snapshot, and stable
   request/entity/policy/bundle projections for every old admitted input.
2. =CedarInputSemanticIdentityRotationClosed= requires stable authority,
   changed semantic identity, and a strictly newer generation.
3. A current refinement rejects the old semantic identity after rotation and
   cannot also bind the old generation.  No theorem assumes global hash
   injectivity; uniqueness remains bounded to authority-admitted inputs.

** Generation-transition verification checklist

- [X] Construct a same-authority, same-semantic-id, increasing-generation
  counterexample whose digest drifts on an old admitted input.
- [X] Prove compatible advances retain old request and snapshot admission.
- [X] Prove compatible advances preserve request and bundle digest projection
  on old admitted inputs; the contract also covers entities and policies.
- [X] Prove a compatible advance cannot reuse the old generation.
- [X] Prove semantic rotation rejects the old semantic identity under the
  current real Cedar input-identity refinement.
- [X] Keep the transition contract on the existing
  =CedarInputContentIdentityAuthority= rather than introduce a parallel
  runtime authority.
- [ ] Implement the runtime producer that emits transition evidence; this is a
  separate executable owner and is not established by Lean.
