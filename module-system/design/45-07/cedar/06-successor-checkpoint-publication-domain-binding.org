* Successor/checkpoint publication-domain binding

** Cross-domain requirement and counterexample

=SuccessorAdmissionClosure= and the authority-issued checkpoint each carry a
=TrustedCheckpointWatermark=.  Validating both against the same
=ReceiptValidationContext= does not prove they refer to the same publication
domain.  =independentWatermarksAllowCrossDomainContextMix= constructs domain
=101= and domain =202= with identical authority =17=, minimum generation =4=,
and the same admitted context.  Both validations succeed independently while
their domain identities disagree.

#+begin_export typst
$
  "CrossOwnerWatermarkClosed"(s, c, d) :=
    s.verifier-watermark = c.verifier-watermark
    and s.admission.publication-domain-id = d.domain-id
$
#+end_export

** Cross-domain decision

The published-predecessor closure now requires
=successorAdmission.verifierWatermark = checkpointWatermark=.  Together with
the existing successor =checkpointBinding= and current-checkpoint
=checkpointAcceptedByWatermark= proof, this derives exact equality between the
successor admission's =publicationDomainIdentity= and
=domain.domainIdentity=.  Context equality is no longer used as a substitute
for domain identity.

** Cross-domain verification checklist

- [X] Construct two distinct publication-domain watermarks that independently
  admit the same authority/generation context.
- [X] Require exact successor/checkpoint watermark equality.
- [X] Derive successor admission publication-domain identity equals the current
  checkpoint domain identity.
- [X] Prove mismatched watermarks cannot close the transition.
- [ ] Emit the exact shared watermark from the runtime successor-admission and
  checkpoint producers.
