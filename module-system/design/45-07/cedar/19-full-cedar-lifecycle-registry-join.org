* Full Cedar lifecycle registry join

** Full-registry requirement

The local =AuthorizationLifecycleEvidence.Closed= model establishes lifecycle
semantics once its authority-path and separation-of-duty predicates are given.
It does not prove that those predicates, the evidence, or the commitment came
from the installed registry/signature lifecycle owner.

Final composition admission therefore MUST additionally consume the existing
=SourceBoundEffectCompletionRecoveryCedarAuthorizationLifecycleEvidence= and
its selected, registered Cedar evidence.  The selected evidence must be the
same evidence carried by an authority-validated binding of the exact capability
grant.

** Carrier mismatch and unregistered-evidence counterexample

The local lifecycle model and the full registry model are intentionally not the
same type:

- the local model uses =Nat= identities and a reduced authorization response;
- the full model uses =String= identities, =Cedar.Spec.Response=, and the real
  Cedar request, entity, and policy values.

No implicit conversion between them is permitted.  A validator owns any
cross-carrier refinement and produces one exact authority-bound binding.

=localClosedAuthorityEpochJoinAcceptsUnregisteredEvidence= constructs locally
closed evidence with the expected authority and epoch, while the evidence is
not the value selected by the active registry at its claimed commitment.  This
proves that local closure is not registry authenticity.

#+begin_export typst
$
  R_(closed)(q, g, b, s) :=
    G_(closed)(q, g)
    and A_(full).validate(b.receipt) = b.binding
    and A_(full).accepted(b.binding)
    and b.grant = g
    and b.evidence = s.registry(s.envelope.commitment)
    and L_(full)(s)
    and L_(full)(s) => "Admitted"(b.evidence)
    and s.envelope.runtime-epoch = q.generation = q.subject.epoch
    and b.evidence.fence = s.envelope.fence
$
#+end_export

** Full-registry decision

- =FullCedarLifecycleSelection= dependent-packs the existing trace, budgets,
  scopes, commitment scheme, signature verifier, registry, envelopes,
  authenticity evidence, and full lifecycle proof.  Composition receives one
  package instead of reproducing its parameter list or semantics.
- =CompositionCedarFullLifecycleRegistryJoinClosed= joins that package to the
  exact capability grant through =AcceptanceAuthority/AuthorityBoundNode=.
- =closedFullLifecycleJoinProvidesRegistryAdmission= calls the existing
  =closedCedarLifecycleAuthorizationAdmitted= theorem.  It does not replace the
  registry or signature owner with a local Boolean.
- =closedFullLifecycleJoinBindsRuntimeAndFence= derives runtime epoch and fence
  equality from the existing full lifecycle =cedarBindings= field.
- Structural similarity between the Nat model and String/Cedar evidence is
  explicitly non-authoritative; the validator owns the refinement relation.

** Full-registry verification checklist

- [X] Lean counterexample: local closure plus authority/epoch equality accepts
  evidence not selected by the active registry.
- [X] Lean theorem: full join rejects unselected evidence.
- [X] Lean theorem: full join rejects stale registry generation.
- [X] Lean theorem: full registry closure requires signature, authority, and
  commitment binding.
- [X] Real Lean theorem: the dependent-packed full lifecycle selection produces
  existing registry =Admitted= evidence.
- [X] Real Lean theorem: the exact grant/evidence pair is authority validated.
- [X] Real Lean theorem: runtime epoch and active fence are derived from the
  existing full lifecycle =cedarBindings= proof.
- [ ] POO Scheme runtime publishes and consumes the full-lifecycle
  authority-bound receipt before capability slots become usable.
