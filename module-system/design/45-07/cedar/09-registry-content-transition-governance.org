* Registry content-transition governance

** Registry content-transition requirement

A registry trust-root generation advance MUST NOT treat stable authority,
stable registry semantics, and an increasing generation number as evidence that
registry content was preserved.  For every descriptor registered by the
predecessor root, the successor MUST either retain that exact descriptor or
carry an acceptance-authority-validated retirement bound to the predecessor
root claim and the exact successor generation.

The registry is not append-only.  Explicit retirement is required for enterprise
revocation and compromised-domain response; the forbidden operation is silent
deletion or replacement without retirement evidence.

** Silent registry-content mutation counterexample

=validRegistryTrustRootTransition= previously constrained only registry
authority identity, registry semantic identity, and increasing generation.
=validRegistryTrustRootTransitionPermitsSilentDescriptorDeletion= constructs a
valid generation advance whose predecessor and successor use the same registry
authority and semantic identities, while a predecessor descriptor disappears
and a descriptor with the same domain identity but different semantics takes
its place.

This is content rollback hidden behind identity monotonicity.  Neither checkpoint
position monotonicity nor stable metadata proves a disposition for the removed
descriptor.

** Registry content-transition Typst model

#+begin_export typst
$
  "Disposition"(d, p, n) :=
    "registered"(n."registry", d)
    or "AuthorityValidatedRetirement"(
      d,
      "RegistryClaim"(p."root"),
      n."generation",
    )

  "ContentGovernedTransition"(p, n) :=
    "ValidIdentityTransition"(p, n)
    and forall d in p."registry": "Disposition"(d, p, n)
$
#+end_export

** Registry content-transition decision

- Preserve =validRegistryTrustRootTransition= and the original lineage as the
  weak identity/generation model and counterexample surface.
- Add =AuthorityValidatedDescriptorRetirementEvidence=, binding the exact
  predecessor registration, canonical registry trust claim, and successor
  generation.
- Add =ContentGovernedRegistryTrustRootTransition=: every predecessor
  descriptor must be preserved or have an inhabited validated-retirement
  witness.
- Add =ContentGovernedPublicationDomainRegistryTrustRootLineage= so every
  adjacent published position exposes this content-governed transition.  Safe
  downstream composition consumes this wrapper rather than inferring content
  safety from the old lineage.
- Keep executable signature and commitment validation at the registry
  acceptance authority.  Lean specifies the evidence contract; it does not
  manufacture a retirement signature.

** Registry content-transition checklist

- [X] Distinguish generation/identity monotonicity from registry-content
  preservation.
- [X] Construct a valid transition that silently deletes or replaces a
  predecessor descriptor.
- [X] Preserve enterprise revocation through explicit retirement rather than
  forcing append-only registries.
- [X] Bind retirement to the predecessor root claim and successor generation.
- [X] Require preservation-or-retirement for every predecessor descriptor.
- [X] Lift the content-governed transition to every adjacent lineage position.
- [X] Prove silent deletion yields a validated retirement witness or cannot
  close.
