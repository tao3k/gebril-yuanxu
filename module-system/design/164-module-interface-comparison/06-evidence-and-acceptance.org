* Follow-up experiments that could change the design

1. Run the same late-bound/frozen-value probes on pinned Nickel, Jsonnet and
   Dhall interpreters. Compare values and error timing, not invented object
   identity equivalences between different language models.
2. Evaluate the NixOS CI module with pinned nixpkgs. Check wrong command types,
   conflicting definitions, missing order entries and user-visible file locations.
   Compare the corresponding admitted POO boundary once that boundary exists.
3. Give users the same five tasks: change a command, relocate a root path, append
   an artifact, add/select a Check and resolve two owners' same-named Check.
   Record concepts, searches, diagnostics and successful consumer output.
4. Build 1000/10000-module metadata catalogs with independently varied selected K.
   Separate source import, index building, object/factory demand, admission and
   projection. Include cold/warm and failure controls with unchanged watchdogs.
5. Inspect published attribute descriptions for both a scalar business field and
   a native strategy object. A user must identify the supported extension without
   opening every internal component or inventing a new Contract annotation.

* Claims deliberately withheld

This study establishes neither faster evaluation than Nix/Nickel nor stronger
configuration safety than Dhall. It does not prove a full-contract user route,
authenticated source provenance, general cycle detection, or a completed Loader.
The previous combined-source memory-guard failure remains a failure record; a
successful isolated lane does not turn it into scalability evidence.

The research result is a set of concrete interface changes to design and qualify,
not a declaration that POO already wins every comparison category.
