This study measured result prediction and feedback transfer, not arbitrary
program generation, complete POO composition, all business tasks or online
weight training. Only three actual ASCENT modules were initially supplied;
their full transitive implementation closure was not supplied. Inputs were
source, facts and ordinary =check-equal?= tasks with missing expectations.
There was no added semantic tutorial, RULES, worked answer or native answer
before the first prediction. Provider text messages still carried context.

* Native computation and observation

All twelve tasks actually executed Scheme =relational-program= admission,
solving and session updates. Independent finite algorithms or existing
qualification contracts checked their results. Successful receipts required
MODULE-OK, HARNESS-OK and final OK, with a five-second real-output silence gate,
an independent heap fence and a process timeout.

Model output was read as inert data: a single prediction datum or the quoted
expected datum of a standard =check-equal? result= expression. Model text was
never evaluated. Byte, character and depth bounds preceded reading; reader
failures were retained. After each candidate, the guard recomputed the current
task, checked source/truth identity and produced the first difference path in
Scheme. Feedback bound the program, candidate, computation log and revision.
Local controls covered recomputation, counterexamples and reader failures.

Separately, 22 whole responses violated datum transport and two raw responses
were empty. These overlapping dimensions must not be added to the table.
Tasks exposed =(check-equal? result '?)= without a single-datum output protocol;
the evaluator nevertheless imposed that protocol on whole responses. Twelve
native truth preflights had not tested actual output transport. This was an
integration design defect, not evidence that all 24 semantic predictions were
wrong. None join/closure sometimes became code review rather than prediction.

The three supplied entry modules omitted evaluate/planning implementations.
Exact diagnostic paths depended on planning's =on-plan-error=. Response 16
recognized an unbound head variable but proposed conflicting locations;
response 21 described withdrawal correctly yet included executable
list/canonical forms. Neither received additional credit by human judgment.
Resource exhaustion, transport acceptance, semantic correctness and teaching
benefit must be recorded independently.

Synchronous/asynchronous answer retelling was removed; historical replay became
pure candidate checking. =temporal.observe= used the existing Scheme owner to
compute live state/row differences bound to an exact request digest.
=predict_temporal_answer= and its asynchronous counterpart sent detached tasks
to IO, then delivered native artifact-bound observations through
=observation_sink=. No automatic model retry or effect authority was added.
