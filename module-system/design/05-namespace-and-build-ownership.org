* One package and one language entry

| Owner | Identity |
|-------+----------|
| Repository | tao3k/gebril-yuanxu |
| Root Gerbil package | yuanxu |
| Ordinary library import | :yuanxu/<owner>/<module> |
| Language entry | :tao3k/yuanxu/prelude |
| Language implementation | root prelude.ss |
| Public function prefix | yuanxu- |
| Object/Contract prefix where qualification is needed | Yuanxu |
| Type fact projections | :yuanxu/types/facts |

The physical core/ submodule checkout does not define a compiler package.
The product Agentic AI Lab retains its own product namespace. Yuanxu imports no
product implementation. Semantic module keys such as core/json-schema are
publication identities, independent of Gerbil library paths.

No parallel package root, forwarding namespace or legacy API alias is kept.
Normal library consumers need no custom prelude. The root prelude bootstraps
on :gerbil/core; explicit build entrypoints bind its actual runtime module
context before importing source-only Yuanxu libraries.

* Publication and build have the same selected graph

=module-system/building/interface.ss= owns =yuanxu-init-build=;
=module-system/building/build-projection.ss= owns
=yuanxu-project-source-spec=. The init declaration publishes the ordinary
build-spec/build-run accessors, dependency scopes and test projections.
Projection checks retained source paths, runtime compiler identities, options
and selected generations. Duplicate retained identities remain an error.

Source-first registration belongs only to the compiler/build entry.
Importing init or projecting build data must not reprioritize runtime
libraries or reinstall held Contract identities. The installed Gerbil
compiler and std/make own compilation and scheduling without source patches.

* On-demand compilation from init.exports

Use Gerbil =defbuild-script= to run a package Make spec. Request a scoped
spec through the init publication when only some leaves belong in that
build. =Mount/module= identifies a leaf without constructing its scope.
Repeated roots contribute once. The existing source guards refuse unknown
or disabled owners before Make runs.

#+begin_src scheme
(defbuild-script
  (.call package.init.exports .make-spec-for '(Modules/clock Modules/nix)))
#+end_src

A package build that narrows its leaf selection can pass =package-roots?: #t=
to =.make-spec-for=, =.compile-selection= and =.clean-selection= to include the targets
declared in =:build-roots=. Mount projections remain leaf-scoped.

An explicit build operation can invoke =.compile-selection= with leaf names,
mount names and a Gerbil Make callback. The action supplies the admitted
targets and their source directory, including any declared FFI prerequisites
needed before Interface expansion. For mixed package owners, the supplied
source directory is the admitted compiler input view.

#+begin_src scheme
(.call package.init.exports .compile-selection '(Modules/clock) '()
  (lambda (targets source-root)
    (make targets srcdir: source-root)))
#+end_src

The [[file:../../t/module-build-command-test.ss][selection regression]] checks
real Gerbil products, repeated and overlapping roots, and the unchanged
default spec. It covers missing and disabled leaves and unrelated cold Modules.

* Cross-package on-demand prerequisite compilation

A downstream package keeps its =build.ss= minimal (ordinary =defbuild-script=
consuming =std-make-spec=, optionally wrapped by =.with-link=) and declares
upstream packages through standard Gerbil =gerbil.pkg= =depend:= entries plus
ordinary =(import :upstream-pkg/...)= edges. =from:= windows remain dedicated
to mounting upstream Yuanxu =ModuleSource= selections rather than duplicating
ordinary Gerbil library imports.

=module-system/building/dependency-packages.ss= owns two-stage cross-package
prerequisite compilation while preserving single-package purity for
=std-make-spec= and =clean=:

1. *Discovery (=plan-dependency-package-builds=)*: Resolve declared =depend:=
   packages transitively under active =pkg/= stores, seed selected local
   sources from =init.ss= / =:build-roots= purely as declaration data, and walk
   imports via Gerbil's native =core-read-module/sexp= reader (no custom parser,
   no module evaluation, zero business scopes constructed). Group missing or
   transitively stale targets by external dependency package root in
   topological order.
2. *Isolated compilation (=ensure-dependency-packages-compiled!=)*: For each
   dependency package with missing or stale targets, run native =:std/make=
   with that dependency package's own =srcdir:= (preserving its own
   =gerbil.pkg=, =package:= prefix, =prelude:=, and native =gxc= FFI support)
   inside =call-with-build-input-path= and =call-with-selected-output-lock=,
   restoring the caller's load-path order on exit. Fresh =.ssi= artifacts are
   reused with zero recompilation; =clean= and =spec= never compile or remove
   upstream artifacts.

In =module-system/source/build.ss=, cross-module imports of another selected
Module's =interface.ss= reconcile ='source= and ='publication= ownership in
either discovery order when path and =compiler-identity= match.

The [[file:../../t/module-build-cross-package-test.ss][cross-package demand build regression]]
verifies cold on-demand compilation (including =C-declare= FFI leaves), unused
module isolation, hot =.ssi= reuse, stale incremental rebuilds, transitive
multi-package topological order, clean isolation, and ='source=/='publication=
coexistence.

* Evidence after migration

Maintained examples and historical Scheme probes use the current namespace.
Renaming an example does not requalify its previous result. Historical
commit identities and failure outcomes remain evidence of their original
source cut. Current runtime, Lean and Quint results are recorded separately
in [[file:../../docs/10-19-design/13-module-loading/13.16-yuanxu-package-and-prelude.org][the package and prelude qualification]].
