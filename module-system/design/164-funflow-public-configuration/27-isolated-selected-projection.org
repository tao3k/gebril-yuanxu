* User declaration, automatic discovery and final values

Root provides build/test/package defaults and an optional unused Check. Its
Pipeline checks map selected symbols through the native outer effective-config
lexical binding, exactly as in the prior receiver controls. The fixture warms
Root.pipeline.checks BEFORE the user declares Release:

#+begin_src scheme
(def parent-pipeline (.get Root pipeline))
(def parent-checks (.get parent-pipeline checks))

(.def (Release @ Root)
  build: =>.+ (.o commands: '("gerbil" "build" "--release"))
  smoke: (.o commands: '("printf" "smoke"))
  pipeline: =>.+ (.o selected-checks: '(build test package smoke)))

;; Internal fixture admission boundary, not another user configuration layer.
(def context (.o target: Release))
(def result (admit-selected-profile FixturePolicy Release context))
#+end_src

FixturePolicy is maintained upstream: static pipeline-selection responsibility,
default Check commands Contract and a stricter per-name build Contract. The
selector must be a duplicate-free symbol list. Protected role names refuse.
Static responsibility admission occurs first, then final selected symbols are
projected into a fresh native descriptor without mutating the shared template.

The public native walker admits those actual child objects. Coverage verifies
typed/correlated parent and child receipts, exact responsibility membership and
no duplicated receipt names. A retained required-checks field is a DERIVED
snapshot for inspection, never a supplied completion claim.

#+begin_example
(automatic-admitted #t)
(required-checks (build test package smoke))
(final-commands (("gerbil" "build" "--release")
                ("gerbil" "env" "unit-tests.ss")

                 ("gerbil" "env" "unit-tests.ss")

The counts are Pipeline construction, checks computation and optional unused
Check evaluation. They include both parent and child receivers. Declarations
leave the first two at 1; admission brings them to 2. Parent object/list identity
remains unchanged. Every final Pipeline Check is eq? to its selected Release
slot, including new smoke. Check receipt identities distinguish smoke's default
Contract from build's stricter Contract and identify the actual final child.

* Refusal and laziness controls

| Case | Executed observation |
|------+----------------------|
| selected smkoe | Projection retains the required typo; public Core returns missing-responsibility; overall admission refuses |
| Missing smoke receipt | A deliberately faulty Contract first performs genuine native admission, then deletes only the smoke receipt; the adapter refuses despite the untouched accepted? header |
| Parent Check receipt substituted | Correct name/count with the wrong parent candidate identity fails receipt coverage |
| Frozen parent checks list | Final-identity obligation refuses the old three-element parent list after smoke is selected |
| Equal-length stale list | Three final names but a refined build still reject the old three-element parent list |
| Forbidden smoke command | Default family obligations reject the actual final smoke |
| Stricter build policy | Generic family would accept cargo build, but the maintained build Contract rejects it |
| Duplicate/non-symbol selectors | Shape/selector admission refuses before projection |
| Reserved pipeline selected as Check | Refused; reading the diagnostic name returns pipeline without recursion |
| Optional unused remains unselected | Not in the projected responsibility map; its evaluation counter stays 0 across successful and negative cases |
| Matched control selects unused | The same inherited thunk is evaluated once, admitted and reused; counter changes from 0 to 1 |

The fault-injected Contract is an explicit protocol-violation control, not a
claim that normal Core drops evidence. Its .admit obtains an authentic receipt
from a clean native descriptor before removing one entry. Expected roles still
come from the final selection; no user completion list is introduced for the
negative case. Correlated successful headers alone cannot bypass coverage.

* Corrections exposed by execution, with failures preserved

Module 26's earlier reader-only result did not qualify execution. Actual execution
required two native corrections, now applied to the CURRENT design blocks:

1. Use the existing :std/list/list delete-duplicates/hash with an explicit
   eq?-keyed table. The assumed delete-duplicates primitive was unbound.
2. Use native bare-slot capture for an outer Scheme value with the same name as
   a new POO slot. evidence: evidence and name: name accidentally reference their
   own receiver-aware slots. The corrected forms are:

#+begin_src scheme
(.o kind: 'selected-responsibility-refused evidence)
(.o kind: 'reserved-check-name name)
#+end_src

This is existing native punning/lexical semantics, not a new escape-hatch macro.
The corrected diagnostic name and evidence are actually read by the controls.
