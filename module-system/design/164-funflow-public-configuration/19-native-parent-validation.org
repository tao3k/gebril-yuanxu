* Correction: inherited slot base is receiver-relative

The original expectation that the child build's direct parent must be eq? to
Root.build failed. Root.build is an inline (.o ...) slot method. The inherited
method is evaluated with the child receiver, so it constructs the base used by
that child's =>.+. That base has inherited values but is not necessarily the
object already cached under the parent receiver.

#+begin_src scheme
(.def Root
  build: (.o value: 'build))

(.def (Child @ Root)
  build: =>.+ (.o value: 'child-build))

;; Observed: false for this inline construction.
(memq (.get Root build) (object-supers (.get Child build)))

(def SharedCheck (.o value: 'shared))
(.def SharedProfile build: SharedCheck)
(.def (SharedChild @ SharedProfile)
  build: =>.+ (.o value: 'shared-child))

;; Observed: non-false for this canonical constant object.
(memq SharedCheck (object-supers (.get SharedChild build)))
#+end_src

Therefore automatic published-Profile association can use the top-level parent
root, but must not assume every nested slot value retains the parent's cached
identity. Module/Check association must come from the declared responsibility
position, canonical exported values, or a separately validated source boundary.
The final field/identity checks still consume the final receiver's values.

* .+ right operand: a provider fact is not necessarily a parent

#+begin_src scheme
(.def RightRoot flag: 'right)
(def Result (.+ Root RightRoot))

;; Result.flag is right, but RightRoot is not a parent of Result.
;; Its own Contract/source association cannot be recovered by parent traversal.

(.def (RightChild @ RightRoot) extra: 'child)
(def Second (.+ Root RightChild))

;; RightRoot is retained as a parent; RightChild itself is not.
#+end_src

This is native .+ behavior, not an adapter bug. Parent-graph discovery is an
INHERITANCE association mechanism, not full value-provider provenance. When the
right operand contributes an independent mandatory obligation, integration must
explicitly preserve that requirement through an admitted boundary or reject the
composition as unsupported. Silently declaring all provenance recovered is
unsound. Do not alter native .+ semantics merely to manufacture a source parent.
A stronger future property should be stated as mandatory-requirement preservation,
not as a claim that native object-supers contains every construction input.

The source-check logs and hashes are in the receipt directory. This was not a
clean full LeanPoo rebuild or a proof of the new Scheme walker. Existing
LeanPoo C4 reachability/graph and generalized-prototype libraries are additional
model candidates; the native Scheme walker does not run C4 linearization and
requires its own explicit correspondence before using their theorems.

A follow-up model belongs in the existing proof workspace, with these explicit
obligations, rather than another implementation of POO:

1. Root association completeness for a finite acyclic native parent graph with
   stable identity and trusted root index; diamonds must not drop roots.
2. Reference-model correspondence for the Scheme DFS and its visited-state rule.
3. Receiver/context-indexed final selection: parent cached data cannot substitute
   for a changed child receiver, even with equal names/count.
4. Distinguish inherited roots from right-operand provider requirements; an
   integration must preserve all mandatory requirements or refuse.
5. Contract/source/policy/graph changes invalidate affected evidence; reuse needs
   an explicit equality or implication proof rather than a matching label.

Module 20 now proves a narrow reference version of root discovery, exact-context
final values and mandatory RHS requirement retention/checking. Its model does NOT
prove the Scheme DFS, mutation invalidation or source projection. Those remaining
correspondences are still required before a runtime soundness claim. Source authentication and consumer
plan admission remain separate premises. Reuse existing LeanPoo machinery where
its premises match; do not assert a formal bridge merely because names resemble
ConstructionCache or ContextSlot.
