* DFS control correspondence, including visited shared parents

DFS.visit is the recursive control translation: active nodes correspond to
native visiting marks, completed nodes to done marks, and visitParents runs
parents in source order. Already-done parents are skipped; a visiting parent
refuses as a cycle. Explicit fuel produces a separate exhausted error. The
Scheme helper has no fuel argument, so the Lean budget is a model boundary.

visitParents_spec and visit_spec prove that a successful visit:

- retains prior completed nodes;
- completes the requested node;
- leaves a completed set closed under direct parents;
- adds only nodes inherited from the requested node, apart from prior input.

From an initially empty state, success_membership_iff proves that done membership
is EXACTLY native parent reachability, not merely a subset. The derived
successful_dfs_association_iff proves index membership plus reachability for every
retained Anchor, including different Contracts sharing one root object.

The actual Scheme helper emits roots on entry, while the Lean model records done
on successful return. Thus the theorem covers completed membership, not identical
emission order or allocation. Generated checks compare canonicalized Contract-ID
lists with multiplicities preserved. No execution schedule is inferred from DFS
or parent order. Cycles/refusals have no accepted partial root result.

This is a proved control model and executable source-to-model comparison, NOT a
formal operational semantics of the Gerbil interpreter. Universal translation
adequacy and a general sufficient-fuel bound are still required. For each emitted
finite graph, successful replay or matching cycle refusal is kernel-checked.

* Identity and parent projection are explicit, inspectable obligations

IdentityProjection has an encode function, an injectivity proof, native direct
parents and the exact equation mapping their encoded list to the model graph.
Under these premises, identity_iff and list_identity_iff prove that projected
identity equality and ORDERED list equality reflect actual equality. Path
projection/lifting is proved in both directions. dfs_native_path_iff then connects
successful modeled DFS membership to the native-object parent relation.

The probe assigns tokens with an eq?-keyed interner; every native graph edge,
Check identity, candidate, context and Contract identity uses that same interner.
It checks injectivity on all observed values and exports an alias/equal-shaped-
distinct-object sample matrix. Lean checks all 144 exported comparisons rather
than trusting a printed accepted flag. Graphs come from actual object-supers and
include every reachable direct parent; the generator refuses incomplete edge
closures or ambiguous boundary call identities.

These checks establish finite observations only. They do not instantiate an
universal theorem about arbitrary future Gerbil heaps, GC, mutable parents or
concurrent updates. In particular, inline parent slots can reconstruct at the
child receiver; encoding the parent's cached slot object instead would violate
the projection premise. The original negative control remains applicable.

* Real .admit, not a substitute predicate result

The probe invokes yuanxu-contract-admit on actual yuanxu-predicate-contract
values and on an actual YuanxuObjectContract. with proto Root,
responsibilities for build/pipeline and final-value obligations. Cases cover:
accepted final child; cached-parent-list refusal; same-count stale Check refusal;
primitive classifier refusal; failed child responsibility; prototype mismatch;
wrong candidate/context replay; and RHS policy failure.

Each projected Receipt includes actual native evidence-type acceptance,
Contract identity, candidate and context identities, classification type/candidate/
context, classification acceptance, failure/obligation identities and final
acceptance. The generated checks recompute receiptGate, not just the accepted
field. CoreRule checks the actual base formula: accepted iff classification
succeeded and the failure list is empty. ResponsibilityRule separately checks
child acceptance and own obligations. Parent obligations are observed not to run
when classification or a responsibility fails.

accepted_receipt_correlated proves the current subject/context/Contract relation.
accepted_receipt_discharged proves classification success and no failures under
CoreRule. responsibility_success_checks_children proves accepted parent receipts
require all projected children to pass under ResponsibilityRule. All three
responsibility groups and all 24 unique receipt rows are checked by Lean on the
actual trace. A trace parser is still an observation boundary, not a verified
Gerbil evaluator or a proof of every future custom .admit override.

Core receipts carry a Contract identity VALUE, not a pointer to the invoking
descriptor. The fixture uses distinct canonical identities. A production view
must bind that identity to the expected descriptor/source/policy (or retain an
explicit call binding); symbol equality alone cannot distinguish two unrelated
descriptors choosing the same identity. Source authentication is not proved here.
Repeated failed calls can allocate different diagnostic objects; no theorem
claims diagnostic-object identity or cached .admit equivalence across calls.

* Joined boundary and the RHS-loss counterexample

Bridge.checkedBoundary joins all DFS-discovered root requirements with explicit
mandatory RHS/provider requirements. It uses receiptGate for EACH retained
requirement at the final candidate/context. inherited_root_receipt_final proves
that successful boundary admission entails current candidate/context correlation
and discharged failures for every indexed inherited root, subject to the identity,
source-index, DFS-success and CoreRule premises. rhs_requirement_checked proves
that success cannot omit or skip a mandatory RHS receipt.

The emitted positive boundary admits both multi-parent roots and the shared-root
Contracts in one context. Two negative boundaries use actual .+ composition:

1. The right provider's own identity/requirement is absent from the native parent
   graph. Its explicit mandatory requirement is not retained: refusal.
2. The requirement is retained explicitly, but its real .admit returns a policy
   failure: refusal again.

This closes the model's gate logic but does NOT automatically discover RHS
provider obligations. The integration must provide the complete mandatory set.
If an obligation is absent from BOTH the graph and that set, these theorems cannot
recover it. Native .+ semantics are unchanged. No integration gate is installed
in the product runtime by this proof task.

* Newly discovered public API gap

YuanxuResponsibilityContract. is defined inside Core types.ss but is NOT in its
public export list. The first external probe using it failed with an unbound
variable; the failure is retained in the receipt directory. The passing probe
uses the already public YuanxuObjectContract. and a declared proto.

Module 15's design constructor referencing the private base must therefore not
be advertised as executable external package code. A future owner must select
the appropriate public prototype-aware Contract or intentionally define a public
boundary for another responsibility protocol. This task does not widen Core's
exports or implement that domain adapter. No private binding is smuggled into
an import or copied as a replacement kernel.
