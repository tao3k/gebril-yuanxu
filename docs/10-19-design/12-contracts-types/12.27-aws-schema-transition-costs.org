The maintained OpenTofu configuration may name =selection-input: 'selection=.

*** Progress-aware execution after garbage collection

The user subsequently reported a Nix garbage collection. Previous receipts of
available provider outputs do not establish availability after that collection.
Native evaluation-cache reuse, derivation registration, output availability and
realization progress are separate observations. A new realization or substitution
after GC is not evidence that native evaluation caching failed.

The current implementation has three elapsed-time ceilings: the Case watchdog,
TestingScript's Ops process timeout derived from the Case duration, and the
outer focused-test watchdog. Neither the Case nor Ops currently implements an
inactivity timeout. A process making genuine progress can therefore be killed
at 60 seconds. This is an execution-policy gap, not a reason to discard source
or admission checks, or to report an interrupted integration as successful.

The required distinction is between an explicit total resource budget and a
no-progress deadline. The latter must follow bounded native activity evidence:
advancing transfer/build counters, completed dependencies, and completed
evaluation or publication stages. Arbitrary output, repeated diagnostics,
unchanged progress counters and synthetic heartbeats must not renew it.
Silent evaluation is not automatically a deadlock; unsupported progress
observation must remain explicit rather than inventing activity. Observation
formatting (=emit?=) must not switch execution safety on or off.

This policy is implemented in the existing Ops execution and testing Case mechanisms,
with native Nix activity supplied at the process boundary. It must cover the
parent waiting for the child as well as the child, preserve process-group
termination and fixture cleanup, and retain a finite overall bound. Merely
raising the 60-second constant, disabling the watchdog, or changing only the
inner Ops timeout would not implement these semantics.

The shared Scheme policy now declares a 60-second inactivity deadline and a
600-second finite total. Case memory sampling also checks inactivity, while
Ops owns external process supervision. TestingScript receives both limits from
the Case Profile; the Just recipe reads the shared total for its outer ceiling.
Nested spans receive the same advancing events. Monotonic, bounded child
records bridge genuine work into the supervising Ops span independently of
=emit?=. Completed source imports also advance liveness; repeated source reads
and guard traversals do not count as new completed imports. The outer ceiling
includes native import time but does not yet detect pre-Case import inactivity.

=t/execution-progress-test.ss= passes its native controls: progress keeps the
parent Case and child Ops alive beyond the idle interval; repeated messages,
replayed counters and changing expected amounts do not; a late event cannot
revive an expired span; the total cannot be renewed; emission-disabled Cases
still reject inactivity; and cancellation removes owned descendants. These
small protocol controls inject Nix-shaped activity records and are not real
downloads. The initial failed control exposed an interrupt/join deadlock during
unwinding; the fix terminates the sampler just as the existing Case watchdog
does. The failed receipt remains a failure, not acceptance evidence.

The existing Ops process-script regression also passes, preserving exact
unterminated stdout, argument/environment boundaries, descendant cancellation,
and the existing timeout receipt behavior with =check-status: #f=. Only GNU
timeout produces that process-total exit code; the new Ops sampler handles
inactivity instead of racing it with another total exception.

The first AWS run under this policy reaches closure publication and package-set
resolution, then hits inactivity in native =flake lock=. This is not a total-
duration rejection or successful AWS acceptance. Lock setup now uses the same
Ops supervision and forwards native activity; talkative native activity output
is enabled without enabling debug dumps on every query. The focused Nix cache
controls still pass after the Ops integration. AWS rebuilding, Schema change,
stale-evidence rejection and final cleanup remain a separate aggregate gate.

The Nix command's native semantics are documented in
[[https://nix.dev/manual/nix/2.34/command-ref/new-cli/nix3-path-info.html][nix path-info]],
including =--derivation=, =--override-input= and =--no-update-lock-file=. The
cache-hit and invalidation claims above depend on native Scheme controls, not
on assuming that every Flake command benefits from the cache.

* Changes with bounded reuse

1. Contribution-index preparation combines adjacent selection-source and
   selected-Graph source guards in the existing synchronous read window. It ends
   that window before route indexing can demand author declarations. The measured
   publication association drops from 5,813 to 5,637 source reads in this control.
2. Nix's prepared publication checks whether artifact realization is already
   cached. Cold realization keeps its source pre/post checks. Warm currentness
   retains a fresh Nix identity query and its source pre/post checks, omitting
   only the redundant guard around a cached artifact read.
3. Linking and source preparation use the private publication lookup immediately
   after eligibility admission. Only private hash operations intervene; the
   lookup no longer repeats that same eligibility guard. Publication reading,
   Contract execution and scope factories retain their post-effect checks.
   Dynamic eligibility callbacks receive an explicit post-policy source check
   before publication initialization.
4. Initial expression construction first performs a readonly Nix evaluation and
   asks =nix-store --check-validity= about that exact drvPath. A valid store entry
   avoids writable registration. A miss uses the original registration path;
   when both evaluations return paths, disagreement refuses construction. A
   failed optional lookup is not admission evidence. Currentness queries retain
   strict failure and never fall back to registration. Flake evaluation keeps
   its existing implementation.

* Checks which remain necessary

Readonly Nix queries still re-evaluate the expression and its arguments. A
completed provider build does not prove that its current selection is unchanged.
[[file:../../../t/nix-derivation-query-test.ss][The native transitive-input control]] changes an undeclared imported Nix file
and adds a previously absent file; source observations alone cannot replace that
query. No process result is reused across arbitrary validators or Context policy.

The store lookup is not a new evaluator cache: Nix re-evaluates transitive inputs
before checking store validity. A local pathname existence test would not suffice.
The configured store executable is reused for both validity and realization;
users supply no new field. Process metrics distinguish readonly evaluations,
store-validity checks, writable registration and realization. A cold construction
may add one registration evaluation; it is separately counted and bounded, never
hidden inside the warm query budget.

Likewise, every failed publication must retain the previous object. Source or
Schema changes, a copied same-name descriptor, stale evidence, invalid fields
and a modified responsibility map remain refusals. None of these assertions is
removed or replaced by a timing assertion.

** Reusing dependency structure without reusing admission

Compiler-tool checks also traversed the same SDK context import DAG on every
reference. The reader now indexes the prepared tool-input references for each
demanded context within that reader's fixed SDK snapshot. Every request still
checks those inputs' current source bytes and performs the original visitor;
no successful guard result is cached. Reload requests still refuse. This index
does not outlive its reader, does not contain contribution scopes or initialized
values, and is not a second selected Graph.

The storage bound is the sum of the demanded tool closures, not a claim of
constant memory for arbitrary SDK graphs. It retains references to existing
prepared inputs rather than copying source text. The premise is the same
immutable, fully expanded SDK context used by the existing tool-source cache;
arbitrary mutation of SDK expander internals is not qualified by this control.

The publication suite now verifies the phase-one negative control and that
repeated dependency requests exceed actual structure walks. It passed with
natural exit zero. Configuration-source controls also passed, including source
mutation during initialization, fresh private scopes and foreign same-identity
source refusal. Thus structural reuse did not replace the pre/post authority
checks in those controls.

In the instrumented root test-spec interval, 287 dependency requests required 38
actual SDK closure walks; it still performed 6,661 observed source reads and

speedup. Per-publication observations attributed approximately 8.40 seconds to

timings are comparable across hosts.

This exposes a remaining architectural boundary: =init.test-spec= filters test
execution, but resolving its selected Graph still expands role bodies needed
by selected publications. Funflow's objects role imports its control-plane,
store and Graph-projection implementations; OpenTofu's types construct several
Schema adapters at module evaluation. Deferring domain exports alone therefore
does not establish cheap declaration discovery. An eventual compiled declaration
reuse must bind code to its complete source/compiler/dependency inputs and must
not reuse macro side effects or initializer results. This work does not add
that persistent cache or a runtime Loader, and does not conceal this cost by
dropping selected init roots or excluding assertions.

The coupling diagnosed before the test-source split was explicit in these owners:

- =building/test-projection.ss:module-test-projection= immediately demands
  =selection.selected-graph= and its =module-order=, even for one requested

  not a measured thousand-module benchmark. The structural index above removes
  repeated SDK graph discovery, not this source-authority cost.

The bounded acceptance target was to separate test-source admission from
full configuration-Graph admission while retaining one selection and its lazy
Graph identity. A one-owner test-source request must not expand unrelated
selected owners' role bodies. It must still observe its native test dependency
closure, reject changed role/test inputs, and retain execution cleanup. Requests
that actually consume a complete configuration Graph must continue to perform
its complete dependency/conflict admission. This requires an explicit guard
boundary, not removal of the Graph getter or a second test tree.

Likewise, shortening reader guards requires either exact demanded-dependency
checks plus a complete final Graph check, or a proven immutable source
capability. Caching an entire publication result, trusting timestamps, or
assuming arbitrary Scheme initializers are pure would not establish that
boundary. No such shortcut or runtime Loader was introduced in this repair.

* Test-source admission split

=module-test-projection= now obtains requested owners from the existing init
selection, rather than forcing =selected-graph.module-order=. Each requested
owner reuses =selection.prepare-publication=, including its existing publication
cache and SDK-observed private/compiler source dependencies. This is still real
source preparation: selected role expansion is not claimed to be free or pure.
Other init roots are not prepared merely to discover one owner's test files.
No business scope is linked and no second resolver or dependency tree is built.

The projection's =selected-graph= slot remains lazy and delegates to the same
selection. Explicit demand still performs complete Module/Feature dependency,
conflict and ordering admission. A missing required module may therefore leave
test-source discovery valid while making configuration Graph admission fail.
Test enumeration follows requested owner order, or init root order without a
filter, then filename; it is not the configuration/task execution order.

=init.test-spec owners= checks only that acquired test projection. It no longer
invokes the aggregate =init.test-current!= traversal of previously acquired
suites. The aggregate entry remains available explicitly. Existing source guards
continue to check actual bytes; package-effect callbacks remain outside the
shared pure-read window, followed by fresh checks. The shared reader retains
all observations already demanded within this source epoch, so a previously
demanded dependency change can still invalidate the epoch.
