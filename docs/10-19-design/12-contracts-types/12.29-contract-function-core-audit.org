#+title: Core Contract, Function and FUN Source Audit
#+date: [2026-10-23]

* Source boundary

The upstream source is [[https://github.com/tao3k/gerbil-poo/pull/13][gerbil-poo PR 13]], revision
=ad206b86dece016962d7cdec4f4cf2d1928a2fc7=. This is an exact revision audit,
not a claim about later PR updates. Core's source baseline was =10a0759=;
the working changes below were unpublished at that audit cut. The failures and
installation gaps below remain historical observations, not current status.

The implemented migration is described in
[[file:12.30-core-function-boundary-migration.org][Core Function Boundary Migration]]. The current immutable dependency is owned by
[[file:../../../gerbil.pkg][gerbil.pkg]]; this historical audit does not override it or qualify a later build.

Read the examples at this revision together:

- =examples/object-contracts.ss=: required value shape, independent diagnostics,
  native refinement, checked-action and Reader composition.
- =examples/function-publication.ss=: multiple results and higher-order Function
  wrapping before exact checked-subject publication.
- =examples/signature-service.ss=: optional/keyword/default handling, typed
  declarations and output callbacks through the same Function descriptor.
- =examples/row-services.ss=: native finite recursive/row descriptors and
  checked-action; no second row solver in the application.
- =examples/polymorphic-services.ss=: prototype-type specialization, finite
  inference and typed declarations; only a unique complete inference result may
  build a service. This API is needed when a domain actually declares these
  parameters, not for arbitrary field validation.
- =examples/service-metadata.ss= and =examples/shared-contracts.ss=: native
  invocation contracts, current dependent meaning and closed preparation inputs.
- =examples/contract-publication.ss=: bind-evidence after normalization; subject,
  descriptor and context are exact references. Prior effects are not rolled back.

* Semantic owners

| Concern | Native owner | Core responsibility |
|---------+--------------+---------------------|
| Primitive/domain value membership | Type. / element? | Define the domain predicate once |
| Required/optional fields | Record / effective Slot protocols | Declare fields and preserve receipt metadata |
| Whole-object relations | ObjectContract. / refine | Supply actual domain relations |
| Callable arguments, results, nested callbacks | Function / Fun / validate | Supply the actual signature and consume the validated function |
| Reader composition and value admission | Observation. / checked-action | Compose source/context policy at explicit boundaries |
| Invocation input/output/logic | declarative-metadata Contract | Supply dependent domain meaning and current policy |
| Publication | bind-evidence / publish | Bind actual checked subject, owning descriptor and current Context |
| Source lineage and contextual responsibilities | Core admission/types | Retain independent currentness checks, identity checks and contextual child receipts |

A Function recognizer can recognize a procedure without checking future calls.
Returning the original procedure after element? therefore loses the declared
argument/output contract. A symbolic diagnostic name is never a validator.
Native invocation Contract is not a synonym for a value Type, and FUN is a
composition protocol rather than a second workflow execution authority.

* Repairs in this change

=module-system/schema/slot-contracts.ss= previously owned a second field walker:
required presence, custom read callbacks and element?-only field checks were
assembled as Core contextual obligations. It now derives a native Record and extends its membership method with the
domain predicate. Required/optional handling and recursive normalization belong
to the inherited native Class validator. ObjectContract diagnostic constraints
do not normalize their values: putting a Record in constraints alone would
repeat the original callable-wrapper bug.
Primitive slot predicates directly specialize Type.; they no longer allocate
classification receipts merely to validate an ordinary field.

The constructor no longer accepts alternate presence/read procedures. All Graph
contract declarations and the JSON Schema contract emitter use the new direct
signature. The JSON diagnostic/codec boundary still owns JSON rows; an emitted
executable field contract consumes POO objects. The unused alternative field
reader/candidate machinery has been removed from the emitter.

=yuanxu-contract-check-slot!= now returns validate's actual result. A Function
therefore returns its checked wrapper, including returned callbacks; no local
argument decoder or wrapper is introduced. Receipt projection accepts ordinary
native Types without requiring project-specific diagnostic slots. The native
=slots= field retains its Class meaning; receipt declarations live in
=slot-schemas=. Projection reads current effective Slot types and optional
policy and refuses incomplete metadata after a field addition. A warmed
parent's metadata cannot silently replace a derived field's actual Type.

=object-types/contracts.ss= composes upstream validate with contextual evidence production.
The one-shot source analysis edge is consumed
before replaceable validation, exactly as before. Contextual children and local/
platform obligations remain Core concerns. Normalized subjects are passed to
those operations; accepted results are not cached.

Ordinary contextual evidence and observability fixtures retain their lightweight
import boundary; importing Core types alone does not import typed FUN printers.
There is no lazy binding, dynamic import or cached acceptance. This direct
functional composition also works during standalone executable initialization.
The existing negative import-closure assertion remains unchanged. Reader/FUN
composition is exercised at its actual native publication boundary.

=admission/publication.ss= already uses the native invocation Contract,
with-meaning, bind-evidence and publish. It is retained. Replacing this with a
new wrapper or moving source-currentness into a generic value Type would lose
its selected-Graph and package-boundary semantics.

* Ops callable boundary

Ordinary Ops configuration, environment and process-script values now use native
Type/Record descriptors. The empty contextual receipt producers for these values
are removed. The process descriptor extends the configuration's native fields;
only the domain relations (finite positive duration, idle/total budget relation,
and nonempty command) remain local predicates.

Progress is a native higher-order Function: a zero-argument factory returns a
one-argument String callback. The callback's result is deliberately Any because
output observation does not consume it. Preview validates once and passes the
actual wrapped factory to execution. Preparing a command also consumes its
validated script. Declaration/preview never invokes the factory. The Scope
contract retains Core's contextual publication role; it does not certify callback
purity or authorize process execution.

=YuanxuProof/Ops/ProcessScript.lean= defines the progress value decoder, returned
callback normalization and factory invocation through LeanPoo's
=FunctionValidation.wrap=. Its five new theorems cover invalid/valid arguments,
installation of the actual checked callback, noncallable results and factory
errors. Executable positive/negative guards use concrete constructors. This is a
pure finite interpretation, not a proof of Scheme procedure execution or OS
effects. Quint receipts also bind the native Ops Type owner, shared slot contract
owner and the maintained composition regression.

* Maintained product consumers

All maintained product calls use the direct constructor signature, including
session policies, sandbox resources/profiles and loop governance/audit contracts.
Sandbox profile recipe checks use native membership/validation; the empty
contextual admission receipt and its public producer have been removed.

Tool grants are native POO values. Their native Record checks every declared
field; final session-policy projections explicitly encode grants in both the
summary and nested policy-slots wire rows. The external wire field order and
values are retained without accepting wire rows as semantic grant objects.

The runtime manifest projection is published through Funflow's func role. The
existing advanced control-plane API remains an independently compiled library;
its source import closure is projected with the existing SDK graph helper from
the explicit Core library roots. Compiling it does not import the aggregate
control plane into ordinary Funflow objects. Source fixtures that override
core-spec retain their own declared roots.

* Package build ownership

The product package selects the POO prelude. Its modules/scenarios directories
select Core's module prelude, matching their actual declarative role files.
That prelude exports the native Gerbil bindings at macro phases one and two as
well as runtime; standalone native compilation uses the same declaration path.
No per-file generated import workaround is introduced.

A product selection may refer to source Modules from Core. The native package
build specification now emits only targets owned by its actual package prefix.
Foreign selected sources remain in the observed input set and retain their
Graph currentness guards. Their own native package build owns compilation.
Merging retained roots still rejects conflicting compiler identities/options.
The package projection refuses Graph output issuance and execution when selected
outputs span package owners; a partial package build cannot publish that Graph.
The product's existing source-guarded SDK build receives no publication authority.

The standard dependency build recipe regenerates installed manifests in dependency
order. The Homebrew SDK environment includes its OpenSSL pkg-config directory,
so native Ascent compilation resolves the same declared library as the C compiler.

* Development runtime cohort

The optional ASP source is selected by =dev/gerbil.pkg= at =0f78289a7ae465a84370f5d94d8d14671f3c43af=.
The old production cache contained a different ASP revision and old POO manifest.
Those sources and artifacts are preserved outside the active load path.

=deps-dev= materializes only the development declaration and verifies the actual
HEAD. Its native POO source, tag and manifest aliases explicitly share the root
package's authoritative POO revision, matching =dev/BUILD.bazel='s existing parent
dependency selection. ASP's immutable source metadata is not rewritten. No
transitive POO fetch or second POO runtime is installed in the development store.
Existing conflicting paths fail before replacement; no package uninstall is used.

=test-root= prepares the native test runtime with =build-testing=: gxpkg builds
ASP without dependency fetching, and the maintained =dev/build.ss= builds the
project's testing interface. The test worker retains the existing heap and
watchdog fences. The single native ASP entry is unit-tests.ss at the project
root, since ASP anchors discovery to its declaring script. Optional profiles are
in dev/testing-profiles.ss; no second entrypoint discovers or executes tests. Native development preparation is outside that worker, not a
replacement test runner or a temporary activation script.

The default root test recipes also prepare the existing hash-locked Nix
qualification inputs and native publication workers. A small environment
transport reads those produced paths and execs the unchanged heap-fenced worker.
The native publication roles share one SDK executable closure, while every role
invocation remains a fresh process with its original watchdog. The build retains
its 240-second limit. A stale object lock from an interrupted build was diagnosed
with a process/lock-holder check and removed; the timed-out runs are retained as
failed local evidence.

* Remaining distinctions identified by the audit

The legacy Funflow control-plane Task/Flow input-contract and output-contract
slots are descriptive values: runner.ss invokes task-executor directly and does
not turn symbolic labels into Function validation. They must not be described
as enforcing a typed callable boundary. Migrating that subsystem requires actual
native signatures across its maintained constructors and consumers; this field
contract repair does not silently reinterpret symbols as executable types.

The schema support transformer's =yuanxu-module-transformer-type-compatible?=
still treats an actual Any field as compatible with a more specific input Type.
This is an operation-admission policy, not proof that Any is a subtype. Native
finite relation/inference results may justify supported structural replacements;
opaque domain predicates need explicit evidence and cannot be inferred from
=module-value-kind= labels. This path remains a separate migration finding.

Loader Backend load and source-collection locate are extension/runtime callbacks.
Their source admission and module ownership checks remain necessary; procedure
recognition alone would not prove their result contract or purity. This change
does not certify every Core callback or replace independent CLOS class lifecycle
semantics with signature inference.

* Qualification

=t/contract-function-composition-test.ss= exercises the maintained shared
constructor and slot gate with native Function signatures: input/output refusals,
optional/inherited fields, host defaults and keywords, multiple values, returned
callbacks, one normalization before contextual obligations, untouched raw values,
FUN composition and refusal of a stale Context at exact evidence publication.
Its seven cases include the maintained Ops higher-order progress callback path.
It is included in the ordinary serial Core test list. Existing Graph, schema,
source admission and publication consumers remain required regression gates.

The declared Gerbil pin, Bazel archive digest/lock and Core replay model revision
are updated together. Existing dirty installed dependency sources are retained
outside the active package path, not discarded. Logs remain local artifacts.

The initial native dependency installation exposed a transitive pin
boundary: Parser =f7db6237= requires published Core =10a0759=, whose immutable
package metadata requests gerbil-poo =80b590b1=. That differs from this unmerged
Core/POO integration. Its explicit tag refusal is retained; no package uninstall,
retagged historical artifact or edit of immutable dependency sources closes it.

The workspace now selects its actual Core checkout with the standard gxpkg link
and build operations. The released Core checkout and original installed caches
are preserved locally. This is explicit development-source selection, not a claim
that an older immutable archive contains these working changes. Direct Parser,
Ascent and Orgize revisions must also match gerbil.pkg before default acceptance.
