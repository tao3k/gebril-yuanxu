* Actual holder, rather than receipt counts

The previous thousand-declaration run refused after 331 publication returns.
Completed Reader programs and expanded bodies had already disappeared from
the weak observations. That did not establish that the remaining SDK bindings
or Graph read dependencies were small. Counts alone could not attribute bytes.

The actual source path is =role-authoring-validate! -> module-interface ->
ModuleAuthoringProfileContract validation -> classification/validation receipts
-> role CLOS admission=. The previous owned-call region began at each CLOS
datum. Interface/Profile validation happened BEFORE that region, so the Graph's
native read trace could strongly retain its temporary evidence and their
dependency graphs even after their only semantic use had finished.

[[file:../../../../../module-system/source/admission.ss][Source admission]] now begins the existing region before constructing that
Interface. [[file:../../../../../module-system/authoring/admission.ss][Authoring admission]] supplies its existing exact maintained method
body identities and carrier-policy guard. It does not add another method
registry, skip Profile admission, reuse an acceptance result, or suppress reads.

* One construction lifetime, unchanged semantic payloads

[[file:../../../../../object-family/read-projection.ss][The shared ownership implementation]] moved from CLOS to object-family;
there is no forwarding implementation. CLOS and Core receipt producers use the
same dynamic region. Only an actual maintained constructor may enroll a fresh
receiver. A kind symbol, nominal Type or contributor's ancestry is insufficient.

[[file:../../../../../types.ss][The two receipt producers]] retain their original lazy slot formulas and
actual candidate, Contract, Context, classification and child references:

#+begin_src scheme
(owned-read-leaf!
  (.o kind: 'yuanxu.contract.validation-evidence
      ;; Original producer fields and formulas remain unchanged.
      admission-contract: contract-value
      candidate: candidate-value
      context: context-value))

;; Only a copy of a receiver enrolled in THIS region inherits that permission.
(owned-read-copy! evidence
  (.cc evidence 'responsibility-evidence children))
#+end_src

This excerpt describes the lifetime boundary, not a replacement producer.
The actual producer retains every existing field and value check. Enrollment
requires a bare factory object without parents, declarations or a MOP protocol.
The first native revision is retained and checked at region completion; an
edit followed by restoration is still a change. Borrowed copies open the full
trace. Read observers inspect only already-demanded receivers and never force
a cold scope to inspect its protocol.

An owned read is crossed until its original external-token frontier. That
frontier remains strong with every original dependency suffix. Only temporary
receiver/token witnesses become weak. A still-live receipt must replay its
original tokens; a missing token refuses. Contract, policy and source reads do
not disappear when a temporary receipt is collected. Returned evidence remains
usable with its original actual identities; this change does not shorten its
semantic lifetime or certify old evidence under a new Contract or Context.

Unknown CLOS bodies, custom descriptor MOP, Context callbacks and nonempty
custom obligation procedures retain the complete original trace. Exceptions,
failed initial replay and generation changes also take that conservative path.
The guard does not infer callback purity from its return value or a Type name.

* Thousand-declaration follow-up: still a refused capacity gate

With the same init-owned fixture, observation, source-only library revision and
unchanged limits, the producer-lifetime implementation completed 578 publication
returns, then refused at 1501550104 live bytes / 1074253992 growth bytes. The
original 1 GiB growth boundary was exceeded. This is a failure, not a thousand-
declaration pass, and the refusal position is not a statistical capacity bound.

At failure, the weak diagnostics reported no surviving effective methods,
invocation frames, argument lists, authoring Interfaces/datums, continuations
or related CLOS read records. Each role retained 578 SDK contexts: interface
4046 local bindings, types 2890, config and objects 2312 each. Tracked programs,
expanded bodies and code-body pointers were all zero. This rules out the
observed completed code bodies as the remaining holder; it does NOT assign
exclusive bytes to SDK contexts or prove that unobserved syntax is absent.

The next ownership question is the support retained by those Reader/SDK bindings
and the remaining semantic Graph dependencies. They cannot be removed simply
because temporary CLOS/receipt counters have reached zero. No SDK table, binding
registry, accepted Graph or read cache was cleared to obtain either result.

* Model division and remaining premises

[[file:../../../../../dev/proofs/quint/OwnedReads.qnt][Quint OwnedReads]] explores bounded finish, mutation, collection and publish
orders, including shared/cyclic owned reads. Its nine expected outcomes cover
frontier omissions, shared policy, missing live tokens, unknown execution,
borrowed constructor authority, changed constructor generation and acceptance.
These checks reuse the existing model rather than create another Graph.

[[file:../../../../../dev/proofs/lean/YuanxuProof/ModuleSystem/Graph/OwnedReads.lean][Lean OwnedReads]] proves arbitrary-identity frontier coverage using the existing
worklist theorem, original-replay requirements for live values and refusal of
borrowed/mutated construction certificates. It does not repeat finite schedule
search or prove a GC implementation, heap bound or SDK capacity.

Native assumptions remain: weak values preserve strongly reachable receivers;
original replay checks original dependencies; the Core DFS implements the
completed cut traversal; audited wrappers do not leak their call frames; and
native sequential revisions report edits. Arbitrary Scheme continuations and
concurrent mutation are not certified. Unknown callbacks keep full dependencies.
