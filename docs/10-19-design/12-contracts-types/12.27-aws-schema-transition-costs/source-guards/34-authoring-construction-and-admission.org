* Actual repeated support

[[file:33-sdk-enrollment-and-declaration-budget.org][SDK enrollment]] removed duplicate registration but did not reduce retained
Graph support or establish capacity. The next change follows the actual
source-policy getter into =make-module-interface=.

The default =authoring= computed slot called the public validated Profile
constructor. Its first evaluation produced classification and responsibility
receipts for the default Profile and its children. Those reads became native
dependencies of the shared computed slot. Every later publication depending
on that slot could replay the construction trace, even though its Interface
constructor independently validates the Profile again.

The old sixteen-module control reported =authoring= with 1918 direct dependency
edges. This is not 1918 business requirements. It includes constructor work
captured by the lazy getter. Removing bytes from source guards cannot remove
that native dependency graph.

* Separate construction from the real boundary

The existing default fields now have one internal construction function:

#+begin_src scheme
;; authoring/roles.ss: fresh candidate; not a validation receipt.
(def (make-default-module-authoring-profile)
  (.o (:: @ ModuleAuthoringProfile.)
      executor: (.mix ModuleAuthoringExecutor.)
      types: TypesSourceRole.
      objects: ObjectsSourceRole.
      funs: FunsSourceRole.
      config: ConfigSourceRole.
      interface: InterfaceSourceRole.
      build: BuildSourceRole.))

;; The public constructor keeps immediate validation.
(def (yuanxu-default-module-authoring-profile)
  (validate ModuleAuthoringProfileContract
    (make-default-module-authoring-profile)))

;; source/admission.ss: one ordinary receiver-local computed default.
(authoring (make-default-module-authoring-profile))
#+end_src

This internal constructor is not a new public configuration interface or an
accepted-value cache. The existing public constructor still checks immediately.
Derived policy receivers keep distinct Profile and executor identities; the
change does not hoist one shared mutable Profile into a constant default.

The existing =make-module-interface= remains the only default source-role
entry boundary, before datum admission or native module expansion:

#+begin_src scheme
(let (admitted-authoring
      (validate ModuleAuthoringProfileContract authoring-value))
  (.o (:: @ (list prototype))
      id: interface-id-value
      schemas: schema-object
      authoring: admitted-authoring
      metadata: metadata-value))
#+end_src

It stores the public validator's actual returned receiver, not the raw
candidate. Contextual role requirements remain in the same Contract and
producer. No responsibility, normalization, obligation or source check is
replaced by an old successful result. Custom policy/getter execution keeps
its existing open-boundary behavior.

The internal candidate is intentionally not pre-admitted merely because a
getter returned it. This changes the internal default's validation boundary.
It does not claim callback-for-callback equivalence with the previous duplicate
validation sequence. Normalizers need not be idempotent; applying one twice is
not an acceptable substitute for one check at the actual Interface boundary.

* Native semantic controls

=t/module-authoring-stage-test.ss= passes three cases:

1. Fresh policy receivers retain separate defaults and executors. Native
   inherited/bootstrap dependencies remain, while the default getter has no
   transitive classification/validation receipt dependency. Invalid fields
   are refused by the actual Interface constructor.
2. A passive native observer sees no Profile =.validate= read at default
   construction, one at Interface construction, and another when the public
   validated factory is explicitly called. No validator is replaced to make
   this assertion.
3. A real completed selected Graph is current before a same-value native
   revision change to =ModuleAuthoringProfileContract=. Both the Graph's
   currentness check and its source-view check then refuse the old result with
   the public native =stale slot dependency= diagnostic, rather than an
   unrelated Type or filesystem failure.

An intermediate probe incorrectly expected zero dependencies of any kind;
native inherited/bootstrap reads are necessary. Another attempted positive
normalization probe mutated the shared Type descriptor and changed its computed
prototype identity before reaching the intended boundary. Both failures are
retained as failed probes. The final controls inspect actual receipt kinds and
observe the real validator without modifying its behavior. Contract mutation
is a separate negative control, never a way to manufacture a positive result.

* Quint and Lean own different claims

[[file:../../../../../dev/proofs/quint/AuthoringStage.qnt][AuthoringStage]] models finite construction, Contract change, admission,
checked-subject selection and publication schedules. Its controls omit
admission, reuse an old Contract decision, use the raw subject, skip final
freshness, and prove non-vacuous acceptance through an expected counterexample.
Existing candidate/location models still own ambient effects, complete Graph
commit, previous-value retention and termination.

[[file:../../../../../dev/proofs/lean/YuanxuProof/ModuleSystem/Graph/SourceClosureWork.lean][SourceClosureWork]] adds independent functional and cost laws:

- =refused_profile_cannot_reach_inspection=;
- =inspection_receives_actual_checked_profile=;
- =normalization_is_not_implicitly_idempotent=;
- =constructor_trace_replay_removed=.

For =N= modules, =B= relevant boundaries, constructor trace width =K= and
actual local support width =R=, replay accounting separates
=N * B * (K + R)= into =N * B * R + N * B * K=. The change prevents that
constructor trace from becoming a shared getter requirement; actual boundary
validation and local support remain. This law assumes the real support
partition and does not bound native predicate internals, source bytes, GC,
macro execution or machine time.

The functional laws assume the public producer supplies its checked value;
they do not prove a Scheme compiler or reconstruct admission evidence. The
native tests bind those laws to the existing Interface implementation. Stable
source-bound qualification must include =authoring/roles.ss=, =source/admission.ss=,
=source/interface.ss=, =module-system/config.ss= and the focused test.

All six new Quint controls and the fifteen existing candidate/location controls
pass on the final source cut; the focused Lean target builds (40 dependency
jobs). One intermediate model run was refused by the source-cut guard while a
Lean syntax fix was being completed. Another timed out after SanyParser during
TLA compilation, under the unchanged five-second output watchdog. It is not a
model counterexample or a proof result. The subsequent independent session,
after the thousand-declaration run ended, completed all six controls. Neither
timeout nor that later pass is discarded or substituted for native capacity.

* Reuse boundaries, not an admission cache

The locked public library's =object-contract-flow= provides =checked-action=:
each invocation validates its own candidate and passes the actual returned
value to the consumer. The existing Interface's direct =validate=/=let= sequence
already implements this single-consumer handoff without another wrapper.

Public =bind-evidence= preserves invocation formulas and exact subject,
descriptor and context associations. It does not provide automatic in-place
freshness or reuse a prior successful approval; see the locked library's
[[https://github.com/tao3k/gerbil-poo/blob/fdeadfa40ca5cee5fe20308985aef1577f2eb49b/doc/evidence-binding.md][evidence-binding contract]]. It cannot justify replacing per-Interface admission
with a shared boolean or identity-only validity cache. Source, Schema,
Context and mutable Contract policies remain owned by their existing guards.
