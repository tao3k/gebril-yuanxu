* Reuse the public validation producer

The locked gerbil-poo ObjectContract protocol already provides all value
semantics. Its validation does structural checking, calls prepared-validation,
then diagnoses the FINAL checked object and runs obligations. The native
rebind-validation implementation creates a fresh checked receiver, forces its
selected fields, and returns the original candidate when no field changes.
If normalization changes a field, it returns the checked receiver instead.

Previously, even an unreturned checked receiver could remain strongly owned by
the Graph's native field-read records. Core receipt enrollment did not include
this upstream-created intermediate. Removing its field checks would lose real
Contract semantics; recognizing it by an object kind would grant false authority.

[[file:../../../../../module-system/types.ss][ModuleSourceRoleValueContract]] now specializes only the EXISTING public
prepared-validation slot. It obtains native validation-fields, wraps each exact
field validator to enroll the actual fresh receiver supplied by native
rebind-validation, and invokes that same native rebind-validation:

#+begin_src scheme
(def (prepare-role-validation fields)
  (let (checks
        (map (lambda (entry)
               (cons (car entry)
                 (lambda (original checked)
                   (owned-read-derived! checked)
                   ((cdr entry) original checked))))
             (validation-fields fields)))
    (lambda (candidate) (rebind-validation candidate checks))))

;; Within the existing ObjectContract-derived Role value Contract:
;; prepared-validation: (prepare-role-validation prepared-responsibilities)
#+end_src

The checks list is private to that recipe. A borrowed object or contributor's
label cannot supply constructor authority. No native validator, membership
check, result-identity decision, field wrapping, final diagnosis or obligation
is duplicated or skipped. The inherited prepared-responsibilities is a native
lexical slot: a child Contract must use its own effective responsibilities,
even after the parent recipe has been cached. Outside an owned Core region,
enrollment does nothing and the public validation behavior remains unchanged.
Enrollment is an internal audited Core callback, not a public authorization
API: its receiver provenance comes from that exact native producer invocation.

* Borrowed ancestors remain policy support

[[file:../../../../../object-family/read-projection.ss][The existing owned-read region]] now also records the FIRST native revision
of each transitive ancestor of this factory-produced receiver. Parent identity
is never inferred from a Contract name. The temporary instance can become weak;
its borrowed ancestors remain strongly retained policy support. Their revisions
are checked before weakening and again whenever the delivered native bundle
is replayed. Mutation followed by restoration does not renew the old witness.

A parent with native MOP/declaration hooks opens the whole region. A changed
parent during the operation also retains the complete original trace. Returned
normalized receivers remain weakly alive and must replay their ORIGINAL tokens;
missing live tokens refuse. Actual Contract, policy and source dependencies
are still promoted as original tokens with unchanged suffixes. This adds no
result/currentness cache or alternate evidence authority.

The parent-policy closure is constructed OUTSIDE the collection frame and
captures only the parent/revision rows. Combining it with the existing carrier
policy also happens outside that frame. A guard must not accidentally retain
the strong temporary-ownership table that it is meant to release.
