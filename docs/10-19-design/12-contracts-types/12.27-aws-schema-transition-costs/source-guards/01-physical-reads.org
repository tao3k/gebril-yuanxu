* Physical source-read attribution at actual publication boundaries

The follow-up retains the existing init qualification selection and its =.run=
entry, observation enabled, and progress-aware idle/total policy. It adds
diagnostic aggregation to =ModuleTestingProfile.=, not another runner or a
currentness cache. =file-read= is emitted immediately before the source
producer opens and reads a file; =file-request= also includes requests served
by the existing pure-window byte cache. These are file-read operations, not
physical storage-device I/O measurements. Package metadata, configuration
assets and Schema files are included; the count is not exclusively Scheme
files and does not instrument the SDK's own internal file opens.

The same real AWS Case still performs 49595 reads, 126253 requests and 530
read windows. Repeated lookup suppression has NOT reduced physical reads.
The bounded diagnostic keeps at most 512 owner/phase/caller rows and 128
effect rows; overflow contributes to an explicit bucket, never disappears.
It retains neither bytes, syntax, SDK contexts nor admission results. Disabled
observation allocates no diagnostic tables. Flushing happens on both normal
return and failure through the existing profile's dynamic extent.

** What may be shared, and what must be rechecked?

- Within an existing synchronous pure window, repeated paths already share
  bytes. Distinct collector enrollments remain distinct even when those bytes
  are shared. The package-entry candidate reduces parsing/query requests only.
- Across macro expansion/native initialization, policy or Contract callbacks,
  Nix/package operations and independent publication invocations, a shared
  Graph identity is insufficient authority to reuse earlier source acceptance.
  The source bytes or dependency registration may have changed.
- Collected-source replay deliberately starts fresh even inside an outer read
  window. The native control mutates a source after the outer read and requires
  replay to reject it. Removing that reset would hide a real mutation.
- =graph-current= is the dominant next audit surface. Its repeated calls must
  be related to the operation between them before coalescing: a private lookup
  is a candidate; lazy author slot evaluation or a validator is not presumed
  pure. These aggregate rows do not prove a safe removable-call count.

No new source cache, metadata-only acceptance shortcut, cross-effect read
window, Contract bypass or reduced source closure is introduced by this audit.
Physical-read optimization remains open; the attribution is not reported as a
completed performance improvement.

** Executable receipt and limits

The original aggregate exits naturally with seven MODULE-OK, two HARNESS-OK
and two final OK markers, without error or overflow failure markers. The AWS
Case retains Schema upgrade, three admission-to-publication negative controls,
stale evidence refusal, previous-value preservation and fixture cleanup. Its
publication-complete checkpoint is 59856 ms / 22415 ms Case CPU; the Ops worker
is 76704 ms. Nix union time is 36272689 microseconds. This is not a speedup
over the earlier 29767 ms receipt, and the measured Nix time must not be
attributed to Scheme file reads or silently excluded from endpoint duration.
Observation and progress-aware deadlines remain enabled throughout.

The focused native observation test checks owner/phase/caller attribution and
the disjoint effect totals using injected diagnostic events. Those events are
test probes; the AWS counts above come from actual source-producer events.
Existing disabled-observation, no-domain-slot-read and failure-release controls
remain in that test. Reproduction uses the normal heap-fenced entrypoints:
