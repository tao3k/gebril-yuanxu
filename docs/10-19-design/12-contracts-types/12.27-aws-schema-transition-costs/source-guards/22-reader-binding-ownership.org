#+title: 12.27.35 Reader Binding Ownership At Real Declaration Scale
#+property: DOCUMENT_ID 12.27.35
#+language: en

* Question and unchanged acceptance boundary

Can one thousand real Module declarations fit the existing source-only test
budget after the owned-call projection? The fixture writes actual role files,
imports the generated init, and invokes the selected Module's =tests .run=.
It does not substitute directory enumeration or publication values for native
expansion. The 2 GiB process heap and 1 GiB live-growth guard remain unchanged.

The first thousand-module run with the preceding owned-call implementation
completed 315 publication returns before the live-growth guard refused it.
The failing sample was 1,502,085,240 live bytes and 1,074,902,904 growth bytes.
This is a retained negative result, not thousand-module acceptance. At 256
publications, the Reader reported 3,328 private role bindings and 57,088
evaluated interface bindings, with zero completed private code-body pointers.
Releasing the latter therefore does not establish that bindings, syntax or
compiled procedures are no longer reachable elsewhere.

* Share the existing SDK weak prelude, not another module registry

[[file:../../../../../module-system/source/preparation.ss][Preparation]] previously emitted a full explicit POO import into every
interface. An interface consequently had approximately 223 local bindings in
this fixture. The existing =source/config-prelude= already exports Scheme and
POO bindings with native weak-prelude semantics. Gerbil's
=core-module->prelude-context= returns the same registered prelude for the same
module context; Core must use that mechanism rather than copy its aliases.

For the default Scheme prelude, both reader and compiler projections now use:

#+begin_src scheme
prelude: :yuanxu/module-system/source/config-prelude
(import
  (only-in :yuanxu/module-system/source/declaration
           .def define-module-build-binding)
  ;; Actual adjacent role imports remain explicit and source-admitted.
  "./types.ss" "./objects.ss" "./config.ss")
#+end_src

The reader uses admitted original role paths; compilation uses the adjacent
projected paths shown above. Explicit role/import bindings retain ownership
over weak defaults. A custom contributor prelude retains the former explicit
POO import path. No SDK table, macro binding, runtime promise or registry entry
is removed. The prelude's source closure remains a guarded compiler dependency.
The native publication suite passed, including two independent interface
contexts whose prelude is identity-equal to the SDK-registered POO prelude.
The sixteen-module run reduced evaluated interface-local bindings from 3,568
to 112 (223 to 7 per interface), while keeping the 208 private role bindings.
Its collected live sample was 536,060,696 bytes. These are separate observations:
the binding reduction is large; the process-memory reduction is modest.

* Bounded original-token ownership at publication return

[[file:../../../../../module-system/source/reader.ss][The Reader]] also bounds its native recording frame to one publication.
It identity-normalizes the returned roots and delivers one native bundle whose
dependencies are those ORIGINAL tokens. First occurrence order is preserved.
Distinct tokens for the same receiver/key must remain distinct. Every suffix,
including an unknown callback's dependencies, stays unchanged and strongly
owned; there is no callback purity exemption here.

All original observers and prechecks still run on every actual access.
Multiple values are forwarded unchanged. A callback exception delivers its
dependency support before rethrowing. Native replay performs the original
currentness checks and final recheck. No approval, source bytes, dispatch result
or replay result is cached. Nonlocal continuation escape is not certified by
this bounded return/exception protocol.

The sixteen-module original-token projection sample retained 537,043,120 live
bytes, versus 538,188,928 in the preceding owned-call sample. This modest
1,145,808-byte difference does not explain or close the capacity problem.
It is not a wall-clock speed claim or exclusive SDK-byte attribution.
The subsequent thousand-module run with token normalization alone completed
325 publication returns, then again hit the unchanged live-growth guard:
1,502,968,584 live bytes and 1,075,842,408 growth bytes. Its final diagnostic
had only one observed effective-method receiver, no invocation frame and two
related read records. This is evidence to pursue Reader/SDK ownership, not
permission to erase the remaining native dependencies or claim capacity closure.

* Observe actual native survivors

The existing trace-enabled [[file:../../../../../module-system/building/test-observation.ss][ModuleTestingProfile]] instruments native compilation
without changing results. Weak-key tables track actual Reader contexts,
expanded bodies and compiled programs; values are closed role labels only.
Rows report surviving contexts, local binding counts, nonempty code pointers,
expanded bodies and programs by role. They never traverse binding values or
force cold scopes. Without tracing, this instrumentation is not installed.

Geometric rows reflect the most recent ordinary GC, not an exclusive retained
byte measurement. The worker's existing collected =graph-held= sample remains
the end-of-Graph comparison point. Weak diagnostics never authorize reuse,
source admission or context deletion.
In the sixteen-module collected sample, each role had 16 surviving contexts.
All tracked expanded bodies and compiled programs had disappeared, and all
completed code pointers were empty. The remaining local bindings were 80 for
Types, 64 for Objects, 64 for Config and 112 for Interface. This contradicts
the hypothesis that completed Reader IR alone explains the remaining growth;
it does not justify discarding any binding or native dependency.

The same final Graph read reported 37,772 direct dependency references and
7,210 distinct tokens. Its scalar attribution included 208 authoring receipts,
128 classification receipts and 128 validation receipts. These receivers are
reachable through the real native dependencies; counts do not establish their
exclusive retained byte cost. Their Contract, candidate and Context support
must be preserved before any further ownership reduction can be justified.

* Thousand-module result: capacity remains open

The final shared-prelude run completed 331 publication returns before the same
live-growth refusal: 1,503,228,680 live bytes and 1,076,132,552 growth bytes.
It is not a pass and does not establish a statistically stable capacity gain
over 315 or 325: GC sampling and in-flight work affect the refusal position.

The unwinding trace had zero surviving observed CLOS carriers/read records.
Each role had 332 native contexts. Only the currently unsuccessful declaration
kept one code pointer and expanded body per role; all tracked compiled programs
were gone. Successful declarations had no remaining tracked expanded bodies.
Preserving that unsuccessful declaration's code is intentional: post-evaluation
source admission did not finish, so the Reader has no release capability.
The original fixture directory was removed after failure.

The next ownership audit must follow the real semantic path, not delete SDK
state: style-policy validation, authoring admission, public value/Context
contracts, their receipt candidates, and the native dependency graph that
retains them. A context-free receipt label alone does not prove non-escape or
complete Contract support. Existing OwnedReads/PublicationReads coverage laws
are prerequisites for a bounded producer projection; they do not certify these
additional factories. No new projection for those receipts is claimed here.

* Quint, Lean and native checks have separate jobs

[[file:../../../../../dev/proofs/quint/PublicationReads.qnt][PublicationReads]] explores finite completion/failure, mutation and publication
schedules. Controls omit a distinct same-key token, lose failure support,
suppress original observations, drop a callback-only suffix or skip replay.
The acceptance control prevents reject-all from appearing safe.
All seven expected Quint outcomes passed against the source-bound candidate;
the focused Lean PublicationReads target also built successfully.

[[file:../../../../../dev/proofs/lean/YuanxuProof/ModuleSystem/Graph/PublicationReads.lean][Lean]] proves, for arbitrary dependency graphs, that root-membership
equivalence preserves every demanded identity. Therefore identity deduplication
preserves the complete currentness proposition, including cyclic/shared
suffixes. It does not prove a GC byte bound or certify the SDK prelude cache.
[[file:../../../../../dev/proofs/lean/YuanxuProof/ModuleSystem/Graph/ImportCorrespondence.lean][Existing import correspondence]] continues to require exact canonical SDK
identity and absence of omitted private registration before cutting a shared
SDK subtree. A matching name alone grants neither condition.

The native publication test checks shared prelude identity, absence of copied
local =.o= aliases, retained explicit =.def=, original-token uniqueness and
refusal after actual SourceRef mutation. Existing macro reuse, deferred Build,
failed source admission and CLOS policy/Contract tests remain separate gates.
The complete native publication suite and focused CLOS dispatch suite passed,
with required module/harness/final markers and no native error/overflow marker.
The sixteen-module init-owned run also passed its same-Graph, cold-scope,
stale-source refusal and fixture cleanup assertions. The failed thousand run
remains a failed gate; passing these focused checks does not promote it.
The real init-owned JsonSchema/Funflow/AWS aggregate also passed: seven module
markers, two harness markers, two final OK markers, exit zero, and no native
error/overflow marker. It retained the observed/progress-aware execution path,
real Schema transition, stale evidence refusal, previous published value on
failure, and fixture cleanup. This is functional regression evidence, not a
thousand-module memory or wall-clock result.

post-collection identity assertion, stale-source negative and failure cleanup.
Logs remain local artifacts. No runtime Loader, upstream change, additional
cache, heap/timeout increase or compiled-cache workaround is part of this work.
