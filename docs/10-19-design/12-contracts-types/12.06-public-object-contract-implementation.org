* Existing mechanisms retained

=Type.=, =element?=, =validate= and slot =.defgeneric= remain authoritative.
=ObjectContract.= is a Type whose membership is derived from diagnosis. A normal
field Type is adapted, while an existing diagnostic Type is reused. The Type
adapter delegates =.validate= as well as =.element?= so Function Types retain
their existing input/output wrappers when explicitly validated.

The existing =declarative-metadata= invocation Contract accepts these Types
through =typed=. No second invocation wrapper, predicate registry, effect
protocol or registration system was introduced. Structural checking does not
implicitly rewrite a procedure-valued field with a checked wrapper.

* Difference from the earlier proposal

The public implementation additionally checks malformed descriptor callbacks
and composed diagnostic lists, adapts plain Types in whole-value constraints,
and prepares constraint lists on the effective Contract receiver. Unexpected
callback errors retain their causes. Generic issues do not embed raw candidate
secrets. Optional/default semantics remain with explicit schema constraints;
the responsibilities map defines required fields.

All ordinary data objects are structural by default. A prototype requirement is
an explicit additional policy, checked before candidate field demand. It does
not establish module origin, source association or authorization. Closed field
checking and delegated external schema checking remain distinct policies.

* Schema adapter stays outside the public library

The qualification now imports =:clan/poo/object-contract= directly. It no longer
generates a generic object-contract fixture or forwarding module, and no longer
extracts generic Type/object implementation from the discussion document.
The JsonSchema-owned blocks
still supply =SchemaContract.= and schema compilation/node validation on the
consumer side. The local AWS factory remains an isolated domain control.

The AWS local-link diagnostic now constructs its ordinary POO issue directly;
it does not depend on a private generic helper. Schema representation, provider
input conversion, resource relationships and Core receipts are not added to
gerbil-poo. A reusable JsonSchema library was subsequently implemented locally;
see [[file:12.07-json-schema-value-contract-implementation.org][the JsonSchema implementation record]]. This section records the earlier gate.

* Validation boundaries

The library tests exercise the actual public module from an isolated source path,
with no Core source on that path. Tests include Type and Function adaptation,
missing/unknown/nested fields, explicit ancestry, inherited/copy-derived prepared
maps and constraints, external diagnostic Types, invalid policies and callbacks,
existing invocation checking and final-child resource projection after parent
cache demand. Schema and admission controls use the public module as a consumer,
not an embedded copy.

Production module adaptation,
automatic source association, Loader integration and publication remain out of
