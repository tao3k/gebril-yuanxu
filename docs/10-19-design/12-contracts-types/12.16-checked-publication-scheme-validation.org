* Checked subject and the actual descriptor

The fixture's value Contract includes an existing public Function Type:

#+begin_src scheme
(def WebContract
  (.cc ObjectContract. responsibilities:
    (.o network-ref: Symbol settings: InstanceInput
        decorate: (Fun String <- String))))

;; Inside the test admission descriptor, using a counted value Contract:
(.admit =>
  (lambda (previous)
    (lambda (candidate context)
      (previous (validate value-contract candidate) context))))
#+end_src

The existing Core producer records the effective derived descriptor. No test
code patches admission-contract into its result. The classifier receives the
same checked object that the receipt and publication return. The Function
forces the distinction: the checked root differs from the raw input and its
callback is wrapped. Calling that wrapper with a number raises the public
TypeError before entering
the raw body; a valid string reaches the body once.

Root validation is instrumented through an ordinary inherited .validate slot.
One publication invokes it exactly once; replay invokes it zero times; a fresh
admission invokes it once more. This does NOT claim one internal field read,
one Schema traversal or one structural/diagnostic pass. Those are separate
parts of upstream validation. No wrapper is added by the publication phase.
