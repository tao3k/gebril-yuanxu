* Context-only child admission

The maintained AWS factory now adds one contextual requirement:

#+begin_src scheme
(define-type (AWSProfileAdmissionContract. @ AWSAdmissionContract.)
  identity: 'aws/profile-context)

(def (aws-scenario-contract input-type)
  (.cc AWSAdmissionContract.
    'identity 'aws/scenario-admission
    'value-contract (.cc AWSScenarioContract. 'input-type input-type)
    'responsibilities (.o profile: AWSProfileAdmissionContract.)))
#+end_src

The child's inherited value-contract is #f. It neither recompiles the provider
Schema nor validates fields again. It requests the actual selected Context's
freshness/requirements check and records the effective Profile as its subject.
The resource slot is the same Profile projection; a second identical contextual
child admission for that alias is unnecessary.

The integration asserts the root evidence candidate is the published checked
root and the child evidence candidate is exactly next.profile. The child retains
the actual requirements-map descriptor and exactly publication.context. The
parent's cached resource stays t3.small while the child's resource is t3.medium.

* Two integration defects repaired

The earlier isolated producer tests did not cover these publication adapters:

1. [[file:../../../admission/contributions.ss][bind-publication-contributions]] previously allowed only the root descriptor in
   its Context method. It rejected the real child's contextual dispatch even
   though the root's responsibilities selected that exact child.
2. [[file:../../../admission/publication.ss][Schema association traversal]] followed value-contract: #f on a context-only child
   as if it were a malformed public Type.

Context binding now snapshots the exact descriptor references reachable through
the root's contextual responsibilities, including revisions of each descriptor
and requirements map. It is identity bookkeeping for the existing publication,
not another field validator or user-maintained registry. Shared references are
visited once. Currentness checks still reject source/object changes. A same-label
copy of a child is refused because it is not the selected reference.

Every permitted child dispatch runs the existing Context currentness check and
any inherited Context policy. Root contribution rows are evaluated only for the
root descriptor: they describe the whole selected composition and must not be
reapplied to a child candidate of a different shape. No new per-child contribution
routing protocol is introduced.

This control uses distinct root and child descriptors. A recursive domain that
uses the same descriptor at both root and nested positions would need an explicit
position-aware contribution policy; descriptor identity alone cannot distinguish
those positions. That case is not qualified by the AWS example.

Schema traversal skips only the explicit optional value-contract: #f edge.
Other malformed Type edges, missing publication metadata and mismatched source
associations still refuse. The traversal still does not infer dependencies
hidden in arbitrary procedures.

* Refusal and update controls

| Control | Verified relationship |
|---------+-----------------------|
| Cached parent, derived instance_type | Parent stays t3.small; published resource and contextual child use t3.medium. |
| Same-label foreign child descriptor | Platform Context rejects a copied descriptor rather than trusting its identity symbol. |
| Contextual requirements map changed after capture | The recorded map revision refuses the old publication rather than authorizing the replacement. |
| Child Context policy refusal | A test probe extends the actual platform Context method, calls its original checks, then refuses the selected child; publication returns the previous object by eq?. |
| Package update 5.99.0 to 5.100.0 | The old selection refuses publication; a fresh .for-export resolves the new actual Schema/Contract/Context. |
| Old receipt replay into the fresh publication | Public bind-evidence refuses the old descriptor/Context binding and preserves the previously accepted value. |
| Fresh admission after update | The same user configuration passes with fresh evidence and its final Profile child. |
| Misspelled instnace_type | The real provider input Schema rejects the field before accepting a new publication. |
| Schema bytes changed after capture | A disposable copy retains the original manifest/index digests; changing the EC2 input bytes refuses publication and old-receipt reuse, preserving the previous object. |

The policy rejection callback is a test probe, not an AWS authorization policy.
The Schema copy is a mutation control, not a fabricated input Schema. The package
versions and provider download hashes come from the existing fixtures; nixpkgs
is the test environment's resolved package set. This does not claim deployment
validity for ami-fixture, live AWS access, IAM authorization or whole-provider SDK
constraint coverage.
