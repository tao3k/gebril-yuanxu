* Ownership before refactoring

| Operation | Owning abstraction | Alignment decision |
|-----------+--------------------+--------------------|
| Select behavior from one receiver's inherited slot | gerbil-poo =.defgeneric= | Prefer the public upstream mechanism; do not import all of CLOS |
| Accumulate inherited method fragments | upstream =MethodDeclaration.= and =method-fragment= | Evaluate replacing local single-receiver fragment assembly |
| Interpret standard/simple/forwarding/inner contributions | upstream method-combination functions | Reuse where invocation semantics match; names alone are insufficient |
| Select methods across independently extensible arguments | Upstream also has a typed sparse =multimethod.ss= engine | Retain Core CLOS behavior until identity, evolution and continuation semantics have a qualified adapter |
| Class/eql/prototype specializers and argument precedence | Core CLOS | Retain the semantic delta; use upstream object precedence for prototype ancestry |
| CLOS replacement =call-next-method= arguments | Core CLOS invocation frame | Retain applicable-method-set validation |
| Graph, package/source/Schema currentness and publication policy | Core admission | Keep separate from generic selection and public value contracts |

The two =.defgeneric= bindings have different grammars and semantics. A native
receiver generic is not a drop-in replacement for a CLOS generic merely
because a particular call currently has one specialized parameter.

Correction to the initial audit: the documented limitation concerns the
receiver generic bridge, not the complete library. Upstream =multimethod.ss=
already provides multiple dispatch, a persistent sparse index, guarded
applicability and bounded candidate/effective-method caches. Its symbolic
prototype names require a stable injective identity mapping from the caller.
Core class/eql identities, argument precedence, lambda-list congruence,
generic mutation and replacement-next checks are not automatically provided
by replacing a Core call with =multimethod.call=.

* Concrete consumers

=admission/contributions.ss= already uses upstream =:clan/poo/mop=
=.defgeneric= to select =.contribution-obligations= from a contract. Preserve
that ownership; adding a CLOS registry here would be a regression.

=module-system/authoring/admission.ss= dispatches on executor strategy and
source role, with interface specialization also represented in its method
signatures. Preserve independent extensibility. The local implementation now
uses existing Core =.defgeneric=, =.defmethod= and deferred method bundles,
with an internal =defrules= for the common signature. This consumer no longer
contains handwritten specializer lists or invocation-frame lambdas.

=modules/opentofu/collections.ss= dispatches on provider collection policy and
evidence transport. Replacing that crossing with receiver-only dispatch would
remove an extension axis. Its import should reach only the required generic
declarations, without class evolution, reflection and load-form publication.

* Semantic obstacles to blind reuse

Upstream standard contributions receive a zero-argument next thunk retaining
the original argument row. Upstream forwarding permits validated payload
replacement while retaining dispatch. Core CLOS permits replacement arguments
only when the complete ordered applicable method groups remain unchanged
(=poo-clos-call-next-method= in =poo-clos/dispatch.ss=). These are different
protocols. Sharing a combination evaluator requires a demonstrated adapter
that preserves this check, no-next behavior, auxiliary restrictions, errors,
multiple values and effect order. No such adapter is claimed here.

Upstream =call<-formals= now delegates Gerbil formal projection to core
signature mechanisms. Core's =&optional=, =&key=, supplied-p bindings and
lambda-list congruence describe CLOS syntax. Keep that grammar where required;
do not independently parse ordinary Gerbil optional/keyword formals. Audit
the lowering boundary before replacing either representation.

Upstream method-fragment merging is inherited receiver-slot assembly. Core
method bundles also enforce generic protocol object identity and defer
registration until explicit composition. Reusing fragments must preserve
both properties, rather than registering at declaration/import time.

* Implemented local convergence

** Single-receiver policy uses the upstream generic

Qualifier admission belongs to the effective combination object. Core now
uses the public upstream generic:

#+begin_src scheme
;; .defgeneric is imported from :clan/poo/mop.
(.defgeneric (poo-clos-method-combination-admits-qualifier? combination qualifier)
  slot: .admits-qualifier?)
#+end_src

The default policy method lives on the existing combination prototype. Its
lexical =kind= and =identity= slots retain built-in CLOS rules. That small
classification remains a pure policy, not a second method selector. A derived
combination refines the method through ordinary POO slots; registration uses
the same generic. Core's standard/short/long execution is not delegated to an
incompatible interpreter.

=ClosMethodCombination= now requires the policy slot to hold a procedure, so
typed construction cannot accept a non-callable policy. A custom method still
owns its semantic obligations; refining qualifier admission does not install
a new standard/short/long execution engine or alter CLOS applicability.

The control forces a parent's callback, derives a short combination with
another identity and checks that qualifier admission follows the child while
the parent's result remains intact. A refined standard policy rejects a
primary before registration, proving the consumer reaches the native slot.

** Authoring keeps independent axes without manual construction

#+begin_src scheme
(.defgeneric module-authoring-admit (executor role interface datum)
  (protocol ModuleAuthoringAdmissionProtocol))

(defrules authoring-method ()
  ((_ role-prototype admit)
   (.defmethod (module-authoring-admit
                 (executor (prototype ModuleAuthoringExecutor.))
                 (role (prototype role-prototype))
                 (interface (prototype yuanxu-module-interface-prototype))
                 datum)
     (admit interface role datum))))

(.defmethod-bundle ModuleAuthoringCoreMethods ModuleAuthoringAdmissionProtocol
  (authoring-method ModuleSourceRole. yuanxu-module-authoring-admit/common)
  (authoring-method ConfigSourceRole. yuanxu-module-authoring-admit/config))
#+end_src

The exported =ModuleAuthoringAdmissionGeneric= is the generated binding's
current generic, not another generic. Explicit composition remains the
registration boundary. Methods retain one owner: replaying already registered
descriptors into another generic is not valid reuse. Another owner requires
fresh method declarations. Protocol identity still matters even when labels
are equal.

** Upstream controls stay outside the CLOS grammar

=t/poo-clos-upstream-alignment-test.ss= calls upstream modules directly. It
covers Gerbil optional/keyword/rest forwarding (false values and a private
rest spine), local method-fragment merging with inherited methods, and
two-axis multimethod selection retaining the parent definition. Gerbil's
keyword-first call row and =#!rest= marker are preserved, rather than parsed
through CLOS =&key=. Symbolic dispatch names and method bodies are fixtures;
the generics, declaration expansion and dispatch are actual upstream calls.
This does not qualify a Core-to-upstream CLOS dispatch adapter.

* Ordered refactoring gates

1. Qualify the exact upstream revision in an isolated dependency environment.
   Do not silently change the repository pin or mix revisions within a run.
2. Classify actual consumers by extension axes. Route single-receiver behavior
   through upstream slots and retain genuine multi-argument crossings.
3. Keep generic declaration imports independent from class lifecycle and
   reflection. The local =generic-syntax.ss= extraction is an import-boundary
   change, not evidence that upstream CLOS alignment is complete.
4. Replace redundant declaration construction with existing declarations.
   Preserve protocol identity, declaration-time non-registration and explicit
   composition. Do not leave parallel registration mechanisms.
5. Consider sharing combination execution only after differential tests cover
   next-method replacement, qualifier order, exceptions, multiple values,
   optional/key forwarding and generic evolution. Retain unsupported semantic
   cases rather than weakening them to fit an adapter.
6. Measure cold imports and first Graph construction through the original Ops
   entry. An import split or a passing syntax test alone establishes neither
   AWS acceptance nor a performance improvement.

Two fixture assumptions were corrected during qualification: =.declare='s
second argument is declaration context, not an inherited base (the runtime
declaration constructor takes =supers:=); and a composed Core method is owned
by its generic, so a production bundle is not replayed into another owner.
Gerbil keyword call rows also retain their native =#!rest= boundary. These
corrections changed the fixtures, not upstream implementation or test limits.
