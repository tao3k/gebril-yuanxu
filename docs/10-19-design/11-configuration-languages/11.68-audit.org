* Review verdict of the superseded 19-file draft

The audited 19 Scheme files (365 lines including comments) were an over-split
semantic sketch, not a usable AWS configuration library. The normal user edit is
small, but understanding its maintained baseline requires too many forwarding
objects, scopes and incomplete infrastructure assumptions. Do not accept this
tree as the target contribution structure. The subsequent design-only revision
removes those 19 fragments; their historical names and findings remain in the ledger below.
No runtime Module, build entry or Loader was changed.

The appropriate distinction is between a reusable library's internal source
organization and the consumer's configuration entry. A scenario fixture should
not contain a miniature Module System and a private admission subsystem just
to change an instance type. Retain native POO where it owns real behavior;
remove boundaries that merely relay values or repeat existing admission.

* What the actual Omnibus organization teaches

The user-facing AWS configuration is one main.ncl. It imports the maintained
AWS interface and the Terraform Contract; aws/modules/aws.ncl joins several
domain implementations. EC2's field Contract, defaults and resource elaboration
are together in aws-simple-ec2.ncl. VPC's derived references and resources are
together in aws-simple-vpc.ncl. Thus the lesson is one understandable domain
entry with maintained internals, not literally one file for the entire library.

#+begin_src nickel
aws.simple.ec2.instances = {
  test = {
    ami = ami-id aws.region,
    type = "t2.micro",
    network = aws.simple.networks.test,
    public_key_name = "${resource.aws_key_pair.ssh_key.key_name}",
  },
},
#+end_src

These are actual fields from main.ncl. The EC2 implementation later reads
=cfg.type= for instance_type and =cfg.network.subnet.id= for subnet_id, generates
a security group using network.vpc.id, and carries the key and AMI into output.
Our two-field object omits those essential parts. It is a receiver/Contract
control, not an equivalent AWS case, and should be labelled accordingly.

The useful comparison is whether a user can understand input, its maintained
Contract, selected references and output without opening admission infrastructure.
File count alone proves neither simplicity nor correctness; 19 fragments for
this reduced control nevertheless introduce no demonstrated maintenance benefit.

* Native reuse: what reflection and dispatch can actually do

** Reuse current native responsibilities and .admit

Actual Core types.ss defines descriptor-owned .admit, recursive responsibility
admission, classification and obligation evidence. Iterating the retained
descriptor set and invoking that public entry is enough for the present
independent policies. A second AWS Provider parameter, Generic and identical
forwarding methods do not make universal admission stronger.

This is not a rejection of multiple dispatch. Keep .defgeneric/.defmethod and
deferred method bundles when two real independent families need different
behavior, such as a qualified provider/backend crossed with domain kinds.
Name those actual owners and distinct methods first. Do not manufacture a dummy
AWSAdmission. prototype to satisfy the two-axis rule. call-next-method still
cannot substitute for checking every retained requirement.

** Reuse semantic parent reflection within its boundary

In the inspected native source, .def expands to an ordinary .o construction.
object-supers and compute-precedence-list! can inspect the semantic ancestry of
.def and native multiple inheritance. With a complete trusted association index,
that graph can find associated ancestor requirements for those operations.
It does not itself create that index, authenticate source or conjoin descriptors.

The inspected mop.ss also has descriptor-owned slot Generics, optional dispatch
through an object's .type, and define-type lowering to .def/.cc. These are useful
existing declaration mechanisms. They do not make every .def automatically record
a mandatory Contract or source location. An ordinary overridable .type slot cannot
replace protected requirement retention. Also distinguish the native slot
.defgeneric binding from Core CLOS's multi-dispatch .defgeneric: generated source
wrappers must import the intended binding, not rely on identical printed names.

Native .+ copies RHS slots/defaults and uses the RHS parents plus the base as
supers. The RHS object itself can disappear. Native .cc copies the original's
slots while retaining its parents, losing the original as a semantic parent.
Neither later reflection nor a CLOS method can reconstruct those missing source
identities. A source-preservation gap remains genuine; it is not solved by
inserting policy objects as extra semantic parents or wrapping a local .+ name.

If universal preservation is required, reuse the existing unified constructor
design at the common Core/native owner, with explicit source operands from .+
and .cc. Do not copy its provenance protocol, token registry or per-object
metadata into AWS. The read path must distinguish declaration origin, resolved
value origin and mandatory policy origin; one undifferentiated origin token does
not answer all three questions.

** Keep evidence collection independent of conflict resolution

Native parent precedence determines values; it must not silently resolve
mandatory policy contradictions. Preserve every required descriptor and evaluate
the final value. Avoid running an identical Contract repeatedly just because
EC2 config and an alias Profile both published it: execution can deduplicate by
canonical descriptor and relevant policy/view identity while retaining all
origins for diagnostics. Never deduplicate by display symbol alone.

index-publications currently reads every selected scope.config to register a
root. This can construct selected default objects before the final Profile is
requested. It is not a scan of every eligible module, but it does not establish
the stronger intended demand boundary either. Audit publication metadata demand
separately from config construction, Schema compilation and resource projection.

selected-network? compares whole-object identity. A legitimately refined Network
with the same selected subnet is therefore rejected. The domain should instead
define which qualified provider/account/region/network/subnet reference is valid,
then check the appropriate identity and Contract. Equality of a bare subnet id
alone is also insufficient; do not replace eq? with an unqualified string match.

A parent-derived object is not automatically invalid just because it was cached.
Distinguish wrong effective inputs, stale admission evidence and a harmless reuse
of equal output. Cache qualification needs final input/Contract/view dependencies;
object identity alone is neither all of that evidence nor a universal ban on reuse.

Keep this case directory as a scenario reference, not a self-contained framework.

This was the source-audit recommendation. The subsequent design-only revision

EC2 published Modules only when independent ownership/reuse/loading justifies

Existing role organization remains useful at library scale, without making each

The normal main entry should show real Omnibus-equivalent fields and consumers:
AMI, named instances/networks, key references and generated resources, not just

pending and must not be shown as current native support.

* Earlier draft expectations (not passed tests or design approval)

The retained checklist below predates this source review. Its proposed wrapper
and Provider architecture is superseded by the findings above; the useful failure
cases remain requirements. Exact-network eq? and blanket parent-cache rejection
are specifically subject to the corrections above.

** Expected admission path

1. Select/authenticate publication scopes; retain disables and dependency chains.
2. Admit VPC scope shape and its final config through VPCConfigContract. Scope
   shape alone is insufficient. Inject that exact scope into EC2/Profile context.
3. Build the complete private publication index from selected scopes. Preserve
   policy origins even when several contributions refer to one root.
4. Explicitly compose AWSAdmissionMethods into the matching Generic protocol.
5. User .def constructs Production with ordinary native semantics. Pending kernel
   construction metadata links it to AWSScenario, InstanceProfiles.config and
   EC2Scope.config. All these roots may contribute requirements.
6. admit-all collects every retained requirement, invokes multi-dispatch separately
   for each, then checks evidence correlation against Production and its context.
7. Validate the exact selected network and demand Production.resource. A complete
   AWS output Contract/renderer is absent: return projected-unadmitted only.

Steps 1--3 and kernel integration are explicit prerequisites, not implementations
hidden behind an init.ss or a fake source registry. instance-preview explicitly
admits the VPC root before admitting the final instance, using the same protocol.
Selected child closure and complete-index certification remain open: a root guard
cannot detect an omitted Budget binding by itself. The selected graph must prove
its index complete before this collector can safely interpret absent entries.

** Existing versus pending

Existing syntax/source foundations: native .def/.o/.+/ .cc, lazy lexical slots,
responsibilities and public admission, prototype specializers, Generic protocol
identity, deferred method bundles and internal defrules. Prior bounded controls
are referenced by the parent design documents; no fresh Scheme test was run here.

Pending: target Core naming, module role wrappers, typed source/scope linking,
automatic publication association and complete sealed indexes, unified constructor
provenance (especially .+ RHS/.cc), nested selected closure, source diagnostics,
full AWS projection/output Contract and production cache invalidation. Arbitrary
Scheme code can forge public-looking evidence: trusted admission/provider ownership
and private view integrity are prerequisites, not authentication proved by eq?.

The activation sketch composes bundles sequentially. It is not a transaction over
the whole selected bundle set. A later failure must block scope/plan publication;
production activation needs preflight plus isolated Generic generations or an
equivalent qualified rollback boundary. No all-or-nothing registration claim is
made for this sketch. A mere shared protocol display name is not identity.

Native POO remains the configuration model. The private provenance DAG preserves
obligations without altering native precedence; multi-dispatch extends behavior
without replacing universal admission with "the most specific policy wins".

* Current correction: ordinary configuration, no mandatory Deployment wrapper

The current [[file:11.69-aws-case-index.org][role split]] supersedes the earlier handwritten domain vocabulary and
Deployment Module. Resource fields reuse generated Provider Contracts. Independent
network/machine/access data and an ordinary user contribution are maintained as

These design sources are not an executed cloud deployment.
