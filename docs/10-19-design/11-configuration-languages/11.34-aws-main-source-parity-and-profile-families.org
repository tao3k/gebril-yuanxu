The source explicitly provides empty rule arrays, false self, ingress description
${null}, and an IPv6 default route. The projector retains those choices rather
than silently replacing the source workload with a different recipe. Their AWS
validity is NOT established by retaining them. Name tags use VPCProfile.tag-prefix
Tf-Ncl for this baseline; a derived Profile can change naming without copying a
projector. The source's provider and assume_role arrays are retained as arrays.

The reference uses ssh-pubkey.sh. Our maintained design instead uses
=a separate Scheme process/JSON adapter= (retired design source) backed by Gerbil run-process. It preserves
the public_key result protocol, not the original executable path/implementation.
The target ./aws-public-key executable must be built and located from the admitted
Module source; the interface command declaration alone does not implement that linkage. No command
or private-key access was performed. Projection/admission must never execute it.

* Profiles are reusable configurations, not six extra Modules

| Profile | Independent responsibility | Reuse/derivation |
|---------+----------------------------+-----------------|
| UbuntuAMIProfile | Region-to-AMI values | Region lookup demands only the selected image value |
| VPCProfile | CIDR block and Name-tag policy | BuildVPCProfile replaces CIDR and tag-prefix |
| EC2Profile | Compute defaults, including t2.micro | LargerEC2Profile changes type; RestrictedEC2Profile also restricts SSH CIDRs |
| SSHKeyProfile | External public-key derivation command and arguments | Multiple instances reuse the same selected key occurrence |
| CredentialsProfile | Assume-role values and session default | Reusable across Scenarios without copying provider projection |
| StateProfile | State bucket/key | Scenario occurrence binds region from its final receiver |

Profiles with unresolved contextual fields are partial configurations, not already
admitted complete deployments. The Scenario supplies AMI, region, network/key
references before selected admission. AWSDevelopment configures the exact source
workload. =AWSBuild= (retired design source) inherits it, preserves test, and adds a build network/instance
using BuildVPCProfile and RestrictedEC2Profile, plus build_ip output. This shows
independent Profile reuse, sparse Profile inheritance and Scenario extension in
one source family; it is not a precomputed language/environment matrix.

AWS exports these native values through profiles/scenarios namespace slots once.
They do not inherit the Module object or acquire per-Profile publication wrappers.
Core must retain each chosen value's associated Contract/source across supported
native derivatives. Namespace publication alone does not implement that property.

* Native receiver and final-resource behavior

AWSDevelopment uses native (.def (name self prototype) ...) syntax, choosing
scenario as the receiver name. Nested state/network/instance slots read that final
receiver when they need region. This avoids capturing AWSDevelopment as a fixed
parent value and avoids inner region-slot shadowing. It is not a new DSL or raw
self/super lambda hook. It remains an unexecuted use of the inspected native form.

The user changes instances.test.type only. Projection reads Production.instances
and emits t3.small; parent preview continues to describe t2.micro. AMI, state,
network links, key derivation, route names and output names retain their maintained
values. Whole-Scenario projection intentionally traverses selected occurrences;
no automatic incremental invalidation or end-to-end speed claim follows.

* Contract and coverage limits

Native Contracts cover the selected domain shape, closed fields, CIDR syntax,
external command list, credentials/state and required references. Output names
must point to selected instances. Missing region-to-AMI data fails when selected.
The source Region enum is represented as a string here; the full source enum and
all optional credential modes are not reimplemented. The concrete main.ncl case
uses the supported assume-role mode. CIDR validation is syntactically stricter
than the source's String/Number shape; this is not equivalence for arbitrary inputs.
The reference's per-network region metadata does not create a second provider;
this reproduction likewise does not claim a cross-region topology implementation.

Target Core names, Module dependency/role injection, automatic provenance and
policy admission, direct dotted assignment, asset staging and full Terraform
Schema/backend validation remain pending. An admitted-preview may be published
only after those required gates, not merely after local application admission.
