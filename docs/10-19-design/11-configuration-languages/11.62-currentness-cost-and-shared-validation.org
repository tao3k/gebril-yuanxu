* Measure the three costs separately

The existing Nix start observer still counts actual CLI starts. An optional
completion observer now measures each run-process boundary, including a failed
or interrupted return. It neither changes argv nor wraps execution in a second
process. Each measured phase records:

- total wall time and summed Nix child-process wall time;
- remaining native wall time, which includes Scheme, filesystem waits, GC and
  scheduling delay and must not be labelled CPU time;
- source-check entries, actual file reads, read requests, stat calls and
  pure-query cache hits/misses;
- selected Contract input reads and compilations, with the original assertions.

The native Scheme qualification entry in t/qualification/opentofu/ independently samples host
load approximately once per second and records waited-for child-cohort
user/system CPU through POSIX /usr/bin/time -p at the test boundary.
Nix daemon workers are outside that CPU accounting. Load average alone cannot
distinguish runnable CPU pressure from other waits. Per-process completion rows
and per-phase rows are flushed to local JSONL even when a later assertion or
watchdog fails. Raw traces stay outside version control.

The selected-graph check, prepared publication guards, configuration-role

reader call created its own byte/query cache. Thus nested guards reread the

to 16.35; the baseline is not an idle-host or download-cold benchmark.

* Reuse one pure validation scope, preserve every effect boundary

The repair reuses the existing source-observation cache at three source-only
owners: build-graph currentness, retained-source validation and configuration
source validation. Nested reader checks inherit that cache. They still execute
their guards; file reads still check regular-file status. Independent calls
start with fresh observations. No permanent validity receipt, scheduler or
second dependency graph is introduced.

#+begin_src scheme
;; Source admission: nested guards share only this synchronous validation.
(def (call-with-module-source-read-cache thunk)
  ;; Optional observation counters/timing omitted here; see implementation.
  (if (source-read-cache)
    (thunk)
    (parameterize ((source-read-cache (make-hash-table))) (thunk))))

;; Existing selected build graph: source guards only, no realization here.
(def (current!)
  (call-with-module-source-read-cache
    (lambda ()
      ((.ref selected-value 'admit-current))
      (for-each (lambda (check) (check)) checks))))
#+end_src

This scope must finish before role evaluation, expansion, file writes, Nix
instantiation or realization. In particular, the Ops package operation's final
currentness guard itself is NOT wrapped: it checks inputs, calls the package
guard (which may execute Nix), then
checks inputs again under fresh validation scopes. Each Nix .prepare guard and
each independent currentness still perform their original checks. Source guard
callbacks are source validation, not an arbitrary effect hook.

The focused native regression verifies one actual read through nested guards,
then changes the file between scopes and requires a new read and rejection of
the old snapshot. The integration retains Config mutation, indirect Nix input
mutation, tampered demand, script mutation during realization, immutable lock,
final .admit failure and parent cached Contract isolation controls. Neither the
60-second Case watchdog nor the 120-second outer test limit is increased.

* Operational ownership

Ops is a built-in Core library published by =:yuanxu/ops/interface=. Neither
Core nor the product root selects it in =init.ss=. Its functional APIs and
Script prototypes are the same inert native values; only an explicit =run= or
=.run= starts a process. Native package compilation owns its library sources.
[[file:../../../ops/README.org][The Ops library design]] records configuration,
Contract and runtime boundaries.

The implementation remains at core/ops. Project-specific test commands and
measurement coordination remain in Core/t/qualification/opentofu. Importing the catalog,
loading the Module, constructing a script or resolving .run starts no operational
process. Explicit invocation delegates to the named run-script function and
Gerbil run-process. Native std/test remains assertion authority. No second
Loader, script DSL, build entry or compatibility publication is maintained.
