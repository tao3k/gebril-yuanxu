* Identity and one public entry

The current native package names are =yuanxu= and =agentic-ai-lab=. The independently
named =:tao3k/yuanxu/prelude= supplies language syntax; it does not rename either
package. Repository URLs, installation directories and mount names are not
package identities.

=yuanxu!= obtains its enclosing native module Context through
=core-context-top= and =expander-context-id=. For =yuanxu/init= it exports
=yuanxu.init.exports=; for =agentic-ai-lab/init= it exports
=agentic-ai-lab.init.exports=. The same declaration can appear in any Scheme module:
=agentic-ai-lab/selection= exports =agentic-ai-lab.selection.exports=. The final native
module separator becomes a dot; preceding namespace components remain intact.
=init.ss= is a conventional entry file, not a required suffix. A REPL-only
declaration without an enclosing module still has no source-qualified export
identity. Explicit Profile forms retain their existing binding syntax.

The existing export object, private namespace getter and selected graph remain
the sole producers. The migration removes public =init.exports=,
=init.Modules=, =init.Scenarios=, =init.modules= and the unqualified intent
binding. There is no compatibility facade, new resolver or cache protocol.

* Ordinary imports and native paths

#+begin_src scheme
(import :yuanxu/init :agentic-ai-lab/init)
(.get yuanxu.init.exports Modules ops scope)
(.get agentic-ai-lab.init.exports Core json-schema scope)
#+end_src

The filename does not grant module-loading authority. For example, the same
directory declaration in =agentic-ai-lab/selection.ss= is valid:

#+begin_src scheme
;; selection.ss, inside the agentic-ai-lab package
(import :yuanxu/module-system/selection/init-syntax)
(yuanxu! :load-modules "./modules" mode: explicit rename: Services
  (checks))

;; A consumer imports the owning module, without prefix-in.
(import :agentic-ai-lab/selection)
(.get agentic-ai-lab.selection.exports Services checks scope)
#+end_src

These are separate source-file examples. Loading remains demand-driven; changing
the declaration filename does not bypass selection, publication or currentness.

The mount names above are owned by the corresponding init declarations.
=rename:= changes a window slot, not the native package identity. A dotted
binding is one Scheme identifier, not an implicit series of slot reads:

#+begin_src scheme
(.ref (.ref (.ref yuanxu.init.exports 'Modules) 'ops) 'scope)
#+end_src

No repeated =prefix-in= is necessary. Native =only-in= and =rename-in= remain
available when a consumer intentionally restricts or renames an import.

* Hygienic expansion and laziness

The following is the expansion shape for the existing Core Modules window;
private identifiers are fresh in the actual macro:

#+begin_src scheme
(defvalues (private-base private-modules)
  (yuanxu-init-build init-source init-declaration))
(def private-value
  (.+ private-base (.o Modules: (.ref (private-modules) 'Modules))))
(defsyntax yuanxu.init.exports
  (identifier-rules ()
    (id (identifier? #'id) private-value)))
(export yuanxu.init.exports)
#+end_src

The identifier transformer is read-only and captures the private value rather
than a caller's same-spelled local. It does not create another object on read.
Obtaining the aggregate does not force a mount, business scope, test graph,
compiler or process. Explicit slot demand and existing operation boundaries
retain source currentness and effect ownership.

* Build and test consumers

Package build.ss files import their own qualified entry and pass its
=std-make-spec= to =defbuild-script=. The guarded dispatch remains internal;
=admit-current= is an explicit inspection boundary, not another build runner.
No new Builder or signing boundary is introduced.

The shared test launcher reads the selected init's native identity with
=core-read-module/sexp= and computes the same export name. It imports that exact
binding; it never assumes every launched package is Yuanxu. Generated-package
test fixtures use native import/rename solely inside their test Contexts.

* Validation and remaining boundaries

The focused gates are =t/module-init-import-test.ss= (cross-package names,
prelude independence, hygiene, removed exports and laziness),
=t/module-windows-test.ss= (same selected graph across mounted build/test
consumers), and =t/module-test-preparation-test.ss= (std/make compilation,
issuance, Harness execution, hot reuse and source-change refusal).

Results must name the actual runtime and completed markers. A passing source
import does not establish complete product CI, AOT relocation, or completion of
the separate Nix C API integration.

** Installed entry and source fallback

The native Core specification now includes =init=, so an ordinary installation
publishes =yuanxu/init.ssi= as well as its existing implementation modules.
The product's public build roots already include =init.ss=. The incremental
Core build after adding this entry completed 234 selected targets in 105.864
seconds, exit 0, compiling three changed source roots. This is a build receipt,
not a latency improvement claim.

The shared test launcher does not register the entire Core source tree ahead
of installed libraries. That temporary missing-install workaround caused native
support discovery to classify already installed Core dependencies as local
sources. The maintained build.ss remains the owner of source-only bootstrap;
explicit source-only qualification still calls its existing registration helper.
Tests use the coherent installed cohort and ordinary configured fallback order.

Qualified names distinguish binding ownership; they do not authenticate a
repository or replace publication admission, origin checks or currentness.
The prelude must not import init implicitly: language bootstrap and a selected
configuration epoch retain independent lifetimes.
