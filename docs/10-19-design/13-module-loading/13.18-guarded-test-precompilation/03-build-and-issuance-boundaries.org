** Runtime upstream baseline, checked 2026-10-22

The design baseline is gerbil-poo PR #13 at
=096da65e0dfb57df397ee16c78f71643847ec46b=. Core previously pinned
=c4b647ef66b735360346c0eb0e27c2cc5430cf72=. After the focused qualification
recorded below passed, Core's =gerbil.pkg= was advanced to the tested revision.
The Core adapter retains file-domain checks. The following
fixed-revision sources define the ownership boundary:

- [[https://github.com/tao3k/gerbil-poo/blob/096da65e0dfb57df397ee16c78f71643847ec46b/object.ss][object.ss]] owns receiver-local reads, runtime issuance, replay protection and
  revision checks. Use public =replay-slot-reads!= / =reobserve-slot-reads!=;
  =call-with-issued-reads= and the record producer are private. Core must not
  synthesize records, copy their authority or implement another read registry.
- [[https://github.com/tao3k/gerbil-poo/blob/096da65e0dfb57df397ee16c78f71643847ec46b/object-state.ss][object-state.ss]] owns weak dependent edges and transitive invalidation.
  Parent/child cache separation is a runtime receiver property, not a Core
  product-label convention. Its mutation protocol assumes serialized use.
- [[https://github.com/tao3k/gerbil-poo/blob/096da65e0dfb57df397ee16c78f71643847ec46b/construction-cache.ss][construction-cache.ss]] owns source-bound selective materialization. Refresh
  of the same immutable source reuses its lookup; changed code/base identity or
  dirty declared dependencies rebuilds the affected cone. Do not add a Core
  freshness cache. This is not a substitute for runtime Make's file checks.
- [[https://github.com/tao3k/gerbil-poo/blob/096da65e0dfb57df397ee16c78f71643847ec46b/component-publication.ss][component-publication.ss]] owns independent publication heads and staged
  requests bound to their exact owner/expected head. Endpoints sharing mutable
  approval policy use the same =approval-domain=. Its =submit!= refuses stale
  installation; callback effects are not rolled back by that protocol.
- [[https://github.com/tao3k/gerbil-poo/blob/096da65e0dfb57df397ee16c78f71643847ec46b/staged-publication.ss][staged-publication.ss]] supplies runtime construction/refresh, contract and
  generic-family staging. [[https://github.com/tao3k/gerbil-poo/blob/096da65e0dfb57df397ee16c78f71643847ec46b/object-contract.ss][ObjectContract]] owns value shape and obligations;
  source-dependent admission and effect authorization remain consumers.

Thus production and tests are independent runtime publication receivers over
the same init selection, not two new Core isolation engines. Adopt runtime
construction/publication where their declared graph and immutable-source
preconditions hold. The existing source projector must first establish that
correspondence; passing a Core selected graph directly to =publication= is not
valid, because that constructor requires an approved runtime =graph-cache=.
No extra Builder is introduced, including a Core wrapper around the upstream
construction module's internal Builder protocol.

Core still owns compilation effects, output directories/digests, source-file
currentness, staging cleanup, process handoff and Harness receipts. Runtime read
issuance authenticates object observations; it does not authenticate compiler
files. Runtime publication coordinates installation; it does not make a file
rename and external execution atomic. Those domain adapters remain necessary.

* One graph, demanded sources, separate product authority

For demanded compiled support, the test projection retains the exact
selected-graph identity. An explicit support-free file demand does not select
business Modules: its init declaration and source inputs are still checked,
but no domain admission is inferred from running that file. The runtime lazy
=selected-graph= slot acquires the original selection guard if demanded.
The projection must not
obtain =production-build.entries= and filter it afterwards: doing so would
already prepare unrelated sources. Extend the existing source-spec producer
with a =demand:= argument referring to the admitted test source. In that mode
it uses the observed runtime import closure of those files, their owning package
metadata and their required support sources. It does not create another graph.

The producer must retain the following relationships:

- The test file list, directory-query observations and source guards belong to
  the same init generation and final demand receiver.
- The runtime support targets and their compiler identities/options come from
  actual imports. Test files remain Harness inputs; they are not compiled as
  support merely because they were requested.
- Input coverage includes the requested files, runtime compiler/macro/prelude
  dependencies and demanded role/assets observations. A new helper dependency
  must be discovered from current source, not hidden by an old helper SSI.
- The guarded build projection composes the original test-source guard with
  its own observed inputs. It must not call back through the executable test
  facade's artifact guard and recursively require its own unfinished issuance.
- Foreign-package tests retain their own publisher and package identity. Core
  does not assign its prefix to arbitrary explicit file paths.

** A collision in today's issuance index

Today =artifacts.ss= indexes =issued= by the build-graph receiver alone. That
cannot distinguish production and tests sharing the same graph. Reusing it
unchanged would overwrite or invalidate the wrong publication.

The previously proposed nested graph/product-cell index is withdrawn as the
isolation architecture. Use the independent runtime publication receivers and
expected-head binding described above. The term /product/ below denotes that
receiver's admitted compilation projection, not another Core identity token.
The existing artifact issuer associates file completion with that exact
projection/publication generation. It must not reconstruct runtime ownership,
revision counters, read issuance or dependency invalidation in another table.

The adapter binds the demanded projection, source epoch, compiler
identities/options, observed inputs, toolchain and output domain to the runtime
publication. A public =tests= symbol or caller-supplied pathname is insufficient.
Repeated demands reuse runtime source-bound construction only under its checked
identity/dependency conditions, then revalidate the external file observations.
No separate approval registry or signature format is introduced.

Consequently =admit-build-artifacts!=, invalidation, clean, restoration and
handoff must address the admitted projection/publication, rather than just
the graph. The projection-based calls below are TARGET signatures. Production
and test outputs remain independent; incompatible writers to the same target
path must be refused, not resolved by last-writer precedence. Overlapping
support may be reused only with matching retained provenance and inputs.

For required compiled support, absence of positive issuance is =build-required=.
Today's source-only fallback when a graph has no issuance must not silently
accept that case. No-support tests remain legitimate source-only executions;
the producer must derive that fact from an empty support specification, not
from a user-controlled trust flag.

* Implemented publication and execution

=yuanxu!= now exports one =yuanxu.init.exports= POO value. The existing namespace
bindings remain lazy identifiers. The old flat build/test function exports are
migrated directly, including the runtime build scripts and consumer tests.

#+begin_src scheme
(import :clan/poo/object (only-in "./init.ss" yuanxu.init.exports))
(def tests (.get yuanxu.init.exports Modules example tests))
;; Optional inspection; no compiler process or business scope runs here.
(def runtime-support ((.get tests std-make-spec)))
;; Explicit execution: prepare support, issue completion, invoke runtime Harness.
(.call tests .run)
#+end_src

Here the declaration uses =rename: Modules=. A =rename: Scenarios= window
instead publishes =yuanxu.init.exports.Scenarios=; an unrenamed window uses =modules=.
These are lazy projections of the existing namespace, not additional module
instances. The existing =init.Modules= identifier and =yuanxu.init.exports.Modules=
return the same object. Reserved build/test export names cannot be mount names.
The aggregate =yuanxu.init.exports.tests= is a selection facade over the same execution
factory. Root-owned =t/= qualifications use its =.for-files= selector; they do
not need a second Script, compiler or Harness implementation.

The production build entry consumes =(.get yuanxu.init.exports std-make-spec)=
through =defbuild-script=. Its =std-make-spec= takes the retained
production roots; the test facade's =std-make-spec= takes no roots and follows
only that facade's demanded test imports. Both refer to the same selected graph.

The implementation is maintained in:

- [[file:../../../../module-system/building/interface.ss][building/interface.ss]]: lazy =source= / =build= / =execution= slots with
  runtime =(:: tests)= receiver binding and the PR's automatic declared-slot
  lexical binding. Do not repeat the slot inventory in the header. Factory
  inputs use =source-value= / =build-accessor= so the declared =source= / =build=
  slots cannot shadow them and create a self-reference. The execution
  Script receives a deferred accessor, not an eagerly demanded compiler graph.
  Its runtime factory retains that accessor in the inherited =.run= closure;
  removing or replacing =Script.build= refuses instead of falling back to source-only execution.
- [[file:../../../../module-system/building/build-projection.ss][building/build-projection.ss]]: =demand:= projects the actual runtime
  import/prelude graph with the existing identity-based =for-each-build-module=.
  Requested test files remain Harness inputs. Shared support is visited once;
  no production =entries= traversal or sibling catalog scan is performed.
  Runtime package/header observations retain external selected owners' compiler
  identities. Current source is imported in a private expander context, so a
  prior support SSI cannot hide a newly added helper import. Explicitly imported
  prebuilt SSI dependencies remain prebuilt inputs: their source is not invented
  or required to reappear, and they retain the existing trusted dependency baseline.
- [[file:../../../../module-system/building/artifacts.ss][building/artifacts.ss]]: each exact issuer receiver owns an upstream
  =component-publication= head and immutable completion cell. Runtime
  =stage=/=submit!= handles expected-head installation; a callback's result is
  also bound to the head that started it. Core's existing weak issuer index
  retains those runtime owners, not another revision or lock implementation.
  Production and test endpoints cannot consume each other's completion.
- [[file:../../../../observability/testing-script.ss][observability/testing-script.ss]]: preparation runs inside the existing
  source Fixture. It does not import artifact/publication machinery for
  standalone source-only Scripts; the demanded producer supplies its existing
  staging-directory parameter through =compile-output=. The existing Ops
  watchdog bounds discovery/preparation at
  120 seconds; the compiler uses the same pre-import heap flags and runtime
  =std/make=. An already frozen package/PATH pair launches =gxi= directly;
  missing initialization still delegates to the Gerbil's =gerbil env=. std/make
  import and execution are separate =-e= forms. There is no separate Builder or generated worker source file.

The compiler receives runtime Make data, =srcdir:= and the issuer-owned staging
=libdir:=. std/make alone schedules dependencies and decides whether current
outputs need recompilation. A successful exit is insufficient: the existing
issuer checks selected dynamic/static outputs, source bytes and package
metadata before installing completion. A nonempty support spec requires
positive issuance before the output directory enters Harness =GERBIL_LOADPATH=.
Support-free tests remain valid source-only executions.

The test output directory is receiver-local and separate from production.
The same receiver reuses its issued directory on a warm run; each Harness run
still executes and admits a new result. Another demand/child receiver does not
inherit that authority or mutable output path. A source change requires a fresh
init epoch; it is not silently incorporated under a cached approval.

* Failure and currentness boundaries

1. Source acquisition checks the original guarded test demand.
2. Runtime expansion captures actual helper/package/compiler inputs without
   running the test or business scope.
3. =.compile= checks currentness before its callback and after runtime Make.
   Failed compilation leaves the endpoint =build-required=.
4. Positive artifact/source admission precedes Harness launch.
5. Fixture release rechecks issued artifacts after successful preparation and
   always rechecks the source, including on preparation or Harness failure.
   Existing Fixture error pairing retains the original and release errors.

The existing artifact handoff now uses the SAME =copy-process-output= pump
as Ops (maintained in =ops/progress.ss=). Its stdin packet still comes from the
retained parent issuer. Child stderr joins the diagnostic transcript and real
progress rows are parsed immediately, in order, rather than withheld by
=read-all-as-string=. Only actual increasing child progress updates the existing
watchdog; no polling heartbeat or synthetic success is introduced. The complete
transcript and nonzero status remain failure diagnostics, and publication
currentness still runs independently after the child effect.

The existing 2 GiB heap fence, 60-second idle and 600-second overall test
limits remain unchanged. Preparation does not reset the outer test budget.
No hot passing-verdict cache, cross-effect source-check cache, filesystem
transaction or trusted cross-process disk-receipt adoption is introduced.
Installed compiler/runtime and immutable runtime callback discipline remain
qualification premises. Hostile external writes between final checks and
execution require a stronger external boundary than this work provides.

* Focused upstream qualification, 2026-10-22

The executable consumer control is =t/test-publication-upstream-test.ss=.
It uses the PR's actual =publication= / =stage= / =submit!=,
=component-group-builder= and construction-cache accessors. It introduces no
Builder subtype, read registry, ownership token or alternative publication
protocol. One approved runtime graph initializes two independent publication
heads in the same runtime approval domain:

#+begin_src scheme
(def domain (publication.approval-domain))
(def production (publication.publication selected domain: domain))
(def tests (publication.publication selected domain: domain))
(def request
  (publication.stage tests (port-edit 5433) construct (lambda (_ __) #t)))
;; Wrong endpoint refuses; it cannot advance production's head.
(defvalues (held wrong-owner) (publication.submit! production request))
(defvalues (next failure) (publication.submit! tests request))
;; Reusing the same endpoint with no edits retains its computed group identity.
(def warm-request (publication.stage tests '() construct (lambda (_ __) #t)))
(defvalues (warm warm-failure) (publication.submit! tests warm-request))
#+end_src

* Final handoff receipt

The optimized owner cohort passed =t/build-artifact-publication-test.ss= through
=just test-file=. The original installed-compiler control still runs its raw
build, corrupted unissued output, guarded fresh build and saved-publication
checks. Independent workers report =HANDOFF-WARM-OK=,
=HANDOFF-JOINT-REFUSED= and =HANDOFF-MISMATCH-REFUSED=. The worker-returned source
change control reports =HANDOFF-CHILD-RETURNED= and is refused by the parent's
independent post-effect admission. Parent plan isolation, both independently

assertions; no control was removed to obtain the receipt.

The worker recipe preserves its 120-second limit and pre-import heap fence.
With an existing package environment it uses installed =gxi= directly; only
missing initialization invokes =gerbil env=. Real output is forwarded while
also retained as the transcript. Ops rethrows the same cancellation/reader
exception after emitting any partial in-memory transcript, so failure evidence
is not lost and existing Fixture cause identity is preserved.

Core's Ops cancellation control keeps the same one-second cancellation policy
and ten-second process timeout. It starts that one-second window on the real
child's =READY= row after the PID has been written, rather than conflating
interpreter startup latency with descendant cleanup. It still requires the
owned descendant to disappear. The Core-default timeout assertion replaces an
obsolete assertion against the removed Nix qualification object's
=SelectedFlake=; no Nix fixture is reintroduced into Core.

The early idle failures, invalid intermediate package fixtures and broad
qualification timeout remain local failed receipts. These focused passes do
not establish a full clean Core build, remote CI completion, hostile-filesystem
atomicity, or a cold/warm speedup under the observed host load.
