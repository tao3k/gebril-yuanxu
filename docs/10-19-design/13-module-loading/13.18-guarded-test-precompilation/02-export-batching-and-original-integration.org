* .for-export boundaries and closed requirement batching

The next attribution follows the actual calls, rather than classifying the
whole Fixture as preparation. The existing observer now keeps bounded scalar
effect/read and effect/check-time rows in ordinary observation mode; deep
receiver/retention tracing remains separately lazy. =export-entry= and
=publication-base= label existing calls without granting reuse authority.

| Boundary | Actual operation | Why the boundary remains |
|----------+------------------+--------------------------|
| export-entry | =admit-build-artifact-publication!=, including the demanded build Graph | Before export scopes may execute author code; artifact recovery is an effect |
| selected-record | =selection .selected-record=, runtime linking, dependency/scope Contracts | Scope factories and validators are open calls |
| publication-base | =module-admission-publication=, descriptor/value paths | Recheck after scope resolution; lazy export getters can run code |
| bind-contributions | route index, guarded =collect=, Context assembly and final =current!= | Before/after exported payload getters, complete provenance and return certification |
| contract-admit | direct or published Contract invocation | Fresh root admission, including contextual child obligations |
| entry-current / meaning-current | publication entry / dependent return meaning | Independent calls and post-effect return checks cannot inherit earlier bytes |

An instrumented intermediate snapshot attributed 16,830 reads to export entry,
3,894 to selected records, and 2,596 to publication-base over eleven fresh
Fixtures. Thus the warm Just process still constructs eleven independent
source-backed selections: it is not eleven accesses to one warm receiver.
Read windows include metadata traversal, file queries and comparisons, not
just disk I/O. Nested operation times are not additive to parent spans.

An attempted schema-free Context deferral removed 649 reads, but was withdrawn.
=compiler-current= is replaceable and is not implied merely by checking an
equal list of source files at return. The existing Lean
=ReturnWindows.defer_covered_check= theorem covers actual byte requirements,
not arbitrary Scheme policy procedures. The expanded existing admission
regression now covers Schema/no-Schema paths and custom compiler/request
refusals; it must preserve their execution before cold handlers and at return.
All original Context/compiler guards remain in the production implementation.

The retained production change is narrower: when collectors are active,
=module-source-admit-current!= uses the existing pure window's runtime identity
tables to avoid traversing the same requirement-list object twice for the same
active collectors. Metadata-only checks without collectors keep their existing
per-source index, rather than allocate an ineffective batch index. It shares
neither a Context, a Contract verdict nor an issued read record. The table is
owned by the existing dynamic window and disappears at its end. Equal but
distinct list objects are not merged; nested collectors use different keys;
only a successfully checked batch is indexed. The collector's original first
diagnostic remains authoritative.

This applies only when no source observer is installed. Open observers retain
the original checks/callback order; no observer is disabled or suppressed.
The closed action reads filesystem inputs and the fixed private collectors,
without calling domain methods. It relies on the existing documented window
condition: bytes and input requirements remain stable, and callers end the
window before writes or callbacks. It does not extend a window over a getter,
obligation, package process or independent admission. An implementation using
structural query keys was rejected because it rehashed source text; the final
index uses runtime identity, as the existing expected-text index already does.

The existing six-Case source-observation suite now exercises this closed path
under the runtime default Case/resource Profile, without installing or removing
a source observer. Its private operation counters prove two independent
windows read twice, a repeated batch avoids another enumeration, and a nested
collector still enrolls its requirements. Conflicting expectations reject;
editing the file makes both enclosing and nested collectors refuse with their
own first diagnostic. The remaining Cases continue to exercise open observers,
parent caching, nested obligations, source mutation and unselected branches.
These are executable Scheme controls; no new Lean or QNT theorem was added.

This distinction also limits the performance claim: the collector optimization
does not remove the cold selected-Graph/role work in eleven fresh Fixtures.
Neither the rejected 649-read deferral nor its intermediate timing is a landed
improvement. Custom =compiler-current= refusal is tested independently of
request refusal and source-file equality, including the no-Schema path. Those
policies and both sides of open callbacks remain executable requirements.

The producer now participates in that data flow: =source-object-slots= creates
one private input batch per file *within one fresh object construction*, and
each located specification retains that batch. Previously it reboxed the same
input row separately for every field. Specifications, locations and procedures
remain distinct; parent/child constructions do not share a mutable snapshot
registry. The existing Gerbil-expansion regression verifies distinct port/client
specifications, one physical read, and no repeated per-source comparison when
their actual macro-produced batches are enrolled together. This qualifies the
producer/consumer association, rather than only a synthetic shared-list fixture.

** Cold Graph algorithm and Gerbil loading ownership

The next source-attribution pass keeps the existing observation mode and adds
bounded scalar =(phase, guard-origin)= counters only while =build-graph= is the
innermost admission bracket. It does not record source contents, cache a
verdict, install a new loader or change a check window. The actual Scenario
again completed eleven Cases and all completion markers (65.46 s wall,
39.36 user, 6.76 system).

=publication-current=. The largest return/caller labels are:

| eligibility | 1,911 |

These sum to 14,267, not the complete 16,830. They identify guard invocation
sites, not ten interchangeable approvals. In particular, declaration expansion,
the authoring-policy validator and scope factories are open boundaries. A
single large byte-read window around all of Graph construction is invalid.

The graph under investigation is =link-module-context='s selected build Graph:
=select-module-graph= resolves Module/Feature dependencies, then
=module-build-graph= projects source/build inputs and their guards. It is not
the business execution graph. The underlying =module-closure= already marks
each module key before traversing its imports using a visited table. The
selected-publication index also reuses each publication within the candidate.
There is no evidence here that replacing DFS with another traversal algorithm
alone removes the 14,267 reader-guard reads. Separate list scans and per-role
input lookups still require a complexity audit, but must not be presented as
the measured source-I/O cause without a matching receipt.

The installed Gerbil source was inspected, without changing it:

- =gerbil/runtime/loader.ss=, =load-module=: process-local runtime lookup,
  loading/error states, mutex/condition-variable coordination and reuse of an
  already loaded module. In this installed version reload is a separate
  =reload-module!= procedure; do not infer its signature from another release.
- =gerbil/expander/module.ss=, =import-module= / =core-eval-module=: runtime
  expansion contexts and memoized module evaluation. Import also supplies
  lexical and macro-phase bindings; =load-module= alone does not.
- =gerbil/runtime/init.ss=, =__eval-import=: runtime per-context import state
  and evaluation coordination. Yuanxu must not implement another runtime
  ready/loading registry.

The source version is the installed
=0.19.20261009110849.1cfb032.patch618d76f9eb72= Gerbil. Current Yuanxu
=reader.ss= already delegates imports to the captured runtime importer and
evaluation to =eval-syntax= / =eval-module=. The remaining cost is not evidence
that Yuanxu wrote the whole runtime loader again. Its outer layer does create
fresh private wrapper filenames/packages, expansion contexts and guarded
dependency projections. Runtime caching is scoped to those actual identities;
replacing one call with =load-module= cannot merge distinct wrappers safely.

The ownership target is therefore:

| Responsibility | Existing owner to retain |
|----------------+--------------------------|
| Lexical/macro imports and expansion identity | Gerbil expander |
| Compilation and incremental outputs | public =std/make= |
| Compiled runtime loading and loaded-state coordination | Gerbil loader |
| Selected Module/Feature requirements and role injection | Yuanxu selection and hygienic role lowering |
| Derived configuration values and receiver-local structural reuse | POO |
| Source association, independent policy calls and final currentness | existing Core publication/admission protocol |

Before changing the reader, compare its interpreted and compiled role paths.
Today =preparation.ss= emits deferred role bindings in
=deferred-reader-forms=, but =compiler-forms= still imports its role list.
Eagerly loading that compiled interface could initialize roles which the
source reader leaves cold. This asymmetry is a concrete prerequisite for a
runtime compiled-consumption refactor, rather than permission to load all roles
or silently bypass the authoring/currentness checks. =load-module= loads and
initializes code; it is not an inert metadata discovery API.

No loading semantic was changed in this attribution pass. Reusing official
loading requires preserving actual artifact/module identity, hygienic bindings,
role demand and source generation. An already-loaded flag cannot establish
currentness, completeness of two contributions or applicability of a cached
parent plan to a final child. No cache protocol or larger timeout was added.

The remaining cold Graph work was traced through =.for-export=, selected-Graph

One smaller duplication is inside a prepared source's local byte/package guard:
the positive package entry explicitly probes regular-file status, then its byte
reader probes the same status again. The guard now uses the existing bounded
source-read window for that local segment only:

#+begin_src scheme
(def (current!)
  (context-current!)
  (call-with-module-source-read-cache
    (lambda ()
      (unless (equal? text (module-source-read source-path))
        (error "stale prepared build source" source-path 'source-bytes-changed))
      (unless (package-snapshot-current? packages)
        (error "stale prepared build source" source-path 'package-metadata-changed))))
  (context-current!))
#+end_src

Both owning Context calls retain their order and remain outside this newly
bounded segment. No window is extended over their callbacks. An independent
guard opens a fresh window unless it is already inside the caller's existing
pure check. No result survives that window, and no guard is removed.

Changing source bytes in the owning callback refuses before the second Context

not evidence that the large cold Graph source-read count has been solved.
