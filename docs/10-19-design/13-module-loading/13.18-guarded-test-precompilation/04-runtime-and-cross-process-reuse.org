* Default single-file execution and measured Scenario reuse, 2026-10-22

** Corrected connection and mount ownership

The default Core =just test-file PATH trace= now imports the current root
=init.ss=, selects =(.call (.get yuanxu.init.exports tests) .for-files (list PATH))=,
and refines that demand's existing execution object for the requested policy.
It no longer constructs a separate source-only =TestingScript.=. This file
selector accommodates Core-owned qualifications outside module =tests/=
folders; module-local runnable tests remain published by their module view.
Both routes use the same execution factory, runtime Make projection, =.compile=
issuer and Harness. There is no additional Builder or test assertion engine.

The namespace slots on =yuanxu.init.exports= are generated from the declaration's
actual =rename:= values. No unconditional =modules= container is inserted for
renamed windows. The window regression checks object identity between the
new projection and the existing hygienic identifier, rather than comparing
independently reconstructed equivalent namespaces.

** Where the hot time remains

The cached import projection is no longer the substantial hot cost. Runtime
Make still starts once and performs its incremental decision even when it
compiles zero units. Compile/issuance costs outside the Make process are about
1.26 s in this hot observation; these include source/artifact checks, not a
second runtime compile.

The cold Harness recorded 20.410 s across eleven Case spans, including 18.960 s
to acquire their fixtures. The hot Harness recorded 21.277 s across those same
spans, including 19.804 s in acquisition. Each control deliberately obtains its
own mutable source tree, reader/link context and Scenario. A passing verdict or
mutable Fixture must not be shared to remove that work. Reuse of immutable
preparation metadata is a candidate for subsequent measurement and proof;
source currentness around effects and before return remains independent.

Observation is opt-in through the existing test policy. Projection time,
retained support count, runtime Make time and compilation count are emitted by
the existing preparation owner. They do not add a process wrapper, compiler
scheduler, synthetic progress or a new source-freshness cache. Existing 2 GiB
heap fencing, 60 s idle / 600 s overall limits and the 120 s compilation boundary
remain unchanged. Raw transcripts remain local under
=/private/tmp/yuanxu-test-chain-20261022/=, outside source control.

** Authority and storage

The normal Gerbil package installation is already a trusted source of imported
compiled code. Test completion handoffs are retained under
=$GERBIL_PATH/lib/.yuanxu-test-publications/= in that same trust domain. Test
products remain separate, under =$GERBIL_PATH/test-lib/=. A product directory,
its writable issuance sidecar, or a candidate-supplied pathname cannot choose
the approval root or expected hashes.

This deliberately names the trust root: package installation and installed
compiler code must remain trusted. It is not cryptographic protection against
a compromised account or replacement of the trusted installation itself. A
readable receipt in an arbitrary product directory is still not an issuer.
Core does not acquire a Nix dependency to obtain this local development reuse.

The existing runtime publication remains the in-process authority. Recovery
first matches the selected compiler identities, source observations and output
directory; it then rebinds the process-local generation and submits through the
same runtime publication owner. Its checks include the approved packet source,
original issuance-record digest, product digests and source currentness before
return. Replacing a product and its local record together cannot replace the
separate package-owned approval.

** Demand identity and diagnostic order

The test artifact location is derived from the test domain, installed Gerbil
version/home, runtime Make specification, compiler-affecting environment,
compiler identities and exact selected source observations. No unselected
module catalog or dependency directory is scanned. Changing selected source
bytes or the bound compiler context selects a different product; an existing
source snapshot also refuses changed bytes independently.

Input observations are canonicalized only for location/matching. Matching
retains every path/value pair; inconsistent duplicates do not become valid.
The actual checks keep the requesting projection's observation order, including
its first diagnostic. Restored issuance retains that current projection order.
This fixes a real control failure where equivalent input sets collected in a
different order received different artifact directories.

** Explicit compilation and recovery

#+begin_src scheme
;; Published by the test projection, never by its production sibling:
build-publication: (test-build-publication projection)

;; Same existing runtime effect boundary:
.compile:
(lambda (libdir action)
  (call-with-build-artifact-issuance projection libdir action))
#+end_src

Before compiling, the existing boundary attempts recovery from the selected
publication when no receiver-local issuance exists. Missing approval takes the
normal fresh-output compilation path. Existing but invalid approval/products
refuse; they are not silently adopted or repaired into authority. Runtime
=std/make= still runs on a successful warm call and makes the incremental
compilation decision. Harness execution and domain admission run again.

A normal Gerbil =std/os/flock= lock serializes recovery, Make and retained
completion for the selected test product. Its timeout stays within the existing
120 s preparation boundary. Runtime publication still owns receiver-local
stage/submit semantics; the file lock does not pretend to make external file
changes or Harness effects atomic. A partially written approval fails closed.

The approved observation and decoded packet are private to the Source's closure,
not mutable public expectation slots. Ordinary inspection exposes only its
artifact/reference paths. Warm completion leaves the existing approved handoff
unchanged. Currentness checks do not carry approval across effects or cache a
passing test verdict.
