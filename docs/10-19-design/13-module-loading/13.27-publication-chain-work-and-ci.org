* One Graph per export assembly

=AdmissionPublication..for-export= previously read =selection.build-graph= at
entry, again while constructing the publication and again for package guards.
These are POO reads, not plain pointer lookups: a cached read retains
and replays the original construction dependency graph.

The assembler now binds the Graph once and uses that same object throughout.
It captures receiver/ancestor revisions with the existing
=module-source-object-policy= and checks them before returning. Replacing the
selection and restoring its old value cannot authorize the assembly. No read
record is forged, merged with another identity or removed from the one original
Graph read. Independent calls still read their own effective selection.

The existing admission suite checks one observed Graph read and separately
injects replace-and-restore during =.selected-record=. Artifact entry admission,
Schema resolution, contribution collection and the binder's final source check
remain in their original order. The real service suite keeps its ordinary
execution path; the slot-observer counter belongs to the isolated assembly
control, not to its performance benchmark.

* Input projection instead of source payloads in query keys

The reader already has a call-local pure-source observation window. Previously
every nested reader guard materialized =hash->list= of its tool sources before
looking up the same bounded query. The query arguments contained the source
texts themselves, even on an eventual hit.

The closed path now passes an actual private input-projection procedure and
the collection's cardinality to that same existing query mechanism. The
procedure identity distinguishes reader/candidate collections. Rows are
materialized only on a miss. There is no additional cache table, persistent
approval, source revision registry or public strategy flag.

This compact key is valid only because =record-source-observations!= enforces
the following producer invariant: a new path grows the collection; inserting
an existing path must preserve equal expected bytes or raise. It cannot be
generalized to arbitrary mutable maps. Guard-list growth also remains part of
the query key. Metadata authentication still executes at its original boundary.
The source window ends at the same points as before, including independent
admissions and callback handoffs.

An installed source observer keeps the original eager snapshot and callback
order. The actual reader regression calls its public guard twice in one window
and once independently: two snapshots on the closed path, three with an open
observer. It neither disables observers nor substitutes a handwritten checker.
The existing source-window formal results remain relevant to lifetime/freshness;
this change does not claim a new proof of arbitrary map or callback purity.

** Remaining design constraint

The 4645 computations were NOT replaced by eager constants. In particular,
module/role lookups and compiler forms can cross deferred-source or extension
