* What Haumea actually does

Its implementation separates =aggregate= (structural filesystem metadata) from
=view= (a perspective-dependent attribute tree). File content is represented by
a fixed point and a selected loader. Nix evaluation controls when those content
thunks are forced. Directory shape and name collision checks still require
metadata work; lazy values do not imply zero filesystem traversal.

Names strip up to two leading underscores before classification and strip the
last file extension. Public names are visible externally. A single leading
underscore is collection-internal; a double leading underscore is visible from
the containing directory's perspective. The implementation uses a prefix test
on the caller perspective, so enclosing-directory internal names remain visible
to descendants. The result is a visibility view, not a sandbox or an authority
to execute another Module.

Normalized collisions reject, including a file/directory collision or an
internal/public name collision. Symlinks are not loaded by the regular-file/
directory branches. Yuanxu currently rejects symlinks in admitted source trees;
that stronger source policy must not be weakened to copy a reference convention.

The default loader imports a value, uses function argument names to select
inputs when it is a function, and provides =self=, =super= and =root=. Its default
loader ignores optional argument defaults; its callPackage variant has different
default/override behavior. Those are concrete Nix function semantics, not generic
dependency-injection laws that can be copied onto Scheme bindings.

Haumea's =self= is the current file result, =super= is its containing directory
view, and =root= is the collection view from that file's perspective. Its
=super= is not a POO inheritance predecessor. Its transformers run over directory
views; =liftDefault= is an explicit transformer with disjoint-union collision
checks. Arbitrary transformers need not preserve cold enumeration.

There are two different recursive structures: POO value-slot dependencies and
Module =requires= edges. A productive self-referential object does not legalize
a cyclic Module dependency or a cyclic native compiler import. Keep their
diagnostics and admission boundaries separate.

Injecting the whole source tree as an ambient =root= would bypass explicit
selection/dependency contracts. Existing admitted aliases and explicit functional
parameters provide the intended dependency values. Do not infer imports or
effects from a Scheme function's argument names or rebind lexical scope through
an unreviewed scoped-import mechanism.

* Namespace-view contract

1. Structural indexing and key enumeration may observe source metadata and
   validate naming/currentness policy. They do not run business scope factories,
   external builds or compilation. Metadata enumeration is not universally free.
2. A view can restrict visible paths or mount existing paths. Direct lookup and
   reflection must agree: hiding a name from enumeration alone is insufficient.
   An excluded lookup refuses before requesting its provider.
3. A permitted leaf returns the original admitted POO object. Do not clone it
   with =.cc= merely to build a view, inject a =scope= slot or reconstruct it per
   path. Aliases must preserve receiver identity and original source provenance.
4. View policy cannot enlarge the admitted selection or authorize operational
   effects. Build roots/options/resources remain owner contributions; views
   cannot turn private role files into independent compilation declarations.
5. Naming and leaf/branch conflicts refuse before conflicting scope factories
   run. No implicit =default.ss=, new entrypoint or underscore-renaming rule is
   adopted. Publication identity and native compiler identity remain authoritative.
6. Original input/currentness and Contract checks still guard permitted demand.
   A previously computed view or warm POO slot is not an approval cache.

Closed metadata projections and ordinary POO/functional composition are the
default abstractions. A general user callback for filtering/transforming views
would need explicit phase/effect semantics before adoption; pure behavior cannot
be inferred merely because a callback is stored in a POO slot.

* Refinement: POO is the abstraction, hierarchy is its expression

Do not introduce Tree, Node, Leaf or View wrapper families. A branch is an
ordinary native POO object. Its finite slot specifications express its names;
its slot thunks reference original admitted children. A leaf is the admitted
object itself. Native =.o= composition expresses fixed projections and aliases;
=object<-fun= expresses a metadata-derived set of the same ordinary slots.
Neither expression needs a new accessor or changes Interface configuration.

The current installed gerbil-poo source cohort
=a84e76c1b1a61de2db52e38ba8d1d8c8671ec601= already supplies receiver-local
slot/layout indexes, persistent ordered =prototype-map=, ordinary hash-table
interfaces, Type/ObjectContract descriptors, and =table-indexes= for correlated
collection snapshots. Use each at its owning boundary:

| Boundary | Existing POO capability | Decision |
|----------+-------------------------+----------|
| Public expression | Native object slots, =.o=, =.get= and prototype composition | Branches and aliases use these directly; no leaf wrapper |
| Structural name grouping | Persistent =prototype-map= and private native hash builders | Reuse the existing symbol-keyed index; pass only a branch's declaration suffixes to its children |
| Changing correlated catalog | =table-indexes= and persistent table snapshots | Available when an actual catalog/delta contract is needed; no second catalog is introduced for this immutable generation |
| Namespace admissibility | Existing Type/ObjectContract phase semantics | Check finite names/origin policy without demanding business fields |
| Business leaf admissibility | Existing Module/Scope Contracts and ManagedBinding | Keep complete requirement and source checks on their original boundary |

Contract use must be phase-correct: ObjectContract's required-field validation,
including its shape routine, can read required values. Calling that routine on
every namespace leaf would defeat cold enumeration. The native control instead
uses an empty responsibility set plus a delegated names-only whole-object Type
constraint; leaf Contracts remain at actual demand. A contract does not imply
purity or harmless evaluation merely because it is a POO object.

Visibility is a restriction of bindings available from the admitted source
namespace, not a string convention or a filter over already materialized values.
Aliases may rename exposed paths but must reference an existing permitted source
binding. They cannot recover a hidden target through a new public name. Closed
slot specifications supply both reflection and direct lookup: inheritance of the
entire source object would also inherit its hidden slots and is not a narrowing
projection. Native POO composition still applies normally within the admitted
leaf; namespace visibility and business prototype inheritance are different axes.

The names-only Contract certifies names, not opaque getter provenance. Native
aliases in these controls reference the restricted source object. A caller
holding a broader source capability can explicitly construct a broader object;
that is a new declaration requiring its own publication/admission, not a breach
of a Scheme sandbox. Source-origin eligibility remains an existing Module
System obligation and is not inferred from names or function captures.

Currentness is explicit at its original owner. A namespace is an immutable
generation snapshot; a cached native slot is not live filesystem IO. Pure warm
=.get= can return its existing object identity. Before graph publication, build
or checked execution, the original owner's currentness/admission boundary must
still refuse stale source/generation. This refinement does not add an observer
to every slot read or claim every warm lookup revalidates source bytes.

* Formal allocation before Scheme changes

=Loading/NamespaceProjection.lean= models bindings as a pure path-to-path
function, not a runtime Tree type. Restriction filters the target binding;
reflection enumerates exactly defined bindings within the supplied finite
domain. Demand delegates to the original resolver verbatim. A hidden name
returns refusal with unchanged state without calling that resolver. Aliases to
one source path invoke the same original binding operation; no reconstructed
Scope or secondary memoization state is modeled.

Here =demand= denotes the cold slot thunk's invocation, not interception of
every warm =.get=. The existing native POO memo/CompiledPlan semantics govern
whether that thunk runs again. Alias equality is stated at the same input
state; cross-call receiver stability additionally uses the original source
slot's memo semantics and is checked with native =eq?=. An arbitrary stateful
resolver is not assumed to return one allocation forever.

The branch-index law states that a suffix is in a child's bucket exactly when
the original input contains that child's name followed by that suffix. The native
grouping uses cons followed by reverse to retain occurrence/order; the
membership theorem alone does not establish an ordering guarantee.
It does not prove hashing, filesystem naming admission, native pointer equality
or compiler behavior. ManagedBinding and DemandMaterialization retain those
existing admission/identity premises; Scheme must establish the concrete bridge.

SysML allocates closed-name visibility, unchanged resolver returns and explicit
currentness, plus measured branch-local indexing. The Scheme acceptance is
ordinary POO expressions, Contracts and the existing source namespace. There is
no public visibility grammar or automatic underscore policy in this increment.

* Efficiency questions with concrete owning source

=scope-tree= already groups immutable rows by the next name using the native
ordered prototype map. It does not scan all siblings for every cold lookup.
=directory.ss= snapshots immediate directory metadata, preserves collision and
symlink checks, and constructs deeper namespace nodes on demand. It explicitly
does not recursively enumerate every Module at Context construction.

The pre-refinement =directory.ss:tree= filtered all selected paths for each
demanded branch. The current implementation groups branch-local declaration
suffixes through the existing persistent prototype map. The paired native
measurement below establishes a gain for its explicit wide-branch corpus.
This remains a generation-owned structural index with no additional semantic
graph or approval cache.

Keep distinct workloads separate when evaluating further changes:

- Metadata-only namespace creation, enumeration, cold path demand and repeated
  warm lookup, with fixed path depth/fanout and explicit versus auto selection.
- Real source declaration/admission, including all explicitly selected headers.
  Current tests require the first scope demand to admit the complete explicit
  selection, while only demanded providers' business factories run. Do not claim
  one declaration read per leaf by changing that contract.
- Native compilation of the selected owner/dependency closure. The 13.34 Nix
  receipt establishes ten targets and zero hot compiler events, not a general
  thousand-Module latency result or a speed comparison against Nix evaluation.

Record source reads/stats, declaration/contract work, factory calls, native
compiler events, wall/CPU time and retained/peak memory separately. Use matched
workloads and the unchanged project budgets. An arbitrary transformer that
forces every leaf is a different workload, not a baseline for lazy lookup.

* Real catalog qualification refinement (13.35)

The acceptance protocol distinguishes physical catalog R, explicit declarations
D, demanded semantic scope closure S and native compiler closure C. A catalog
with 1000 directories is not evidence that 1000 declarations were admitted.
Admitting every declaration does not authorize construction of every scope.
A downstream build uses its own explicit selection; hiding namespace names
never changes compiler authority. Owner Build contributions enter C through
that same selected owner, with original native source identities.

=NamespaceProjection.scope_demand_stays_in_admitted_catalog= reuses the existing
=Graph.TestAdmission.Demanded= relation. The finite star fixture establishes
that demand for module-1 reaches only module-1 and module-0 within a closed
thousand-node region. Compiler exactness remains the existing
=SelectedPackages.successful_target_iff= obligation, and product ownership
remains the existing SourceView/downstream environment contract. No parallel
graph engine, loader or cache is introduced. These are model laws; actual
reader, scope factory, compiler and cleanup behavior require native gates.

The original =module-declaration-1000-test.ss= passed in the qualified private
Core runtime with 1000 actual four-role declarations, cold business exports,

Case limit during first-scope demand; the trace was in publication metadata

*** Ten-thousand-owner module-system design

Yuanxu projects authorized Interface names into the existing POO
branch index. An alias stores its canonical owner binding. Scope
identity and lazy evaluation follow that owner through native =.get=.
Bulk directory construction reads name metadata once per projected
directory generation. It does not expand Interface bodies or force
scope slots. The original roster remains available for enumeration
and full catalog certification.

The admission request supplies the roots. An explicitly selected
request explores those roots and their declared dependency closure.
Full catalog certification supplies the full roster and preserves its
existing refusal semantics, including failures in unrelated
declarations. Replacing an existing full certification boundary with
selection requires an explicit contract change.

For one admission, an indexed worklist checks membership once per
popped root or edge. It reads outgoing edges once per reached owner
and retains ordered results for diagnostics. With bounded native
index operations, the traversal work is proportional to the roots
plus reached owners and reached edges. Directory construction and
source authentication are separate costs. A shared provider can be
enqueued several times but is admitted once in this traversal.
Pending work, unknown owners and failed admission cannot certify a
closed selection.

Reusable declaration data belongs to the original owner's existing
POO slot. The binding includes owner, source window, source identity
and policy identity. Reuse checks the original support against the
live view. Disjoint changes outside that support cannot affect the
result for an unchanged key. Gerbil expansion and author callbacks
each retain independent entry and return checks. A hit retains
declaration data and dependency identity, never a freshness verdict.
No separate Yuanxu cache, loader or scope identity is required.

Lean's =discover_indexed_refines= proves that indexed membership
preserves the ordered reference traversal.
=completed_indexed_discovery_exact= characterizes the completed
selection as exactly the reachable dependency closure.
=declaration_slot_hit_exact=, =declaration_reuse_local_to_support=
and =declaration_effect_return_rechecks= cover reuse and invalidation.
The executable scale cases cover 10,000 catalog owners with a

and order rather than Scheme latency or hash collision bounds.

**** Admission and incremental certificate repair

First demand checks the directory and live admission evidence for
every owner in the completed forward closure. Full certification
starts from the complete roster and, for a closed catalog, checks
every owner in it. A failed unrelated declaration can therefore
refuse full certification while a selected demand succeeds.
A partial worklist cannot approve either request. Directory membership
does not grant permission to execute a missing Interface.

For a change in an already certified view, seed the changed canonical
owners and follow the existing POO provider-to-consumer registration
buckets. Walk every reached receiver, even when that receiver itself
has no retained entry in the certificate being repaired. Point-check
certificate membership only on reached receivers. Recheck exactly
that intersection. An ordinary hit checks the requested evidence at
the existing effect boundary without enumerating the full roster.
The resulting work depends on the affected registered receivers and
edges, and on the actual revalidation work for their certificates.

The repair theorem assumes exact reverse buckets for the registered
read relation, prior certification, and equal verification for
unaffected retained owners. Source and policy changes must be
observed and enrolled. A changed dependency declaration seeds its
owner. Use the old registration to invalidate existing consumers,
then admit newly reachable owners forward before publishing a new
certificate with updated dependencies. A catalog membership change
needs separate roster validation. Untracked changes or an incomplete
reverse walk cannot justify repair. Gerbil expansion and author
callbacks keep separate entry and return checks.

Lean proves the two admission boundaries and the equivalence of
local repair with rechecking every retained owner under these
premises. The 10,000-owner repair fixture checks exactly three
owners after one change. Native registration completeness and
runtime costs remain Scheme correspondence obligations.

**** Dependency edit publication

Keep the old registration visible to invalidation until its reverse
walk completes. Affected entries cannot satisfy reads from the old
certificate, even if replacement admission fails. While the reverse
walk is incomplete it cannot certify any old entry as unaffected.
Use a point lookup in the affected membership index to check an old
entry, rather than enumerating the catalog.

Seed one forward worklist with affected retained owners and any new
requested roots. Follow the new dependency declarations. At a clean
retained owner, stop the walk and reuse its evidence. This cut is
sound when the old certificate was dependency-closed, the old reverse
registration covered its reads, and every clean owner retained its
outgoing edges. An owner with changed dependency bytes must be a
change root. With these premises, any new reachable owner not covered
by clean evidence is visited and checked. One visited index deduplicates
the affected repair roots and new dependencies.

Publish only after both worklists complete and the independent entry
and return checks succeed. Publication grants scope access according
to reachability from the public roots in the new graph. Internal
repair roots grant no public scope access. Removing the last path to
a provider removes its authority for that request, even if its own
unaffected evidence remains available for another request. Rejected
new admission publishes no replacement and does not revive affected
evidence. Updating the live POO registration and exposing the new
certificate must share the publication boundary in Scheme.

The executable 10,000-owner fixture uses a three-owner affected
component. Deleting its outgoing edge checks those three owners;
replacing the edge checks the same three and one new provider.
Refusing that provider, or failing the return check, blocks publication.
The fixture also checks that the old affected consumer is unavailable.
These are model checks and do not establish runtime timing.

**** Atomic certificate handoff

A view contains the certificate slots and both directions of its
dependency registration. One publication cell selects the view and its
read restriction. Starting a change advances its ticket and fences old
reads. Sealing walks the old reverse index and keeps the old view,
then restricts it by point lookup in the completed affected index.
An incomplete reverse walk leaves the fence in place.

A reader captures one view, reads from that view, and validates the
same ticket before returning. Entry and return evidence checks are
separate from the ticket check. Across any sequence of serialized
edits, equality of the final ticket implies that the entire captured
state is unchanged. A successful read therefore gets its certificate
and reverse registration from one view. This includes the race in
which a previously clean reader overlaps the final switch.

A writer stages against a captured sealed view. Admission evidence is
indexed by that view and the exact replacement bundle. The forward
worklist uses the replacement's declared dependencies. Its admission
check also requires a certificate entry for each reached owner.
The replacement's reverse registration must be the exact reversal of
its forward edges. The commit consumes this stage as a whole and
checks its ticket against the live cell. It installs the staged
certificate and both directions of registration together.

A new observed change during fencing or admission appends its roots
to the outstanding change roots, advances the ticket and fences
readers again. If the old reverse walk has already sealed, resealing
resumes it with only the added roots. Its affected set is exactly
the union of the two old-index closures. A stale result remains rejected after
resealing and through later transitions. A failed current stage
leaves the union restriction in place. Independent entry and return
evidence checks remain part of approval.

The 10,000-owner fixture stages one edit, receives a second change,
then checks a four-owner reverse walk and a six-owner forward walk.
The latter contains the four affected retained owners and two new
providers. It tests rejected stale and failed stages, unaffected old
reads after failure, and the two new registrations after commit.
This is a proof over serialized cell transitions. Scheme still must
supply atomic installation and issue the evidence for the captured
view and exact replacement, with changes enrolled before affected
reads can return.

**** Retire the old registration at commit

The successful commit replaces the active bundle. The next edit
reads only the replacement registration. A reader may still hold
the old bundle, but its old ticket cannot authorize a return after
commit. Once readers and staged writers release their references,
the old registration may be reclaimed by the native runtime. The
proof establishes loss of active authority, not reclamation timing.

Before commit, a completed reverse walk can resume on the same
immutable old registration. Keep its visited index and enqueue
only the newly observed roots. =resumed_reverse_exact= proves that
a completed resumed walk gives the same affected set as starting
from the combined roots. The 10,000-owner fixture needs two extra
reverse steps after the first two, and the next edit observes that
the removed old provider bucket is empty. The publication transition now uses
the resumed worklist directly. The two-step reseal succeeds where
restarting from both roots with the same budget leaves work pending.
An already visited owner consumes its queue entry without expanding
its bucket again. Resume across a committed registration switch is
outside this contract.

** Ordinary authoring stays short

Start with an actual configuration value and native lexical slots:

#+begin_src scheme
(.def BuildProfile
  executable: "gerbil"
  flags: '("build")
  argv: (cons executable flags))

(.def (DebugProfile @ BuildProfile)
  (flags => append '("--debug")))

(.get DebugProfile argv) ; ("gerbil" "build" "--debug")
#+end_src

=argv= reads the derived profile's flags even if the parent's =argv= was already
forced. The parent cache remains its own. Direct assignment replaces a known
value; =(flags => append ...)= transforms the inherited value; =config: =>.+ ...=
refines an inherited object while retaining its other slots. Use an explicit
per-slot =(sup)= only for conditional inheritance or more complex expressions.
It is a computation, not a promise that repeated calls are separately memoized;
bind its result once if a formula needs to reuse that result. No new accessor,
configuration DSL or general =lambda (self super)= authoring hook is introduced.
The inherited computation follows the remaining native C4 precedence chain for
this slot. It need not be a single directly declared parent and cannot be used
as a reified parent object for arbitrary other-field lookup.

Native keyword shorthand consumes one transform expression. With extra function
arguments, use =(flags => append '("--debug"))=, or the unary functional spelling
=flags: => (cut append <> '("--debug"))=. Do not write
=flags: => append '("--debug")=: the quoted tail can be parsed as a separate
slot specification rather than an argument to =append=. The native control
checks both supported expressions and absence of an accidental =quote= slot.
This is syntax discipline over the existing POO forms, not new sugar.

Module consumption and business derivation stay separate:

#+begin_src scheme
(def Nix (.get consumer.init.exports modules nix))
(def Source (.get Nix prototypes Source))
(.def (LocalSource @ Source)
  config: =>.+ (.o nix: "/opt/local/bin/nix"))
(.get LocalSource config nix)
#+end_src

Here =Nix= remains the original admitted Module scope. =LocalSource= is an
explicit new business value derived from its public prototype; it retains other
configuration defaults. It does not clone the Module scope for namespace
visibility or acquire new source/build authority. Interface remains the loading
configuration. This example constructs configuration without realizing a Nix build.
These are module expressions under the declared Yuanxu Prelude. A standalone
=gxi use.ss= script must explicitly import the POO construction bindings it
uses (as the product fixture does); it must not rely on ambient interactive
bindings or assume package metadata changes the interpreter's script language.

** Nested objects and functional boundaries

Native hygienic slot bindings may reference the enclosing effective receiver.
An inner same-named slot shadows that binding. An explicitly named inner =self=
denotes the inner receiver; it is not an alias for the outer namespace. Use
descriptive native names such as =self: profile= / =self: task= where necessary.

function-argument injection/scopedImport is not an excuse to change Scheme's
