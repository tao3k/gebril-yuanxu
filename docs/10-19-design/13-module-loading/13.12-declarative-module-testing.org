* Case-owned phase observations

An atomic test declares its fixture and assertions. Init's existing execution
projection selects observation at the process boundary; authors do not repeat
that policy in every module:

#+begin_src scheme
(yuanxu-test-fixture "publication remains current"
  (workspace Workspace)
  (yuanxu-test-checkpoint 'before-publication)
  (check-equal? (file-exists? workspace) #t))
#+end_src

=yuanxu-test-checkpoint= uses the same memory policy and typed receipts as
the Case watchdog. Phase elapsed time starts at Case entry; it excludes cold
imports and macro expansion before the body. Counters are process-wide and
last-GC live bytes do not establish exclusive ownership. The default policy
does not emit checkpoints or force collection. A diagnostic Profile may use
the existing collection option for weak-reachability controls, but the original
Ops acceptance workload must retain its original policy and limits. The fixture
continues to own release on both success and failure; no runner or environment
probe is added.

** Module observation uses the same macro and POO policy

Module authors declare fixtures and assertions, without a module-specific
Profile declaration. The existing init-owned execution object controls whether
observations are enabled:

#+begin_src scheme
(yuanxu-test-fixture "Schema transition preserves accepted values"
  (workspace Workspace)
  (yuanxu-test-checkpoint 'selected)
  (check-equal? (file-exists? workspace) #t))

;; Execution-site policy; never repeated in module test declarations.
(def tests (.get init.Scenarios aws tests integration))
(.def (Observed @ tests)
  execution.profile.emit?: #t)
(.call Observed .run)
#+end_src

This configuration uses the existing =:yuanxu/object-syntax/path-slots= authoring
bindings. The assignment replaces only the =emit?= leaf; its ancestors retain
their inherited slots. It lowers to ordinary POO, without a wrapper:

#+begin_src scheme
(.def (Observed @ tests)
  execution: =>.+
  (.o profile: =>.+ (.o emit?: #t)))
#+end_src

Shared prefixes are emitted once. For example, adding
=execution.environment.TMPDIR: workspace= in the same declaration retains both
changes and the inherited environment. The derived execution uses the identical
guarded test source and its existing spec; =.run= reads the derived receiver's
execution. Receiver-local surface slot caches need not have identical list
identities. The parent test projection and its default observation setting are
unchanged. Missing or non-object ancestors fail on demand, rather than silently
creating a namespace. Existing fixture cleanup and before/after source guards
are not replaced by path lowering.

** One authoring surface for JsonSchema, Funflow and AWS

The same init test projection is used for each owner. Ordinary module tests
declare only fixtures and assertions; no per-module observation Profile is
required. Select the atomic suites through =init.Modules.json-schema.tests=,
=init.Modules.funflow.tests= and =init.Scenarios.aws.tests=. AWS's real Schema
transition is selected separately through its =tests.integration= slot.

#+begin_src scheme
(def json-tests (.get init.Modules json-schema tests))
(def flow-tests (.get init.Modules funflow tests))
(def aws-tests (.get init.Scenarios aws tests integration))

;; Each ordinary endpoint defaults to observation off.
(.call json-tests .run)
(.call flow-tests .run)

;; Demand observation without reconstructing a source or execution tree.
(.def (ObservedJson @ json-tests)
  execution.profile.emit?: #t
  execution.environment.TMPDIR: workspace)
(.def (ObservedFlow @ flow-tests)
  execution.profile.emit?: #t
  execution.environment.TMPDIR: workspace)
(.def (ObservedAWS @ aws-tests)
  execution.profile.emit?: #t
  execution.environment.TMPDIR: workspace)
(.call ObservedJson .run)
(.call ObservedFlow .run)
(.call ObservedAWS .run)
#+end_src

=workspace= is acquired and released by the existing outer fixture, not a
new execution wrapper. The real JsonSchema-only and Funflow-only qualification
uses the same relative declaration for either selected owner. It checks ordinary
execution without observation output, observed execution with Case-owned output,
identical source bindings, unselected sibling laziness, fixture release after
an injected failure, and rejection after selected test source changes. Its
failure-injection environment field is a test probe, not a public module option.
The Funflow atomic case also replaces a command through =tasks.build.command:=;
it does not refine an old command when the intent is complete replacement.

*** Evidence binding belongs to publication

The integration Case no longer constructs a separate invocation Contract,
meaning rule or evidence projection for replay. =AdmissionPublication.=
provides =.bind-evidence=, which delegates to the existing public
=bind-evidence= with the publication's actual admission Contract, Context and
evidence projection. The normal =.publish= path uses that same method after
one admission of the candidate and passes the returned checked object onward.
No second value validation is performed merely to bind the receipt.

#+begin_src scheme
;; Resolve the maintained association; do not reconstruct its descriptor.
(def publication
  (.call AdmissionPublication. .for-export selection 'aws 'Scenario))
(defvalues (receipt checked failure)
  (.call publication .publish previous Release))

;; Negative test: submit an old receipt to the freshly resolved association.
(def binding (.call fresh-publication .bind-evidence checked))
(defvalues (rejected preserved reason)
  (metadata.publish binding checked
    (lambda (subject) (values receipt subject)) checked))
#+end_src

Only the callback returning an old receipt is fault injection. It is not an
alternate admission producer. Independent controls change only the actual
Contract reference (retaining its name) or only the Context reference. Both
must fail at the public Contract's logical identity rule, without a nested
source exception masking that result. The real provider/Schema update resolves
a fresh publication from the selected Graph and rejects the previous receipt
through the same binding. Every refusal preserves the previous object by
identity; the enclosing fixture still owns temporary-directory cleanup.

=.bind-evidence= returns an existing public invocation Contract. Binding alone
does not admit a value, establish a legitimate module association, or execute
package-currentness checks. The complete =.publish= path retains those checks
on both sides of admission and checks Context currentness during invocation.
The same-name Contract and copied-Context controls are adversarial test values,
not a replacement for Graph-based publication resolution.

The isolated checked-publication tests use the same production publisher and
binding method as well; their duplicate invocation Contract and =replay=
helper have been removed. Their AWS-shaped fields, normalization counters and
revision-vector Context remain synthetic controls. The Core AWS qualification
instead resolves its actual Contract and Schema through =.for-export= and
uses the platform Context. Neither control claims an AWS deployment.

*** Changes between admission and publication

The Core-owned Case declares Schema, Context and Contract mutations in one
private table of ordinary POO values. A single =for-each= body preserves the
inherited =package-current= callback and counts its invocations:
the first precedes admission, while the second runs after accepted evidence
has been produced and bound, before the public invocation accepts its result.
Each control must reach exactly two calls and refuse publication, preserving
the previous accepted object by identity. This prevents an early admission
failure from masquerading as coverage of the publication window.

- Schema/source: switch the real selected package input from provider =5.99.0=
  to =5.100.0= during the second callback. The bound Context must reject the
  now-stale input; a fresh Graph association is subsequently resolved normally.
- Context: use a private copy of the platform Context and change its
  =graph-generation= after binding. Its existing currentness check must reject
  the mismatch; the original publication Context remains available.
- Contract: change the actual selected Contract's =responsibilities.profile=
  after binding. The captured requirement observations must reject the edit,
  even though the root Contract reference and its name have not changed.

The counter, boundary refinement and refusal assertions occur once in that
Core test body, rather than once per mutation or in module author code.
=yuanxu-test-fixture= owns the workspace and cleanup. Existing Case
Observability records phase names and scalar =publication-fault-boundary= /
=publication-fault-refused= totals. It never performs injection; disabling
observation does not disable the mutation or its correctness assertions.
The observed execution checks that both totals equal three. The default
execution still exercises and asserts all three rows without an observation
table. The original AWS atomic suite has no references to the Core matrix;
its empty integration projection does not import or register these controls.

The qualification does not locate =scenarios/aws/config.ss= relative to its own
file. It obtains the baseline Profile from the selected module's published
=Profiles.Web=, checks that its =instance_type= remains =t3.small=, and invokes
the final publication's existing Graph source guard. That guard owns the role
source observations, including configuration. Moving a test does not change
module lookup semantics or require a new path helper, fixture macro or API.

These mutations and counters are test-only fault injection. Admission, checked
object production, public evidence binding, package checks and final rejection
remain the maintained production path. The Case does not add a publication
hook, custom receipt protocol or runner. Its enclosing init-owned execution
continues to check source validity and fixture cleanup in both observation modes.

Here, excluding additional runtime Loader work does not mean bypassing
=yuanxu-load-modules=. That existing entry already performs directory/init
selection, lazy module namespace resolution, selected Graph construction,
publication linking and build/test projections; this test uses it. No separate
runtime loading backend or reload protocol is introduced by this qualification.

* One testing execution boundary

=:yuanxu/observability/testing-script= provides =TestingScript.=, an ordinary
prototype inheriting =ProcessScript.=. Its only process implementation is the
existing Ops =run-script= calling the original =gxtest=. It does not enumerate
cases, interpret assertions, schedule tests or replace =std/test=.

Init binds =spec= and =admit-current= on the same inert POO source, then
associates a lazy =execution= slot producing the existing =TestingScript.=.
The caller
only selects suites and invokes =.run=. The existing fixture
boundary brackets the operation: validate explicit nonempty inputs; check the
guard; execute Ops; admit the receipt; recheck the guard before returning.
The post-check also runs if Ops or receipt admission raises. If both execution
and post-check fail, the existing fixture mechanism retains both exceptions.
An empty spec is rejected before process preparation, because =gxtest= with
no files means implicit current-directory discovery.

The source is an existing projection-shaped POO value, not an Ops object or
another Graph. Its lazy slots share init's existing selection and projection
cache:

#+begin_src scheme
(.o source-root: (path-directory (path-expand source))
    selected-graph: (.get (selected!) selected-graph)
    spec: (test-spec)
    admit-current: test-current!
    .select: test-source)
#+end_src

These closures are installed by the init factory, not by each caller.
The factory associates execution through ordinary POO composition:

#+begin_src scheme
(def (executable-tests source-value)
  (.+ source-value
      (.o (:: tests) source: source-value
          execution: (module-test-execution source-value)
          .run: (lambda () (.call (.get tests execution) .run))
          .select: test-source)))
#+end_src

Both the default init source and each cached owner projection use this same
association. There is no new Script prototype or execution implementation.
=TestingScript.= obtains both files and guard from =source= and never consults
independently overridable Script =spec= or =admit-current= slots. Raw file lists
and source objects missing a guard are rejected. There is no fallback that
silently disables currentness. The existing =init.test-spec= still returns an
ordinary list for inspection and standard-library consumers; it is not the
source capability used by =TestingScript.=.

Bounded suite selection uses the native source method and returns an already
cached projection with its associated guard:

#+begin_src scheme
;; Selection returns the cached executable object, including its source guard.
(def SchemaTests (.call init.tests .select '(json-schema)))
(.call SchemaTests .run)
#+end_src

This filters suites inside the existing selection; it does not link modules.
The selected source retains the same init-owned root and automatic guard.
Importing init or obtaining =init.tests= does not resolve the Graph or enumerate
test directories. First source-field demand discovers only the requested owners.
It reuses =selection.prepare-publication= and its existing reader/cache for those
owners: role source validity and SDK-observed private/compiler dependencies remain
guarded. It does not resolve unrelated selected publications, satisfy their
Module/Feature requirements, or admit the complete configuration Graph.
An explicit =tests.selected-graph= demand still returns the original selection's
Graph and performs the complete resolver admission. No second dependency tree is
maintained. Test-only imports beyond the observed publication closure and adjacent
test helpers are not claimed as a complete dynamically discovered source closure.

* One namespace, independent leaf demands

The existing directory =namespace= / qualified =scope-tree= resolver accepts a
leaf-view function. Init uses it to retain one module object at each existing
leaf, instead of linking a business scope just to reach test metadata:

#+begin_src scheme
(def (module-view owner scope!)
  (.o identity: owner
      scope: (scope!)
      tests: (test-source (list owner))))

;; The accessor returns the existing namespace; no second path registry.
(def (module-namespace) (.get (selected!) modules))
#+end_src

The existing =yuanxu!= hygienic expansion binds this accessor to a private
generated name and exports =init.modules= as a computed identifier. Its native
Gerbil =identifier-rules= expansion calls that accessor on an identifier read.

=module-system/source/declaration.ss=; no new public macro spelling is added.

variable or another POO proxy. Returned root and leaf

=init.tests .select= projection. Namespace branch caches and source observations

=yuanxu-load-modules= keep their existing resolver behavior; init explicitly
requests the module-object leaf view. Dependency linking still obtains the
original admitted scope, not a scope with an injected =tests= field.

links the business interface. Tests may import their real implementation modules
through native Gerbil imports. This is not a claim that test processes execute
no implementation source. A module outside the selected Graph is not activated
by a test request. Auto-discovered extra demand roots and test-purpose Graph
expansion remain separate policies, not silently added by this projection.

** Why fallback was removed, rather than patched locally

The inspected public gerbil-poo implementation routes =fallback-to= through
=no-applicable-method=. Its =.slot?= reads the effective slot-function table;
=.all-slots= reads effective declaration names. Its current MOP hooks for C3
precedence and effective slot computation do not add an enumeration hook.
Consequently a successful fallback value read does not make the delegate's keys
appear in either reflection operation. That is ordinary fallback semantics,
not evidence of a broken inheritance engine.

Init has no local slot overrides requiring fallback priority. Removing this
unnecessary wrapper is simpler than adding public-library hooks or a Core-local
reflection implementation. The returned namespace uses original =.all-slots=
and =.slot?= directly; it has no fallback-handler keys, copied slot catalogue or
parallel path tree. General fallback reflection remains unchanged in gerbil-poo.

#+begin_src scheme
(.all-slots init.modules)                   ; module/category names
(.slot? init.modules 'json-schema)           ; #t when declared
(.slot? init.modules 'missing)               ; #f, no scope demand
(.all-slots (.get init.modules json-schema)) ; identity, scope, tests
#+end_src

Reflection forces source metadata needed to determine names, not the selected
Graph, business scope, test files or test executor. Branch and leaf values retain
native caching. The accessor checks currentness on every exported identifier
read, including repeated reflection after keys have been cached. A separately
captured object remains a snapshot; its direct reflection is not a live watcher.
Full field documentation, recursive test catalogs, Feature-specific suites and
automatic test-purpose Graph expansion are not supplied by namespace reflection.

* Hygienic fixture binding

=:yuanxu/observability/testing-fixture= exports =yuanxu-test-fixture=,
=with-yuanxu-fixture= and their functional implementation. A fixture is an
ordinary POO object with =.acquire= and =.release= methods. The macro introduces
only the requested local binding and expands to existing test-case observation
plus a dynamic-wind resource boundary:

#+begin_src scheme
(yuanxu-test-fixture "module behavior" (workspace Workspace)
  (check-equal? (.get (.call Release .run workspace) steps build output)
                "release"))

;; Expansion, using hygienic library bindings:
(yuanxu-test-case "module behavior"
  (call-with-yuanxu-fixture Workspace
    (lambda (workspace)
      (check-equal? (.get (.call Release .run workspace) steps build output)
                    "release"))))
#+end_src

Acquisition is once per invocation, not suite registration. Cleanup executes
after normal return or an exception from the body. Acquisition must roll back
its own partially acquired resources if it raises before returning. If both
body and cleanup fail, both exceptions are retained in the reported error.
Fixtures must not use continuation re-entry to revive released resources.
There is no implicit global fixture, provider loading or shared mutable state.
The macro cannot impose the pre-import heap fence; existing Just/Ops entrypoints
retain that responsibility.

* Purpose and existing foundation

Module testing is a Core Module System capability, not a product-specific runner.
At ecosystem scale, a module owner must be able to qualify one contribution,
selected Features, Contracts and consumer interactions without importing every
module or executing every provider. Test selection must retain the same admitted
source identity and positive/negative Feature decisions as build selection.

The existing foundation is Gerbil =std/test= and =gxtest=,
=core/observability/testing-case.ss=, its POO testing Profiles and watchdog,
=Selected Graph=, Ops and Funflow. The existing =yuanxu-test-case/with= macro
already hygienically wraps a native case with an inherited resource Profile.
It does not replace assertions, discovery or the standard harness.

Actual current syntax, without a new assertion language:

#+begin_src scheme
(import :std/test :clan/poo/object
        :yuanxu/observability/testing-case
        (only-in :yuanxu/modules/funflow/objects Job. Task.))

(.def (AtomicBudget @ yuanxu-testing-case-profile-prototype)
  max-duration-milliseconds: 1000)
(.def (Upstream @ Job.)
  tasks: (.o build: (.o (:: @ Task.) command: (list "printf" "build")))
  selected: (quote (build)))
(.def (Release @ Upstream)
  tasks: =>.+ (.o build: =>.+ (.o command: (list "printf" "release"))))
(.def (Invalid @ Upstream)
  tasks: =>.+ (.o build: =>.+ (.o command: (list "printf" 1))))

(export module-tests)
(def module-tests
  (test-suite "module atomic behavior"
    (yuanxu-test-case/with AtomicBudget "final receiver preserves user value"
      (check-equal? (.get Release tasks build command) (list "printf" "release")))
    (yuanxu-test-case "invalid argv is refused without executing a process"
      (check-exception (.get Invalid graph) error?))))
#+end_src

The example uses existing native declarations and contracts. The executed
Funflow/Null/AWS tests additionally exercise context drift, failed processes and
finalization.

* Further selection and publication design

The proposed Module publication contribution is an inert testing catalog, with
separate atomic, integration and benchmark entries. Each entry identifies its
source, module owner, required test dependencies, effect policy and budget.
The actual enclosing publication supplies source identity; authors do not repeat
it in each case. Test-only dependencies must not enter ordinary build/runtime
selection. A disabled required dependency refuses the selected test with its
module/Feature path; it is never silently re-enabled.

Implemented and proposed =yuanxu!= exports:

- =init.test-spec=: implemented ordinary native file list; callers may append
  repository-maintained test files with Scheme's =append=.
- =init.benchmark-spec=: proposed separate benchmark workloads and policies.
- A richer discovery value (proposed): lists stable module/suite identities and declared effects
  without importing case bodies or starting a process.

These are projections of the admitted selection, not another scanner, registry
or selection resolver. Source roots and validity checks belong to existing source
preparation. Paths must stay within the publication's admitted source closure.
Editing a suite, fixture, dependency, contract or macro input invalidates its
qualification identity. Ordinary init/build evaluation does not run tests.

Atomic means an explicitly bounded owner and fixture, not necessarily zero
dependencies. A test can use an admitted real dependency or an explicitly typed
fixture replacement. Results label those choices; a fake provider never qualifies
real provider integration. Per-case resources are fresh by default, cleanup runs
on assertion failures, and shared mutable fixtures require an explicit policy.
A module's positive cases do not replace missing-field, wrong-type, stale-context,
conflict, disabled-dependency and failure-path controls.

* Macro responsibilities and limits

A stronger declaration macro is justified only where hygiene or phase semantics
remove real repeated work. Its reviewed surface should bind a fresh fixture and
module scope, generate stable test identities, guarantee cleanup and emit native
=test-suite= / =yuanxu-test-case/with= forms. Assertions remain =check-equal?=,
=check-exception= and other std/test operations. Domain case families can use
internal =defrules= to generate typed positive/negative matrices instead of
copying fixtures and lambdas throughout downstream tests.

The implemented fixture spelling and expansion above have focused native tests.
Compile-time declaration cannot discover arbitrary dynamically generated Scheme
case names without evaluating them. Static discovery lists declared suite or
parameter-family IDs; actual generated case IDs are reported by the native
harness. Macro expansion must not load provider catalogs, run init recursively,
start Nix, spawn Ops processes or inspect user credentials.

The heap fence must exist before the test module is imported. A case-body macro
cannot provide that protection by itself. Ops and the existing bounded Just
entrypoints own process launch; no new shell runner or handwritten gxtest
replacement is needed. Natural exit zero alone is insufficient: MODULE-OK,
HARNESS-OK and final OK, with no error markers, remain required.

* Functional and domain qualification

Funflow's atomic gates qualify Category/Arrow composition, pair/fanout semantics,
Kleisli value-dependent binding, local memoization and exception values.
Job integration qualifies selected dependency closure, Ops handoff and finalizer
activation. Null integration actually initializes, validates, applies, reads
output and destroys a local resource. AWS integration qualifies real Schema and
configuration validation without credentials, not cloud deployment.

Contracts qualify values and relationships; test execution receipts describe
observed behavior. Neither substitute for the other. Lean/model results remain
separately labeled assumptions and properties rather than being treated as
observed process execution.

* Benchmark policy

A benchmark entry identifies workload, input generation, warmup, repetition,
resource budget and a semantic control. Separate source import, macro expansion,
Graph construction, contract admission and steady-state execution costs. Report
cold and warm runs separately; a cache hit is not proof of currentness.

Use the existing observability sampling and Ops timing. Retain wall time, GC/live
heap metrics where supported, variance and machine/runtime/source identities.
A comparison requires equivalent workloads and result checks before a regression
threshold is meaningful. Do not turn one faster run into a performance claim.
Timeouts, stale inputs and failed cleanup are failures, not benchmark samples.
Raw logs remain artifacts, not repository documents.

Worker admission uses discovered available CPUs together with aggregate memory
and effect budgets. A CPU count is an upper bound on CPU capacity, not permission
to start that many 1-GiB workers or simultaneous writes to a shared workspace.
Each chosen worker must fit the combined budget. Process-global heap counters
cannot be represented as independent per-thread allocations.

* Concrete catalog shape for review

This is proposed publication data, not syntax accepted by today's declaration:

#+begin_src scheme
testing:
(.o atomic:
    (.o sources: '("tests/atomic.ss") effects: 'pure)
    integration:
    (.o sources: '("tests/integration.ss") effects: 'local-process)
    benchmarks:
    (.o sources: '("benchmarks/projection.ss") effects: 'pure))

The declaration layer should derive the owner, source closure and stable module
identity from the enclosing admitted publication. Common budgets come from
maintained POO test Profiles; module overrides refine those Profiles. Catalog
admission checks source existence/confinement and effect/budget compatibility.
It must not import tests merely to discover this metadata.

At thousands of modules, select the reachable test dependency closure, including
only explicitly chosen parameter families. Do not generate the Cartesian product
of every Profile, Scenario and Feature combination. A seed/budget-bound property
family can test many values while reporting reproducible failures and shrinking
controls; it remains distinct from a claim of exhaustive verification.

Cached qualifications include test/macro/fixture source closure, actual contracts,
Schema, selected Features, runtime and policy identity. A passing artifact must
still be admitted as current before reuse. External-state/effect tests need an
explicit freshness policy and cannot be skipped because a pure input hash matches.
