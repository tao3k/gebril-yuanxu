* What Haumea actually does

Its implementation separates =aggregate= (structural filesystem metadata) from
=view= (a perspective-dependent attribute tree). File content is represented by
a fixed point and a selected loader. Nix evaluation controls when those content
thunks are forced. Directory shape and name collision checks still require
metadata work; lazy values do not imply zero filesystem traversal.

Names strip up to two leading underscores before classification and strip the
last file extension. Public names are visible externally. A single leading
underscore is collection-internal; a double leading underscore is visible from
the containing directory's perspective. The implementation uses a prefix test
on the caller perspective, so enclosing-directory internal names remain visible
to descendants. The result is a visibility view, not a sandbox or an authority
to execute another Module.

Normalized collisions reject, including a file/directory collision or an
internal/public name collision. Symlinks are not loaded by the regular-file/
directory branches. Yuanxu currently rejects symlinks in admitted source trees;
that stronger source policy must not be weakened to copy a reference convention.

The default loader imports a value, uses function argument names to select
inputs when it is a function, and provides =self=, =super= and =root=. Its default
loader ignores optional argument defaults; its callPackage variant has different
default/override behavior. Those are concrete Nix function semantics, not generic
dependency-injection laws that can be copied onto Scheme bindings.

Haumea's =self= is the current file result, =super= is its containing directory
view, and =root= is the collection view from that file's perspective. Its
=super= is not a POO inheritance predecessor. Its transformers run over directory
views; =liftDefault= is an explicit transformer with disjoint-union collision
checks. Arbitrary transformers need not preserve cold enumeration.

There are two different recursive structures: POO value-slot dependencies and
Module =requires= edges. A productive self-referential object does not legalize
a cyclic Module dependency or a cyclic native compiler import. Keep their
diagnostics and admission boundaries separate.

Injecting the whole source tree as an ambient =root= would bypass explicit
selection/dependency contracts. Existing admitted aliases and explicit functional
parameters provide the intended dependency values. Do not infer imports or
effects from a Scheme function's argument names or rebind lexical scope through
an unreviewed scoped-import mechanism.

* Namespace-view contract

1. Structural indexing and key enumeration may observe source metadata and
   validate naming/currentness policy. They do not run business scope factories,
   external builds or compilation. Metadata enumeration is not universally free.
2. A view can restrict visible paths or mount existing paths. Direct lookup and
   reflection must agree: hiding a name from enumeration alone is insufficient.
   An excluded lookup refuses before requesting its provider.
3. A permitted leaf returns the original admitted POO object. Do not clone it
   with =.cc= merely to build a view, inject a =scope= slot or reconstruct it per
   path. Aliases must preserve receiver identity and original source provenance.
4. View policy cannot enlarge the admitted selection or authorize operational
   effects. Build roots/options/resources remain owner contributions; views
   cannot turn private role files into independent compilation declarations.
5. Naming and leaf/branch conflicts refuse before conflicting scope factories
   run. No implicit =default.ss=, new entrypoint or underscore-renaming rule is
   adopted. Publication identity and native compiler identity remain authoritative.
6. Original input/currentness and Contract checks still guard permitted demand.
   A previously computed view or warm POO slot is not an approval cache.

Closed metadata projections and ordinary POO/functional composition are the
default abstractions. A general user callback for filtering/transforming views
would need explicit phase/effect semantics before adoption; pure behavior cannot
be inferred merely because a callback is stored in a POO slot.

* Refinement: POO is the abstraction, hierarchy is its expression

Do not introduce Tree, Node, Leaf or View wrapper families. A branch is an
ordinary native POO object. Its finite slot specifications express its names;
its slot thunks reference original admitted children. A leaf is the admitted
object itself. Native =.o= composition expresses fixed projections and aliases;
=object<-fun= expresses a metadata-derived set of the same ordinary slots.
Neither expression needs a new accessor or changes Interface configuration.

The current installed gerbil-poo source cohort
=a84e76c1b1a61de2db52e38ba8d1d8c8671ec601= already supplies receiver-local
slot/layout indexes, persistent ordered =prototype-map=, ordinary hash-table
interfaces, Type/ObjectContract descriptors, and =table-indexes= for correlated
collection snapshots. Use each at its owning boundary:

| Boundary | Existing POO capability | Decision |
|----------+-------------------------+----------|
| Public expression | Native object slots, =.o=, =.get= and prototype composition | Branches and aliases use these directly; no leaf wrapper |
| Structural name grouping | Persistent =prototype-map= and private native hash builders | Reuse the existing symbol-keyed index; pass only a branch's declaration suffixes to its children |
| Changing correlated catalog | =table-indexes= and persistent table snapshots | Available when an actual catalog/delta contract is needed; no second catalog is introduced for this immutable generation |
| Namespace admissibility | Existing Type/ObjectContract phase semantics | Check finite names/origin policy without demanding business fields |
| Business leaf admissibility | Existing Module/Scope Contracts and ManagedBinding | Keep complete requirement and source checks on their original boundary |

Contract use must be phase-correct: ObjectContract's required-field validation,
including its shape routine, can read required values. Calling that routine on
every namespace leaf would defeat cold enumeration. The native control instead
uses an empty responsibility set plus a delegated names-only whole-object Type
constraint; leaf Contracts remain at actual demand. A contract does not imply
purity or harmless evaluation merely because it is a POO object.

Visibility is a restriction of bindings available from the admitted source
namespace, not a string convention or a filter over already materialized values.
Aliases may rename exposed paths but must reference an existing permitted source
binding. They cannot recover a hidden target through a new public name. Closed
slot specifications supply both reflection and direct lookup: inheritance of the
entire source object would also inherit its hidden slots and is not a narrowing
projection. Native POO composition still applies normally within the admitted
leaf; namespace visibility and business prototype inheritance are different axes.

The names-only Contract certifies names, not opaque getter provenance. Native
aliases in these controls reference the restricted source object. A caller
holding a broader source capability can explicitly construct a broader object;
that is a new declaration requiring its own publication/admission, not a breach
of a Scheme sandbox. Source-origin eligibility remains an existing Module
System obligation and is not inferred from names or function captures.

Currentness is explicit at its original owner. A namespace is an immutable
generation snapshot; a cached native slot is not live filesystem IO. Pure warm
=.get= can return its existing object identity. Before graph publication, build
or checked execution, the original owner's currentness/admission boundary must
still refuse stale source/generation. This refinement does not add an observer
to every slot read or claim every warm lookup revalidates source bytes.

* Formal allocation before Scheme changes

=Loading/NamespaceProjection.lean= models bindings as a pure path-to-path
function, not a runtime Tree type. Restriction filters the target binding;
reflection enumerates exactly defined bindings within the supplied finite
domain. Demand delegates to the original resolver verbatim. A hidden name
returns refusal with unchanged state without calling that resolver. Aliases to
one source path invoke the same original binding operation; no reconstructed
Scope or secondary memoization state is modeled.

Here =demand= denotes the cold slot thunk's invocation, not interception of
every warm =.get=. The existing native POO memo/CompiledPlan semantics govern
whether that thunk runs again. Alias equality is stated at the same input
state; cross-call receiver stability additionally uses the original source
slot's memo semantics and is checked with native =eq?=. An arbitrary stateful
resolver is not assumed to return one allocation forever.

The branch-index law states that a suffix is in a child's bucket exactly when
the original input contains that child's name followed by that suffix. The native
grouping uses cons followed by reverse to retain occurrence/order; the
membership theorem alone does not establish an ordering guarantee.
It does not prove hashing, filesystem naming admission, native pointer equality
or compiler behavior. ManagedBinding and DemandMaterialization retain those
existing admission/identity premises; Scheme must establish the concrete bridge.

SysML allocates closed-name visibility, unchanged resolver returns and explicit
currentness, plus measured branch-local indexing. The Scheme acceptance is
ordinary POO expressions, Contracts and the existing source namespace. There is
no public visibility grammar or automatic underscore policy in this increment.

* Efficiency questions with concrete owning source

=scope-tree= already groups immutable rows by the next name using the native
ordered prototype map. It does not scan all siblings for every cold lookup.
=directory.ss= snapshots immediate directory metadata, preserves collision and
symlink checks, and constructs deeper namespace nodes on demand. It explicitly
does not recursively enumerate every Module at Context construction.

The pre-refinement =directory.ss:tree= filtered all selected paths for each
demanded branch. The current implementation groups branch-local declaration
suffixes through the existing persistent prototype map. The paired native
measurement below establishes a gain for its explicit wide-branch corpus.
This remains a generation-owned structural index with no additional semantic
graph or approval cache.

Keep distinct workloads separate when evaluating further changes:

- Metadata-only namespace creation, enumeration, cold path demand and repeated
  warm lookup, with fixed path depth/fanout and explicit versus auto selection.
- Real source declaration/admission, including all explicitly selected headers.
  Current tests require the first scope demand to admit the complete explicit
  selection, while only demanded providers' business factories run. Do not claim
  one declaration read per leaf by changing that contract.
- Native compilation of the selected owner/dependency closure. The 13.34 Nix
  receipt establishes ten targets and zero hot compiler events, not a general
  thousand-Module latency result or a speed comparison against Nix evaluation.

Record source reads/stats, declaration/contract work, factory calls, native
compiler events, wall/CPU time and retained/peak memory separately. Use matched
workloads and the unchanged project budgets. An arbitrary transformer that
forces every leaf is a different workload, not a baseline for lazy lookup.

* Real catalog qualification refinement (13.35)

The acceptance protocol distinguishes physical catalog R, explicit declarations
D, demanded semantic scope closure S and native compiler closure C. A catalog
with 1000 directories is not evidence that 1000 declarations were admitted.
Admitting every declaration does not authorize construction of every scope.
A downstream build uses its own explicit selection; hiding namespace names
never changes compiler authority. Owner Build contributions enter C through
that same selected owner, with original native source identities.

=NamespaceProjection.scope_demand_stays_in_admitted_catalog= reuses the existing
=Graph.TestAdmission.Demanded= relation. The finite star fixture establishes
that demand for module-1 reaches only module-1 and module-0 within a closed
thousand-node region. Compiler exactness remains the existing
=SelectedPackages.successful_target_iff= obligation, and product ownership
remains the existing SourceView/downstream environment contract. No parallel
graph engine, loader or cache is introduced. These are model laws; actual
reader, scope factory, compiler and cleanup behavior require native gates.

The original =module-declaration-1000-test.ss= passed in the qualified private
Core runtime with 1000 actual four-role declarations, cold business exports,
1000 completed publications and the existing stale-source rejection. The
subsequent =module-runtime-values-1000-test.ss= failed its unchanged 180000 ms
Case limit during first-scope demand; the trace was in publication metadata
currentness. This is retained negative evidence, not an accepted runtime
capacity result. Neither the Case budget nor the heap fence was enlarged.

The new downstream gate must create 1000 valid Interface directories, select
module-0 and module-1 in a distinct consumer, count exactly those scope factory
invocations, derive C from the projected native spec, compare cold compiler
events against C, require hot zero compilation, and clean one downstream
environment while the second remains usable. The original full-catalog runtime
value gate remains independent and must pass before claiming its capacity.
