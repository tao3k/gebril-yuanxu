** Protected fixed checkpoints, not effect-wide approval

Repeated validation is not one indivisible effect boundary. Gerbil expansion,
module initialization, public callbacks and unknown observers remain opaque
boundaries: validate their original source and metadata support on entry and
return. No accepted verdict survives one of those operations. Directory
selection still admits all declared owners and keeps unreached scope bodies
cold; it does not silently reduce the declared workload.

A fixed internal checkpoint that only checks source observations and policy is
different. =module-source-measure-replay= now uses native POO
=reobserve-slot-reads!= for that checkpoint: authenticate the complete original
read DAG, retain the native selected-receiver write protection while executing
the checkpoint exactly once, then authenticate again on successful return.
=without-observation= prevents native synthetic read delivery from recursively
adding the same metadata support; it does not disable filesystem observation.
A checkpoint exception is preserved. Failed preflight follows the original
split path for its refusal diagnostic and cannot turn into acceptance.
Arbitrary user code is never executed in this protected checkpoint.

The selected Build Graph and its prepared inputs can enter one such frame
when the linker owns the exact selection receiver and the cached guard is
still the original linker procedure. The guard runs first, followed by each
prepared-input guard in its existing order. A replacement guard, an open
observer, or unsupported receiver state keeps the independent route. Every
effect boundary starts fresh, and the native replay still authenticates the
issued records at frame exit.

Within that frame, the paired Reader and directory check is one observation
in the existing source window. Each frame has its own query identity even
when several frames share an enclosing source window. The publication
checkpoints still run in order against the original issued roots.

The indexed publication check previously authenticated the same metadata both
before and after a fixed batch. It now uses one protected operation. The
compatible observer-free publication tail replays the original preparation
and admission roots together; incompatible or unknown observers retain the
original split checks. Neither change substitutes cardinality for freshness.

** Tool execution provenance and owner build demand

A captured Gerbil tool context has three identities: its actual object, module
ID and artifact path. A loaded installed =.ssi= is not executed again merely
because its checkout =.ss= changes. Treating that mutable checkout as every
Module's execution input conflates package ownership with running code and
multiplies unrelated reads. A fresh or mutated native context must still be
refused; runtime context identity is not inferred from a matching module name.

Actual source-executed tools retain their byte guards. Selecting an owner's
build source is a separate demand: project the existing native import closure
through that owner's declared source boundary, retain module identities and
source observations, and include the resulting inputs in the original build
projection. Installed prerequisites do not acquire ownership of checkout
source. This distinction changes neither namespace membership nor the
=yuanxu! / Interface / .get= user expression. Gerbil remains responsible for
package resolution and installed artifacts; Yuanxu owns selected Module
admission and projection.

The same reader dependency index stores native context topology, rather than
repeatedly reconstructing execution and build support from projected tool
source objects. It stores neither a successful currentness verdict nor an
initializer result. Optional source aliases cannot replace the actual
installed context; mandatory owner build inputs must still be resolved and
checked. Public checks and open callbacks reauthenticate native bindings on return,
including an observer which removes itself. Closed candidates use only the
existing fixed source checks within their pure window; they do not retain an
approval across an initializer. A native negative control mutates the artifact
path on =publication-guard-end= and clears the observer. It fails against the
entry-only implementation and must be refused after the return refinement.
Model success alone must not be reported as a runtime performance result.
