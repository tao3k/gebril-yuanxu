* Selected owner source versus installed prerequisite

The Lab downstream replay exposed an ownership regression: filtering selected
Graph entries by the consumer package prefix returned only its retained
=("init" "main")= roots. A prefix mismatch cannot change admitted owner source
into an installed prerequisite. The normative disposition is:

| Input provenance | Compiler action | Product owner |
|------------------+-----------------+---------------|
| Selected Graph owner source, including required owners and owner public libraries | Compile the complete selected source closure with original identities/options | Current downstream environment |
| Consumer retained ordinary library | Preserve the native spec/options; include in the same downstream build | Current downstream environment |
| Installed canonical Gerbil/Core/POO import outside selected source entries | Resolve using native import/Make; do not add a source target | Existing prerequisite environment |
| Explicit external build request | Keep its existing contribution/realization boundary | Existing declared owner contract |

An installed artifact does not cancel an explicit selected-source obligation.
Graph =entries= already carry admitted owner/input provenance; no new package
registry, user origin tag or prefix-based authority is needed. Unknown/missing
imports fail through Gerbil instead of authorizing a rebuild of another checkout.
A source owner retains public roots, FFI options, assets, original source/package
observations and all existing currentness guards. The native namespace remains
Interface configuration followed by ordinary =init.exports= / =.get= demand.

For a local-only plan, retain ordinary source paths and existing Make names.
For a cross-package selected plan, reuse the existing downstream-owned compiler
source view for the merged entries, full original compiler identities as target
names, and an absent Make prefix (#f). Gerbil still expands/imports and
=std/make= still compiles, checks hot products and cleans. Source-view descriptors
are the existing adapter's materialization, not a loader or cache layer.
