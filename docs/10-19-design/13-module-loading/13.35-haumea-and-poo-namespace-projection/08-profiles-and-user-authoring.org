* Governance-only downstream compilation

The Lab qualification consumer declares =governance= in its own
=init.ss= source window. The selected owner lives in
=modules/governance/publication= so existing Gerbil imports of
=agentic-ai-lab/modules/governance/interface= keep their identities.
The owner's Build role declares that public library root. The same
init export supplies the visible namespace and =std-make-spec=.
The downstream build adds its own application roots and installs the
selected foreign artifacts in its own Gerbil environment.

The native fixture's specification, cold compiler events and emitted
=.ssi= identities agree on eleven targets. Nine belong to Governance
and two to the consumer. The qualification prerequisite path omits
Lab products. The hot build emits zero compilation events, and the
consumer imports the Governance library and reads the declared owner
through native =.get=. On a hot projection, an owned library's =.ssi=
context must be replaced by the context of its confined declared source

are still checked. This rule applies only to owner library roots.

For a one-off selection, the Yuanxu build-script wrapper accepts
=./build.ss spec --modules governance= and
=./build.ss compile --modules governance --debug=. It consumes the
module IDs before asking init for the build specification. The existing
selected graph resolves the IDs and their dependencies, and the
native script receives its original command and remaining options.
The Lab's explicit selection bypasses its legacy retained roots.
Downstream application roots still belong to the downstream build
declaration. Native =gerbil build= continues to use the package's
unflagged build script.

The fixture starts with an available Lab source checkout. It does not
qualify the producer's default install build or migrate Lab's other
retained public roots.

* Profile selection by declared Interface tags

A Module Interface explicitly declares its tags as literal metadata
under the Interface authoring Contract. Its tag list is nonempty and
contains distinct classification symbols. A tag is a classification of the canonical
owner and grants no visibility or admission authority. Classification
must be readable without expanding author callbacks or forcing a scope.

The consumer's =yuanxu!= declaration owns the selected Profile and
its scope. Scope specifies the source window and allowed owner domain.
The Profile name is itself the tag used to select roots within that
domain. There is no second tag selector in the init declaration.
With several windows, matches for the same category are combined. A window
without matching roots may still supply differently classified dependencies;
a category with no matches in any of its declared windows is refused.
Relative paths, including parent components, resolve against the downstream
declaration. The declared windows and owner/currentness admission remain the
source boundary. Aliases deduplicate by
canonical owner. No tag match can widen a source window, enable a
denied owner, or replace the owner's dependency declarations.

Resolve this root set once through the existing namespace metadata
projection. Runtime demand, =std-make-spec= and selected tests all
consume the same selection. Required dependencies follow their own
edges within the source policy even when they have different tags.
An independent full catalog certification retains its own root set.
Build and test projection do not construct runtime scopes to find
their classification. Source and effect currentness checks still
belong to the individual admission boundaries.

The source-window syntax is =mode: auto profile: security=. It
matches the =security= tag in an Interface's declaration such as
=tags: '(security audited)=. Differently classified
dependencies can enter the closure through their declared edges and
are kept outside the root namespace. Existing windows without a
Profile do not perform this classification pass. The =./build.ss tags Security.TAGS= action sends the selected
build graph's original source files to native Gerbil's TAGS writer.
It uses the existing guarded compiler-input route so Interface roles
resolve and editor entries point to live sources. Currentness is
checked before indexing and before replacing the named output. The
normal editor =TAGS= file remains managed by Gerbil.

Lab classifies OpenTofu as =deployment=, Nix as =package-management=,
Durable as =engine policy=, and D2 as =graph diagram=. These capability
categories can group multiple owners. The Governance consumer declares
=profile: governance= without listing module identities. Its selected test
source and runtime namespace share the same selected Graph. The test harness
consumes that source's file list against the downstream compiled products.

The real Lab deployment consumer declares only categories:
#+begin_src scheme
(yuanxu!
  :load-modules "../../../modules" rename: Lab mode: auto profile: deployment
  :load-modules "../../../core/modules" rename: Core mode: auto profile: deployment)
(.get yuanxu-deployment-consumer.init.exports Lab services opentofu)
#+end_src
These paths belong to Lab's downstream test package, not to Yuanxu's package
runtime. OpenTofu is the only root. Its =requires= edges bring Nix
(=package-management=), JsonSchema (=schema validation=), and Funflow
(=workflow=) into the selected Graph. No dependency names are repeated in init.
The Core namespace has no category roots; those owners still enter through
the cross-package edges. Native imports outside the selected owner sources
remain installed Gerbil prerequisites. The same selected Graph owns Make
projection and test discovery; the Lab gate compares actual native compile
events and product identities, runs selected tests against B's compiled
products, and checks A's cleanup against B's product hashes.

Ordinary public libraries also need an owner compilation declaration.
=library-roots= strings retain nearest-package-relative paths; a symbol names
a native library in that owner's already declared package kernel. Nix declares
=library-roots: '(agentic-ai-lab/nix-contracts)=. OpenTofu declares
=library-roots: '(agentic-ai-lab/opentofu-contracts)=, whose native imports
include =services= and =nix-contracts=. The existing confined public-library
projection checks native package/header identities and source currentness,
including when its runtime Context is a downstream hot product. It never
admits a new source window. These explicit roots keep cold, hot and clean
inventories identical. Merely finding an optional checkout beside an installed
library or compiler tool must not promote it to a compilation target.

Default Profile test discovery follows this same selected Graph's owner order.
Explicit owner test requests and ordinary non-Profile discovery retain their
bounded, Graph-lazy behavior. Test discovery admits source declarations without
constructing business scopes; execution uses the existing test harness.

* Ordinary authoring stays short

Start with an actual configuration value and native lexical slots:

#+begin_src scheme
(.def BuildProfile
  executable: "gerbil"
  flags: '("build")
  argv: (cons executable flags))

(.def (DebugProfile @ BuildProfile)
  (flags => append '("--debug")))

(.get DebugProfile argv) ; ("gerbil" "build" "--debug")
#+end_src

=argv= reads the derived profile's flags even if the parent's =argv= was already
forced. The parent cache remains its own. Direct assignment replaces a known
value; =(flags => append ...)= transforms the inherited value; =config: =>.+ ...=
refines an inherited object while retaining its other slots. Use an explicit
per-slot =(sup)= only for conditional inheritance or more complex expressions.
It is a computation, not a promise that repeated calls are separately memoized;
bind its result once if a formula needs to reuse that result. No new accessor,
configuration DSL or general =lambda (self super)= authoring hook is introduced.
The inherited computation follows the remaining native C4 precedence chain for
this slot. It need not be a single directly declared parent and cannot be used
as a reified parent object for arbitrary other-field lookup.

Native keyword shorthand consumes one transform expression. With extra function
arguments, use =(flags => append '("--debug"))=, or the unary functional spelling
=flags: => (cut append <> '("--debug"))=. Do not write
=flags: => append '("--debug")=: the quoted tail can be parsed as a separate
slot specification rather than an argument to =append=. The native control
checks both supported expressions and absence of an accidental =quote= slot.
This is syntax discipline over the existing POO forms, not new sugar.

Module consumption and business derivation stay separate:

#+begin_src scheme
(def Nix (.get consumer.init.exports modules nix))
(def Source (.get Nix prototypes Source))
(.def (LocalSource @ Source)
  config: =>.+ (.o nix: "/opt/local/bin/nix"))
(.get LocalSource config nix)
#+end_src

Here =Nix= remains the original admitted Module scope. =LocalSource= is an
explicit new business value derived from its public prototype; it retains other
configuration defaults. It does not clone the Module scope for namespace
visibility or acquire new source/build authority. Interface remains the loading
configuration. This example constructs configuration without realizing a Nix build.
These are module expressions under the declared Yuanxu Prelude. A standalone
=gxi use.ss= script must explicitly import the POO construction bindings it
uses (as the product fixture does); it must not rely on ambient interactive
bindings or assume package metadata changes the interpreter's script language.

* Nested objects and functional boundaries

Native hygienic slot bindings may reference the enclosing effective receiver.
An inner same-named slot shadows that binding. An explicitly named inner =self=
denotes the inner receiver; it is not an alias for the outer namespace. Use
descriptive native names such as =self: profile= / =self: task= where necessary.
At an ordinary function boundary, pass values/receivers explicitly; Haumea's
function-argument injection/scopedImport is not an excuse to change Scheme's
lexical scope. Fetching a parent's already computed list and assigning it to a
child intentionally captures that value and cannot substitute for receiver-aware
inheritance. Named functional combinators preserve this distinction.

SysML =LeafReceiverAndInheritance= records these separate capabilities. Lean
=ProfileComposition.Prototype.ancestor_uses_final_receiver= reuses LeanPoo's
actual prototype composition; its captured-parent counterexample separates the
two computations. Native =namespace-leaf-expression-test.ss= checks warm parent
caches, sibling isolation, per-slot =sup=/=super:= equivalence, lazy missing
inheritance, discarded ancestor refusal, nested shadowing and explicit containing
namespace values. Existing =path-slots-test.ss= covers the maintained Pipeline
configuration through the hygienic path adapter. These native observations are
not inferred from an isolated numeric Lean example.
