* Structural reuse without input omission

The reader previously traversed the SDK import graph again on every hit of a
shared source context. The new reader-local index caches only the completed SDK
context list. It does not cache an accepted guard, an initializer result, a Nix
result or a captured input-registration projection.

Input registration can grow while declarations are imported. Every consumption
therefore resolves =kernel-inputs= against the cached context list again. In
[[file:../../../dev/proofs/lean/YuanxuProof/ModuleSystem/Graph/ImportCorrespondence.lean][ImportCorrespondence.lean]], =current_registration_is_never_omitted= and
=later_registration_is_visible= prove why filtering registrations only when the
topology was first cached would be incorrect.

The index has the same completed-context premise as the existing compiler-tool
index: the SDK context import topology is stable within this reader snapshot.
It is not a certificate for arbitrary out-of-band mutation of expander context
internals. Source changes still require a fresh reader, and normal source,
package identity and confinement guards are retained. A general proof that the
SDK enforces immutable completed contexts remains outside these Lean models.

The first native publication control now checks that each actual SDK child is
discovered once per demanded closure, that repeated demands exist, and that
kernel requests exceed first walks. The original confined macro initializer
still runs once; the independent canonical-import negative control still fails.
The source-admission gate also reads one real publication twice through the same
reader, checks the private helper input is retained both times, changes the
helper, and requires old-source refusal. This exercises actual context reuse,
not a test-owned completed-input list.

* Exact source checks

The correspondence reuses =Admission.Source.checkSources=,
=checkSources_certifies= and =returnCheck_certifies=. The new adapter proves:

- =checked_texts_are_current=: the public text checker supplies the demand
  model's actual current-input relation.
- =native_guard_supplies_source_admission=: completed discovery plus complete
  input coverage and a successful current check supply source admission.
- =return_guard_supplies_current_evidence=: initial success alone is insufficient;
  the returned evidence is tied to the after-effect observation.
- =two_revisions_of_one_path_cannot_both_pass=: a later observation cannot erase
  an earlier conflicting revision by merely retaining the same path.
- =native_guard_exact=: regular text, actual absence and nonregular paths are
  distinguished; changed kind/text refuses. A directory or symlink cannot be
  used as evidence for an absent input.

These laws do not prove filesystem snapshot atomicity, path authentication or
SDK import completeness. The kind correspondence additionally assumes reliable
metadata classification: =module-source-type= currently maps metadata exceptions
to false, so error-versus-absence classification is not certified by this model.
That is a specific remaining primitive boundary, not a reason to weaken guards.
The positive-input adapter must not silently treat a failed read as an admitted
negative observation.

** What is reused

Three changes reduce repeated work without caching admission authority:

1. A completed private Graph lookup no longer runs a source guard immediately
   before =link= performs the same fresh eligibility guard. This applies to
   ordinary namespace resolution and =.selected-record=. An unseen demand
   still runs the resolver, including its final check after author slots;
   scope factories and Contracts retain their post-call checks.
2. =.with-packages= seeds the realized view with the original selected Graph.
   The package result must first name the exact build Graph and pass its own
   currentness guard. Realization changes dependency scopes, not source
   selection. A new Schema/source selection creates a new generation instead
   of inheriting this private cache. No business scope or admission receipt is
   copied into the new view's scope cache.
3. The build Graph's source traversal uses =module-source-observe= inside its
   existing pure read window, keyed by the current input-check list. Adding an
   input changes that key. Independent checks, expansion, Contract callbacks,
   file writes and external commands do not inherit this observation window.

Query reuse also includes the active source collectors in its key. Otherwise
a guard observed before a new admission collector could be skipped inside
that collector, omitting evidence needed by its final replay. Each collector
therefore receives its own enrollment; byte comparisons can still reuse the
same stable read-window bytes. This is not a second evidence system.

** Private reader expansion lifetime

The reader must distinguish its generated interpreter wrappers from canonical
SDK contexts. A wrapper is never a compiler input: build projection prepares
the guarded original source with its original compiler identity. The private
context still owns live macro bindings, imports, phase tables and runtime values.
Those are not disposable expansion intermediates.

The release boundary now requires all of the following:

1. The normalized context path is an exact member of the current operation's
   generated-wrapper set. A directory prefix or a Core-looking identity is
   insufficient. Shared canonical dependencies are excluded.
2. The SDK compiler receives the identical =module-context-code= body in phase
   zero. An arbitrary expression evaluated in that context is insufficient.
3. The SDK evaluator successfully returns from that exact compiled program.
   A completed macro-phase initializer or an import alone is insufficient.
4. The requested binding returns and the operation's post-evaluation source
   guard passes. A failed guard preserves the bodies for failure inspection.
5. The context still holds the identical body when release occurs.

The scoped adapter delegates to the existing =current-expander-compile= and
=current-expander-eval= functions and returns their values unchanged. Its
temporary program/body association is lifecycle tracking, not a result or
admission cache. After the boundary it releases only the private context's
=code= reference through Gerbil MOP and clears its own completed-work table.
It does not alter the SDK module registry, imports, phase bindings, runtime
promise, initializer results, or canonical library bodies. The SDK source
separates =module-context-e= (runtime evaluation) from =module-context-code=
(expanded compiler body); both initially refer to the body. Merely removing
one reference before evaluation would neither be safe nor prove reclamation.

The module-evaluation hook alone was rejected as a completion detector:
Gerbil's runtime =__eval-import= calls the runtime evaluator directly, whereas
=current-expander-module-eval= also participates in expander-phase imports.
An earlier isolated cleanup experiment that imported wrappers to obtain their
contexts was also rejected: it expanded an unused related role. Neither
experiment's passing subtests qualify the final lifetime rule.

controls use the ordinary source-only Justfile entry, without compiled Core or
