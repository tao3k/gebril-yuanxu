* Scope and decision

** Official Harness publication, 2026-10-26

A test declaration is a native Gerbil module exporting =TestSuite= values.
The installed =gerbil/tools/gxtest= prepares that module by examining its
runtime exports whose names end in =-test=. A file list is the resulting
Harness input projection; it must not become another maintained inventory of
Suite declarations. A module may use native =export (import: ...)= to publish
existing Suites without reconstructing Cases or invoking a second runner.

The product Context/Temporal qualification now publishes this way. Its former
six-file spec and standalone =t/build.ss= are removed. Both Core and product
test trees inherit their root package identity; no =t/gerbil.pkg= or separate
test language is required. Explicit test macro imports keep the ordinary
Gerbil lexical semantics.

The init-owned =tests= object exposes =.compile= through the same execution
owner as =.run=. Both enter =call-with-prepared-testing-script=, preserving the
captured compiler association, source guard, native artifact issuance and
post-operation checks. =.compile= returns a prepared execution value without
starting the Harness. =.run= independently authenticates currentness and uses
the issued native outputs before invoking =gerbil test=. Returning that value
does not cache an admission result.

An explicit file demand may include auxiliary command inputs (for example,
the qualification's actual watchdog script). These are source observations,
not Harness arguments or Make roots. They remain checked before and after
the operation and never expand the Suite set.

Package-level implementation regressions can use =tests.for-directory= over
their bounded =t/= tree. Discovery reads names and prunes excluded branches;
leaf bytes are bound at first admission and checked again after execution.
Module public behavior remains exported by the existing owner-confined
=modules.<owner>.tests= projection. Both publish ordinary native file specs.

The new split-phase and module-publication paths require their own executable
qualification. Earlier compile counts or passing Harness logs below must not
be treated as results for this migration.

The discovery regression must not execute the complete selected test group
inside one Case. That demand compiled 54 production support units before the
bounded inner run failed; it was integration work hidden inside a mechanics
test. The complete group is retained as the external =test-selected-modules=
gate. Native test values must be exported with the installed Harness's =-test=
suffix; an exported value named only =atomic= does not establish Case execution.
The preparation control therefore checks both a module-load marker and an
actual TestCase marker: neither may exist after =.compile=, and both must
exist after =.run=.

SDK-only progress and role-name utilities now explicitly use =:gerbil/core=.
This changes import cost, not execution policy or wire format. The focused
support-free run passed in 30.13 seconds, followed by 24.57 seconds in a fresh
process; neither result qualifies the compiled-support path. That path first
refused a mismatched compiler-tool context for =source/declaration.ssi= in a
mixed local library environment. Its identity check remains mandatory; no
fingerprint update or successful minimal run substitutes for rebuilding a
consistent declaration cohort and rerunning the stronger controls.

Recompiling =declaration.ss= and =deferred-declaration.ss= into the first
library prefix changed the reported path to that new prefix but did not remove
the identity refusal. Consequently stale bytes or a mixed prefix alone are
not an established cause. The reader's exact context association still needs
diagnosis; its identity check has not been weakened. The diagnostic now names
the native context identity and path instead of reporting only a generic
publication failure.

*** Context identity, not module-name uniqueness

The expanded diagnostic established two observed contexts with the same
=yuanxu/module-system/source/declaration= name: one has a =.ss= source path,
the other the installed =.ssi= path. The previous bootstrap name index retained
only one. Using that index as the complete context-membership predicate was
incorrect even when no source bytes changed.

=yuanxu-bootstrap-contexts= now accepts an optional native DFS visitor. Its
existing name projection remains available for named lookups. The reader uses
that visitor to retain every exact observed context in an identity table and
builds its input/path indices from that table. Publication, configuration and
private-closure cuts use the same captured identity membership. The table is
not extended by subsequent imports: an unobserved same-name or same-path object
still fails. Currentness and per-demand source checks are unchanged.

This repairs the implementation's correspondence premise rather than weakening
it. The existing =ContextWalk= model distinguishes node identity from names;
the existing =expanded_identities_unique= theorem in =SourceClosureWork.lean=
assumes equality on those identities. Neither proves that a name projection is
injective. The native publication oracle now collects exact contexts through
the same visitor and still compares full versus pruned traversal order. These
models are not new proofs of the Scheme index or runtime execution. The
compiled-support regression must pass independently.

The focused native =module-context-walk-test.ss= subsequently passed all three
Cases through default =just test-file=, with =MODULE-OK=, =HARNESS-OK=, final
=OK= and no error/overflow markers. Its new bootstrap Case checks one visit
per exact context and coverage of the name projection. Existing Cases retain
postorder/cut equivalence and bounded synthetic context-graph traversal. This
is not a ten-thousand-module Loader qualification. Total wall time was 61.96
seconds; the three Cases took 3.767, 0.080 and 1.117 seconds respectively.
The demand had zero support units; remaining startup is not Case execution.

The stronger preparation regression passed the former context-refusal point
and reached native Make with 23 actual support units. It then failed the
unchanged 120-second compilation budget (outer wall 152.60 seconds), before
Harness execution. The failed record is retained locally. It does not prove
the support-free poison-role Case, signed hot reuse, source-change refusals or
the complete publication oracle passed on this snapshot. No further identical
cold rebuild is warranted until the support compilation cost is attributed.

*** Empty support does not import compilation/signing

The next source audit found two eager imports even after graph selection was
deferred: the test build accessor imported =building/build-projection= to
discover an empty spec, and =TestingScript= statically imported artifact APIs.
Native runtime module reuse cannot eliminate these imports in a new process.

The existing owners now separate the phases:

- =source/build.module-test-source-spec= discovers the demanded native import
  closure, retains source observations and returns a POO spec. No directory
  catalog or peer suites are scanned. The discovery body was moved from the
  build adapter; target-name validation is shared through =source/preparation=.
- The init facade acquires that function through a private native promise.
  Importing init still does not import =source/build= or construct its products.
- An empty spec returns observed data and its currentness / lazy selected-graph
  guards, without a build publication. =tests.compile= remains a checked no-op.
- Only nonempty support requests acquire =artifacts.test-build-projection=.
  That owner attaches the existing endpoint, =.compile= and =admit-artifacts=
  through native prototype inheritance. Empty support is rejected by that
  attachment function before publication construction.
- =TestingScript= acquires the two existing artifact bindings only inside its
  nonempty preparation branch. The promise retains native function identities,
  never a guard result. Private expansion contexts first import =:gerbil/core=
  so =only-in= and ordinary value syntax have native bindings.

An import/initializer is not a pure observation window: discovery rechecks
its source guard after the artifact producer returns. Compiler authority,
required build-accessor identity and final currentness remain with their
existing owners. No Builder, restored-verdict cache or alternative Harness is
introduced. Empty support intentionally does not expose signing operations;
the user-facing =tests.compile= / =tests.run= interface is unchanged.

*** Delegate to public std/make; preserve compiled-library boundaries

The installed Gerbil =std/make.ss= exports =make= and =make-clean=, together
with platform/configuration helpers. Its =make= entry owns spec normalization,
duplicate-target refusal, inputs/outputs, dependency timestamps, dependency
completion waiting and worker scheduling. =std/build-script.defbuild-script=
owns ordinary CLI dispatch. Core must not mirror those algorithms or reach
into private =make-build=, =build?= or =dependency-timestamp= implementations.

Native Make schedules the targets supplied in a spec; it does not select Core
Modules/Features or enumerate additional private test helpers for us. The
remaining projection must therefore identify only the selected, owned targets
and retain provenance. Byte/currentness admission and approved publication
are distinct from Make's timestamp-based incremental decisions. They do not
justify another build scheduler or a second compilation cache.

The existing execution still calls the public entry directly:

#+begin_src scheme
(make spec srcdir: root libdir: output)
#+end_src

The next audit found that the discovery import hook remained active *inside*
compiled =.ssi= libraries. It could redirect their native dependencies to
package source files, depending on prior SDK imports. This reconstructed
library sources as test targets. The hook now delegates the complete compiled
library import to the captured native importer, matching the existing reader
boundary. Explicit source files/private helpers retain their original input
guards. The full native dependency graph is still visited and compiled
interfaces are still source observations; no discovered edges are filtered
out to manufacture a smaller count.

*** .for-export boundaries and closed requirement batching

The next attribution follows the actual calls, rather than classifying the
whole Fixture as preparation. The existing observer now keeps bounded scalar
effect/read and effect/check-time rows in ordinary observation mode; deep
receiver/retention tracing remains separately lazy. =export-entry= and
=publication-base= label existing calls without granting reuse authority.

| Boundary | Actual operation | Why the boundary remains |
|----------+------------------+--------------------------|
| export-entry | =admit-build-artifact-publication!=, including the demanded build Graph | Before export scopes may execute author code; artifact recovery is an effect |
| selected-record | =selection .selected-record=, native linking, dependency/scope Contracts | Scope factories and validators are open calls |
| publication-base | =module-admission-publication=, descriptor/value paths | Recheck after scope resolution; lazy export getters can run code |
| bind-contributions | route index, guarded =collect=, Context assembly and final =current!= | Before/after exported payload getters, complete provenance and return certification |
| contract-admit | direct or published Contract invocation | Fresh root admission, including contextual child obligations |
| entry-current / meaning-current | publication entry / dependent return meaning | Independent calls and post-effect return checks cannot inherit earlier bytes |

An instrumented intermediate snapshot attributed 16,830 reads to export entry,
3,894 to selected records, and 2,596 to publication-base over eleven fresh
Fixtures. Thus the warm Just process still constructs eleven independent
source-backed selections: it is not eleven accesses to one warm receiver.
Read windows include metadata traversal, file queries and comparisons, not
just disk I/O. Nested operation times are not additive to parent spans.

An attempted schema-free Context deferral removed 649 reads, but was withdrawn.
=compiler-current= is replaceable and is not implied merely by checking an
equal list of source files at return. The existing Lean
=ReturnWindows.defer_covered_check= theorem covers actual byte requirements,
not arbitrary Scheme policy procedures. The expanded existing admission
regression now covers Schema/no-Schema paths and custom compiler/request
refusals; it must preserve their execution before cold handlers and at return.
All original Context/compiler guards remain in the production implementation.

The retained production change is narrower: when collectors are active,
=module-source-admit-current!= uses the existing pure window's native identity
tables to avoid traversing the same requirement-list object twice for the same
active collectors. Metadata-only checks without collectors keep their existing
per-source index, rather than allocate an ineffective batch index. It shares
neither a Context, a Contract verdict nor an issued read record. The table is
owned by the existing dynamic window and disappears at its end. Equal but
distinct list objects are not merged; nested collectors use different keys;
only a successfully checked batch is indexed. The collector's original first
diagnostic remains authoritative.

This applies only when no source observer is installed. Open observers retain
the original checks/callback order; no observer is disabled or suppressed.
The closed action reads filesystem inputs and the fixed private collectors,
without calling domain methods. It relies on the existing documented window
condition: bytes and input requirements remain stable, and callers end the
window before writes or callbacks. It does not extend a window over a getter,
obligation, package process or independent admission. An implementation using
structural query keys was rejected because it rehashed source text; the final
index uses native identity, as the existing expected-text index already does.

The existing six-Case source-observation suite now exercises this closed path
under the native default Case/resource Profile, without installing or removing
a source observer. Its private operation counters prove two independent
windows read twice, a repeated batch avoids another enumeration, and a nested
collector still enrolls its requirements. Conflicting expectations reject;
editing the file makes both enclosing and nested collectors refuse with their
own first diagnostic. The remaining Cases continue to exercise open observers,
parent caching, nested obligations, source mutation and unselected branches.
These are executable Scheme controls; no new Lean or QNT theorem was added.

This distinction also limits the performance claim: the collector optimization
does not remove the cold selected-Graph/role work in eleven fresh Fixtures.
Neither the rejected 649-read deferral nor its intermediate timing is a landed
improvement. Custom =compiler-current= refusal is tested independently of
request refusal and source-file equality, including the no-Schema path. Those
policies and both sides of open callbacks remain executable requirements.

The producer now participates in that data flow: =source-object-slots= creates
one private input batch per file *within one fresh object construction*, and
each located specification retains that batch. Previously it reboxed the same
input row separately for every field. Specifications, locations and procedures
remain distinct; parent/child constructions do not share a mutable snapshot
registry. The existing SDK-expansion regression verifies distinct port/client
specifications, one physical read, and no repeated per-source comparison when
their actual macro-produced batches are enrolled together. This qualifies the
producer/consumer association, rather than only a synthetic shared-list fixture.

Today =artifacts.ss= indexes =issued= by the build-graph receiver alone. That
cannot distinguish production and tests sharing the same graph. Reusing it
unchanged would overwrite or invalidate the wrong publication.

receiver's admitted compilation projection, not another Core identity token.

publication. A public =tests= symbol or caller-supplied pathname is insufficient.
