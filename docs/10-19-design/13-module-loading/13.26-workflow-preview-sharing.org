#+title: 13.26 Unified Preview Ownership: Closure, Diagnostics and Doctor

* Architecture and complete refactor boundary

This document is the owner of the complete preview dataflow, not a sequence of
independent helper optimizations. Evaluation owns the module closure and root
diagnostics; workflow and doctor consume evaluation; pure diagnostic algorithms
operate on that already-closed list. Admission/publication retain their separate
source and effect boundaries.

| Data | One owner | Consumers |
|------+-----------+-----------|
| Final root module | preview config slot | evaluation, runtime/root projections |
| Ordered module closure | evaluation.modules | ids, phase order, hooks, options, diagnostics, doctor |
| Root value diagnostics | evaluation.root-validation-receipts | root view and aggregate view |
| Structural report | doctor.doctor-report | status, warning details |
| Admission/currentness | existing publication/Contract invocation | explicit independent release only |

The earlier doctor path computed a closure in its factory, then computed it again
in doctor, diagnostics, missing-import findings and evaluation. Source inspection
identified five reachable closure constructions in that path. This is a source
call-path count, not a runtime profiler measurement. Those calls now terminate at
the one native modules slot; ordinary metadata passes over its list remain.

#+begin_src scheme
;; Existing evaluation object:
config: module
modules: (agentic-ai-lab-module-closure (list config))
module-ids: (agentic-ai-lab-module-names modules)
;; Phase order, projections and aggregate diagnostics also consume modules.

;; Existing doctor object:
config: root-module
evaluation: (agentic-ai-lab-module-evaluate config)
doctor-report: (agentic-ai-lab-module-doctor/closed (.get evaluation modules))
module-ids: (.get evaluation module-ids)
#+end_src

The closure is no longer captured in an eager outer let. Native lexical config
references bind it to the final receiver, so derived evaluation/doctor objects
do not accidentally reuse a captured parent graph. No extra graph wrapper,
per-module preview-node family, revision registry or global memo is added.

Public standalone doctor/diagnostic functions still accept roots and close them
once. Their internal pure algorithms accept the closed list. The explicit
doctor/closed and missing-imports/closed functions allow existing preview owners
to supply that list without reclosing it. They are data-processing APIs, not
tokens certifying completeness or permission. Missing import semantics remain
owned by Core module-missing-imports; Core DFS, key deduplication and cycle
termination are unchanged.

The delivery boundary for future edits is this entire ownership chain. A local
helper count is insufficient: changes must jointly check producer demand,
all consumers, fresh/derived receivers, diagnostic order and real publication
refusal. This refactor updates the existing call sites together rather than
leaving a parallel old preview pipeline.

* Source finding and ownership

Workflow root-validation-receipts called the module diagnostic producer directly.
Its evaluation's aggregate validation-receipts called the same producer again
for the root. Reading both views therefore repeated the root analysis.
The two fields were native slots, but they did not share the same producer slot.

The existing evaluation object is now the owner of root-validation-receipts.
Workflow root and aggregate views both read that object. No per-module cache-node
family, promise, hash memo, restore protocol or admission cache was introduced.
The implementation lives in Agentic AI Lab's existing
modules/workflow/scenario/configuration/module-runtime-presentation.ss.

#+begin_src scheme
;; Inside the existing evaluation object:
root-validation-receipts:
(agentic-ai-lab-module-option-validation-receipts config)
validation-receipts:
(agentic-ai-lab-module-append-projection
  modules
  (lambda (current)
    (if (eq? current config) root-validation-receipts
      (agentic-ai-lab-module-option-validation-receipts current))))
#+end_src

The root is identified by actual object identity, not an invented name-to-result
registry. Existing closure order/deduplication remains owned by Core's module
closure function. The root still occupies its original position in the aggregate;
its diagnostic objects are reused rather than reconstructed.

The native correspondence is the pinned
[[https://github.com/tao3k/gerbil-poo/blob/85a76738093622aff7e2a3482ad00d035ff38c1e/object.ss][POO lexical slot/read implementation]]. Ordinary cache-hit read/dependency
replay remains native. No raw read records are manufactured or dependency edges
removed, and no observer is disabled to obtain sharing.

* Final receiver rather than a captured parent evaluation

Workflow previously constructed runtime/evaluation objects in its outer let.
Deriving the workflow's config could therefore retain a captured parent view.
Those views now depend on the workflow's native lexical config slot:

#+begin_src scheme
;; Inside the existing workflow object:
config: module
runtime-module: (agentic-ai-lab-module-apply config)
evaluation: (agentic-ai-lab-module-evaluate config)
root-options: (agentic-ai-lab-module-option-configs config)
option-schemas: (agentic-ai-lab-module-option-schemas config)
root-validation-receipts: (.get evaluation root-validation-receipts)
validation-receipts: (.get evaluation validation-receipts)
#+end_src

Runtime projection is still data construction, not handle creation/execution.
Both evaluation and its diagnostics are demanded through existing native slots.
The inherited expression receives the final workflow receiver; a child whose
config differs constructs its own evaluation. Parent evaluation/results retain
their identities. No second wrapper object is added around evaluation.

Measurement channels remain distinct:

- Gambit's native =##exec-stats= measures instrumented workload wall, CPU and GC
  time. VM allocation accounting is labelled explicitly, never owned heap bytes.
- Native slot observers count all delivered events without deduplication. Actual
  source-observer replay start/end and visit events measure reader replay; zero
  events mean no such reader hook ran, not that all MOP work disappeared.
- After timing, an identity DFS inspects original issued records and every
  dependency occurrence. Shared record/receiver identities are counted once;
  edges and deliveries remain distinct. The census neither replaces replay nor
  retains strong record roots after its frame returns.
- Explicit post-GC process live bytes are auxiliary process measurements. Weak
  record keys report surviving identities while the preview is held and after
  its construction frame returns. These observations do not assign Gerbil memory
  to every preview or establish exclusive transitive closure bytes.

** Existing convergence versus unsafe reductions

Inside the six 126-request windows, the existing byte cache serves 67 requests
without another physical read, for 402 avoided reads across the invocation.
The path census finds ZERO repeated physical paths inside each active window.
This does not make identical paths across different windows redundant: their
observed worlds can differ. It also does not merge two contributors' expected
revisions or their diagnostic origins.

The six reader passes occur at distinct boundaries. Within a pass, the existing
link-current query reuse and native issuer-owned traversal projection already
apply. A structural projection hit still authenticates original tokens and
installs/unwinds its own frame. This study does not derive a right to reuse a
previous token-current result, suppress an observer, concatenate callback frames
or erase repeated signed edges.

The 54312 count is visitor deliveries, not the count of all authentication
instructions or distinct records. In the fixed native =object.ss=,
=replay-slot-reads!= calls =current!= before delivering each record and
=call-with-issued-reads= calls it again over the traversal before returning.
Thus the six successful 9052-visit reader passes imply 108624 =current!= calls
in those passes, by source correspondence. Projection acquisition also checks
issuance. This is a source-derived count, not separately instrumented timing,
and excludes SourceAdmissionContract's own recorded-source replay. It must not
be used as an exclusive allocation or duplicate-work estimate.

Consequently this unit does NOT claim a new 417-to-smaller read reduction or a
54312-to-smaller authentication reduction. It closes the end-to-end attribution
and adds executable convergence checks to the same cohort. Arbitrarily widening
the byte window would implement the QNT cross-effect bug rather than an
optimization. Further work must distinguish topology preparation, fresh token
authentication, domain callbacks and filesystem observations at these boundaries.
