This is analyst-written code using the inspected API, not an official Gitea
component or a complete deployable Stack:

#+begin_src typescript
const config = new pulumi.Config();
const port = config.getNumber("postgresqlPort", { min: 1, max: 65535 }) ?? 5432;
const giteaPort = config.getNumber("giteaDatabasePort") ?? port;

Changing the one stack setting to 5433 changes the derived client default.
Explicit mismatch can be checked in the component. The SDK already supplies

relationship checks are a separate concern. This source reasoning is sufficient
to reject the claim that only our language can express the relationship. It is
not a measured preview, full port Contract or provider correctness result.

* Unknown endpoints change the problem

For an endpoint produced by a resource, the value carries dependency information.
The pinned apply implementation propagates allResources, isKnown and isSecret
into the derived Output. When the value is not known and the callback has not
requested unknown handling, applyHelperAsync does not run the callback. This is
existing SDK behavior, not an alleged missing feature.

A known local Scheme port equality check cannot demonstrate equivalent unknown,
secret or resource-edge handling. The official manual warns against creating
resources inside apply when their absence from preview would hide changes.
Native lazy POO slots alone do not solve this; an external-value protocol and
appropriate admission phases remain our design obligations.

** Analyst-written known-data application guard

This function addresses our extra JSON-like application envelope, not Pulumi's
engine plan. It is unexecuted analysis code, not an upstream component or a
requirement on ordinary users. Its route/source inputs have the same bounded
meaning as the Nix adapter in 20.10; their trusted collection is still a separate
maintainer responsibility.

#+begin_src javascript
const { readFileSync } = require("node:fs");
const { createHash } = require("node:crypto");
const { isDeepStrictEqual } = require("node:util");
function admitApplication({ candidate, rows, requiredRoutes, sources }) {
  const key = r => JSON.stringify([r.owner, r.exportPath]);
  const actual = rows.map(r => key(r.origin));
  const expected = requiredRoutes.map(key);
  if (actual.length !== expected.length ||
      !expected.every(id => actual.filter(x => x === id).length === 1))
    throw new Error("application: incomplete or substituted contribution routes");
  for (const s of sources) {
    const digest = createHash("sha256").update(readFileSync(s.path)).digest("hex");
    if (digest !== s.digest) throw new Error("application: observed source changed");
  }
  const port = candidate.config.postgresql.settings.port;
  const client = candidate.config.gitea.database.port;
  if (!Number.isInteger(port) || port < 1 || port > 65535)
    throw new Error("config.postgresql.settings.port: invalid port");
  if (!rows.every(r => r.payload.allowedPorts.includes(port)))
    throw new Error("config.postgresql.settings.port: conflicting requirements");
  if (client !== port) throw new Error("config.gitea.database.port: connection mismatch");
  if (!isDeepStrictEqual(candidate.plan.configuration, candidate.config) ||
      candidate.plan.postgresql.port !== port || candidate.plan.gitea.databasePort !== client)
    throw new Error("plan: stale projection");
  return candidate;
}
#+end_src

The function accepts already-known, correctly shaped ordinary data. It does not
preserve Output dependencies or secrets, defer unknown checks, authenticate
routes, capture transitive inputs, make checks atomic, or implement an engine
transaction. Do not apply it directly to an unresolved Output or claim this is
all code needed for a production Pulumi policy system. A component or policy
library could centralize equivalent domain checks.

Reflection: our candidate difference is centralizing collection and binding of
selected obligations before domain admission. Pulumi's existing engine plan is
counterevidence against a broader exclusivity claim. Source-bound requirement
coverage across native object derivation, external Output adaptation and the
relative authoring cost require distinct evidence. Responsibility comparison:
[[file:../../30-39-research-foundations/32-module-assurance/32.02-maintainer-publication-comparison.org][32.02]]. The reported #20536 interaction is not fixed by either synchronous
guard shown here; no related resolving PR was verified.
