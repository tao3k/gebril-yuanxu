* Pulumi: a general language still needs dependency-bearing values

Primary sources:
- [[https://www.pulumi.com/docs/iac/concepts/inputs-outputs/][Pulumi inputs and outputs]].
- [[https://github.com/pulumi/pulumi/blob/master/sdk/python/lib/pulumi/output.py][Pulumi Output implementation]].
- [[https://github.com/pulumi/pulumi/issues/20536][Pulumi issue 20536]], reported 2025-09-22.
- [[https://github.com/pulumi/pulumi/issues/10209][Pulumi issue 10209]], reported 2022-07-21.

Pulumi tracks dependencies through Inputs/Outputs; outputs are not ordinary
strings. Its SDK carries knownness, secrecy and resource relationships, and
provides transformation helpers. Access convenience does not justify discarding
these properties. The implementation warns against creating resources in apply
callbacks because those callbacks may not execute when values are unknown.

Issue 20536 reports a nested component configuration interacting with a resource
transform such that a mapping becomes an Output and validation fails. This is a
report about composition and abstraction boundaries, not proof that every Pulumi
component behaves that way. Issue 10209 discusses partial provider configuration
and ambiguity between empty responses and unknown results in preview.

Our inference: a Scheme value transformation must preserve unknownness, secrecy
and dependency origin wherever an external result is involved. A lazy POO slot
is not, on its own, an asynchronous provider Output. Contract admission needs
an explicit policy for unknown values instead of accepting an empty placeholder.

Reflection: can simple fields remain simple when one nested field is unknown?
Can final-value validation wait without converting the entire object into an
opaque wrapper? Can diagnostics name both the user's field and the transformation
that changed its meaning? These are required design experiments, not solved facts.

Conclusion: choosing Scheme over a DSL does not eliminate effect and dependency
semantics. The prospective gain is a coherent native object/function vocabulary;
the missing part is a specified adapter for external values and partial plans.

* Independent reflection and questions

1. Can one unknown ingress-rule field remain local rather than wrapping the whole user configuration?
2. What transformations preserve dependency and secret information?
3. What can preview promise when a component or provider value is not known?

* Conclusion

The reviewed material identifies a concrete design boundary; it does not establish
Scheme/POO superiority. The questions above and the matched scenario determine
what must be investigated next. Do not mark this dossier complete merely because
its organizational structure exists.
