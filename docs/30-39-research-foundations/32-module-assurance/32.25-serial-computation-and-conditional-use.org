#+title: 32.25 Serial Computation and Conditional Use
#+language: en

* Decision

[[file:32.24-revision-aba-and-use-boundaries.org][32.24]] established that endpoint checks do not fence later use. This follow-up
asks whether existing MOP frames or dynamic parameter scopes supply that fence.
Only qualification tests, formal models and documentation change. Production
Scheme and Loader do not change. No caller-supplied purity flag, invented native
epoch, manually installed active frame, or new public DSL is used.

The answer is deliberately narrower than a transaction:

- A real cold slot computation prevents supported writes whose invalidation
  closure intersects an actual active receiver/construction in that thread.
- The same serial call can still mutate an independently read object or write a
  file. A source-observer parameter scope does not turn either into a transaction.
- Cached method lookup and calling the resulting procedure are distinct. A
  complete admission call is not automatically an active MOP computation.
- Final replay/source checks protect returned certification, not an earlier
  effect. An external conditional commit needs an authority that atomically
  compares its own version/precondition and applies the effect.

re-entry are not qualified by these tests.

** Cold protection, warm caching and return boundary

#+begin_src scheme
(.def Root
  port: 5432
  preview:
  (let ((before (object-revision Root)) (value (.get Root port)))
    (set! calls (+ 1 calls))
    (refuses "object mutation during computation"
      (cut .putslot! Root 'port ($constant-slot-spec 9999)))
    (check-equal? (object-revision Root) before)
    value)
  unused: (error "unselected branch forced"))
(check-equal? (.get Root preview) 5432)
(check-equal? (.get Root preview) 5432)
(check-equal? calls 1)
(.putslot! Root 'port ($constant-slot-spec 5433))
(check-equal? (.get Root preview) 5433)
(check-equal? calls 2)
#+end_src

No active state is fabricated: evaluating the cold slot establishes it. The
attempted write is refused before revision changes. The warm read returns a
value without rerunning the body. Once evaluation has returned, supported writes
are allowed and invalidate the preview. The unused branch stays unforced.

** A serial cold computation can edit an external demand

#+begin_src scheme
(.def Database port: 5432)
(.def Application
  preview:
  (let (value (.get Database port))
    (.putslot! Database 'port ($constant-slot-spec 5433))
    value))
(def roots (recorded (cut .get Application preview)))
(check-equal? (.get Database port) 5433)
(refuses "stale slot dependency"
  (cut replay-slot-reads! roots (lambda (_receiver _key) (void))))
#+end_src

The Application frame is active, but Database.port has already returned and
Database is not its prototype/invalidation ancestor. The write succeeds; the
Application revision stays unchanged. Full demand replay rejects the old read.
This is a same-call sequential counterexample, requiring no scheduler race.
The expression demonstrates a rejected impure computation, not recommended
configuration code.

** Warm replay is not callback exclusion

A recorded Root.port read is replayed with an observer that increments a local
counter and changes Root.port. The native final sweep raises
=stale slot dependency=. The counter is still one and the new port remains 5433.
Suppressing read observation during replay does not suppress arbitrary effects
in the observer. This control exercises actual native replay, not a replacement.

** Source writes remain possible inside a cold frame

DirectoryFixture supplies a temporary =input.json=. Root.preview reads =before=,
then inside an actual source-observer parameter scope writes =after= and reads
it back. The slot returns =before=; the observer binding restores, and the file
still contains =after=. Dynamic scope and active MOP computation do not guard a
file. This test does not publish or execute an external deployment.

* Serial guarantee versus external commit

A serialized sequence of already-closed kernel reads with no intervening
callback/mutation can compare and consume the same in-memory state. That is a
conditional reasoning boundary, not a blanket property of =.admit= or any
procedure called inside =parameterize=. This work tests hostile operations to
show exactly where native protection ends; it does not relabel arbitrary Scheme
functions as closed or infer purity from their names.

For Gitea/PostgreSQL, admission must still retain both independent port
requirements, child Contract obligations, final candidate/plan identity and
selected source checks. A valid preview says which effective configuration was
admitted. Returning it does not reserve a database port, freeze a source file or
force a deployment engine to apply that exact plan.

If a later effect depends on an external version, the external owner must offer
one of the following sufficiently strong boundaries: atomic compare-and-apply,
a transaction/snapshot with a conditional write, or an equivalent enforced
fencing protocol. The condition must bind the applicable candidate/plan and
relevant resource identities, not just a timestamp or a local cache hit. A local
hash comparison followed by an unguarded write still has a gap. Detecting a
restored-value history also requires a monotonic external version if that history
matters; content equality alone certifies bytes, not absence of intervening edits.
No such external authority is implemented here.

* Lean correspondence

[[file:../../../dev/proofs/lean/YuanxuProof/Admission/SerialUse.lean][Admission/SerialUse]] imports the existing LeanPoo-backed admission models
through SnapshotLifetime. Its actions are concrete: affected edit, independent
demand edit, source edit and read. The =cold= argument projects a real captured
native frame, never a user assertion of purity. Native identity-based closure
membership and complete projection remain premises.

- =serial_cold_trace_preserves_root=: every modeled action sequence preserves
  the active root's revision because intersecting edits are vetoed.
- =cold_does_not_freeze_demand= and =cold_does_not_freeze_source=: that same
  root protection permits an independent demand/source revision to change.
- =checks_keep_requirements=: acceptance retains both requirements, child owner
  and complete projected state equality.
- =changed_version_refuses_commit= and =version_aba_refuses_commit=: an atomic
  conditional-commit relation rejects changed external versions, including a
  two-step revision even if external values could be restored.
- =local_success_not_commit=: an earlier local success does not imply success
  at a later version. The conditional relation is an external-provider premise,
  not a proved native file API or a new Scheme implementation.
- =preserves_diagnostic_schedule=: reuses the earlier ordered-failure theorem;
  it does not reorder source failure behind a later stale-plan diagnostic.

The trace theorem is about the concrete transition model under serialized
supported calls. It neither extracts all Scheme procedures nor proves native
thread synchronization. A rejected write can still have unrelated effects
before attempting the write; whole-callback rollback is not inferred.

* Quint correspondence and matched controls

[[file:../../../dev/proofs/quint/SerialUse.qnt][SerialUse]] models preparation, an intervening operation, use, ordered
certification, a later external write, and conditional commit. Terminal states
have an explicit self-step. Native active protection and external conditional
commit are separate transitions; the latter is an explicitly assumed atomic
relation. Its monotonic source version is not a native MOP field.

| Variant | Required observation |
|---------+----------------------|
| positive | Active-root protection, both requirements, child owner, complete read currentness, source-first diagnostics and conditional commit |

| dropB | Unsafe omission of the second independent requirement |

* Relation to the real Scenario

The unchanged lifetime regression first caches the parent's plan at 5432, derives
Release at 5433, and admits the child through the real published Contract with
two contributions. Its final Gitea plan reads 5433 while the parent cached scalar
remains 5432. Source-observer ABA then modifies the selected JSON, and native
=.admit= rejects =configuration source changed=. If both source and read record
are stale, that earlier source diagnostic still wins. These are independent
regression controls, not properties supplied by the new conditional-commit model.

Ordinary users retain assignments and native refinement. They do not supply
frame flags, version histories or source lists. Any future effect boundary must
be owned by the runtime/provider; pushing those details into configuration would
hide a missing system guarantee rather than repair it.

* Consequence for the proposed optimization

Do not remove a before/after or return source check merely because both occur
inside one dynamic parameter scope or one =.admit= call. Cold getter protection
is narrower than read-graph stability; replay observers are still callbacks.
The existing raw-state extraction can identify selected records and actual
frames, but it does not certify every user procedure's behavior. Reuse across
such a callback remains unqualified. A future stronger production boundary must
justify its own exclusion/conditional-use mechanism rather than accept a manual
"pure" declaration. The native and formal controls here identify that remaining
obligation; they do not implement the optimization.
