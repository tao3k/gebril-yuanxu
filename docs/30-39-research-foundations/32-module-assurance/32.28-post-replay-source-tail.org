#+title: 32.28 Post-Replay Source Inspection Can Invalidate Admission
#+language: en

* Result: an actual limitation, not a repaired guarantee

[[file:32.27-source-admission-body-observation.org][32.27]] verified changes made during the observed body. This chapter moves
fault injection after the production MOP replay, into the real final source
collector. The current SourceAdmissionContract can return accepted evidence
after the selected objects or an already checked source become stale.

The production code is unchanged. Passing a limitation test means the undesired
behavior was reproduced; it does not mean that behavior is safe. No production
Scheme fix or Loader adaptation is included.

The native controls establish three different outcomes:

- Changes in the context callback or at MOP replay entry are rejected by replay.
- During final source inspection, object changes can escape: source bytes still
  match and there is no subsequent MOP sweep.
- During an ordered multi-file pass, a later file's observer can change an
  earlier file that will not be checked again. Each comparison passed at its
  own time, but the complete source set is stale when admission returns.

** Before replay: the existing checks still reject

1. A context =admit-current= callback edits the observed External.port. Native
   replay raises =stale slot dependency=.
2. A source observer at actual phase =slot-replay=, event =checks=, edits the
   dependency before native replay starts. The same refusal occurs.

The writes are not rolled back. These controls preserve the earlier qualified
body/callback boundary rather than weakening it to make late witnesses pass.

* Lean: historical checks versus applicable return

[[file:../../../dev/proofs/lean/YuanxuProof/Admission/ReturnTail.lean][Admission/ReturnTail]] explicitly separates the live selected object/file
versions, the successful earlier MOP check, and the source versions seen at each
file comparison. These are projections of the native controls, not new runtime
epochs or trusted user labels.

- =object_tail_counterexample=: the actual sequence can accept with a stale
  receiver, candidate or external dependency after an earlier valid replay.
- =earlier_file_counterexample=: both source comparisons can pass while the
  live first file no longer matches at return.
- =retained_requirements=: acceptance still records the earlier replay result,
  per-file matches, both evaluated requirements and child owner identity. It
  deliberately does not conclude current object/source/policy truth at return.
- =closed_inspection_trace= and =quiet_tail_preserves_replay=: a structurally
  read-only trace preserves a checked state. Its event algebra has no writes
  to admitted objects or sources; private instrumentation is outside that state.
  This is a conditional law, not a native mechanism restricting arbitrary source
  observer procedures. The current observer API has not been proved to map to
  that closed algebra, and cannot acquire the property from a manual pure flag.
- =late_source_failure_first=: the completed-source-error order remains intact.

The revision projection remains necessary rather than sufficient for full MOP
currentness; native checks also cover cache/instance/checker identity. Stronger
cache controls from prior chapters remain in the full regression catalog.

* Quint: three limitation witnesses on the correct implementation model

[[file:../../../dev/proofs/quint/ReturnTail.qnt][ReturnTail]] models early callbacks, MOP replay, first-file inspection,
second-file inspection and final return. It records the object revision at replay
and the source versions at their respective read times, rather than inventing a
single atomic snapshot. Terminal states have an explicit self-step.

| Predicate/control | Meaning |
|-------------------+---------|
| recordedChecks | Earlier replay and individual source matches, evaluated requirements, child identity, parent isolation and diagnostic order |
| skipReplay | Unsafe omission misses an early dependency change |
| skipFile | Unsafe omission accepts an actually mismatched source read |
| dropB / parent | Unsafe omission of second requirement / wrong candidate owner |
| prefix | Unsafe replacement of the source error with a stale-object error |
| objects | Correct-algorithm limitation: accepted evidence can contain stale objects at return |
| sources | Correct-algorithm limitation: accepted evidence can have a stale source set at return |
| plan | Correct-algorithm limitation: returned configuration can differ from cached plan |
| acceptance | Stable valid data can still be accepted; the model is not vacuously rejecting |

=recordedChecks= is deliberately not named a proof of end-to-end return safety.
The limitation traces refute that stronger claim without changing the modeled
production algorithm. Passing the gate means obtaining those expected
counterexamples, not asserting the stronger predicates.

* Reflection and design consequences

The final file checks assumed stable, effect-free inspection. The source code
comments state that assumption; the public observer is an arbitrary procedure
and the tested native path does not enforce it. These witnesses do not refute
a theorem conditioned on a closed read-only tail. They refute inferring that
premise automatically from the existence of fresh reads, restored dynamic scope,
a successful MOP pass or the name of an instrumentation callback.

Do not repair this with a user-maintained source table, more purity booleans or
an endless alternation of source and object checks. If the last check can call
another writer, there is another gap. A future production design needs a
qualified boundary with no later writes to the admitted footprint, or a final
trusted non-callback object inspection after all callbacks, retaining its actual
read graph. Such inspection must preserve the established diagnostic order and
must not invoke cold hooks/foreign checkers as if they were closed metadata.
No syntax or implementation of that boundary is introduced here.

An object-only final sweep would not make a multi-file filesystem read atomic.
External writers still require a snapshot/immutability assumption or an external
atomic conditional-commit/fencing authority. Immutable packaged source bytes may
help that particular premise but do not freeze Scheme objects or make arbitrary
observers read-only. Neither proof artifacts nor accepted preview evidence alone
authorize applying a stale plan.
