#+title: 32.27 Actual Source Admission Observes Nested Function Bodies
#+language: en

* Decision

[[file:32.26-call-lookup-body-and-observation.org][32.26]] exercised MOP observation scopes directly. This chapter uses the real
[[file:../../../admission/source.ss][SourceAdmissionContract.]] admission method, rather than a test-side =recorded=
window or an explicit replay call. Qualification tests, Lean/Quint models and
English documentation change; production Scheme and Loader do not.

The native results distinguish:

1. Hot =.admit= reuses its function but runs classification, child admission and
   obligations again. Cached function identity is not a cached accepted receipt.
2. An ordinary nested child Contract can return after an effect; the outer
   SourceAdmissionContract still observes its body reads and rejects before
   returning to its caller.
3. A source-aware child performs its own guarded return and rejects earlier.
   Its escaping failure is not replaced by a later root diagnostic.
4. The source-first check order is preserved for a body that completes. Both a
   source change and an invalidated read produce the original source diagnostic.

The mutation itself can succeed; rejecting admission does not roll it back.
These controls certify a refusal boundary, not an external execution transaction.

(def evidence
  (call-with-source-slot-reads
    (cut source-contract-admit @ (inherited) candidate context)))
(parameterize ((current-module-source-phase 'return-currentness))

=call-with-source-slot-reads= wraps actual execution, collects native read roots,
then invokes the real MOP replay before returning its result. It starts a fresh
source-read window for that replay. =source-contract-admit= retains entry and
post-obligation source checks, including replaceable context callbacks. The
outer collected-source return check remains independent. None is bypassed here.

The native responsibility kernel delegates to each child's =.admit= while
consuming its one-shot root-owned analysis edge. That optimization does not make
child obligations disappear or convert an arbitrary child body into a pure one.

** Hot root and child methods

The vector counts root and child obligation bodies, not field getters. The
child receipt retains the exact selected child candidate and Contract identity.
An unused candidate branch throws if evaluated and remains unforced.

** Nested obligation edits its Contract receiver

An ordinary YuanxuContract child reads its marker and changes that same
Contract receiver. The warm method's acquisition frame has already unwound, so
the supported write succeeds and advances the child Contract revision once.
The child and root obligation bodies each complete for the second time, but
root admission raises =stale slot dependency= before returning evidence.

#+begin_src scheme
(set-box! (.get probe effect)
  (lambda (actual _candidate _context)
    (.get actual marker)
    (.putslot! actual 'marker ($constant-slot-spec 1))
    (set! applied? #t)
    '()))
(reject-admission (.get probe contract) (.get probe candidate) #f
  "stale slot dependency")
(check-equal? applied? #t)
(check-equal? (vector->list (.get probe calls)) '(2 2))
#+end_src

=reject-admission= only calls the public =.admit=, catches the actual error and
asserts that normal return was never reached. It performs no source check or
read replay of its own.

* Lean correspondence

[[file:../../../dev/proofs/lean/YuanxuProof/Admission/AdmissionBody.lean][Admission/AdmissionBody]] imports the existing CallPhases and LeanPoo-backed
admission closure. Its =Read= rows project actual receiver identities and
revisions, not configuration field names. This is a necessary revision projection: native currentness also checks cache,
instance, checker and dependency identity. Unchanged projected revisions alone
never authorize admission. Existing SnapshotEntry/DFS controls retain those
stronger checks. The native checker and complete selected observation remain
correspondence premises; list concatenation represents observation union and
does not prescribe duplicate work or change native identity-based deduplication.

- =nested_window_current=: complete outer/inner observation requires both
  portions to be current.
- =member_current= and =changed_nested_read_rejected=: one selected stale nested
  record prevents the complete graph from being current.
- =changed_child_prevents_root_return=: changed nested reads cannot produce an
  accepted root return under that complete observation relation.
- =accepted_preserves_all=: acceptance retains source currentness, read
  currentness, both independent requirements and child identity.
- =completed_body_source_first=: a completed body with both source/read failure
  retains the earlier source diagnostic.
- =nested_adapter_failure_preserved=: an escaping child-adapter failure is not
  replaced by a later root check. =diagnostic_schedule= retains the earlier
  general ordered-failure theorem.

These are laws of the projected admission boundary, not a proof that every
possible raw Scheme I/O operation is observed. Native tests supply the current
production correspondence cases; no manual source-path or completed-check list
is passed into the admission consumer.

* Quint correspondence

[[file:../../../dev/proofs/quint/AdmissionBody.qnt][AdmissionBody]] begins after a successful warm call and models another nested
obligation execution. It distinguishes ordinary and source-aware children, a
completed body, child-adapter refusal, root source checks, root replay and normal
return. Terminal states have a self-step. An escaping child error is distinct
from ordinary rejected domain evidence, which follows normal completed-body
checks. The two requirement booleans project domain analyzer results; they do
not replace the actual service Contracts or authenticate contribution sources.

| Control | Meaning |
|---------+---------|
| positive | Warm bodies execute, nested guarded return is retained, observed stale values cannot certify, two requirements/child identity/parent cache/source order remain |
| acquisitionOnly | Incorrectly observe only function acquisition, omitting nested body reads |
| skipReplay | Collect actual body reads but omit the root replay |
| trustHot | Incorrectly treat cached .admit function as cached successful execution |
| skipChild | Incorrectly remove the source-aware child's own return rejection |
| dropB | Omit the second requirement |
| parent | Accept parent identity for the child |
| prefix | Check stale reads ahead of an earlier source error |
| noWrites | Limitation witness on the correct algorithm: rejecting admission does not undo prior body writes |
| acceptance | A stable valid configuration can return accepted evidence |

The model deliberately keeps the seven unsafe policies separate from the
correct-algorithm limitation. The finite checks do not infer concurrency safety
or run effectful callbacks during metadata inspection.

* Remaining boundaries

The real adapter owns observation through the actual function body and checks
before return. This does not make nested obligations pure, prohibit arbitrary
writes at body entry, or implement rollback. A caller that overrides/bypasses the
adapter, reads through unsupported raw I/O, mutates from another thread or runs
an effect after admission needs a separate qualified boundary.

The external conditional-commit requirement from 32.25 remains. Returning an
accepted configuration does not atomically reserve its external resources or
freeze future source changes. This work does not remove source checks, change
production caching, introduce a new admission wrapper or connect Loader.
