* Corrected boundary: use installed Gerbil, change Core

The installed Gerbil compiler, runtime loader and their sources are unchanged.
[[file:32.42-source-built-loader-call-edges.org][32.42]] is a historical isolated experiment, NOT the production implementation
plan. Its original-loader cache return is normal Gerbil behavior, not by itself
a Gerbil defect. Core publication authority is different from native loading.

This change uses the installed =std/build-script= / =std/make= dispatcher and
the existing Core selected Graph and =AdmissionPublication.= protocol. It neither
rebinds =load-module= nor intercepts SDK imports, eval, FFI or raw primitive load.
An ordinary Gerbil cache hit never stands in for Core publication admission.
The installed loader/compiler source hashes still equal those recorded in
32.42. No =.data/gerbil= source file, installed SDK file or dependency revision
was changed for this implementation.

* Existing build entry, with a Core-owned completion boundary

The root =build.ss= keeps the installed native dispatcher:

#+begin_src scheme
(def native-main
  (let ()
    (defbuild-script (init.build-spec core-spec)
      libdir: (current-build-output-directory))
    main))
(def (main . args)
  (init.build-run core-spec native-main args))
#+end_src

[[file:../../../module-system/building/interface.ss][The init build owner]] emits =init.build-run= from the existing hygienic
=yuanxu!= expansion. Only compile/default-build commands execute the projected
POO =.compile= method; spec/meta stay inert and clean invalidates prior issuance.
The installed dispatcher still owns command parsing, scheduling and compilation.
The output directory defaults to the same =gerbil-path/lib= as native make.

[[file:../../../module-system/building/build-projection.ss][The source projection]] provides compiler identities and exact source observations
from its already merged selected/retained entries. Its native POO =.compile=
delegates to [[file:../../../module-system/building/artifacts.ss][artifacts.ss]] around that native dispatcher. No additional module,
asset or artifact checklist is maintained by a user. Importing init does not
compile, enumerate compiler outputs or execute an Ops Script.

The completion sequence is:

1. Recheck the source projection and mark this exact build Graph unavailable.
2. Execute the installed compiler through the native build dispatcher.
3. Require normal completion and recheck source inputs.
4. Discover actual outputs for selected compiler identities only.
5. Retain their digests and source observations in a private Graph association.
6. Write an ordinary readable record; retain its digest separately in memory.
7. Recheck before returning success. Failure leaves =build-required=, rather
   than falling back to an earlier successful build.

For a first or invalidated build, Core supplies a fresh temporary output
directory through the native =libdir:= setting. Missing outputs cause actual
compilation; untrusted existing files are not adopted. Verified produced bytes
are copied to the requested output directory and compared there before issuance.
The publisher refuses additional selected outputs not belonging to that completed
job and does not delete another job's files. Unknown higher object generations
require an explicit clean/rebuild. Per-file copy is not an atomic multi-file
filesystem commit; Core remains unavailable until the final checks pass.

On the SAME Graph with a valid retained issuance, native make may reuse its
ordinary output directory. No new compiler scheduler or dependency engine is
introduced. The installed =std/make= accepts a =force:= setting but its observed
build predicate does not consume it; native run 08 retained the resulting
poisoned-cache failure. The fresh-directory mechanism replaces that ineffective
setting without changing Gerbil source. Compiler correctness and exclusive job
ownership of temporary output remain premises.

Output discovery groups selected names by directory and visits each selected
directory once per check. It includes native named runtime sections such as
=types~TypeName~0.o1= and later object generations such as =.o2=. Unselected
directories are never visited, and unselected files are not hashed or compiled.
This is filesystem observation, not a second compiler dependency scheduler.

* Private issuance, readable records and cache admission

The internal =issued-build= is a compact private struct, not a user DSL or an
Evidence object users have to construct. Its association uses a weak identity
table keyed by the exact build Graph. The stored value contains plain copied
source observations, identities, generation and output hashes, not a closure
back to the Graph key. A live saved publication retains its Graph normally.

Disk records NEVER refresh the retained expected digests. Replacing the output
and updating its record to match still differs from the completed build's
retained record. Missing/non-regular/symlinked files, changed selected outputs,
new runtime generations and source changes reject.

[[file:../../../admission/publication.ss][Publication]] checks artifacts at =module-admission-publication= before resolving
an exported admission, and in the existing context currentness function before
and after its source checks. The normal =.publish= entry, Contract work, effect
boundaries and dependent meaning/return checks therefore retain their existing
order. No artifact/source approval is cached across an arbitrary Contract or
package callback.

Saving the actual =.publish= function is safe within this protocol:

#+begin_src scheme
(def saved (.get publication .publish))
(saved Parent Release) ; always invokes publish-current, including on hot slots
#+end_src

It does not cache a successful authorization decision. A new =.for-export=
request must also check the same Graph's issuance before exporting an admission.
Neither Core entry relies on replacing an already captured Gerbil procedure.

* Source mode, process lifetime and explicit limits

An existing source-reader publication with no managed compiled build remains a
source publication: the actual reader checks its source closure and constructs
its source-bound scope. The change does not infer code authority from the
native loaded-module table or adopt arbitrary compiled files it finds on disk.
Once THIS Graph starts a managed build, failed/incomplete issuance refuses;
it cannot silently downgrade that Graph back to the source-only path.

The private association is process-local. A standalone build command may emit
a record and exit; that file is useful for inspection, but another process must
NOT treat it as a trusted issuer. Portable compiled-publication admission needs
an authenticated build-service/parent-process handoff or a protected signer and
verification policy. This patch does not claim that cross-process trust has
already been established. Fresh source-mode Graphs are also not a mechanism for
authenticating arbitrary previously loaded native code.

Additional limits remain explicit: trusted Core/build code, filesystem/host
authority, single build owner per Graph, and no external atomic commit guarantee.
This is not a hostile-Scheme sandbox. Byte equality at checks does not lock the
filesystem through a later external deployment. Hashing/re-enumeration costs
must be measured before introducing any cross-check reuse.
