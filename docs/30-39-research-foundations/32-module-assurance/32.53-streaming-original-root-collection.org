* Boundary established before implementation

[[file:32.52-demanded-read-graph-retention.org][32.52]] found 999 repeated root references, not 999 disposable objects. Root
storage can be compacted only if original identities, first-occurrence order,
dependency edges and every observer event survive. The installed Gerbil compiler
is unchanged. gerbil-poo's existing integration branch advanced to
=6a43e2ad7c72a3b2bb1c5380c3a33f70d964711e= before this change; that other-session
work was retained with a fast-forward and an additional baseline run.

* Native collection and Core consumers

=slot-observation.ss= has one recording implementation with an internal
=unique-roots?:= option. The default exact trace is essential: native object
construction, computed slots, preparation and query capture use this function
to construct dependency lists. Changing its default would delete edge
occurrences before native issuance. Those callers remain unchanged.

#+begin_src scheme
(%call-with-recorded-slot-reads action unique-roots?: #t)
#+end_src

Only root consumers request compaction. Their private per-call identity table
stores the first reference to each record, without copying records or changing
their fields. =%deliver-slot-read= runs its complete observer loop OUTSIDE that
storage branch, on duplicate deliveries too. =without-observation=, prechecks,
nested dynamic scope and exception propagation retain their original boundaries.
The table is not an issuance registry, source cache or admission verdict.

Core's =call-with-owned-read-projection= and =call-with-publication-reads= opt in.
Their former post-collection identity maps are removed. The same original root
sequence is forwarded and replayed; no dependency list is edited. Reader's
diagnostic counter now says =stored-roots= rather than mislabelling compact
storage as total deliveries. The publication regression checks equality with
the actual root list, while observer multiplicity is checked independently.

* Proof and executable correspondence

[[file:../../../dev/proofs/lean/YuanxuProof/Admission/RootCollection.lean][RootCollection.lean]] establishes:

- =callbacks_unchanged=: for an arbitrary world transition, every input delivery
  still updates the observer world, in input order, for every finite prefix.
- =roots_are_original_first_occurrences=: streaming storage equals original
  identity deduplication, preserving first occurrence rather than sorting.
- =first_diagnostic_unchanged=: a stable per-record failure predicate finds the
  same first failure after compaction.
- =dependency_binding_retained= and =demanded_closure_unchanged=: original token
  bindings and their demanded closure survive; payload equality is not identity.

The graph/currentness premises from 32.52 remain. In particular, the diagnostic
lemma does not authorize treating an effectful checker as pure or sharing an
approval across callbacks. Native protected replay and SourceAdmissionContract
still own those checks. This is not a VM, GC-scheduling or external-effect proof.

[[file:../../../dev/proofs/quint/RootCollection.qnt][RootCollection.qnt]] checks eight controls: normal streaming, suppressed duplicate
callbacks, reversed observer order, reordered first diagnostics, receiver-only
coalescing, copied identities, deleted edge occurrences and a progress witness.
The model and Lean source binding passed before production collection changed.

Native regressions compare exact original record references and observer event
payload/order for the same input. They also cover an exception on the second
duplicate callback, a newer record for the same field retaining its stale
predecessor, duplicate dependency edges under an enclosing compact root frame,
and identical first stale diagnostics. These controls connect the abstract
prefix model to the real production entry rather than reconstructing tokens.

* Real Scenario comparison

[[file:../../../t/read-retention-cost-test.ss][read-retention-cost-test.ss]] uses actual reader/link, Contracts and =.admit=.
It alternates raw/unique order across three rounds, with two fresh children per
round and both cold-child and warm-child admissions. Each child must yield
5433/5433, preserve exact final Config/plan identity and contextual child receipts,
retain both contributions, and leave the parent's cached 5432 plan unchanged.

A first unmatched run had 2,659 observer events on the first raw admission and
2,396 on the next compact admission. It was retained as a FAILED comparison:
the shared Contract descriptor/catalog had only been cold in the first call.
The corrected control admits the parent once before both measurements. It warms
descriptor functions/data, not child values or approvals. Every measured call
still performs 224 physical source reads and its return-currentness boundary.

The corrected twelve samples compare the ENTIRE ordered observer-key sequences,
not just their lengths. Same-context native tests additionally compare exact
record identities; different normalized child instances need not share identities.

The 999-reference reduction applies to an individual collector buffer. Core's
old publication output was ALREADY unique. This change avoids building that
temporary duplicate list and removes its later deduplication pass; it does not
shrink the authenticated graph or prove shorter payload/prototype lifetimes.

Wall times fluctuate and the VM allocation stream regresses. An independent
read-only host check also found load averages about 26--34 and several busy
processes belonging to another checkout. Those processes were not changed.
No latency, allocation-byte or retained-heap improvement is admitted from this
run. Structural storage reduction and semantic controls are the supported result.
