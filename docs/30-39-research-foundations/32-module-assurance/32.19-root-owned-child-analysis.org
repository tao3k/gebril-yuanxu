* Ownership in the existing Contract kernel

=SourceAdmissionContract.= supplies a pending exact descriptor/candidate/context
edge around its inherited kernel invocation. The kernel consumes this one-shot edge and
clears it before running normalization, classification, obligations, or platform
callbacks. Only its own responsibility traversal installs the next exact edge.
A separate admission invoked by an obligation therefore starts independently.
An overridden =.admit= calling its inherited producer twice cannot reuse the
consumed edge on its second call.
This is internal execution provenance, not an unforgeable security capability.

The ordinary =.contract-obligations= callback remains the independent admission
entry. Root-owned children may use =.responsibility-obligations= on the same
Context. The contribution Context uses this entry only without an inherited
platform callback, without the root contribution callback, and with its exact
bound platform handler unchanged. A replaced/derived handler remains an open
callback and is not silently skipped. Otherwise it
falls back to the original guarded entry. Nested SourceAdmission adapters start
their own root and retain their own source certification.

#+begin_src scheme
;; Kernel-owned responsibility delegation; no user-side Requirements list.
(parameterize ((current-contract-analysis
                (and owned? (make-contract-analysis descriptor value context #t))))
  (yuanxu-contract-admit descriptor value context))

;; The contribution Context's internal analysis entry.
(lambda (actual candidate)
  (unless (hash-get contracts actual)
    (error "admission descriptor differs from selected publication"))
  (observations-current! observations)
  (if (or (.slot? base '.contract-obligations) (eq? actual descriptor)
          (not (eq? (.get @ .contract-obligations) platform-obligations)))
    (yuanxu-context-contract-obligations @ actual candidate)
    '()))
#+end_src

=contracts= and =observations= are the existing publication-bound collection,
including descriptor/responsibility revisions and deep contribution receivers.
There is no second field catalog, cached admission decision, or source-byte
window across child obligations. Actual cold field checks and MOP cache replay
continue to feed the root source collector. Root certification still checks
complete contribution coverage, payload/origin identity, graph generation,
prepared source records, and the selected source closure.
