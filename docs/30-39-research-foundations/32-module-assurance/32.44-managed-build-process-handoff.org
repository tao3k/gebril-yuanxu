* Existing authority and question

Can a fresh process reuse a completed Core build while refusing jointly replaced
artifacts and readable records? [[file:32.43-core-build-publication-authority.org][32.43]] already owns retained issuance and the
publication gate. Source-package publication does not authenticate independently
compiled artifacts. The compiler-pipe experiment in
=t/qualification/mop-state/artifact-authority.ss= supplies a useful parent-retained
transfer pattern; its loader interception is NOT reused.

The solution extends the same Core association, not a signature system, disk
issuer registry or second publication protocol. Gerbil remains unchanged.

* Production ownership and transfer

=module-system/building/artifacts.ss= owns the existing private =issued-build=.
The source build projection adds =.process= alongside =.compile=. Its named
functional implementation, =run-build-artifact-process=, checks the existing
association, starts the selected worker through =std/misc/process= and sends
only retained expectations on the parent-owned stdin pipe:

#+begin_src scheme
(list 'yuanxu-build-handoff-v1
      (issued-build-identities state) (issued-build-inputs state)
      libdir (issued-build-files state)
      (issued-build-record state) (issued-build-record-digest state))
#+end_src

The parent closes the pipe's write half after one datum. Failed process output
is retained in the error. A successful child return is followed by an independent
artifact/source check: child execution is an effect boundary.

=accept-build-artifact-handoff!= is INTERNAL trusted worker bootstrap, before
compiled-publication scope resolution. It is not an ordinary Module export or
a disk-record import API. Calling it on arbitrary stdin is NOT authentication.
Trusted parent/worker executables and the OS-owned pipe remain premises.

The receiver independently constructs its selected graph. It checks exactly one
packet followed by EOF, matching compiler identities, complete ordered source
observations and output directory. No unselected catalogue is enumerated.
Graph =generation= is a process-local gensym, so it cannot be compared across
processes. Only after projection matching are the parent's retained observations
installed under the CHILD's receiver/generation. The existing artifact and
projection currentness gates then run before returning.

Parsing starts with =build-required=. Refusal leaves that graph blocked; it
cannot downgrade to source-only admission. An already-associated graph refuses
replacement handoff. The existing =.for-export= and =.publish= perform subsequent
checks, including saved procedures, hot slots and post-callback currentness.

* First build, warm reuse and publication

| State | Behavior |
|-------+----------|
| No completed association | Fresh empty output directory invokes installed compiler; existing binary is not adopted |
| Valid local association | Existing checked warm completion |
| Fresh managed worker with matching transfer | Receiver-local association enables the same warm completion |
| Coherently replaced binary and record | Refused against private expected values |
| Different selected projection | Refused; graph remains build-required |
| New independent process with only a disk record | No compiled authority recovered |

Warm child completion can produce a new readable record without replacing its
parent's association. No process infers its authority from the record filename.

The regression uses real Gitea/PostgreSQL selection, linker, =.for-export=,

The worker script is a test bootstrap, not another production Loader.

Independent exec workers cover warm compilation with no new probe compiler job,

* Lean and Quint correspondence

=CoreBuildHandoff.lean= proves exact projection equality for acceptance, joint
replacement refusal, warm transfer, receiver-indexed parent isolation, and final
checking plus both-requirement necessity. =CoreBuildHandoffCheck.lean= decodes
four actual worker outcomes in fixed order; a changed rejection must fail.
These are protocol/extraction proofs, not compiler or operating-system proofs.

=CoreBuildHandoff.qnt= separates transfer binding, callback and final publication.
Six negative variants expose disk-derived expectations, omitted selection
matching, omitted final artifact/source checking, parent mutation and eager unselected access.
An acceptance witness excludes an implementation that rejects everything.

* Reflection and remaining boundary

The benefit is reuse of existing build/publication responsibilities across an
owned process channel, without putting keys or Evidence objects in user config.
The cost is an explicit managed-parent lifetime and trusted worker bootstrap.
This is supervised cross-process reuse, not autonomous durable authentication.

When every trusted owner exits, a later process cannot recover authority solely
from disk. That requires a governed protected build-service handoff or other
durable authority. No writable sidecar hash can replace it. Hostile same-user
processes, multi-file atomic publication, concurrent build owners, external
conditional deployment commit and full binary dependency closure remain outside
this result. Workers must accept handoff before resolving compiled scopes.
Byte currentness at the checked boundaries is not proof that an external writer
never changed and restored a file between checks; external atomic/conditional
commit remains a separate requirement.
