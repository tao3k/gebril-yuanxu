* Native root forwarding

The reader now forwards the original root identities:

#+begin_src scheme
(def (deliver-publication-reads reads)
  (for-each
    (lambda (read) (%deliver-slot-read read (slot-read-value read)))
    reads))
#+end_src

The roots have already been deduplicated by identity in first-delivery order.
Neither their receiver, checker, revision nor dependency list is reconstructed.
Nested dependency edges remain native-owned, including cache-miss observations.
The root collector is not an authenticity oracle; native replay still refuses
an unissued token anywhere in the selected closure.

The construction scope uses the same conservative rule:

#+begin_src scheme
(def (deliver-original-reads reads)
  (def seen (make-hash-table-eq))
  (for-each
    (lambda (read)
      (unless (hash-key? seen read)
        (hash-put! seen read #t)
        (%deliver-slot-read read (slot-read-value read)))) reads))
#+end_src

Successful and failed actions retain their complete original trace. Failed
actions rethrow the original exception. This is observation forwarding, not
admission: with no weak projection to certify, the scope does not insert an
extra replay into the middle of the caller's action. The enclosing native
consumer retains its existing replay/admission boundary. It receives no cached
approval bit or application-issued substitute token.

Delivery uses the maintained observation boundary. It does not rerun getters;
observers can see forwarded deliveries as well as the original computation.
No identical observer-count or allocation-cost claim is made. An arbitrary
observer's effects are not made rollback-safe by this change.

* Parent and carrier policy support must also be genuine

The former synthetic checker included weak witnesses and raw revision policies.
Simply deleting it while dropping those requirements would weaken acceptance.
Instead:

- =owned-read-derived!= observes each selected ancestor's =.all-slots= query.
  This records its real native preparation/names/revision support without reading
  the values of unselected fields. A parent edit followed by restoration still
  invalidates the prior token.
- =clos-carrier-policy-guard= observes native names queries for its concrete
  Type/prototype owners. Its existing identity and revision comparisons remain.
  The guard runs within the same recording frame before and after the action.
- Unknown bodies and MOP owners still call the existing open-operation boundary;
  full traces no longer need an application-made =owned-call/full= marker.

These concrete Core policies are native object policies. This does not certify
arbitrary lexical mutable state hidden in a user callback as an automatically
observed source. Such state still needs a declared source/owner. There is no
new purity annotation or second field table.

* Deliberate retention tradeoff

Weak witness projection is removed in this step. A retained native graph may
keep temporary receipts/validation carriers alive longer than the former weak
projection intended. The earlier GC/retention claims and work-count comparisons
must not be reused as evidence for this version.

The existing =evidence-read-ownership= and =evidence-witness-replay= suites include
assertions about synthetic bundle tags, raw test-made read probes and collection
of carriers while an enclosing cache remains live. Those optimization-specific
expectations are not claimed green here and are not rewritten merely to pass.
They require a separate native-issued retention design if that optimization is
restored. In particular, do not reintroduce a weak application checker into the
native graph under another name.

This preserves demand laziness: only already observed reads are forwarded; no
whole Module catalogue or unselected field values are scanned. Lower temporary
retention and faster replay are different properties and remain unqualified.

* Lean and QNT correspondence

[[file:../../../dev/proofs/lean/YuanxuProof/Admission/IssuedRootForwarding.lean][IssuedRootForwarding.lean]] models tokens as original native registry identities:

- =exact_membership=: identity deduplication neither adds nor drops a root.
- =preserves_issuance=: genuinely issued roots stay genuine after forwarding.
- =cannot_hide_unissued=: deduplication cannot authenticate a foreign root.
- =forward_keeps_dependency_closure=: unchanged dependency edges give exactly the
  same reachable token set, including shared/transitive nodes.
- =changed_source_refused= / =both_requirements_retained=: root transfer alone
  does not replace independent currentness and domain admission.

The model does not prove the Scheme interpreter, pointer identity extraction,
native private registry, arbitrary callback purity or filesystem atomicity.
Native tests exercise the corresponding identities and refusals; there is no
new verified Scheme-to-Lean compiler or automatic extraction theorem.

[[file:../../../dev/proofs/quint/IssuedRootForwarding.qnt][IssuedRootForwarding.qnt]] has a normal safety control and matched omission,
fabrication, source-check removal, second-requirement removal, eager-branch and
acceptance controls. Runs use 1000 samples, 6 steps and seed 50. Negative controls
must produce actual invariant violations, not arbitrary failures. It models
set coverage, not the full DFS diagnostic schedule; the implementation keeps
first-delivery order and delegates native DFS to the existing replay owner.
The Lean source binds the same QNT digest. Initial bounded simulations used
1000 samples, 6 steps and seed 50; those alone were not exhaustive verification.
The models are now also registered with the existing Core TLC runner: all seven
finite safety/counterexample controls passed with final input-cut checking.
That finite-state result does not prove the runtime projection or renew earlier
memory cost claims.

- [[https://github.com/tao3k/gerbil-poo/blob/b8f487da294192d05bc4ab0a2218e8057f69286f/examples/object-contracts.ss][object-contracts.ss]] combines a normal ObjectContract responsibilities object,

- [[https://github.com/tao3k/gerbil-poo/blob/b8f487da294192d05bc4ab0a2218e8057f69286f/examples/row-services.ss][row-services.ss]] demonstrates explicit prototype parameters, closed Object rows,

  binding rather than inventing another Config DSL. It explicitly does not
  promise rollback of effects performed by a callback before later refusal.

This is a useful counterpart to the ergonomic goal of NixOS =mkOption= /
=types.submodule=: maintain one native field Contract and reuse its parameters,
normalization and obligations, rather than repeating field/predicate wrappers
at each Module boundary. It is not a claim that the two module systems are
semantically identical or that POO already supplies durable execution authority.

The reviewed =object-contracts.ss= expresses that split directly (an upstream
source excerpt, not a newly qualified Core dependency):

#+begin_src scheme
(def ServiceShape
  (.cc ObjectContract. identity: 'service
    responsibilities:
    (.o host: String port: Port capacity: Integer used: Integer secure: Bool)))
(def ServiceContract
  (.cc ServiceShape
    obligations: (diagnostic-all [capacity-issues transport-issues])))
#+end_src

The same file defines =Port= with the native Type recognizer, and the two named
obligations inspect the whole admitted value. Core's existing parameterized
=GiteaValueContract.= / =ApplicationValueContract.= follow this shape-versus-
relation separation. This is the direction to extend: reuse Types, native
responsibilities, normal functions and checked functional composition. It does
not remove domain connection checks, independently contributed requirements,
source currentness or the exact config/plan identity check.

For Core the intended layering is:

1. Ordinary JSON/Scheme values remain the simple configuration surface.
2. =types.ss= owns native Types and =ObjectContract.= responsibilities; object
   construction and normalization reuse them once. The current Gitea/PostgreSQL
   Contracts already use this route; this fix does not duplicate their shape.
3. =objects.ss= assembles reusable Profiles and Scenario objects. Inheritance,
   lenses and ordinary functions are exposed when a real extension requires them.
4. Closed rows diagnose spelling mistakes; open/disjoint rows are deliberate
   extension contracts, not a reason to silently accept arbitrary misspellings.
5. =refine= / checked FUN actions express domain relations and effect boundaries.
   Source association, contribution completeness and release authorization remain
   separate from structural typing.

Important version boundary: Core currently pins =fdeadfa...= and the installed
checkout also contains uncommitted producer-issuance/route defenses used by these
tests. The reviewed feature revision does not contain those defenses in the same
form: its slot-observation still exports raw-checker replay. A blind pin bump
would discard an actual assurance boundary. A trial three-way combination in the
disposable review checkout refused conflicting file changes; it was not adopted,
and the installed dependency stayed untouched. No patch file is maintained in Git.

Thus =b8f487d= is reviewed design/source evidence here, not a claimed qualified
runtime upgrade. Future integration must preserve the native mint and route
defenses on the existing upstream branch, then qualify the concrete revision
before changing package pins. Default master, a dirty installed checkout and
the reviewed feature commit must never be reported as the same artifact.
