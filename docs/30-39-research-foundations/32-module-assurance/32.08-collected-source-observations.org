* Implemented scope

This implements only the first step of
[[file:32.07-demand-collected-source-admission.org][32.07]]. SourceAdmissionContract. no longer declares or consumes source-paths.
Gitea retains its ordered preflight and explicit source guard paths. Its field
Contracts, contextual child obligations, two independent port policies and plan
identity rules are unchanged.

The collection point is the existing module-source-admit-current!, rather than
only admit-origins!. Native slot guards delegate to that function, as do JSON
input and selected-publication guards. Collecting only at admit-origins! would
miss a nested SourceAdmissionContract. that declares JSON inputs but does not
inspect a Scheme field.

The Loader's selection, linking and activation code is unchanged. Its shared
source-check helper gains scoped observation collection; outside an active
collector it still performs the same source checks.

* Ownership and data

[[file:../../../module-system/source/admission.ss][Core source admission]] owns call-with-collected-module-sources. Every successful
source check reports the original path/bytes-or-absence observation and its
refusal message to all active enclosing collectors. An admission scope keeps
private source-observation structures, not another field table or public
configuration object. Observed source strings are copied so the final check
does not adopt subsequent mutation of a caller-owned pair/string as its baseline.

Deduplication is by path and identical observed contents, without hashing whole
source texts. Distinct revisions of one path are retained in first-observation
order. The later revision cannot authorize forgetting an earlier one. This
conservatively retains absent-file observations too.

The final replay uses the original observations, with fresh reads, not a walk
through the current candidate. Replay does not enroll new observations or
re-report itself to outer scopes. Nested *actual checks* already report to
every enclosing scope when they run. Dynamic parameter restoration prevents
failed invocations from leaking observations into an independent admission.

* Maintainer surface

Gitea's existing dependency order remains explicit. These are actual maintained
excerpts, not the proposed native field-access hook:

#+begin_src scheme
;; Existing preflight retains these source paths once.
(source-diagnose-at database-type '(config postgresql)
  '((config postgresql settings port)))
(source-diagnose-at client-type '(config gitea)
  '((config gitea database port)))

;; ApplicationContract: no source-paths slot.
.preflight: (.get value-contract preflight)
.locate-diagnostic: (config-diagnostic-locator documents '(config))
#+end_src

The generic .admit implementation wraps the existing lifecycle:

#+begin_src scheme
(call-with-module-source-fresh-reads
  (lambda ()
    (call-with-collected-module-sources
      (lambda (sources-current!)
        (def evidence
          (source-contract-admit @ (inherited) candidate context))
        (sources-current!)
        evidence))))
#+end_src

The inherited admission is still invoked once only after preflight succeeds.
The shared read cache covers that inherited invocation, not the final replay.
Root source-inputs are still checked at entry and after contextual currentness;
they are not replaced by inferred field discovery.

Diagnostic decoration is explicitly materialized inside the collection scope.
Native .cc is a function with eagerly evaluated arguments; this refactor does
not repair an alleged lazy-.cc behavior. The explicit local values make the
collection boundary clear and prevent a future deferred diagnostic projection
from performing its checks after the collector closes. Original contextual
child receipts, descriptors and normalized candidate identities remain intact.

The lifecycle is: collect during preflight, inherited admission, diagnostic
decoration and contextual currentness; check root inputs; then replay the retained
source set with fresh reads before return. No collect-until-stable loop or full
candidate scan is introduced.

* What remains unchanged or unproved

- Ordinary domain relationships are still checked by application-issues and
  port-contributions; neither is replaced by source observations.
- Native responsibility admission still requires exact normalized child identity.
- Selected contribution completeness, object revision checks and source binding
  remain owned by the existing publication protocol.
- Collection is limited to actual source checks. It does not discover arbitrary
  .get/.ref reads or hidden dependencies of cached computed slots. The explicit
  preflight guards must remain until the separate native-access work is qualified.
- No unselected branch is traversed to construct a manifest. A publication's
  existing selected-source checks may already read its source closure; this
  collector rechecks what those checks actually observed. It does not promise
  fewer file reads or a performance improvement.
- Observations are dynamically scoped and synchronous. They are not a global
  dependency graph, atomic filesystem snapshot or sandbox against arbitrary
  effects. Fault-injection writes in tests are deliberately outside normal pure
  obligation behavior.

* Qualification ownership

The new source-observation-test.ss uses DirectoryFixture and the existing SDK
read-overrides helper to expand real temporary Scheme source files. There are
no hand-built origin rows or supplied observation sets. ObservationContract is
a domain-free test classifier over the production SourceAdmissionContract.; it
is not a replacement source collector or evidence producer.

Its five controls cover cached guarded fields and exception cleanup, a JSON-only
nested child's source changing after child admission, an untouched branch with
an erroring value and a changed source file, source checks during diagnostic
decoration, and two different source revisions observed under one path.

The first collected-source-controls.log run is retained as a FAILED fixture run:
a scalar Range was passed to the object diagnostic entrypoint, and a local path
variable named unused was shadowed by the native unused slot. The controls were
corrected to use ObjectContract like the real preflight and distinct path names;
no production guarantee, timeout or assertion was weakened.
