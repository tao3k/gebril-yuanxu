* Refactoring ownership

** Functional Types are the ordinary path

Types and Contracts are first-class values. Native constructors such as
=IntegerRange= and =List= compose those values; an ordinary function may return
an =ObjectContract.= specialization, and =refine= adds a named domain relation.
This does not require a parameterized prototype family or type inference for
each fixed application field.

The attempted fixed-port conversion through =capture-type-catalog= and
=expression-type= was withdrawn: it added token extraction and intermediate
bindings without removing a domain obligation. Those APIs belong to actual
dynamic descriptor capture and finite inference requests, not every static
configuration declaration.

The Gitea candidate now replaces two private parameterized value-contract
families with ordinary constructor functions. The public contextual admission
Contract remains an extensible POO object. Its existing child obligations,
source guard and contribution protocol are not replaced by field validation.
The focused consumer qualification below validates this candidate. It does not
stand in for rebuilding and qualifying every production dependency.

#+begin_src scheme
(def (gitea-value-contract Port)
  (.cc ObjectContract. identity: 'gitea/config-value
    responsibilities:
    (.o database: (.cc ObjectContract. responsibilities: (.o port: Port))
        allowed-ports: (List Port))))
#+end_src

** Preserve independent semantic obligations

Field structure and normalization belong to upstream Type/ObjectContract.
Cross-service port equality, both independently published port requirements,
source currentness and final-plan subject identity remain real application or
Core admission obligations. Their presence is not evidence that the native
type system was ignored. Conversely, a second field table or repeated structural
classifier needs a concrete justification before being retained.

Keep ordinary configuration as values. Use native functional refinement when
retaining an inherited value is the user's intent. Neither numeric inference
nor a storage-policy API belongs in a user's port-setting example merely to
demonstrate a new feature.
