#+title: 32.42 Source-Built Loader Call Edges
#+language: en
#+startup: overview

* Current implementation decision

[[file:32.43-core-build-publication-authority.org][32.43]] supersedes this experiment as the implementation route: use installed
Gerbil unchanged and enforce Core build/publication authority in Core. The
SDK-wide rebuild obligations below apply only to the stronger hypothetical
requirement of intercepting arbitrary native loads; they are not a prerequisite
for Core publication admission and are not the current implementation plan.

* Question and bounded experiment

[[file:32.41-issuer-bound-native-loading.org][32.41]] retained an actual bypass: an original SDK procedure value returned a
cached module without visiting the later installed issuer. Changing a global
binding cannot rewrite a compiled procedure's internal call edge.

This experiment compiles the installed SDK's actual =src/gerbil/runtime/loader.ss=
in an isolated namespace BEFORE capturing procedure values. No installed SDK
source or global loader binding is modified. The transformation is a local
qualification input, not a production SDK patch or alternative public API. It
keeps the native cache, mutex, condition variable, resolver and reload logic.

The real =loader.ss:32= checks the cache inside =load-module=. Its =:75=
=reload-module!= also has an early cached return when the resolved path has not
changed. Reload needs its own entry check even though its fallback calls load.

The compiler has further ownership obligations:

- =compile.ss:1083,1147=: runtime import generation emits =load-module= calls.
- =driver.ss:803=: generated loader code calls =load-module= for its runtime unit.
- =compile.ss:1272,1293,1482=: phase/runtime blocks emit the same binding.
- =runtime.ss= includes/reexports the loader; =runtime/init.ss= owns evaluator,
  import bootstrap and raw load integration.

Recompiling one facade does not replace these edges. A production SDK build must
bind its own native implementation at every owned entry and qualify bootstrap,
compiler products and dependency closure together. This is not that SDK rebuild.

* Checks compiled into the native bodies

[[file:../../../t/qualification/mop-state/compile-store-boundary.ss][The existing compiler job]] copies native source into an isolated module, changes
package/prelude/import locations, inserts authorization before BOTH cache-entry
locks, and redirects its single primitive load expression to the already
qualified byte-consumption function. It requires exactly two entry insertions
and one load site; SDK source drift fails compilation. No patch file is saved.

The entry insertion is an ordinary function call:

#+begin_src scheme
(core/t/qualification/mop-state/artifact-authority#authorize-request! modpath)
#+end_src

Observed emitted Scheme places this in the internal typed implementation.
Its wait/retry and reload branches directly call the same compiled entry:

#+begin_src scheme
(core/t/qualification/mop-state/source-loader#__load-module modpath)
#+end_src

The full copied SDK bodies are compiled by native =compile-module=, optimization
and GSC. Retained source/runtime hashes join =RESOURCE-ISSUANCE= on the compiler
child's pipe. Bootstrap loads verified =source-loader~0.o1= from the private
pool and sets its own native load path; it never assigns the SDK loader globals.

* Native controls and domain consumers

[[file:../../../t/source-loader-authority-test.ss][The focused test]] captures the compiled entry BEFORE loading its target:

#+begin_src scheme
(prepare-source-authority! state)
(core/t/qualification/mop-state/source-loader#set-load-path! (load-path))
(def saved core/t/qualification/mop-state/source-loader#load-module)
(saved entry)
(saved entry) ; hot authorization, no new consumption
#+end_src

The attack replaces the callback binary with the real unlowered binary and
recomputes a structurally coherent record. Saved, direct and reload entries must
refuse =issued source or record changed= without another completed consumption.
Restoration must permit the same saved procedure again. Expected issuance is
never refreshed from the changed files. SDK =load-module= identity is unchanged.

The genuinely loaded callback retains the Parent/Hot/Cold control: Parent is
cached at 5432; Hot supplies replay observations; Cold is unforced. A shared
specification write of 5440 must fail before storage; all final values remain
5432 and the unused error slot is never forced.

The actual =SourceAdmissionContract.= consumer remains separate: BOTH port
contributions, child obligations, final child plans, explicit mismatch and
changed-source rejection still apply. Loader authorization is not domain policy.

* Lean, actual observations and QNT

[[file:../../../dev/proofs/lean/YuanxuProof/Admission/SourceLoader.lean][SourceLoader.lean]] proves =changed_cache_refused=, =stable_cache_allowed=,
=saved_edge_independent_of_rebinding= and =both_requirements=. Its explicit
=old_edge_counterexample= distinguishes an old unchecked procedure from the
rebuilt checked one. These are call-edge protocol theorems, not compiler proofs.

[[file:../../../dev/proofs/lean/SourceLoaderCheck.lean][The independent decoder]] consumes actual error messages, authorization event
deltas and completed-consumption deltas. It requires four ordered observations,
positive authorization and zero new consumption on each hot request. Changed
cases must agree with the Lean decision and the exact native refusal.

[[file:../../../dev/proofs/quint/SourceLoader.qnt][SourceLoader.qnt]] has eight scoped outcomes: positive safety plus old saved
edge, missing reload check, unchecked retry, dropped second requirement, parent
corruption, eager unused work and acceptance controls. Negative controls must
produce counterexamples. Retry coverage is source inspection plus a finite
call-edge model, NOT a native concurrent condition-variable test.

* Production gaps and reflection

1. Integrate into the actual SDK source/build/bootstrap. The copied native module
   demonstrates the strategy; the original SDK remains unchanged and retains
   the 32.41 bypass.
2. Rebuild or reject old clients and runtime units. Compiler-emitted imports and
   phase blocks still reference SDK globals; this experiment does not silently
   retarget the entire dependency closure.
3. Protect issuer bootstrap, metadata and private bytes. Compiler child, host and
   authority implementation remain trusted; no hostile-Scheme sandbox or remote
   publisher authentication has been established.
4. Keep fixed-byte loading separate from current external state and conditional
   publication, as demonstrated by 32.41's late public-path change.
5. Qualify threads, issuer revocation, shared cache ownership and exception paths
   against a rebuilt SDK. Serial fixtures do not establish concurrency safety.

Capturing a procedure no longer defeats a check compiled into that procedure's
own cache entry. Complete build/capability closure remains the real production
burden; another runtime rebinding layer would not solve it.
