* One read protocol, multiple physical access routes

| Route | Actual behavior |
|-------+-----------------|
| .ref cold | Capture preparation and getter dependencies; commit value and record only after successful computation |
| .ref warm | Deliver the existing receiver-local record; do not rerun the getter |
| .ref/cached hit | Deliver the same value record |
| .ref/cached miss | Invoke the native default thunk; record cache absence without invoking the slot getter |
| .ref/inline hit | Preserve receiver/revision/layout guard, then deliver the same record when tracking is active |
| .ref/inline miss | Existing .ref computation, then native access-site binding |
| Bootstrap anchors | Bind explicit anchor value/revision, including an already-warm inline anchor |
| Presence/name queries | Record structure and preparation dependencies without evaluating unselected values |

No observer registry retains every receiver globally. Each receiver owns its
read table; native invalidation clears it with its instance/layout caches. Tokens
retained by one admission attempt intentionally retain their receivers. Ordinary
GC can collect unreferenced object/token cycles. This is not a measured memory
bound or a concurrency proof.

Cold slot preparation can read a protocol's configuration BEFORE the getter
frame begins. A preparation record therefore belongs to the receiver, and value
and structure records retain it. A warm value cannot discard those inputs.
This is tested independently of the analogous first structural query case.

A cache-only miss is not a missing declared field. Later population of the
cache invalidates its negative observation even if no object revision changes.
Each default-thunk invocation has its own dependency observation. False remains
a valid cached value. Replay refuses stale dependencies; it does not silently
recompute getters that may have effects.

* Consumer wiring and actual field selection

#+begin_src scheme
;; gerbil-poo MOP exports, consumed by Core
(call-with-slot-read-observer observe action before: check-source)
(replay-slot-reads! roots check-source)
#+end_src

Before-read checks use the actual receiver/key to inspect existing source
specifications. Observer callbacks run with observation suspended, avoiding
recursive observation of their own metadata checks. Nested observers receive
the same read events. Core collects roots, then traverses the shared graph once
before returning; it does not replay every transitive prefix at every hit.
Replay validates each node before its callback and validates the visited set
again at the end, catching a later callback invalidating an earlier node.

SourceAdmissionContract still owns source-input checks, ordered preflight,
ONE inherited admission call, exact normalized candidate/child receipts,
contribution checks and eager diagnostic decoration. Its MOP observer does not
replace child obligations, field Types, domain relationships or plan identity.
The existing source collector performs its fresh source checks after the MOP
consumer returns. A previous accepted attempt is not a currentness cache.

* Maintained Scenario, not a synthetic replacement Contract

The Scenario remains under scenarios/gitea-postgresql. config.ss holds ordinary
PostgreSQL defaults and a missing client port. objects.ss applies missing-only
defaults to the supplied final scopes. Gitea's lexical native default follows
the final database receiver. Explicit client values are checked rather than
silently rewritten. The regression Fixture adds a counted database obligation;
it no longer replaces production preflight or wraps .admit with a private hook.

#+begin_src scheme
(def cached (.get Parent plan)) ; force both parent ports before deriving
(.def (Release @ Parent)
  config: =>.+ (.o postgresql: =>.+ (.o settings: =>.+ (.o port: 5433))))
(def receipt (.call Contract .admit Release #f))
(def final (.get receipt candidate))
;; final.plan.postgresql.port = final.plan.gitea.database-port = 5433
;; final.plan.configuration is final.config; cached remains at 5432.
#+end_src

The intermediate =>.+ operations retain maintained objects; port: 5433 is an
ordinary replacement. The test is not evidence that a scalar replacement needs
an inheritance operator. Assigning cached to Release.plan is deliberately
rejected as stale-parent-plan; normalization must not repair away that control.

* Leaf guard removal gate

Production explicit port leaf arguments are removed only AFTER the consumer
suite passes against the producer source closure. Domain preflight stages remain:
check envelopes, database settings, client settings and then plan fields. This
keeps null/malformed settings from forcing derived port computations too early.
The Contract's actual field reads, not a second field inventory, supply the leaf
observations. Unknown-field diagnosis must not force the unknown getter, even
while attaching JSON baselines and source locations.
