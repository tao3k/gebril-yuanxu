#+title: Core Proof Ownership

* Proof projects

| Package | Scope | Dependency boundary |
|---------+-------+---------------------|
| [[file:lean/README.org][lean]] | Module composition, source identity, slot demand, cache, publication, parent association and construction laws | Lean 4.34.0; LeanPoo v0.1.1 is a locked Git dependency |
| [[file:quint/README.org][quint]] | Unified Graph operations and native semantic Query boundaries | Quint 0.33.0; bounded positive cases and matched negative controls |

Run =just proofs= in Core. =just proofs-quint= checks the finite models separately;
=just check-core-lean= in the consuming workspace checks the Lean packages only.
Core file/module paths use =PooFlowCoreProof= to avoid Lake assigning shared
modules to the product library. Existing theorem namespaces remain unchanged,
so statements and callers retain their logical identities. Imports target the
single Core-owned Lake dependency; no forwarding source files are needed. Product Cedar/runtime/FFI, temporal, Context, Funflow and Healthcare
proofs remain consumer-owned. Core must not acquire those dependencies merely
because a historical proof collection grouped them together.

* Migration and evidence

53 shared Lean 4.31 models, nine Profile association Lean 4.34 models and the
NativeSemanticQuery TLA/CFG pair moved from the product proof tree. All 64
source files retain the same proof statements and bodies. 24 files are byte-identical;
40 files only change imports to the new Core module paths. Theorems, guards,
premises and historical theorem namespace names are unchanged. The complete transitive local
import closure is owned by Core, rather than copied back into the product.

The product's Lake lock now records a local Core dependency. Its Cedar and
batteries pins are unchanged. The association package retains the exact existing
LeanPoo revision and toolchain; temporal and Context consumers retain their own
independent lock. Generated .lake caches are not published source or new evidence.

Native Scheme correspondence remains subject to each theorem's explicit premises.
These models do not prove Loader integration, source authentication or deployment
execution. No Loader or module adaptation is implemented by this migration.

These are local migration checks, not remote CI or production acceptance.
The association build reused the already-installed immutable LeanPoo dependency;
no dependency revision was upgraded. The first TLC attempt was refused by the
sandbox's local socket restriction; a bounded rerun with local port permission
completed. Historical validation artifacts were not rewritten.

Core CI now owns the single Lean proof project build. Product CI initializes Core and
builds its consumer libraries; the independent product FFI smoke remains covered.
Publishing this work still requires a coordinated Core commit and product gitlink
update. Neither is performed by this local migration.

* Current finite-model owner

The historical TLA/CFG pair has been removed. The already-maintained Quint
NativeSemanticQuery source moved from the product to =core/proofs/quint/=
without changing its model. Product query checks consume this exact source.
GraphOperations and five explicit mutants now live beside it.
The verifier may generate transient backend TLA internally; maintained model
authoring and checking entrypoints use Quint only.

* Single Lean project

The former =lean-poo/= source project is merged directly into =lean/=.
Its nine association modules keep their theorem bodies and namespaces. Both
libraries build under Lean 4.34.0, with LeanPoo as one pinned Git dependency.
The preceding migration validation table is historical evidence under the old
separate toolchains, not a result for this consolidation.
